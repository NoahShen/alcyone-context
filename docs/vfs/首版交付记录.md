## 2. 已交付核心能力概览

VFS 首版作为嵌入式 Agent-native VFS Library，提供以下已闭环能力：

1. **统一逻辑寻址与路由**：
   - 统一使用 `alcyone://<namespace>/<path>` 逻辑 URI 寻址；
   - 命名空间由 Runtime 配置（`VfsRuntimeConfig.namespaces`）定义，各挂载项由 `mounts: List<MountConfig>` 提供；
   - 挂载路由按已解码的**最长完整路径段**匹配，非段边界不匹配。
2. **多存储后端支持**：
   - 本地文件系统（`MountBackend.LocalFs`）；
   - WebDAV 远程存储（`MountBackend.WebDav`，配置协议支持 HTTP / HTTPS 基础认证与 TLS；本轮测试套件在实机 HTTP WsgiDAV 隔离环境下完成闭环实测）。
3. **核心文件与目录操作**：
   - 读取：全量读取 `read`、分块流式安全读取公开入口 `openStream(uri, options)`；调用方须对返回的完整 `VfsStreamResult` 使用 `.use { ... }` 确保释放流通道并触发完成状态；ByteArray read 受 defaultReadMaxBytes 与 ReadOptions.maxBytes 的较小值约束；openStream 按实际读出字节受 streamTotalLimit / VfsStreamOptions.maxTotalBytes 收紧，默认可不设总量上限（按块分块读取，不将全量载入内存）；
   - 写入：`CREATE_NEW`、`REPLACE_EXISTING`、`UPSERT` 三种模式；成功路径先完成物理 I/O 再提交 SQLite 逻辑元数据；失败时按实际副作用（`NONE` / `PARTIAL` / `UNKNOWN`）如实报告错误模型，不承诺跨 Storage 物理与 SQLite 逻辑的“联合原子一致”，首版无自动分布式事务回滚；
   - 状态查询与目录列出：`stat` 确认底层资源后懒注册 UUIDv7 Node ID、`getNode` 查询已登记逻辑节点、`list` 合并物理直接子项与已配置目录入口再关联已登记 Node ID；不从历史 Node 恢复已消失的物理条目，也不批量登记；
   - 移动：同 Mount 优先根据后端能力选择原生 rename，当前目录移动走安全复制回退；跨 Mount 移动严格按“读源-写目标-确认-删源-迁移 Node”编排；移动过程保持 Node ID 身份不变，复制回退 / 跨 Mount 复制路径的单个文件受读写限额约束（原生 rename 不读入文件内容，不受此限额约束），目录移动仅发单条根级 `DIRECTORY_MOVED` 事件；
   - 删除：文件删除与目录递归删除；物理删除成功后，在同一 SQLite 事务内标记 Node 删除、清理 Metadata 并追加一条目标级删除事件；事务提交成功后才异步通知（发单条根级 `FILE_DELETED` 或 `DIRECTORY_DELETED` 事件）。
4. **节点身份与元数据管理**：
   - 基于 UUIDv7 的稳定 Node ID；移动/跨后端移动保持身份不变更；
   - 支持元数据（`NodeMetadata`）整体替换与时间戳同步更新。
5. **事件与通知机制**：
   - 逻辑状态与事件日志在 SQLite 单连接严格事务（`BEGIN IMMEDIATE`）中原子提交；
   - 提交后通过内存通道向订阅者（Consumer）异步分发；
   - 异常分层隔离：普通 Consumer 抛出 `Exception` 被隔离记录并继续后续 Consumer；Consumer 自抛 `CancellationException` 时，若 worker 仍活跃则处理后续事件；worker 自身取消会退出，未捕获的 `Error` 也可终止 worker；
   - 有界队列（默认容量 256，可由 eventBufferCapacity 配置）满时记录 WARN 并丢弃通知，但不删除数据库中已持久化的事件记录；首版通知为尽力而为（Best-effort），不保证必定送达。
6. **生命周期与状态持久化**：
   - 控制平面基于 SQLite 单连接严格事务（`BEGIN IMMEDIATE`）；
   - 优雅关闭（`close` 协调等待 in-flight 任务完成、释放 Operator 与数据库句柄、取消分发协程）；
   - 正常关闭后支持原路径重新打开并保证节点身份一致性。

## 3. 支持边界与已接受限制

为确保接入方在合理假设下设计系统架构，明确以下已接受的设计与运行边界：

1. **平台支持边界（Mac-Only 承诺）**：
   - 仅在 **macOS arm64**（Apple Silicon）完成实机完整测试与验证；
   - Linux (x64 / arm64) 构建配置已保留但当前未做实机实跑验证，不作正式支持承诺；
   - 本地打包发布的 Mac 产物中，OpenDAL 的 native classifier 固定为 `osx-aarch_64`，跨架构机器直接引用会因缺少 native binary 失败。
2. **网络等待与阻塞边界（方案④）**：
   - 底层 JNI/Rust 原生网络请求与 `close()` 不提供最长耗时保证；
   - 当遇到网络挂起或远端无响应时，禁止外部宿主线程强杀（强杀可能导致 JVM 进程崩溃或 JNI 内存泄漏），需等待原生层完成或超时。
3. **状态库与事务边界**：
   - SQLite 状态库仅支持**正常关闭后的离线冷备份与原挂载路径恢复**（必须同时保全状态库、物理数据与挂载配置）；
   - 不承诺在线热快照、崩溃自动恢复（Crash Recovery）或跨后端物理操作与 SQLite 的分布式事务原子回滚；
   - 跨后端移动过程中若目标写入成功但删源失败：Core 尚未进入 `commitMove`，源文件可能完整、部分残留、甚至远端物理已删但响应超时丢失（报 `UNKNOWN`）；系统不主动发起破坏性补偿，逻辑移动不提交，保留可观察现场供只读核对，**不保证两端物理文件仍完好无损**，禁止上层盲目静默清理源端。
4. **安全与权限边界**：
   - VFS 无内置 Agent 身份体系，亦无 ACL 访问控制权限模型；
   - Agent 的工作目录范围隔离与访问权限必须由上层 **Context System** 在调用 VFS 之前约定和实施。
5. **事件边界**：
   - 事件仅保证进程内尽力而为分发与基础持久化日记，不包含分布式消息重试、持久化消费位点与重启重放能力（规划于后续 E05 扩展）。

    mavenCentral {

            excludeGroup("com.github.noahshen.alcyone")
