# Alcyone VFS SDK 运行维护说明

> 本次修改（2026-10-13，T30 复核修复 R1～R5）：彻底撤回“SQLite 采用 WAL/checkpoint”无依据表述，对齐单连接与默认 DELETE 日志模式及正常关闭冷备份事实；纠正错误码与 effect 映射（仅预检阶段拒绝为 NONE，目录复制超限等实际产生 PARTIAL，删源确认失败保留 UNKNOWN）；纠正跨后端移动失败处置（禁止盲目 stat 两端后补删源，改为停止写入保留现场并只读核对）；覆盖六类典型运维诊断（初始化、Storage、状态提交、Consumer、队列丢弃、关闭）；更正 limits.readBytes 为 defaultReadMaxBytes / defaultWriteMaxBytes；收窄凭据脱敏范围；精简术语。

本文档面向 Alcyone VFS 的运维人员及系统集成工程师。

## 1. 状态库定位与重开独占机制

### 1.1 状态库是持久逻辑状态存储（不是缓存）
Alcyone VFS 的 SQLite 状态库（`stateDatabase` 指定的文件）保存着文件系统全部的核心元数据，包括：
- 节点全局身份（UUIDv7 格式的 Node ID）
- 逻辑路径映射与命名空间
- 用户自定义元数据（Tags、Description、时间戳）
- 挂载点身份对齐记录（Mount 表）
- 历史操作事件流水

> **严禁操作**：
> - **切勿将状态库当做普通缓存随意删除！** 删除状态库将导致所有文件的 Node ID 丢失、元数据清空、移动链路断裂，且未登记文件的逻辑属性失效。
> - 本地挂载的物理根目录下**不能包含状态库文件**，防止底层递归扫描时将自身状态库文件纳入受管物理资源。

### 1.2 进程独占与重开一致性
1. **文件锁独占**：同一个状态库同一时间仅允许一个 `AlcyoneVfs` 实例打开。运行时会在数据库同级目录生成独占锁文件（`<dbName>.lock`）。若检测到冲突，启动将直接抛出 `CONFLICT`。**切勿通过强行删除锁文件绕过冲突检查**，否则多进程并发写入会损坏 SQLite 数据库。
2. **挂载身份比对**：重新打开状态库时，VFS 会严格比对当前配置与历史记录中的挂载身份（`storageKey`、后端类型、规范化物理路径/WebDAV endpoint+root）。若发现相同 `storageKey` 被指向了不同的物理根，将视为挂载冲突并拒绝启动（抛出 `VfsException: VFS configuration conflict`）。

## 2. 状态库文件机制与离线冷备份恢复规范

### 2.1 底层存储与文件布局事实
Alcyone VFS 的 SQLite 驱动使用标准单连接模式（默认 `DELETE` journal 模式，**非 WAL 模式，无 wal/shm 伴随文件，亦无需也不支持 checkpoint 操作**）。
- **正常关闭后**：数据库仅存在单一的主文件（如 `state.db`），临时 journal 已自动清理；
- **异常中断/崩溃后**：同级目录下可能残留 `<dbName>-journal` 回滚日志文件。**切勿手工删除该 journal 文件**，否则会导致 SQLite 无法执行崩溃回滚恢复。

SQLite 仅保存逻辑状态，**不包含文件内容本身**。本地文件数据保存在本地磁盘，WebDAV 数据保存在远端服务器。本系统不提供在线快照或跨存储后端的分布式原子快照。备份必须在**离线冷环境**下进行。

### 2.2 离线冷备份标准步骤
1. **停机阻断**：暂停所有业务写入。
2. **正常关闭**：调用 `vfs.close()` 并确认正常退出。检查状态库目录：确认单连接已断开，文件锁（`<dbName>.lock`）已释放。
3. **备份文件复制**：
   - 复制主状态库文件（如 `state.db`）；
   - 若遇到异常关闭且存在伴随文件（如 `state.db-journal`），必须原样完整复制，绝不可遗漏或单方面删除；
   - 复制对应本地挂载的全部物理目录及文件数据；WebDAV 数据需按远端存储系统的备份方案独立备份。
4. **归档配置**：将启动配置中的非秘密身份参数（挂载逻辑路径、storageKey、规范化物理根、WebDAV endpoint 与 root）归档备案。**安全凭据（密码）必须通过宿主凭据管理系统安全保管，切勿将明文密码直接写入归档文件**。

### 2.3 灾备恢复与隔离验证步骤
当物理介质损坏或需要冷备恢复验证时：
1. **原挂载路径环境恢复**：将备份的状态库文件及所有本地物理存储数据回拷到配置指定的物理路径。
2. **配置重开**：使用原配置（保持一致的挂载路径、storageKey 与后端身份）启动 `AlcyoneVfs.create(config)`。
3. **一致性检查**：
   - 执行 `stat(uri)` 核对 Node ID 与备份前一致；
   - 执行 `getMetadata(nodeId)` 核对 Tags 与 Description 完整；
   - 执行 `read(uri)` 核查文件内容。

> **注意**：恢复时必须保持挂载身份（路径与 key）一致，否则启动将触发挂载冲突检查而拒绝启动。

## 3. 错误模型与六类典型故障诊断

### 3.1 异常结构：`VfsException`
当领域操作失败时，VFS 抛出 `VfsException`（协程取消场景直接抛出 `CancellationException`，不被 VfsException 包装）：
- `code`（`VfsErrorCode`）：稳定错误枚举。
- `effect`（`VfsEffect`）：
  - `NONE`：确认没有任何逻辑或物理变更提交（例如参数校验、路径越界等预检阶段被拒绝）；
  - `PARTIAL`：已产生部分变更（例如跨后端移动已在目标端成功写入，但删除源端失败，或者目录复制过程中部分子项因超限失败）；
  - `UNKNOWN`：无法确认底层状态（例如网络超时、确认响应丢失、rename 返回失败），不能假设没有提交。
- `cause` / `suppressed`：保留底层原始引发异常及附带的清理异常。

### 3.2 常见错误码与运行时 Effect 真实映射

| 场景 | 错误码 | 阶段与副作用 (`effect`) | 排查方向 |
| :--- | :--- | :--- | :--- |
| **挂载/路径不存在** | `MOUNT_NOT_FOUND` / `NOT_FOUND` | 预检阶段拒绝：`NONE` | 检查命名空间是否已配置、URI 拼写是否正确。 |
| **实例已关闭** | `CLOSED` | 预检阶段拒绝：`NONE` | 在 `vfs.close()` 之后调用了操作，检查生命周期。 |
| **单项超限** | `LIMIT_EXCEEDED` | 预检读取超限为 `NONE`；目录跨 Mount 移动部分子项超限为 `PARTIAL` | 检查 `VfsLimits.defaultReadMaxBytes` / `defaultWriteMaxBytes` 或使用 `openStream`。 |
| **目标冲突** | `ALREADY_EXISTS` | 预检阶段拒绝：`NONE` | 写入（CREATE_NEW）或移动目标已存在，VFS 不隐式覆盖。 |
| **并发独占冲突** | `CONFLICT` | 初始化预检拒绝：`NONE` | 同一状态库已被另一实例持有锁，排查残留进程。 |
| **底层存储拒绝** | `STORAGE_ACCESS_DENIED` / `READ_ONLY` | 按执行阶段：预检为 `NONE`；已写目标后删源失败可能为 `PARTIAL` 或保留底层 code | 检查磁盘文件权限或 WebDAV 只读属性。 |
| **网络响应丢失** | 底层保留或转换 | `UNKNOWN` | 物理操作可能已完成但客户端未收到响应，不能武断视为 NONE。 |

### 3.3 六类典型故障诊断排查

1. **初始化失败**：
   - 常见原因：命名空间非法、挂载根包含状态库文件、多个 storageKey 指向不同后端冲突、独占锁文件已存在、SQLite 版本不兼容或 schema 迁移失败。
   - 排查：检查传入的 `VfsRuntimeConfig`、检查 `.lock` 文件及对应进程存活。
2. **Storage 访问失败**：
   - 常见原因：本地磁盘权限缺失、磁盘空间满、WebDAV 服务端不可达、HTTP 401 认证失败、服务端返回 403。
   - 排查：检查物理磁盘读写权限；检查 WebDAV 凭据（认证异常已脱敏，检查宿主提供的网络连通性）。
3. **状态库提交失败（STATE_ERROR）**：
   - 常见原因：物理文件已写入成功，但 SQLite 事务在最后提交时发生冲突或磁盘 I/O 错误，导致**物理文件已落盘但逻辑状态未提交**。
   - 排查：查看异常的 `cause` 与 `suppressed`；排查 SQLite 状态库所在磁盘空间与写入权限；此时底层文件已存在但逻辑未登记，重新写入或 stat 会触发未登记状态处理。
4. **Consumer 异常**：
   - 现象：`vfs.write` 成功，但 Consumer 逻辑未生效或报错。
   - 原因：Consumer 抛出的普通 Exception 被内部分发器捕获并记录日志（SLF4J 日志，宿主需提供如 Logback / SLF4J Simple 等绑定实现方可输出日志）；Consumer 抛出的 CancellationException 会被重抛但常驻 worker 会继续执行后续事件。
5. **事件队列丢弃（Queue Dropped）**：
   - 现象：高并发写入或慢 Consumer 场景下，部分事件未收到通知。
   - 原因：事件通道为固定容量有界队列（默认 256）。丢通知**不等于删除持久化事件**，数据库 `event` 表中仍完整记录历史变更。排查是否存在阻塞慢 Consumer。
6. **实例关闭失败**：
   - 现象：`close()` 抛出异常或超时。
   - 原因：关闭失败不得当作正常备份的前提。检查是否有未关闭的流、后台协作任务阻塞。方案④下底层 native WebDAV 请求若卡死，`closeGracePeriod` 无法强杀，切勿强制 kill 线程。

### 3.4 凭据安全保护范围
- **受管范围**：VFS 内部保证受管配置对象的安全打印（`MountBackend.WebDav.toString()` 屏蔽密码）、挂载身份串及持久表不存密码、真实 WebDAV 认证失败异常管线脱敏。
- **未受管边界**：VFS **没有全局日志脱敏器**。`EventDispatcher` 直接记录 Consumer 抛出的异常对象；若宿主应用或 Consumer 自行在异常消息中拼接入敏感凭据，VFS 不会主动清洗。

## 4. WebDAV 等待限制与部分失败应对（方案④）

### 4.1 方案④机制说明
1. **无全局超时强杀保证**：底层 native 请求与网络 I/O 并不提供全局超时强行中断保证。
2. **`closeGracePeriod` 语义**：该参数仅代表运行时进入 closing 状态后，等待在途任务完成的协作等待期限；**不等于 native 请求或 close 调用的最长绝对耗时**。
3. **禁止强杀线程**：若远端服务端无响应或网络阻塞，不建议外部调用方强行终止工作线程，否则容易损坏底层的 OpenDAL native 状态及资源句柄。

### 4.2 跨后端移动部分失败处置指南
当跨后端移动（如 Local FS ↔ WebDAV）返回 `PARTIAL` 或 `UNKNOWN` 时：
- **物理现状**：可能目标端已成功写入并确认，但源端删除失败（两端均有文件）；或者确认响应丢失，目标端状态未知。
- **严禁直接无条件重试**：
  - 严禁直接重新执行整个 `move` 命令（目标端可能已存在，重试将直接因 `ALREADY_EXISTS` 失败）；
  - **切勿草率通过公开 `stat` 两端后直接公开 `delete` 源端**：因为公开 `stat` 会对目标端物理文件触发**懒注册**（分配新 Node ID），而公开 `delete` 源端会**彻底废弃原 Node ID 与 Metadata**，从而破坏原有节点身份与元数据的连续性！
- **推荐处置步骤**：
  1. 立即暂停针对该路径的后续业务写入；
  2. 保留异常现场、原始 Node ID 以及源/目标逻辑路径映射关系；
  3. 使用宿主底层工具或只读 Storage 检查两端物理文件的完整性（比对哈希与长度）；
  4. 确认目标端内容完整无损后，由人工运维在存储底层清理源端物理冗余文件，或制定受控的修复脚本（当前版本不提供跨后端分布式自动崩溃修复）。
