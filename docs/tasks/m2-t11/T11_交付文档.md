## 需求目标

在 `vfs/persistence` 实现 VFS 状态库基础设施：SQLDelight Schema（Node / Metadata / Event / Mount 四张表）、T07 四个 Repository 接口实现、`UnitOfWork` 事务实现、数据库打开/关闭/迁移生命周期。全部用**真实 SQLite** 验证（内存 + 临时文件），不引入 mock driver。

不含：事件分发（T14）、文件操作编排（T15+）、Mount 写入编排（T18）、操作恢复（E04）、跨进程独占检测。

## 主要实现

### Schema 与唯一约束（四张表）

| 表 | 设计 |
| --- | --- |
| `node` | `id` 主键、`vfs_path`、`node_type`、`physical`（0/1 CHECK）、`registered_at`、`updated_at`、`deleted_at`（可空） |
| `metadata` | `node_id` 主键、`payload`（NodeMetadata 的 JSON 文本） |
| `event` | `event_id` 主键、全字段对齐 `EventRecord`（可空列对应可空字段） |
| `mount` | `vfs_path` 主键、`storage_key` |

- **当前有效路径唯一由数据库保证**：`CREATE UNIQUE INDEX node_active_path ON node (vfs_path) WHERE deleted_at IS NULL`（部分唯一索引）
- `register` 用 `INSERT OR IGNORE` + 按路径读回：竞争时由索引裁定谁生效，落败者返回既有记录，不靠调用方先查后插
- `markDeleted`（`deleted_at` 非空）立即释放路径占用，可被新 Node 复用
- 时间戳统一 epoch 毫秒（INTEGER，UTC）

### 四个 Repository（T07 R1～R11）

- `NodeRepository`：`findByPath` / `findById` / `register` / `updatePath` / `touch` / `markDeleted` / `findSubtree` / `findByPaths`
- `MetadataRepository`：`get` / `put`（整体替换）/ `delete`
- `EventRepository`：`append`
- `MountRepository`：`list`（只读）

两个 SQLite 陷阱的处理：
1. **大小写敏感**：路径等值比较用 SQLite 默认 BINARY，无 `COLLATE NOCASE`、不用 `LIKE` 做精确匹配；`/A` 与 `/a` 是两条不同记录
2. **`_` 通配符**：`findSubtree` 不用 `LIKE`，改用精确前缀 + 段边界（`instr` / substr 方案），`/notes/a` 匹配 `/notes/a` 与 `/notes/a/b`，不匹配 `/notes/abc`

### 事务与 UnitOfWork

- **单连接驱动** `SingleConnectionJdbcDriver`：整流库共用一条 `Connection`（SQLite 事务属于连接不属于线程），替代 `JdbcSqliteDriver` 的按线程连接（后者会导致跨挂起的事务静默失效）
- **显式事务控制**：`BEGIN IMMEDIATE` / `COMMIT` / `ROLLBACK` 裸 SQL，不使用 SQLDelight 的阻塞式 `Transacter.transaction {}`
- 回调正常返回提交、抛异常整体回滚；回滚包 `NonCancellable`（取消路径也必须执行，否则事务与写锁留在库里）
- `TransactionScope` 逃逸到回调外使用抛 `IllegalStateException`，不退化为自动提交
- `CancellationException` 原样传播，不被包装成 `STATE_ERROR`
- **修复了首版死锁**：原实现用 `runBlocking` 在阻塞式事务回调里驱动挂起 block，取消路径下外层 `withContext` 与内层 `runBlocking` 互相等待（实测挂死 48 分钟）；重构后取消测试瞬时完成，并加 `@Timeout(60)` 看门狗

### 生命周期与迁移

- `VfsStateDatabase.inMemory()` / `file(path)` / `close()`
- 打开时读 `PRAGMA user_version`：`0` → `Schema.create` + 写回版本号（同一事务）；`0 < v < Schema.version` → `Schema.migrate`；`v == Schema.version` → 不删除不重建
- 首版基线 = 1；将来加迁移：在同包路径放同名 `.sqm`，`Schema.migrate` 与 `Schema.version` 自动跟进，版本号只增不减
- 数据库失败统一映射 `STATE_ERROR`（`cause` 保留原始异常），不吞异常

### 模块边界

- `persistence → core → api`；对外只暴露 `VfsStateDatabase`、各 Repository、`SqliteUnitOfWork` 与 Core 类型
- SQLDelight / JDBC 类型全部 `internal`，不泄漏到 `vfs/core`、`vfs/api`
- 不依赖 Storage / Router / Guard；`build.gradle.kts` 依赖已核对

## 关键设计决策

1. **部分唯一索引而非应用层锁**：当前有效路径唯一由数据库裁定，并发注册不产生双记录（A01）。
2. **自研单连接驱动**：SQLDelight `JdbcSqliteDriver` 对文件库按线程持有连接、语句后关闭，导致跨挂起事务静默失效且语句级 BEGIN 不成立；单连接是正确且更简单的模型。
3. **显式 BEGIN IMMEDIATE**：立即取写锁，避免延迟升级锁在并发写入时中途失败。
4. **不用 `runBlocking` 驱动挂起回调**：这是首版死锁的根因，改用普通挂起协程 + 显式事务边界。
5. **`findSubtree` 不用 `LIKE`**：`_` 是合法路径字符也是通配符，改用精确前缀 + 段边界。
6. **并发 `inTransaction` 不支持（已知边界）**：整库一条连接，多个协程并发调用会在同一连接上交错，第二个 `BEGIN` 被 SQLite 拒绝 → `STATE_ERROR`（明确失败，不静默写坏）；调用方需串行，串行化留给 T13/T15。

5. **不承诺回滚外部 Storage**：事务只覆盖 SQLite 内部（T03 §3）。
