# T08 使用说明

## 本次修改（2026-09-30，首版落地）

- 新增 `scripts/check` 作为本地与 CI 的统一检查入口：编译 + 单元测试 + 格式检查，失败返回非零且**不改写源码**。涉及第 1～3 节。
- 新增 `.github/workflows/check.yml`：`macos-14`（Apple Silicon arm64）、`permissions: contents: read`、60 分钟超时、失败时仍上传 JUnit XML 与检查日志。涉及第 3、4 节。
- 明确版本单一来源：workflow 不写任何版本号，JDK / Gradle 版本与校验和由 `gradle/toolchain.versions` 经 `./scripts/dev bootstrap` 提供。涉及第 2、5 节。

状态：**IN_PROGRESS**，交付后转 IN_REVIEW，等待独立验收。

## 1. 首次准备

项目工具链完全放在仓库内的 `.local/`，不需要改系统 Java、全局 Gradle 或 shell 配置。

```sh
git clone git@github.com:NoahShen/alcyone-context.git
cd alcyone-context
./scripts/dev bootstrap    # 下载并校验项目内 JDK 与 Gradle，下载到 .local/jdk 与 .local/gradle-dist
```

`bootstrap` 复用 `gradle/toolchain.versions` 里的版本号、下载地址和 SHA-256，是版本的唯一来源。首次下载体积较大，之后再次运行会校验并复用已有安装。

## 2. 日常检查

```sh
./scripts/check
```

等价于 `./scripts/dev gradle clean build --console=plain`，包含：

| 阶段 | 内容 |
| --- | --- |
| 编译 | `common`、`vfs/api`、`vfs/core` 真实编译；`vfs/runtime`、`vfs/storage-opendal` 等后续模块当前为空，显示 `NO-SOURCE` 属正常 |
| 测试 | 三个模块的单元测试，当前 120 个（common 10 + api 62 + core 48） |
| 格式 | Spotless + ktlint 的 `spotlessCheck`，已挂在 `check` 里 |

支持透传参数，网络不可用时可加 `--offline`：

```sh
./scripts/check --offline
./scripts/check :vfs:core:test      # 仍会先 clean build，再附加执行该任务
```

**检查入口永不修改源码。** 格式不平时它只报告失败并返回非零。

## 3. 修正格式

```sh
./scripts/dev gradle spotlessApply   # 显式修正，只在你确认要改格式时运行
./scripts/check                      # 再跑一次确认
```

不要把 `spotlessApply` 塞进 `scripts/check` 或 CI：CI 的职责是发现不合规，不是替你改代码。自动格式化会掩盖「谁引入了不合规」，也让 diff 出现与本次改动无关的行。

## 4. 报告位置

| 报告 | 本地路径 | CI |
| --- | --- | --- |
| JUnit XML | `common/build/test-results/test/*.xml`、`vfs/api/...`、`vfs/core/...` | 随 artifact `check-reports-<run_id>` 上传 |
| 测试 HTML 报告 | `<module>/build/reports/tests/test/index.html` | 同上（`build` 目录下） |
| 格式检查结果 | 只出现在控制台与构建日志里 | 同上，随 `ci-check.log` 上传 |

Spotless 没有独立的报告文件，`spotlessCheck` 的违规列表只打到控制台，所以 CI 额外把整个检查输出 `tee` 到 `.local/tmp/ci-check.log` 一并上传。

## 5. 平台限制

`scripts/dev` 在非 macOS arm64 上会直接拒绝执行：

```
T05 supports only verified macOS arm64; other native platforms are unverified.
```

| 平台 | 状态 |
| --- | --- |
| macOS arm64（Apple Silicon） | **已验证**，本地与 CI 均在此平台 |
| macOS x86_64 / Linux / Windows | **未验证**，脚本主动拒绝；OpenDAL 的 native classifier 与 SQLite 驱动在这些平台的加载未测试 |

CI 使用 `macos-14`，因为它是 GitHub 托管的 Apple Silicon 运行器标签，与本仓库唯一的已验证平台一致。换运行器会让 `scripts/dev` 直接失败，而不是悄悄换个架构跑。

CI 的运行环境按公开仓库的免费额度估算：一次 `bootstrap` 加一次完整构建约十几分钟，在 60 分钟超时内。若仓库转为私有或 Actions 额度变化，需要另行确认额度与运行器可用性。

## 6. 常见失败处理

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `Run bootstrap first` | 项目工具链未准备或安装损坏 | `./scripts/dev bootstrap`；提示损坏时先删掉 `.local/jdk` 或 `.local/gradle-dist` 对应目录再重跑 |
| `Checksum mismatch` | 下载损坏或被篡改 | 删掉对应的 `.part` 或压缩包后重跑 `bootstrap`；不要跳过校验 |
| `spotlessKotlinCheck FAILED` | 格式不合规 | 按第 3 节显式运行 `spotlessApply` |
| `There were failing tests` | 断言失败 | 打开第 4 节的 HTML 报告定位；检查入口不会替你改断言 |
| `--offline` 仍报缺依赖 | 本地缓存不全 | 去掉 `--offline` 联网补一次缓存 |
| CI 步骤失败但 artifact 为空 | `bootstrap` 就失败了，还没产生报告 | 直接看 bootstrap 步骤日志；上传步骤设了 `if-no-files-found: warn`，不会伪造测试结果 |

## 7. 设计取舍

- **检查入口只有一个 Gradle 调用**，没有拆成「先编译、再测试、再格式」三段。拆开只会让失败时多跑几遍，且 `build` 已经把三者串起来了。
- **不做缓存**。缓存 Gradle 依赖需要处理 `gradle/toolchain.versions` 的校验与目录布局，本轮收益有限；等 CI 时长确实成为问题时再加。
- **不引入发布、部署、凭据、分支保护**。T08 只负责「能否构建并通过检查」。
