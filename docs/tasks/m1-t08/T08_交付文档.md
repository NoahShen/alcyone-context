## 关键设计决策

1. **单一入口**：`scripts/check` 仅一条 `exec ./scripts/dev gradle clean build` 调用，不拆成多段，不因失败而重试。
2. **版本单一来源**：JDK / Gradle 版本号与 SHA-256 仅在 `gradle/toolchain.versions` 声明一次，`scripts/check` 与 CI workflow 均不硬编码。
3. **平台白名单**：`scripts/dev` 按 `uname` 判断，只允许 macOS arm64、Linux x64、Linux arm64 三个**已配置支持**的平台，其余主动拒绝。三个平台的实际验证程度不同：macOS arm64 已实跑完整构建，Linux x64 仅验证工具链与配置逻辑，Linux arm64 仅静态检查。CI 选用 `ubuntu-latest`（Linux x64），不与运行器预装 JDK 混用——`./scripts/dev bootstrap` 会安装项目内 JDK 并使用它。
4. **不自动格式化**：`scripts/check` 不调用 `spotlessApply`；格式违规时仅报告失败，由开发者显式修正。
5. **CI pipefail 修复**：GitHub Actions 默认 shell 不含 `pipefail`，`| tee` 会吞掉退出码；显式 `shell: bash` 启用 `-eo pipefail` 后修复。
6. **不引入缓存**：Gradle 依赖缓存非本轮必需，待 CI 时长真正成为瓶颈再加。

## 已知问题 / 限制

1. **Linux arm64 未验证**：远端 CI 只覆盖 Linux x64。`linux-aarch_64` 归档的下载、校验和与完整构建从未运行，需 ARM runner。
2. **artifact 内容未独立核对**：下载需鉴权（无 token 时 API 返回 401）；产物名称与字节数与报告一致，但内部文件列表需登录确认。
3. **OpenDAL native 未加载验证**：R1 修的是配置阶段与依赖 classifier。CI 中该模块无源码、只解析依赖，并未加载 native；实际加载属 T12。
4. **PR 与手动触发未实跑**：本次为 `push` 事件，`pull_request` 与 `workflow_dispatch` 未经真实运行。
5. **运行器额度与镜像漂移**：`ubuntu-latest` 内容随时间漂移，未固定版本标签；额度按公开仓库免费额度估算。
6. **Spotless 无结构化报告**：违规只打控制台，CI 用 `ci-logs/check.log` 替代；未改构建脚本生成报告文件。
7. **未启用 Gradle 依赖缓存**：CI 每次从零下载。
