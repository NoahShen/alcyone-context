## 关键设计决策

1. **单一入口**：`scripts/check` 仅一条 `exec ./scripts/dev gradle clean build` 调用，不拆成多段，不因失败而重试。
2. **版本单一来源**：JDK / Gradle 版本号与 SHA-256 仅在 `gradle/toolchain.versions` 声明一次，`scripts/check` 与 CI workflow 均不硬编码。
3. **平台严格匹配**：`scripts/dev` 仅允许已验证平台（macOS arm64、Linux x64、Linux arm64）；非验证平台主动拒绝，拒绝方式是通过 `uname` 判断而非版本号对比。CI 选用 `ubuntu-latest`（Linux x64），不与运行器预装 JDK 混用——`./scripts/dev bootstrap` 会安装项目内 JDK 并使用它。
4. **不自动格式化**：`scripts/check` 不调用 `spotlessApply`；格式违规时仅报告失败，由开发者显式修正。
5. **CI pipefail 修复**：GitHub Actions 默认 shell 不含 `pipefail`，`| tee` 会吞掉退出码；显式 `shell: bash` 启用 `-eo pipefail` 后修复。
6. **不引入缓存**：Gradle 依赖缓存非本轮必需，待 CI 时长真正成为瓶颈再加。

## 已知问题 / 限制

1. **远端 CI 未实际运行**：无 GitHub 远端推送权限，首次运行需下载约 300 MB 工具链。验收记录已明确区分"本地已实跑"与"远端未运行"，**不宣称 CI 已绿**。远端首次运行后需在验收记录第 6 节补提交号与运行链接。
2. **运行器额度**：`ubuntu-latest` 按公开仓库免费额度估算，未核实账号实际配置。
3. **Linux 未构建验证**：工具链脚本（R1 的 classifier 选择、R2 的 bootstrap、R3 的日志路径）已在 macOS 上逐项验证逻辑，但**整套链路未在真实 Linux 上跑过**；Linux x64 为部分验证，Linux arm64 为仅静态验证。macOS x86_64 / Windows 仍不支持，`scripts/dev` 主动拒绝。
4. **OpenDAL native 未加载验证**：R1 修复的是配置阶段与 classifier 选择，不代表 Linux 上 native 能实际加载；后端与 native 加载验证属 T12。
5. **Spotless 无结构化报告**：违规只打控制台，CI 用 `ci-logs/check.log` 替代；未改构建脚本生成报告文件。
6. **未启用 Gradle 依赖缓存**：CI 每次从零下载。
