## 2. 必须修改

### R1 / P2：两条取消用例的通知断言存在订阅竞争

位置：`DefaultVfsRealStackTest.kt:793–797、851–856` 的预置写入和随后订阅，及 `837、904` 的收件箱断言。`write(a.txt)` 返回只保证创建事件已入队；`AsyncEventNotifier` 在分发时读取订阅者，明确允许晚订阅者收到尚未分发的旧事件，因此先 write 再 subscribe 不能证明收件箱没有 a.txt 的 FILE_CREATED。

合法时序是「a 的创建事件入队 → 测试订阅 → 后台才分发创建事件」；此时两条测试分别多一个 written ID，本次全绿不消除这个竞争。末尾哨兵只能确认前面的通知已处理，不能排除预置事件；这影响通知断言的稳定性，不否定原始取消、物理状态与事务回滚断言。

修复要求：在预置写入之前订阅，并按该次创建事件的 ID 等待、将其明确计入预期，或改为真盘 + 真库预置而不生成通知。保留末尾按 ID 哨兵及原异常检查，不用 sleep、忽略所有旧 ID 或重跑次数替代时序保证；修复两条新增取消用例即可，不要求改生产通知语义。
