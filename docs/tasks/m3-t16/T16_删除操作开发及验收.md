## 1. 目标与范围

实现现有 `Vfs.delete(uri, DeleteOptions)`，替换 DefaultVfs 的阶段拒绝；复用 Storage.delete、NodeRepository.markDeleted/findSubtree、MetadataRepository.delete 和 EventPipeline。Core 只依赖 Port，真实 SQLite + Local FS 验证仍放 integration-tests，不提前实现 Metadata 公共 API、移动或 Runtime。

例：删已登记的 a.txt 后，物理文件消失、旧 ID 查不到、Metadata 清空；重新 write 同一路径可成功且获得新 ID，历史事件仍保留旧 ID。

## 2. 开发内容

### 2.1 预检与唯一持锁者

复用共享 StateBoundary，一次持锁覆盖检查、Storage 删除及逻辑提交；使用 T14/T15 的 commitInsideBoundary，SQLite 事务只覆盖最后的状态与事件。先拒绝已知配置结构冲突，再按路由确认物理存在性与实际类型，按真实类型构造删除 intent 并执行 Guard 检查；不能用会懒注册的 stat/Registry 入口给未登记对象先造身份。

逻辑根、命名空间根、Mount 根及承载后代 Mount 的祖先均不可删除，即使 recursive=true。已知只读、缺失挂载、类型/状态冲突在删除副作用前拒绝；不为这些检查新增权限或身份机制。

例：`/resources/work` 下有子 Mount `medical`，整体删除 work 被拒；删除 work 下不属于该配置目录的普通文件允许。

### 2.2 文件与目录语义

文件删除不要求 recursive；缺失目标返回 NOT_FOUND，不当作幂等成功。空普通目录可非递归删除，非空目录返回 DIRECTORY_NOT_EMPTY；recursive=true 删除普通目录子树，不顺带删除目标以外的空父目录。

使用 T12 已实现的 Storage.delete，不在 Core 重写物理递归遍历或逐项删除算法；已登记 Node 的类型若与确认的物理类型冲突，不通过删除静默修复，按既有 CONFLICT 语义拒绝。外部并发修改仍沿用首版边界，不承诺跨进程原子条件删除。

例：删 `/resources/a/b.txt` 后 a 保留；删除不存在的 b.txt 不清理旧逻辑记录，也不发布成功事件，外部变更修复仍属 E04。

### 2.3 逻辑记录与 Metadata 清理

在物理删除前读取必要的已有逻辑记录，避免可预知的状态查询失败落在副作用之后；删除成功后在同一事务中标记这些 Node 删除、清理各自 Metadata 并追加事件。文件处理目标记录；目录处理目标及完整段边界内的已登记子树，不依赖根目录是否登记，也不批量注册物理子项。

目录成功删除后，其范围内已登记但物理上已缺失的子记录也随之失效，包括非递归删除实际空目录的情况；目录已不存在这一成功事实允许清理该逻辑子树。严禁匹配同名前缀兄弟，历史事件不删除；物理失败时保留原逻辑状态，不尝试按猜测部分清理。

例：a 未登记但 a/b.txt 已登记，递归删除 a 仍须清理 b 的记录和 Metadata；`a-old` 与 `A` 不属于 a 的逻辑子树。

### 2.4 删除事件的最小口径

本任务采用一次成功 delete 产生一条目标级事件：文件为 FILE_DELETED，目录为 DIRECTORY_DELETED，uri 为请求目标，nodeId 为目标已有 ID；未登记目标则为 null。目录事件表示整次目录删除完成，不为每个后代另造事件或身份；这是本轮明确的事件粒度，使用说明与交付需回写该选择，Consumer 应将目录事件理解为子树失效。

例：未登记目录 a 下有三个已登记文件，成功后清理三个 Node，追加一条 `DIRECTORY_DELETED(a, nodeId=null)`。追加失败则整批逻辑变更回滚，无成功通知。

### 2.5 失败事实与取消

Storage 删除失败时，不提交成功状态或事件，原错误码与 effect 按后端事实传播，不能把 PARTIAL/UNKNOWN 降为 NONE。Storage 已成功但状态清理或事件提交失败返回 STATE_ERROR + PARTIAL，保留 cause；物理删除不可用数据库回滚恢复，不自动补偿。

CancellationException 原样传播，提交附近取消不等于没有发生删除；通知丢弃或 Consumer 失败不改变已提交结果。例：递归删除已删掉一个子文件后失败，保留后端 PARTIAL，原 Node/Metadata 暂不清理，也不发布整个目录删除成功的事件。

## 4. 验收标准

| 编号 | 必须满足 | 核心证据 |
| --- | --- | --- |
| A01 基础删除 | 已登记/未登记文件、空目录删除正确，缺失报 NOT_FOUND，非空目录非递归拒绝 | 真实盘验证；删除未登记对象无新增 Node，文件事件 ID 可空，非空拒绝不改状态/事件 |
| A02 结构与预检 | 根/命名空间/Mount/其祖先受保护；路由、只读、类型冲突先于副作用 | 替身确认 Storage.delete 未调用；recursive 不绕过保护，普通同目录文件仍可删 |
| A03 子树与身份 | 递归清理已有 Node/Metadata，无需根登记；完整段、大小写边界正确，父目录与兄弟不动 | 真库预置非空 Metadata、根未登记但子已登记、物理已缺失的子记录；删除后旧 ID NOT_FOUND，同路径重建获得新 ID，历史事件保留 |
| A04 事务与事件 | 一次目标级事件与所有逻辑清理同事务，提交后才通知 | 真盘删除后制造真实 SQLite 追加冲突，验证 Node/Metadata 回滚、旧事件保留、STATE_ERROR/PARTIAL；失败无通知用按 ID 末尾标记确认 |
| A05 Storage 失败 | NONE/PARTIAL/UNKNOWN 保真，失败不提交成功状态/事件，不自动补偿 | 受控 Port 故障覆盖三种 effect；部分删除可让包装器真的删一个测试文件再抛错，明确其为故障注入而非 OS 自发故障 |
| A06 串行与取消 | delete 整链共享边界，不与 write/stat 发生未协调状态交错；取消原样传播且锁释放 | 受控占锁删除时启动后续变更，明确请求已执行到挂起点且未碰 Storage；取消从 DefaultVfs 调用内部捕获值检查，随后同边界操作能完成。只做最小组合，不穷举 T27 |
| A07 模块与范围 | Core 仅认 Port，复用 Adapter 递归；只解锁 delete，其他阶段方法保留 | 依赖审查；修订原“四个未交付方法”的测试为三个，read/write/stat/list/getNode 无回归；不扩大公共 API |
| A08 构建与交付 | 原 508 例无回归、新增用例实际执行、证据诚实 | 项目工具链 spotlessApply / scripts/check；分模块 XML、提交号、真实栈/替身/源码审查分别记录，明确平台未验证项 |

例：测试中模拟 Storage 部分删除只能证明编排保留 effect，不能当作所有真实后端故障行为都已验证。重复通过不能代替已进入竞争的证据，移除锁/包装取消的变异可用于核对关键断言，需明确是否实际运行。
