## 6. 取消用例的稳定性（复核 R1 要求）

R1 修复后，两条取消用例所在类 `DefaultVfsRealStackTest`（19 例）**连跑 10 次全部通过**，无一次出现收件箱多出预置创建事件的情况：

```
for i in $(seq 1 10); do ./scripts/dev gradle :integration-tests:vfs:test --tests "*DefaultVfsRealStackTest"; done
→ pass=10 fail=0
```

稳定性依据不是重跑次数本身，而是时序保证：**先 `subscribe` 再 `write`**，并按真库的 `lastEventId()` 显式 `await` 到那条创建事件被分发处理完，才固定收件箱基线；之后的断言是「基线 + 期望的新事件」逐条比对，末尾哨兵按 ID 确认排在它之前的通知都已处理。没有使用 sleep，也没有忽略旧 ID。

## 7. 已知边界（交付给复核方）

1. **目录事件粒度**是本轮的契约决定（一条 `DIRECTORY_DELETED` 表示子树失效），已写进 [使用说明](T16_使用说明.md) 第 4 节与本任务文档 §2.4；若复核方倾向逐文件事件，需要同时改契约与本轮用例。
2. A04 用例的预置**不走 `DefaultVfs`**：主键冲突包装器会把每个事务的第一条事件换成固定 ID，所以文件、Node、Metadata、历史事件都直接用真仓库预置，只让待测的删除撞主键；这不是绕过验证，删除链本身完全真实。
3. 取消现在有**两个**用例，分别覆盖两段路径：物理删除前（`Storage.delete` 挂起点）与提交附近（第一次 `markDeleted` 写入之后、`metadata.delete` 之前，`commitInsideBoundary` 内）。提交附近那个因此直接证明的是 **Node 回滚 + Metadata 保持原样**；「Metadata 也随事务回滚」由 A04 的真实主键冲突用例证明（那里 `metadata.delete` 已经执行过）。两处回滚都由 `SqliteUnitOfWork` 在 `NonCancellable` 里真实执行。
4. `PausingCommitUnitOfWork` 只让**第一次** `markDeleted` 挂起；后续操作的 `markDeleted` 不再被拦，用例用 `pausedMarks() == 1` 固定这个前提。
