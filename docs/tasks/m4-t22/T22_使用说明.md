## 1. 一句话

`move` 现在支持**普通目录**：同 Mount 与跨 Mount 都能移动，空目录不丢，已登记子 Node 保持自己的 ID 与 Metadata。

## 2. 怎么用

```kotlin
val vfs = AlcyoneVfs.create(config)
try {
    // 物理目录 work/{a.txt, images/b.png, drafts/}，drafts 是空目录
    val moved = vfs.move(
        VfsUri.parse("alcyone://resources/local/work"),
        VfsUri.parse("alcyone://resources/archive/work"),
    )
    println("${moved.uri} ${moved.id}")   // 目标位置 + 根身份
} finally {
    vfs.close()
}
```

移动之后：
- 目标树下文件内容、空目录都在，源树整棵消失；
- 之前 `stat` 过的子文件仍是**同一个 Node ID**，`getNode(旧 ID)` 现在指向目标路径；
- Metadata 原样保留；
- 事件日志里只多**一条** `DIRECTORY_MOVED`。

## 3. 身份语义

| 情形 | 行为 |
| --- | --- |
| 根已登记 | 复用原 ID、`registeredAt`、Metadata |
| 根未登记、子已登记 | 只为**根**建一次 `DIRECTORY` 身份；子 Node ID 不动 |
| 完全未登记的后代 | **不批量注册**，移动后仍是物理文件 |

`findSubtree` 按**完整路径段**选取：移动 `a` 只会带上 `a/...`，`a-old/...` 与 `A/...` 原地不动。

## 4. 目录事件粒度

一次成功目录移动只发**一条根级** `DIRECTORY_MOVED`：

| 字段 | 值 |
| --- | --- |
| `nodeId` | 源根身份（未登记则为空） |
| `uri` | 目标根 |
| `sourceUri` / `targetUri` | 源根 / 目标根 |

它表示该根之下**按完整段边界**的整棵子树路径已迁移。**不**为每个已登记子 Node 发 `FILE_MOVED`，也**不**为复制过程中产生的目标文件发 `FILE_CREATED`。Consumer 需要逐文件信号时自行展开子树。

## 5. 不同后端怎么走

| 情形 | 策略 |
| --- | --- |
| 同 Mount + 后端支持原生目录移动 | `storage.move`（一次调用，不读内容） |
| 同 Mount + 不支持原生目录移动 | **复制回退**：枚举 → 逐条复制 / 建目录 → 整树确认 → 删源 |
| 跨 Mount | **复制**：同上，源与目标各用各自的盘 |

Local FS 的 `nativeDirectoryMove` 恒为 false，所以本地磁盘上的目录移动实际都走复制。

## 6. 复制路径的限额

目录复制会**真的把内容读进内存**再写出去，所以单文件受 Core 读写限额约束：

- 上限 = `min(VfsLimits.defaultReadMaxBytes, VfsLimits.defaultWriteMaxBytes)`，默认各 16 MiB；
- 某个文件超限 → 报 `LIMIT_EXCEEDED`，**整棵源树保持**，目标允许留已复制部分的内容；
- 原生目录移动不读内容，不受这个限额影响。

## 7. 失败时的事实

| 阶段失败 | 结果 |
| --- | --- |
| 枚举源树失败 | 目标一个字节都没碰，effect `NONE` |
| 某个文件读 / 写 / 确认失败 | **整棵源树保持**，目标可能留部分内容，**一个源删除都没发生**，effect 至少 `PARTIAL` |
| 整树确认发现目标条目集合 / 类型 / 可用长度不符 | `CONFLICT`，同样不删源 |
| 目标确认阶段的后端 `list` / `stat` 失败 | 保留后端 `code` / `cause`（含 `UNKNOWN`），只把 `NONE` 升 `PARTIAL`——此时目标已经写完，不谎报「什么都没发生」 |
| 删源前源树复查发现集合 / 长度变化 | `CONFLICT`，**禁止进入删除** |
| 删源失败 | 目标完整、源可能残缺，逻辑路径仍指向源，后端原码（含 `UNKNOWN`）+ `PARTIAL`，不自动回删目标 |
| 物理搬完但状态 / 事件提交失败 | `STATE_ERROR` + `PARTIAL`，**全部逻辑路径回滚**，物理不回移，不发成功通知 |
| 取消 | 原样传播；停在条目边界，不再继续复制 / 删源 / 提交，边界随后可用 |

> 整树确认与删源前复查是**检测保障**，不是目录原子快照：不锁外部进程，也不消除最终检查之后的竞争窗口。

## 8. 什么时候会被拒（不变）

- 源或目标是**受保护配置目录**（逻辑根 / 命名空间根 / 挂载根 / 承载子挂载的祖先）→ `UNSUPPORTED_OPERATION`；
- 源树里**含另一块挂载** → 整个移动拒绝，物理变更之前；
- 目标**已存在**（文件或目录都算）→ `ALREADY_EXISTS`，不合并目录树、不当作「移进去」；
- 目标落进源自己的子树 → `INVALID_ARGUMENT`。
