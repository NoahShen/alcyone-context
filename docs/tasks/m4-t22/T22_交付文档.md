## 3. 执行顺序（`moveDirectoryByCopy`）

```
1. 目标全新（文件或目录都 ALREADY_EXISTS，不合并、不当作「移进去」）
2. 枚举源树（DFS，目录条目也收集、属性保留）      ← 失败时目标一个字节都没碰
3. 目录根身份（未登记则建一次 DIRECTORY）
4. 补目标父目录 + 建目标根
5. 逐条（父先于子）：目录 → createDirectory；文件 → copyOneFile（记实际字节数）
   每条开始前 ensureActive()，取消落在条目边界
6. 目标整树确认：重新枚举目标树，比较条目集合 + 类型 + 每个文件的可用长度
   └ 目标 list / stat 的后端失败：保留 code / cause / UNKNOWN，NONE 升 PARTIAL
7. 源复查：重新枚举源树，比较条目集合 + 类型 + 可用长度
   └ 已知矛盾 → CONFLICT，禁止进入删除；枚举失败同样合并已知变化
8. 确认通过后才 delete(源, recursive = true)
9. 同一事务：根与全部已登记后代 updatePath + 一条 DIRECTORY_MOVED
```

**关键约束**：整树复制**并确认**之后才允许任何源删除，不会「复制完第一个文件就删源」。第 6 / 7 步是**检测保障**，不是目录原子快照：不锁外部进程，也不消除最终检查之后的竞争窗口。

## 4. 决定与理由

| 决定 | 理由 |
| --- | --- |
| 目录复制用 `enumerateTree` 显式遍历，不调 `storage.delete(recursive)` 之外的批量接口 | Storage Port 只有单层 `list`；显式遍历才能建空目录、逐文件复用 T21 确认 |
| 目录条目自身也进枚举列表 | 否则空目录不会出现在目标树 |
| 整树确认比**条目集合 + 类型 + 可用长度** | 逐文件已比过一轮，最终再对目标 list 的可用长度复核；源复查防止「复制期间源变化后递归删除带走新项」。不把长度一致说成哈希一致，`null` 只表示未知 |
| 确认 / 源复查的后端失败合并已知目标变化 | 此时目标已经写完；照抄后端 `NONE` 会谎报「什么都没发生」。保留 `code` / `cause` / `UNKNOWN`，只把 `NONE` 升 `PARTIAL`，不改成 `CONFLICT` |
| 删源一次 `delete(recursive = true)` | 递归与符号链接防护交给 T12；不自己写递归删除。删源部分失败如实报告 `PARTIAL` / 后端 effect |
| 只发一条根级 `DIRECTORY_MOVED` | 一次目录移动是一个变更；为 20 个文件发 20 条事件既冗余又会让 Consumer 重复处理 |
| `commitDirectoryMove` 用 `findSubtree` | 它按完整段边界选取（`a/...` 不会误伤 `a-old/...` / `A/...`），且必须在 `updatePath` 之前查 |
| 根未登记时 `ensureSourceIdentity(…, DIRECTORY)` | 复用 T20 R1 的规则：缺失记录报状态错误，不补注册 |

## 5. 目录事件粒度

一次成功目录移动产生**一条** `DIRECTORY_MOVED`：
- `nodeId` = 源根身份（未登记则为空）；
- `uri` = 目标根；
- `sourceUri` / `targetUri` = 源 / 目标根；
- 表示该根之下**按完整路径段边界**的整棵子树逻辑路径已迁移；
- **不**为已登记子 Node 造 `FILE_MOVED`，**不**为复制过程中产生的目标文件发 `FILE_CREATED`。

已回写 T01 §8，T02 §7.2 有入口。

## 6. 契约范围

公开 `Vfs.move(source, target): NodeInfo` **签名未动**；无新增 `MoveOptions`、Manager 或执行器。复制路径（文件与目录）受 Core 读写限额约束（默认各 16 MiB），原生路径不受。
