## 5. 说明与未验证项

**旧版本库怎么造的**：版本 1 与版本 2 的差别只有 `mount` 表新增的两列，
`node` / `metadata` / `event` 三张表逐字未变。因此「真实旧版本库」的做法是：
先用当前代码建库、写入真实 Node 与事件 / 挂载行，再用 `ALTER TABLE mount DROP COLUMN …` 把 mount 退回两列形状，
最后 `PRAGMA user_version = 1`。得到的是一个真的 SQLite 文件，结构与版本 1 代码写出来的等价。
这比复制一份历史 DDL 更省事，但**前提是「两版只差这两列」成立**——该前提可由 `1.sqm` 与 `Mount.sq` 直接核对。

**平台**：本轮所有证据都在 **macOS arm64**、项目内 JDK（Temurin 21.0.12.1+1）上实跑。
**Linux x64 / arm64 本轮未验证**（文件锁语义在 Linux 上同样是 POSIX `fcntl` 锁，但没实跑过，不作结论）。

**未验证 / 本轮不承诺**：

- 公共流式读取、遗漏流回收（任务 §2.4）——未做，`vfs/api` 本轮**一行未改**；
- 关闭等待期、`closing` 状态、关闭后新操作返回 `CLOSED`（任务 §2.5）——未做；
- `close()` 期间正在进行的操作会怎样：当前实现**不等**，这些调用可能报 `STATE_ERROR` / `CLOSED`；
- 不可中断的 native 阻塞（`LocalFsStorage` 的 OpenDAL 调用）超时后的行为——本轮没有超时逻辑，也不宣称能强杀；
- 事件可靠投递 / 回放——沿用 T14 的有界队列，满了丢通知；
- 多进程**并发写**同一个状态库：只验证了「第二个启动被拒」，没有验证两个已启动实例的数据竞争（独占锁就是为此存在的）；
- `VfsStateDatabase` 的跨进程独占检测（T03 §7 原写「首版不做」）现在由 Runtime 的锁文件承担，但**库层本身**仍不检测；
- Windows 平台行为：未跑，也未评估（`tryLock` 语义与 POSIX 锁不同）。

**工程约束遵守情况**：

- Schema 升级第一次发生，按 T11 的规则命名迁移文件：`1.sqm` = 版本 1 → 2；
- 既有 542 例无回归（A01～A04 新增 25 例，总数 567）；
- 写完代码跑过 `./scripts/dev gradle spotlessApply`，交付前 `./scripts/check` 全绿；

### 6.6 第二片未验证 / 不承诺

- **已撤回的旧口径**：本节原写「超时后直接释放、不等在途」——**该结论已被 §7 的 R6 收尾等待取代**：
  取消后关闭会等所有在途操作的必要收尾完成再关库放锁，不再存在「关库早于旧操作回滚」的窗口。
  本行保留只为说明旧结论已作废，不再作为当前行为描述。

- Linux / Windows 平台：本轮证据仍在 macOS arm64；Linux 文件锁语义未实跑，不作结论。

### 7.5 R6 取消/等待职责分离（2026-10-06，复核 §10.2 / §10.3）

**问题**：R6 之前用独立的无父无子 `Job()` 作在途记录。`close()` 的 `cancelInFlight()` 对它 `cancel()`，
会让它**立刻完成**，于是随后的 `joinAll()` 直接返回、根本没等清理；而且这个 Job 没挂实际工作，取消也传不到
`openStream`。既没取消实际工作，又提前关库放锁。

**修法**：在途记录 `InFlightOp` 拆成两件事：

| 字段 | 作用 | 谁动它 |
| --- | --- | --- |
| `work`（`Job?` + 补齐机制） | 这次调用自己的子协程，取消请求发给它 | `close()` 的 `cancelInFlight()`；`work` 还没到位时先记账，到位后补发 |
| `done`（`CompletableDeferred<Unit>`） | 「这次调用彻底结束」信号，含失败清理 | **只有调用自己的 `finally`** 完成它；`close()` 只 `await()`，绝不 cancel |

取消指向 `work`（不碰宿主父 Job）；`close()` 等 `done`（取消改不动它）。

**验证**（真 SQLite / 真 Local FS / 真独占锁）：

| 用例 | 断言 |
| --- | --- |
| `a close after the grace period cancels the real work without touching the parent job` | 等 `beforeWaitingForInFlight` 确认 close 已发取消，实际工作在协程里收到 `CancellationException`；宿主父 Job 仍正常 |
| `close waits for stream cleanup to complete before releasing the database` | 清理卡住时 close 未完成、同库 `CONFLICT`；放行后 close 完成、同库可重开。清理门在 `finally` 放行，断言失败也不挂死 |
| `cancellation in scope child after block completes closes stream before runtime close` | 作用域退出点取消：流当场关闭、跟踪计数归零 |

**变异实跑**（改 `AlcyoneVfs.kt` 后 `--rerun-tasks`，立即还原）：

| # | 变异 | 结果 |
| --- | --- | --- |
| 1 | `close` 不等 `done`（直接跳过等待） | **失败**：`close waits for stream cleanup to complete before releasing the database` |
| 2 | `cancelInFlight` 改为 cancel `done`（只取消完成信号） | **失败**：`a close after the grace period cancels the real work without touching the parent job` |

两条都咬住，覆盖复核 §10.3 要求拦的两种错误。

**结论边界**：已验证的是**协作取消路径**（交接取消、等待期到点取消、清理受控阻塞时 close 必须等）。
**未验证**：不可中断的 native 阻塞、崩溃恢复。不再声称「任何 close 都严格阻拦」。

### 7.6 R6 登记原子性与断言收紧（2026-10-06，复核 §11）

**问题一（登记与待取消请求不是原子的）**：`InFlightOp.attachWork` / `cancelWork` 原本各读各写普通字段，
存在「关闭线程读到 work==null 还没写 cancelPending，工作线程写 work 后读 cancelPending 仍为 null」的交错，
取消永久丢失、close 一直等 done。

**修法**：登记 `work` 与检查 / 更新 `cancelPending` 放进**同一临界区**（`synchronized(lock)`），
读到待取消 Job 后在锁外执行 cancel。保持 work / done 分工，不换整体结构。

**问题二（宿主未取消断言过宽）**：`parentJob.isActive || parentJob.children.none { it.isActive }`
在父 Job 已取消且子任务结束时右半边为 true，证明不了「不影响宿主父 Job」。
改为 `parentJob.isActive && !parentJob.isCancelled`，删掉未使用的 `parent` 变量，`finally` 清理 caller / parentJob。

**新增用例**（`InFlightOpAtomicityTest`，`InFlightOp` 放宽为 internal）：

| 用例 | 断言 |
| --- | --- |
| `cancelWork before attachWork registration still receives cancellation` | 先取消后登记，登记后 Job 收到取消，不丢请求 |
| `attachWork then cancelWork immediate cancellation` | 先登记后取消，立即生效 |
| `cancelWork does not complete done` | `done` 不被 `cancelWork` 提前完成 |

**变异实跑**（改 `AlcyoneVfs.kt` 后 `--rerun-tasks`，立即还原）：

| # | 变异 | 结果 |
| --- | --- | --- |
| 1 | `attachWork` 不补发待取消请求 | **失败**：`cancelWork before attachWork...` |
| 2 | `cancelWork` 不执行实际 cancel | **失败**：`attachWork then cancelWork...` |
| 3 | `cancelWork` 顺带 `done.complete` | **失败**：`cancelWork does not complete done` |

另验证断言强度：临时在断言前 `parentJob.cancel()`，用例 FAILED（旧写法此时会通过）。

测试 606 → **609**（runtime 44 → 47），源码 `@Test` 与实跑 XML 差额为 0。
