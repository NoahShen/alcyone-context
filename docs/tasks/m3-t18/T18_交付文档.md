## 3. 组装顺序（`create`）

```
1. resolve(config)            纯校验：命名空间 / 挂载结构 / 物理根规范化与重叠 / 状态库路径 → 非法就拒，零资源
2. StateInstanceLock.acquire  文件锁；已被占用 → CONFLICT（排在开库之前）
3. VfsStateDatabase.file      打开 / 升级（mount 表 1 → 2）
4. reconcileMounts            核对旧映射；冲突 → CONFLICT（排在开 Adapter 之前）
5. AsyncEventNotifier + 各 LocalFsStorage.create
6. AssemblyProbe.beforeReturn 仅同模块测试用：卡住 / 失败这一刻
7. DefaultVfs / NodeRegistry / EventPipeline / CapabilitySnapshot 接线，返回实例
```

任何一步失败或被取消：**逆序释放已取得的资源**（在 `NonCancellable` 里），原始异常原样抛出，
清理失败挂 `suppressed`。释放顺序与创建顺序相反：Adapter → 通知器 → 状态库连接 → **独占锁最后放**。

## 4. 决定与理由

| 决定 | 理由 |
| --- | --- |
| 身份 = `storageKey` + `backendType` + 规范化物理根 | 只比 key 认不出「同 key 换根」，旧 Node 会静默指向另一块盘。凭据不入库 |
| 规范化后的根写进身份 | 用原始写法（相对路径、别名）会让同一块盘看起来像两块；这条是被 A02 测试逼出来的修正 |
| 同一个 key 挂两个逻辑位置不算重叠 | 那是一块盘挂两次，只开一个 Adapter；重叠检查只发生在**不同的**根之间 |
| 缺身份的旧行明确拒绝，不自动认证 | 拿当前配置替旧行背书，就等于允许「换个目录就接管旧 Node」 |
| 冲突检查放在开 Adapter 之前 | 配置对不上时不该白开一块盘 |
| 独占用 `FileChannel.tryLock` | 简单、平台自带；覆盖同进程与遵循同协议的多进程 |
| 锁文件不删 | 残留文件不是「仍被占用」的证据；删它反而制造竞态 |
| `VfsLimits` 从 core 走 `api` 暴露 | Runtime 是 SDK 入口，宿主配限额要能看见这个类型；公开签名里仍没有基础设施类型 |
| A04 用 `internal` 重载做注入点 | 不为了测试在公开 API 上开挂载开关；`internal` 只有同模块测试可见 |
| 流式限额与 `read` 的 16 MiB 分开 | 同一 `null` 若既表示「用默认限额」又表示「无限」，宿主无法表达「流式不限量」；两套选项各自明确 |
| 调用级上限只能收紧 | 允许放宽会让「配置的兜底上限」形同虚设 |
| 关闭等待期是「自助时间」不是强杀期限 | 卡在 native 里不响应取消的操作无法安全强杀；本轮只发协作取消，卡死的可能拿 `STATE_ERROR` |
| 关闭时先收流再收盘 | 流还指着盘上的文件句柄，盘先关就没人能再收它们 |
| 清理跑在 `NonCancellable` 内 | 调用方正好在取消时，清理不能跟着被取消，否则资源没人收 |
| 操作登记跑在调用方的**子**协程 | close 要取消的是「这一次调用」，顺着取消会连带弄挂宿主的父 Job |
| 调用方关流后立即从跟踪集合移除 | 否则长生命周期实例每开一个流泄漏一个集合项；`VfsStreamResult.onClose` 就是为此留的 |

## 5. 流式与关闭（第二片 S3 + S4）

### 流式读取

- `openStream(uri, options)` 返回 `VfsStreamResult`（`uri` / `sizeBytes` / `stream` / 幂等 `close()`）。
- 限额：实际取 `min(Runtime.streamTotalLimit, options.maxTotalBytes)`，`null` 表示不设总量上限；超限报 `LIMIT_EXCEEDED`。
- 只读语义与 `read` 一致：不登记 Node、不发事件、分块读；目录报 `TYPE_MISMATCH`，缺失报 `NOT_FOUND`。
- 所有权：流交给调用方后由调用方关闭；创建后交给调用方前被取消则当场释放；Runtime `close()` 回收调用方漏关的流。

### 关闭

```
close() → 转 closing（新操作 CLOSED）→ 等在途操作 closeGracePeriod
       → 对未完成的操作发协作取消 → 流 → 通知器 → 各块盘 → 状态库 → 独占锁
```

- `close()` 是挂起函数，幂等；并发调用共享同一次完成结果（含失败）。
- 清理在 `NonCancellable` 内，一个资源失败不阻止其余；首错抛出，其余进 `suppressed`。
- 锁最后放，放完才算没人占着状态库；已提交的 Node 与事件留在库里，重开还在。
- 不取消宿主父 Scope / Job；不强杀 native 卡死线程。
