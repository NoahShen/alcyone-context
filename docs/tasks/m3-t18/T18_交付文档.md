## 3. 组装顺序（`create`）

```
1. resolve(config)            纯校验：命名空间 / 挂载结构 / 物理根规范化与重叠 / 状态库路径 → 非法就拒，零资源
2. StateInstanceLock.acquire  文件锁；已被占用 → CONFLICT（排在开库之前）
3. VfsStateDatabase.file      打开 / 升级（mount 表 1 → 2）
4. reconcileMounts            核对旧映射；冲突 → CONFLICT（排在开 Adapter 之前）
5. AsyncEventNotifier + 各 LocalFsStorage.create
6. AssemblyProbe.beforeReturn 仅同模块测试用：卡住 / 失败这一刻
7. DefaultVfs / NodeRegistry / EventPipeline / CapabilitySnapshot 接线，返回实例
```

任何一步失败或被取消：**逆序释放已取得的资源**（在 `NonCancellable` 里），原始异常原样抛出，
清理失败挂 `suppressed`。释放顺序与创建顺序相反：Adapter → 通知器 → 状态库连接 → **独占锁最后放**。

## 4. 决定与理由

| 决定 | 理由 |
| --- | --- |
| 身份 = `storageKey` + `backendType` + 规范化物理根 | 只比 key 认不出「同 key 换根」，旧 Node 会静默指向另一块盘。凭据不入库 |
| 规范化后的根写进身份 | 用原始写法（相对路径、别名）会让同一块盘看起来像两块；这条是被 A02 测试逼出来的修正 |
| 同一个 key 挂两个逻辑位置不算重叠 | 那是一块盘挂两次，只开一个 Adapter；重叠检查只发生在**不同的**根之间 |
| 缺身份的旧行明确拒绝，不自动认证 | 拿当前配置替旧行背书，就等于允许「换个目录就接管旧 Node」 |
| 冲突检查放在开 Adapter 之前 | 配置对不上时不该白开一块盘 |
| 独占用 `FileChannel.tryLock` | 简单、平台自带；覆盖同进程与遵循同协议的多进程 |
| 锁文件不删 | 残留文件不是「仍被占用」的证据；删它反而制造竞态 |
| `VfsLimits` 从 core 走 `api` 暴露 | Runtime 是 SDK 入口，宿主配限额要能看见这个类型；公开签名里仍没有基础设施类型 |
| A04 用 `internal` 重载做注入点 | 不为了测试在公开 API 上开挂载开关；`internal` 只有同模块测试可见 |
| `close()` 本轮只做最小版 | 等待期与在途跟踪是 S3 的范围；与其做个半成品语义，不如把「不保证什么」写清楚（见使用说明第 6 节） |
