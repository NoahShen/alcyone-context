## 1. 目标与范围

提供宿主可直接使用的 `AlcyoneVfs.create(config)` 与 `suspend close()`，组装 Local FS、SQLite、Core 和进程内通知；宿主不创建 Operator、Driver、Repository 或各 Manager。本轮接入已实现的 read / write / stat / list / getNode / delete / Metadata，并补公共流式读取；move 仍明确返回阶段性 UNSUPPORTED_OPERATION。

不实现 WebDAV（后续 T24）、Git Consumer、动态挂载、数据迁移工具或中断恢复。T19 用公开 Runtime 做更完整的纵向样例与回归，但本任务的启动、关闭和配置安全不能推迟到 T19。

## 2. 开发内容

### 2.1 最小配置与组装

配置至少描述状态库文件、命名空间、Mount 与 Local FS 根、I/O 限额和关闭等待期限；复用 T09 配置校验和 T12 物理根规范化 / 重叠检查，拒绝非法值而不改系统环境。创建一套共享 StateBoundary，交给 Registry、DefaultVfs、EventPipeline；所有查询与事务仓库必须来自同一状态库，含 T17 的 MetadataRepository。

例：`resources` 命名空间下挂 `/resources/docs` 到本机目录，调用者只提交配置、使用 Vfs 方法并在 finally 中关闭。具体配置类与字段由实现确定，不加入 ACL、Agent 身份、可配置只读开关或尚未支持后端的空框架。

### 2.2 配置持久化与冲突

首次启动原子保存已接受的 Mount 映射；重开时先核对旧映射，再开放服务，旧 Mount 移除、逻辑位置变化或物理资源身份变化均拒绝（CONFLICT），不替换原映射、不重新注册旧 Node。**不能只比较 storageKey**：Local FS 身份须含后端类型与规范化物理根，凭据不入库；同一个 key 改根也必须被发现。

新增 Mount 只有不改变旧资源路由才允许：至少检查旧挂载覆盖范围及已有物理 Node 的解析结果，不能仅看新增位置有没有已登记 Node 就认定安全。例：已有 `/resources` 指向 A，在其下新增 `/resources/photos` 指向 B 会遮蔽 A 的子树，即使该子树没懒注册也不能静默接受；新增到独立命名空间且不改变旧映射可接受。命名空间删除不能让已有 Node 无法寻址；新增命名空间 / Mount 不产生文件事件。

当前 mount 表仅有路径与 key，允许为资源身份补最小字段或表及内部持久化入口，SQL / JDBC 操作留 persistence，Runtime 不直接写 SQL。若 Schema 升级，提供真实旧版本库迁移测试；旧库已有 Mount 但缺少物理身份时不得把任意新配置自动认证为旧身份，给出明确拒绝与处理说明，空 mount 的旧库可正常初始化。

### 2.3 状态库独占与初始化失败

在打开状态库和持久化配置前取得实例独占，覆盖同进程及遵循同协议的多进程启动；使用简单文件锁等现有机制即可，锁随实例关闭 / 初始化失败释放，锁文件残留本身不等于仍被占用。状态库路径规范化，至少防住相对路径、绝对路径和可识别的符号链接别名绕过；不承诺阻止外部工具直接写 SQLite。

配置冲突在可行范围内先于资源创建检查；部分 Adapter、数据库或通知器已创建后失败 / 取消，需清理已拥有资源，保留原异常及清理失败 cause / suppressed。例：第二个 Mount 初始化失败后，第一个 Adapter 与数据库均被释放，修正配置后可再次 create；不删除已有用户文件或状态库来“回滚初始化”。

### 2.4 公共流式读取

在 `vfs/api` 为 Vfs 增加最小流式方法与独立的流结果 / 选项类型，Core 负责路由与只读查询语义，Runtime 跟踪资源，复用 Storage.readStream；公共签名不泄漏 StorageStream 或 OpenDAL。可采用持有 InputStream 的可关闭结果，明确单次打开、重复关闭和关闭后读取行为；读取不登记 Node、不发事件，不得先整文件读入内存。

**本任务选定限额口径**：ByteArray 的 16 MiB 默认不变；流式有独立总量上限配置，默认不设总量上限、仍分块读取，调用级上限只能进一步收紧配置上限，实际读取途中校验。与 ByteArray 的 ReadOptions 分开，避免同一 null 同时表示“用默认限额”和“无限”；零长度读取及超限沿用 T12 行为。

例：大于 16 MiB 的文件 read 默认拒绝，流式可逐块读完；带上限的流越界时报 LIMIT_EXCEEDED。创建流后、交给调用者前取消必须释放流；已交出的流由调用者关闭，Runtime 关闭时回收遗漏的流，不持有 StateBoundary 直到调用者读完。

### 2.5 运行状态与关闭

所有公共操作在同一生命周期入口登记在途状态，进入 closing 后新操作返回 CLOSED；已接纳操作先获得配置的等待期，超时后请求取消 Runtime 跟踪的工作，再安全释放流、通知器、Adapter、数据库和独占锁。close 幂等，并发 close 共享同一次完成结果；必要清理不被关闭调用者的取消中断，不取消宿主的父 Scope / Job。

**等待期限不是强杀期限**：T12 native 阻塞调用和不配合取消的 Consumer 不能安全强制终止，不得超时后直接销毁仍被使用的 Operator / DB，或对外宣称资源已释放。正常 / 可协作取消路径必须能完成，阻塞路径的实际等待边界如实回写 T01 §9；本轮不增加强杀线程、硬超时回收或崩溃恢复。

例：读流尚未关闭时触发 close，Runtime 负责回收它；一个资源 close 报错不能阻止其他资源获得清理尝试，保留最初异常及后续失败。数据库独占只在安全释放后解除，不能让新 Runtime 与仍在使用旧连接的操作重叠。

### 2.6 事件接入与模块边界

以 Runtime 配置或最小订阅入口接入宿主消费者，暴露 API 的 VfsEvent，继续使用 T14 的有界通知与异常隔离，不开放 Repository / EventDispatcher 等内部对象。首版不保证回放、可靠投递或退出前完成外围业务；回调内触发关闭不得等待自身形成死锁，复用既有语义并做最小验证。

Runtime 负责配置与资源所有权，文件编排仍在 Core，持久化规则在 persistence，native 访问在 storage。例：Consumer 自抛异常不影响已提交写入；SDK 不要求宿主手动关闭注入的内部 Driver 或 Operator。

| A06 关闭与在途调用 | closing 拒新操作，等待期内已有操作可结束，超时请求取消，重复 / 并发关闭不双重释放 | 可控挂起操作测试期间发起 close，再验证 CLOSED、取消、最终资源释放；一个资源关闭失败仍尝试其余资源；真实重开确认持久化保留 |
| A07 通知与安全释放 | Consumer 失败不撤销提交；回调触发关闭无自等死锁；流读 / close 与 Runtime close 不造成先释放后使用 | 最小可控并发序列与真实流验证，区分已证明的协作取消和未模拟的不可中断 native 卡死；不宣称强杀或可靠通知 |
| A08 范围、工具链与交付 | API 无基础设施类型泄漏，Core 不依赖 Runtime；原 542 例无回归 | 项目内 scripts/check、分模块 XML、公开入口示例；如实记录平台、失败注入与未验证项，无强制十连跑或变异数量指标 |

例：关闭测试需让操作实际到达受控挂起点，再触发 close；单纯“启动协程后还没完成”不能证明关闭与在途操作相遇。测试重复执行时明确是否真的执行，不把 UP-TO-DATE 当作新证据。
