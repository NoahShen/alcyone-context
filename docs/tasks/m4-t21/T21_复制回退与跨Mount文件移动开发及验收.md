## 1. 目标与范围

实现普通文件的 `COPY_FALLBACK_MOVE` 与 `CROSS_MOUNT_COPY_MOVE`：复制内容 → 确认目标 → 删除源 → 提交同一 Node 的新路径与一条 FILE_MOVED。沿用 Core 编排、Runtime 生命周期与现有 Storage / Repository Port；同 Mount 原生移动保持 T20 行为。

例：`/resources/local/a.txt → /resources/archive/b.txt` 分属两个挂载点，即使背后都是 Local FS，也走复制删除流程。本任务以两个不重叠的本地目录验证，不新增 WebDAV、目录移动、流式写入、重试、补偿或崩溃恢复；目录仍留 T22，失败组合扩展留 T23。

## 2. 开发内容

### 2.1 策略与预检

复用 Guard 的策略输出，按源 stat 的真实类型判断；已知参数、结构、只读、目标存在与阶段拒绝先于注册源、补目录及物理复制。同 Mount 仅在能力判定为复制回退时走复制，不在原生 move 已报错后盲目重试复制，因为此前可能已改变文件。

例：目标已有 b.txt 时直接拒绝；写入仍使用 CREATE_NEW，避免预检之后目标出现时被覆盖。跨 Mount 不能仅因 storageKey 相同就改用原生 move，源与目标分别按各自路由获取 Storage 和相对路径。

### 2.2 有界复制与父目录

现有 Storage.write 只接收 ByteArray，首版复用有界 read / write，读取上限不超过现有 Core 的读写限额；后端更严格的限制仍生效，超限报 LIMIT_EXCEEDED，不能先无限读入再检查。读取成功并确认实际字节数后再补目标父目录和写入，补目录沿用 T20，不批量登记或发目录事件。

例：默认限额下，小文件可以跨 Mount 移动，超限文件拒绝并保留源；T20 原生移动不因此新增大小限制。不要用分块 UPSERT 冒充追加写入；把复制限额的具体取值与原生移动的差异回写 T01 / 使用说明，不新增公共 MoveOptions。

### 2.3 目标确认与删源

写入成功后确认目标为文件，并将可获取的源 / 写入回执 / 目标长度与实际复制字节数核对；明确哪些属性来自 read、write 或目标 stat，任何确认失败或已知不一致都不能继续删源。检测到已知内容长度变化按 CONFLICT 报告，后端调用失败保留原错误；长度核对不等于哈希校验，也不承诺防御外部进程任意并发改写。

例：复制了 100 字节，但目标确认只有 80 字节，移动失败、源保留、残留目标不自动删除。确认通过后才调用源 Storage.delete；确认取得的目标属性可用于 NodeInfo，不为拼返回值再追加一次无关查询。

### 2.4 身份、锁与提交

复用 T20 的单次 StateBoundary、源身份确认和末尾提交：已登记源保留 ID / Metadata / registeredAt，未登记源只注册一次，目标不另建身份。SQLite 事务只更新路径 / 时间并追加 FILE_MOVED，提交后通知；不能调用公开 Vfs.read/write/delete 来拼移动，否则会重复取锁、生成中间身份或事件。

例：跨盘移动带标签的笔记后，getNode(原 ID) 指向新路径，重开仍成立；只有一条 FILE_MOVED，没有 FILE_CREATED / FILE_DELETED。提交视图找不到原 Node 沿用 T20 的状态错误，不通过补注册掩盖问题。

### 2.5 失败与取消

按阶段保留已知事实：写入或确认失败不删源；目标成功但删源失败不提交新映射；删源成功但状态 / 事件提交失败报 STATE_ERROR + PARTIAL，保留 cause、不回移、不通知成功。已建目录或已写目标不能被后续 NONE 抹掉，后端 UNKNOWN 不因已知某些变更就降级；源懒注册可能保留，取消仍原样传播而非包装成成功或零副作用。

例：目标完整但源删除报错，可能两份文件都在，逻辑路径仍指向源，调用方收到失败。选择一个进入复制流程后的受控取消点，验证取消后没有继续删源或提交，并能释放边界；不要把这个用例写成所有取消窗口均已覆盖。

### 2.6 真实验证与文档承接

跨 Mount 正例走公开 Runtime + 真 SQLite + 两个临时 Local FS 根，数据库放在挂载根外；同 Mount 回退用能力受控的 Storage 包装或替身，证明没有调用 native move。更新 T18～T20 使用说明及现有阶段断言中“所有跨 Mount / 复制回退都拒绝”的当前口径，保留目录拒绝与历史记录。

例：真实移动后核对两块盘、原 ID / Metadata、事件字段和重开；注入“确认失败”时明确是受控反例，不称真实磁盘损坏。无需重新实现 Router、Guard、事务框架或扩充通用执行器。

## 4. 验收标准

| 编号 | 必须满足 | 核心证据 |
| --- | --- | --- |
| A01 两种复制策略 | 同 Mount 非原生回退、跨 Mount 文件移动均成功；原生路径无回归 | 回退的调用顺序与 native move 未调用；公开 Runtime 双 Local FS 的源消失、目标内容一致；T20 回归 |
| A02 身份与事件 | 已登记源保留 ID / Metadata，未登记源只注册一次；同事务更新路径与一条 FILE_MOVED，提交后通知 | 真库 / 公开 API 核对，正常重开后 ID 与 Metadata 不变；事件 nodeId、uri、sourceUri、targetUri 正确，无中间创建 / 删除事件 |
| A03 预检与限额 | 目标不覆盖、结构 / 只读 / 目录边界保持；读取有界，超限不删源、不写目标 | 代表反例与实际读取超限证据（不能只依赖 stat 长度）；CREATE_NEW 接线；原生移动大文件原用例仍通过 |
| A04 复制与确认失败 | 源读取失败、目标写入失败、目标确认失败或长度不一致均不能进入源删除 / 状态成功提交 | 受控故障断调用顺序、源 / 目标事实、逻辑路径和事件；含写入已留目标的部分失败，不把所有失败都假设为零变更 |
| A05 删源与状态失败 | 删源失败保留原逻辑映射且无成功事件；删源成功后提交失败为 STATE_ERROR + PARTIAL、不补偿 | 断两侧物理事实、原 ID / Metadata、日志与通知；至少一条真 SQLite 事务失败证据，可用包装注入 |
| A06 副作用合并 | 建目录后复制失败保留 PARTIAL；目标已成功后删源报 NONE 仍反映已变更；UNKNOWN 不降级 | 少量定向替身用例，覆盖新增复制阶段；复用 T20 helper 证据并指出本次接线，不能全部留 T23 |
| A07 串行与取消 | 复制流程全链单次取锁；一个已进入流程的取消点原样传播、不继续删源或提交、后续操作可用 | 受控相遇证明第二个变更未碰后端；协程内捕获实际异常并核对取消处物理事实；finally 放行和等待清理 |
| A08 工程与交付 | 642 例基线无回归，无新公共 API / 模块；阶段拒绝测试与说明更新 | 项目内完整检查、源码与 XML 计数、可运行双 Mount 样例、A01～A08 证据分层及未验证边界 |

一个用例可覆盖多项；既有 T10 / T12 / T18 / T20 证据可引用，新增重点是两侧 Storage 接线与复制后删源顺序。无需追求固定测试数、变异数量或十连跑；失败测试需区分无事件入库与直接观测无通知，不能相互冒充。
