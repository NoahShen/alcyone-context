## 1. 目标与依据

在 `vfs/storage` 实现 Core 的 Storage Port，首发使用 Apache OpenDAL Local FS，真实数据放在测试临时目录。模块名按职责命名，内部实现可按 OpenDAL 分包，不为未来引擎预建通用插件框架。

阅读依据：[T04 依赖与能力验证](../../vfs/VFS_依赖与能力验证_v0.1.md)、[T02 路径与操作语义](../../vfs/VFS_路径与文件操作语义_v0.1.md)、[T07 Core 边界](../m1-t07/T07_Core边界定义与验收.md)，以及 `vfs/core/.../storage/Storage.kt`、`StoragePath.kt` 的当前契约。T10 的能力预检不代替真实后端检查；遇到 Port 无法表达的必要行为，先回写设计决定，不静默改变契约。

例：Adapter 接到 `reports/a.txt` 后访问物理根下对应文件；它不知道 `/resources`、Agent、Node ID 或 SQLite。

## 2. 开发内容

### 2.1 创建、关闭与模块边界

提供可供后续 Runtime 组装的 Local FS 创建入口，接收物理根与必要限额配置，隐藏 Operator / JNI 类型；明确根目录必须存在还是由入口创建，并验证根为目录。文件访问以 OpenDAL 为主，JDK 本地路径 API 用于路径检查和可识别物理根校验，不另造一套文件后端。

同步阻塞调用放在 IO 执行环境；Adapter 关闭释放 Operator，重复关闭可安全处理，关闭后新调用明确失败（CLOSED）。流的关闭责任见 2.4；Runtime 的停接请求与等待在途操作仍属 T18 / T27。

例：在临时目录创建 Adapter，写入后关闭，再创建新实例仍能读回文件。

### 2.2 物理根与符号链接

按 StoragePath 的已解码路径段定位资源，不再次 URI 解码；根路径需显式映射为后端根，不能把 `.` 当成普通文件名。对目标及已有路径组件、move 两端、列举条目与递归删除中的符号链接明确拒绝，不跟随链接进入根外；使用说明记录根规范化策略及拒绝错误码，拒绝后不得修改链接目标。

提供简单的本地物理根集合校验或等价可复用入口，识别规范化后相同 / 包含关系并拒绝配置，供 T18 组装时调用，不让 Adapter 依赖 MountRouter。按完整路径段比较；不承诺抵御外部进程在检查后替换路径的竞争，也不扩展为硬链接或不可识别别名的全面防护。

例：根 `data/a` 与 `data/a/sub` 冲突，`data/ab` 不因字符串前缀而误判；`link/out.txt` 中 link 指向根外时读写均拒绝。列举与递归删除采用的链接拒绝及部分失败策略须在交付中说明。

### 2.3 基本文件操作与能力

实现 read、stat、单层完整 list、write、createDirectory、原生 move、delete 及 capabilities，遵循 T07 的错误和类型契约。CREATE_NEW 不覆盖已有文件，REPLACE_EXISTING 不创建缺失文件，UPSERT 两者皆可；write 不隐式补父目录，move 目标不得被覆盖，父目录自动补齐留给 Core 编排。

补齐后端与 Port 的差异：删除缺失资源返回 NOT_FOUND，非递归删除非空目录返回 DIRECTORY_NOT_EMPTY，目录已存在的 createDirectory 成功。能力值按实际适配效果给出，尤其不能因支持文件 rename 就声明目录原生移动；T04 已测目录 rename 不支持时应返回 UNSUPPORTED_OPERATION，复制删除回退留 T20～T22。

例：已有 `a.txt` 时 CREATE_NEW 失败且原内容不变；缺失 `a.txt` 时 REPLACE_EXISTING 失败且不产生文件。readOnly 表达可确认的后端限制，不新增可配置只读 Mount，也不靠一次权限检查承诺以后总能写入。

### 2.4 大小限制与流式读取

ByteArray read 按传入 maxBytes 限制实际读取量，不能先完整读取再检查，也不能只信 stat；write 通过 Adapter 创建配置落实可调整的默认 16 MiB 上限，在存储副作用前拒绝超限，后续 Runtime 统一接入配置。测试可使用小限额验证边界，避免大文件占用。

readStream 的非空 maxBytes 同样约束实际读取，null 保持 Port 的“不设上限”含义；由调用方关闭资源，InputStream 的 read / skip 等入口不能绕过计数。开发中明确单次打开或重复打开策略、关闭后的行为、读取中异常转换及 Adapter 与流的关闭关系，回写使用说明；同步 InputStream 的读取仍是阻塞操作，不声称 suspend 工厂让后续读取自动异步。

例：限额 8 字节，恰好 8 字节成功，第 9 字节触发 LIMIT_EXCEEDED；无上限流可读取更大文件，不先转成完整 ByteArray。

### 2.5 错误与取消

将可识别的缺失、已存在、类型冲突、非空目录、拒绝访问、不支持、超限和已关闭等情况映射为已有 VfsErrorCode，其他真实 I/O 失败映射 STORAGE_ERROR。不要把后端原始消息、物理路径或凭据直接拼进公开错误；Storage 不伪造逻辑 URI，底层诊断信息遵循公共异常边界。

CancellationException 原样传播，取得资源后的取消与异常路径要释放资源；发生写入或部分删除后失败时按事实给 effect（NONE / PARTIAL / UNKNOWN），不能统一用默认 NONE。首版不补偿、不恢复，不承诺阻塞 JNI 调用能即时中断。

例：模式预检失败且没有写入，effect 为 NONE；递归删除中途失败已有文件被删除，则不能报告没有副作用。
