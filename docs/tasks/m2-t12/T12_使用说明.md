## 1. 这个模块是干什么的

VFS 说「挂载点 `/resources/medical/` 对应某个存储」，真正去碰磁盘的是本模块：它把**挂载根内的相对路径**翻译成宿主上的真实文件，完成读写、列举、移动、删除，并把后端五花八门的失败翻译成 VFS 统一的错误码。

它**只做物理层**：不知道 `/resources` 是什么，不知道 Agent 是谁，不生成 Node ID，不写事件，不碰 SQLite。

| 它做 | 它不做 |
| --- | --- |
| 定位物理文件、读写 / 列举 / 移动 / 删除 | 补父目录（属 Core 编排，T15） |
| 拒绝符号链接，不让访问逃出挂载根 | 嵌套 Mount 的结构保护（T10 / T16） |
| 校验可配置物理根集合不重叠 | 逻辑挂载路由（T09 的 MountRouter） |
| 按实际读取量执行限额 | 跨挂载点复制删除回退（T20～T22） |
| 把后端错误映射成 `VfsErrorCode` | 生成 Node ID、写 Event（T13 / T14） |

例：`StoragePath.parse("ct/a.dcm")` 配物理根 `/data/resources/medical` → 真实文件 `/data/resources/medical/ct/a.dcm`。

## 2. OpenDAL 0.50.6 实测事实

本轮在 macOS arm64 上直接对 `opendal-0.50.6.jar` + `opendal-0.50.6-osx-aarch_64.jar` 探测（`javap` 看签名 + 直接跑小程序验证行为）。**这些是事实，不是推测**：

| 事实 | 适配层处理 |
| --- | --- |
| `Operator.of(ServiceConfig.Fs.builder().root(abs).build())` 接受绝对路径；能力为 `read/write/stat/list/createDir/delete/rename = true`，`listWithRecursive = false`，`writeWithIfNotExists = true`，`writeWithIfNoneMatch = false`，`shared = true` | 按能力派生 `StorageCapabilities` |
| **Operator 关闭后继续使用会让 JVM 崩溃（SIGSEGV）**；native 流关闭后再读同样崩溃 | 每次触碰 native 前检查关闭状态，转 `CLOSED`；流关闭在 Adapter 已关时只置标记 |
| `fs` **不支持 range read**（`ReadOptions` 报 NotFound） | 有界读取改为包装流按实际读取计数 |
| `write` **自动补父目录** | 写前先 `stat` 父级，缺失即 `NOT_FOUND`，Storage 不建目录 |
| `write` 父级是普通文件时返回 `AlreadyExists` | 写前 `stat` 父级并自行报 `TYPE_MISMATCH`（Port 允许确认类型冲突时这样报） |
| `write(..., ifNotExists = true)` 命中已存在文件返回 `ConditionNotMatch` | 映射为 `ALREADY_EXISTS`，CREATE_NEW 用它做原子兜底 |
| `rename` **覆盖**已有目标 | 移动前先 `stat` 目标，存在即 `ALREADY_EXISTS` |
| 目录 `rename` 返回 `IsADirectory` | 自行判为 `UNSUPPORTED_OPERATION`，`nativeDirectoryMove = false` |
| 删除不存在的路径**返回成功** | 删前 `stat`，缺失即 `NOT_FOUND` |
| 删除非空目录返回 `Unexpected`（os error 66），无法从错误码判断 | 删前列举子项，非空即 `DIRECTORY_NOT_EMPTY` |
| `list("a")` 只返回目录**自身**，`list("a/")` 才返回子项**并且包含自身** | 目录路径统一补尾斜杠；结果里过滤掉自身 |
| `list` 会 `stat` 每个条目，**悬空符号链接被静默跳过** | 可见的链接条目报 `STORAGE_ACCESS_DENIED`；悬空链接的缺失已记录为已知限制 |
| `delete` 目录必须带尾斜杠（空目录不带尾斜杠也会失败） | 删除目录时用带斜杠形式 |
| `createDir` 逐级创建；目录已存在返回成功 | 与 StorageFakeImpl 语义一致 |
| 目录的 `metadata.lastModified` 为 `null` | `StorageAttributes.modifiedAt` 允许为 `null` |
| `Operator.duplicate()` 存在于 API 表面 | 本轮**未使用**：流与 Operator 生命周期用「先关流再关 Adapter」规则约束即可（见第 6 节） |

## 3. 创建与关闭

```kotlin
val storage = LocalFsStorage.create(Path.of("/data/resources/medical"))
// 或带限额
val limited = LocalFsStorage.create(root, LocalFsOptions(defaultWriteLimitBytes = 8 * 1024 * 1024))
```

- **物理根必须已存在且是目录**，否则 `INVALID_ARGUMENT`（不自动创建）。
- 根会用 `toRealPath()` 规范化：**根本身是符号链接会被解析成真实目录**；根**内部**的链接一律拒绝（第 4 节）。
- `create` 是挂起函数，内部的 `Operator.of` 与文件检查都放在 IO 调度器上。
- 构造中途失败会释放已建的 Operator；`close()` 幂等，关闭后任何新调用都是 `CLOSED`。

```kotlin
storage.close()
storage.close() // 安全
storage.stat(StoragePath.parse("a.txt")) // VfsException(CLOSED)
```

## 4. 物理根与符号链接

**校验一组物理根**（T18 组装配置时调用，与 Adapter 无关，不依赖 MountRouter）：

```kotlin
val roots = LocalFsRoots.requireNonOverlapping(listOf(Path.of("/data/a"), Path.of("/data/ab"))) // 通过
LocalFsRoots.requireNonOverlapping(listOf(Path.of("/data/a"), Path.of("/data/a/sub"))) // INVALID_ARGUMENT
```

比较按**完整路径段**（`Path.startsWith`），所以 `data/a` 不会因为字符串前缀误判包含 `data/ab`。错误消息不带物理路径。

**符号链接一律拒绝，不跟随**：

- 检查目标本身，以及**已存在的每一级路径组件**；
- `move` 的**两端**都检查；
- `list` 结果里的每个条目都检查，出现链接则整个 `list` 失败；
- 递归删除**先规划整棵子树**再删除，规划阶段遇到链接就拒绝，**此时一个字节都没删**（`effect = NONE`）；
- 错误码 `STORAGE_ACCESS_DENIED`，且**不修改链接目标**。

选这个错误码的理由：被拒绝的不是「类型不符」也不是「不存在」，而是适配层策略不允许通过链接访问该位置；`STORAGE_ACCESS_DENIED` 表达的正是「拒绝访问」。判断「是否越界」需要目标路径信息，反而会泄露宿主结构，因此不按越界与否区分——**指向根内的链接同样拒绝**。

## 5. 文件与目录操作

| 方法 | 行为要点 |
| --- | --- |
| `stat` | 不存在 `NOT_FOUND`；目录的 `sizeBytes` 为 `null` |
| `read(path, maxBytes)` | 按**实际读取**限额；目标是目录 `TYPE_MISMATCH`；缺失 `NOT_FOUND` |
| `readStream(path, maxBytes)` | 见第 6 节；`maxBytes = null` 表示不设上限 |
| `list(path)` | 单层完整，条目 name 是相对单段；不含自身与孙级；**不承诺排序**；目标是文件 `TYPE_MISMATCH` |
| `write(path, content, mode)` | 不隐式补父目录；父级缺失 `NOT_FOUND`，父级是文件 `TYPE_MISMATCH`；目标是目录 `TYPE_MISMATCH` |
| `createDirectory(path)` | 已存在视为成功；目标是文件 `TYPE_MISMATCH`；逐级创建 |
| `move(source, target)` | 目标存在 `ALREADY_EXISTS`（**不覆盖**）；源缺失 `NOT_FOUND`；目录源 `UNSUPPORTED_OPERATION`；目标父目录缺失 `NOT_FOUND` |
| `delete(path, recursive)` | 缺失 `NOT_FOUND`；非空目录非递归删除 `DIRECTORY_NOT_EMPTY`；`recursive = true` 自底向上删除 |
| `capabilities()` | `nativeFileMove = true`、`nativeDirectoryMove = false`、`createDirectory = true`、`boundedRead = true`、`readOnly = false` |

### 写入模式

| 模式 | 目标已存在 | 目标缺失 |
| --- | --- | --- |
| `CREATE_NEW` | `ALREADY_EXISTS`，原内容不变 | 创建 |
| `REPLACE_EXISTING` | 替换 | `NOT_FOUND`，**不产生文件** |
| `UPSERT` | 覆盖 | 创建 |

**模式预检不是原子操作**：存在性检查用的是先 `stat` 再写，检查与写入之间有窗口。所以：

- `CREATE_NEW` 额外用后端的 `if_not_exists` 条件写（实测 `writeWithIfNotExists = true`，命中时返回 `ConditionNotMatch` → `ALREADY_EXISTS`），这一层是原子的；
- `REPLACE_EXISTING` **没有**条件写可用（`writeWithIfNoneMatch = false`），只靠预检。并发场景下「先删后写」「外部替换文件」仍可能覆盖别人的内容——这是首版接受的边界。

## 6. 限额与流

- `read(path, maxBytes)`：包装流按块读取并累计计数，请求量被裁到「剩余额度 + 1」，最多只多读 1 字节用于判定超限；**不会先完整读进内存再判断，也不只看 `stat` 的大小**。
- `readStream(path, maxBytes)`：非 null 限额同样约束实际读取；`null` 是真正的不设上限，不先转成完整 `ByteArray`。
- **流是单次打开的**：`openStream()` 第二次调用报 `STATE_ERROR`，需要再读请再次调用 `readStream`（每次独立计数）。
- **关闭顺序：先关流，再关 Adapter。** 流还没关就关 Adapter 是允许的，流的下一次读取会抛 `CLOSED`（而不是碰 native 句柄把 JVM 弄崩），之后 `stream.close()` 只置标记、不再触碰 native。
- `skip` **计费**：跳过的字节消耗同一个额度，否则「跳过大文件再读 1 字节」就能绕过限额。`available()` 只返回剩余额度内的字节数。`mark` / `reset` 不支持（会让已读取量失去意义）。
- 写入限额由 `LocalFsOptions.defaultWriteLimitBytes` 落实，默认 **16 MiB**（T04 §6）；**在任何存储副作用之前**拒绝超限，不截断、不先写再报错。
- **同步流仍是阻塞的**：`openStream()` 与之后的 `InputStream` 读取都是同步调用，`readStream` 是挂起函数**不代表**后续读取自动异步。

## 7. 错误码与 effect

| 情况 | 错误码 |
| --- | --- |
| 路径段非法 | `INVALID_URI`（`StoragePath` 自己抛） |
| 根不存在 / 不是目录、限额为负、`maxBytes` 为负 | `INVALID_ARGUMENT` |
| 资源不存在 | `NOT_FOUND` |
| 已存在 | `ALREADY_EXISTS` |
| 文件 / 目录类型冲突（含经链接、目标是目录） | `TYPE_MISMATCH` |
| 非空目录非递归删除 | `DIRECTORY_NOT_EMPTY` |
| 符号链接、权限不足 | `STORAGE_ACCESS_DENIED` |
| 后端不支持（如目录移动、根 / 目标操作） | `UNSUPPORTED_OPERATION` |
| 读或写超限 | `LIMIT_EXCEEDED` |
| Adapter 已关闭 | `CLOSED` |
| 其他真实 I/O 失败 | `STORAGE_ERROR` |

- **公开消息不含物理路径、凭据或后端原始响应**，形如 `local storage read failed (NOT_FOUND)`；原始异常挂在 `cause`。
- **`CancellationException` 原样传播**，不被包装。
- effect 与事实一致：

| 场景 | effect |
| --- | --- |
| 所有预检失败（模式不符、目标 / 父级缺失、类型冲突、链接、限额、已关闭） | `NONE` |
| `write` 进入后端后失败 | `UNKNOWN`（分不清「文件没创建」和「已创建但内容不全」） |
| `move` 调用后端后失败 | `UNKNOWN`（rename 要么全成要么没动，但失败点无法证明没动） |
| 递归删除中途失败（前面已删掉条目） | `PARTIAL`；第一条就失败仍是 `NONE` |

## 8. 错误映射的实测依据

| OpenDAL 错误码 | VFS 错误码 |
| --- | --- |
| `NotFound` | `NOT_FOUND` |
| `AlreadyExists`、`ConditionNotMatch` | `ALREADY_EXISTS` |
| `IsADirectory`、`NotADirectory` | `TYPE_MISMATCH` |
| `PermissionDenied` | `STORAGE_ACCESS_DENIED` |
| `Unsupported` | `UNSUPPORTED_OPERATION` |
| `ConfigInvalid` | `INVALID_ARGUMENT` |
| `IsSameFile`、`Conflict` | `CONFLICT` |
| `RangeNotSatisfied` | `LIMIT_EXCEEDED` |
| `RateLimited`、`Unexpected` | `STORAGE_ERROR` |

JDK 侧：`NoSuchFileException` → `NOT_FOUND`，`AccessDeniedException` → `STORAGE_ACCESS_DENIED`，其余 `IOException` → `STORAGE_ERROR`。

## 9. 它不管的事

不补父目录、不做结构保护、不做跨挂载复制删除回退、不生成 Node ID、不写 Event、不碰 SQLite、不做中断恢复或补偿，也不承诺阻塞 native 调用能被协程取消即时中断。

## 10. 已知限制

1. **不抵御检查后的竞争**：链接检查与后端调用之间，外部进程可以替换路径组件。这需要文件系统级手段（`openat` / `O_NOFOLLOW`），超出本轮范围。
2. **不防护硬链接与不可识别别名**：指向根内的硬链接、bind mount 等不会被识别。
3. **悬空符号链接在 `list` 中不可见**：后端列举会 `stat` 每个条目，stat 失败的悬空链接被静默跳过（已实测）。对可见的链接条目仍然报 `STORAGE_ACCESS_DENIED`。
4. **Operator 关闭后的并发**：单个调用会先检查关闭状态再进 native，但「检查通过、调用 native、期间 Adapter 被另一个线程关闭」的窗口仍可能导致 JVM 崩溃。首版假设 Runtime 按顺序关闭（T18 / T27）。
5. **权限类验证依赖宿主身份**：以 root 运行时 POSIX 权限不生效，相关用例会显式跳过而不是伪装通过。
6. **平台**：只实测过 macOS arm64；Linux x64 需 CI 实跑，Linux arm64 未验证。
