## 4. 后端差异（实测 → 适配）

| 实测行为 | 适配 |
| --- | --- |
| `write` 自动补父目录 | 写前 `stat` 父级，缺失即 `NOT_FOUND` |
| `write` 父级是文件返回 `AlreadyExists` | 自行判为 `TYPE_MISMATCH` |
| `rename` 覆盖已有目标 | 移动前 `stat` 目标 → `ALREADY_EXISTS` |
| 目录 `rename` 返回 `IsADirectory` | 自行判为 `UNSUPPORTED_OPERATION`；`nativeDirectoryMove = false` |
| 删除缺失路径返回成功 | 删前 `stat` → `NOT_FOUND` |
| 删除非空目录返回 `Unexpected`（os error 66） | 删前列举 → `DIRECTORY_NOT_EMPTY` |
| `list("a")` 只返回自身；`list("a/")` 含自身 | 补尾斜杠 + 过滤自身条目 |
| `delete` 目录需带尾斜杠 | 删除目录时用带斜杠形式 |
| 无 range read | 包装流按实际读取计数 |
| `list` 跳过悬空链接 | 记录为已知限制（可见链接仍拒绝） |
| Operator 关闭后使用会 SIGSEGV | 进 native 前检查关闭状态 |

两条被后端事实推翻的初始假设：`write` 不会补父目录、`move` 不会补目标父目录——两者都需要预检才能满足 Port。

其他未验证 / 未承诺事项：

1. **SIGSEGV 本身没有复现过**。`NativeLifetime` 的读写锁让「Operator 关闭后触碰 native」的窗口不可达，并有测试证明关闭会等在进行的操作收尾，但**没有真的崩过一次**来证明崩溃路径已被封死。
2. 构造中途释放 Operator 只有代码审查，没有可确定性触发的运行时用例。
3. 「检查后被外部进程替换路径」的竞争、硬链接与 bind mount 别名不做防护（已知限制）。
4. 阻塞 native 调用不能被协程取消即时中断；`CancellationException` 的原样传播是单元级验证。
5. 不做补偿与恢复（E04），不做可靠事件投递（E05）。
6. `Operator.duplicate()` 在 API 表面存在但本轮未使用，也未单独实测其生命周期语义。

### 本轮方法论边界

- **并发与取消是确定性编排，不是压力测试**：关闭竞争用闩锁暂停 continuation，线程归属用实例注入的 `onNativeCall` 捕获线程名。没有用重试或高并发压测碰运气，也没有赌 native 崩溃。
- **权限类用例在 root 环境下会被 `assumeTrue` 显式跳过**，跳过原因写在用例里，不静默通过。请在非 root 环境复跑一次以覆盖 `UNKNOWN` / `PARTIAL` 两条 effect。
