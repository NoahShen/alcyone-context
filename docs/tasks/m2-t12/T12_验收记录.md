## 3. A01～A08 逐条结论

| 编号 | 结论 | 证据 |
| --- | --- | --- |
| **A01 真实后端与生命周期** | 通过（macOS arm64 实跑） | `LocalFsStorageLifecycleTest`：① `OpenDAL.enabledServices()` 含 `fs`——这是 native 调用，native 未加载会直接 `UnsatisfiedLinkError`；② 创建 → 写入 → `close` → 新实例读回，且中间用 `Files.readString` 核对物理文件内容，证明写的是宿主真实文件；③ `close()` 两次安全，`nativeHandleDisposed()` 为 true（**不用「文件还能删」当资源已关闭的证据**）；④ 关闭后 8 个入口全部 `CLOSED` 且无副作用；⑤ 流晚于 Adapter 关闭时读取抛 `CLOSED` 而不崩 JVM。构造中途的释放是代码审查项（无法确定性地让 `Operator.of` 在合法根上失败） |

## 4. 后端差异（实测 → 适配）

| 实测行为 | 适配 |
| --- | --- |
| `write` 自动补父目录 | 写前 `stat` 父级，缺失即 `NOT_FOUND` |
| `write` 父级是文件返回 `AlreadyExists` | 自行判为 `TYPE_MISMATCH` |
| `rename` 覆盖已有目标 | 移动前 `stat` 目标 → `ALREADY_EXISTS` |
| 目录 `rename` 返回 `IsADirectory` | 自行判为 `UNSUPPORTED_OPERATION`；`nativeDirectoryMove = false` |
| 删除缺失路径返回成功 | 删前 `stat` → `NOT_FOUND` |
| 删除非空目录返回 `Unexpected`（os error 66） | 删前列举 → `DIRECTORY_NOT_EMPTY` |
| `list("a")` 只返回自身；`list("a/")` 含自身 | 补尾斜杠 + 过滤自身条目 |
| `delete` 目录需带尾斜杠 | 删除目录时用带斜杠形式 |
| 无 range read | 包装流按实际读取计数 |
| `list` 跳过悬空链接 | 记录为已知限制（可见链接仍拒绝） |
| Operator 关闭后使用会 SIGSEGV | 进 native 前检查关闭状态 |

两条被后端事实推翻的初始假设：`write` 不会补父目录、`move` 不会补目标父目录——两者都需要预检才能满足 Port。

3. 阻塞 native 调用不能被协程取消即时中断；`CancellationException` 的原样传播是单元级验证。

5. `Operator.duplicate()` 在 API 表面存在但本轮未使用，也未单独实测其生命周期语义。

## 6. 复核建议

复核时可重点看三处：`LocalFsStorage.delete` 的「先规划后删除 + effect 取值」、`BoundedInputStream` 的计数与请求裁剪、`LocalFsStorage.create` 的根规范化与异常路径释放。权限相关的两个用例在 root 环境下会被跳过，请在非 root 环境复跑一次以覆盖 `UNKNOWN` / `PARTIAL` 两条 effect。
