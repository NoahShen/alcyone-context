**关于「是否用了替身」——准确的说法是以下组合，不是「全部真实目录、没有任何替身」**：

| 类别 | 数量级 | 是否碰 native |
| --- | --- | --- |
| 真实后端文件操作（CRUD、list、限额、生命周期、路径与符号链接边界） | 主体 | 是，真实临时目录 + 真实 `opendal` native |
| 流白盒单测（`StorageInputStreamTest`） | 20 | 否，计数替身流 |
| 错误映射与 effect 单测（`LocalFsEffectPhaseTest`、`LocalFsFailureReportTest` 的一部分） | 若干 | 否，替身在**指定第 N 次调用**上注入后端异常 |
| 执行环境与取消（`LocalFsExecutionContextTest`） | 10 | 部分，Operator 与文件是真的，线程与取消窗口靠实例注入的观测点 |
| 静态边界检查（`LocalFsModuleBoundaryTest`） | 3 | 否，源码扫描 + 反射 |

用替身的三处都有明确理由：流契约要看「delegate 被碰了几次」、effect 阶段要看「第 N 次 `stat` 失败时状态是什么」、取消窗口要停在 `withContext` 边界上——这三件事在真实后端上没有可观测点。凡是能看真实行为的断言（如文件内容是否被删、字节是否写入）都仍然走真实后端。

上表记录交付方对所列阶段分支的变异验证，不代表所有异常分支均有独立变异用例；后置属性失败由新增测试验证，递归首次删除失败的 UNKNOWN 本轮另经代码审查确认。

## 4. 后端差异（实测 → 适配）

| 实测行为 | 适配 |
| --- | --- |
| `write` 自动补父目录 | 写前 `stat` 父级，缺失即 `NOT_FOUND` |
| `write` 父级是文件返回 `AlreadyExists` | 自行判为 `TYPE_MISMATCH` |
| `rename` 覆盖已有目标 | 移动前 `stat` 目标 → `ALREADY_EXISTS` |
| 目录 `rename` 返回 `IsADirectory` | 自行判为 `UNSUPPORTED_OPERATION`；`nativeDirectoryMove = false` |
| 删除缺失路径返回成功 | 删前 `stat` → `NOT_FOUND` |
| 删除非空目录返回 `Unexpected`（os error 66） | 删前列举 → `DIRECTORY_NOT_EMPTY` |
| `list("a")` 只返回自身；`list("a/")` 含自身 | 补尾斜杠 + 过滤自身条目 |
| `delete` 目录需带尾斜杠 | 删除目录时用带斜杠形式 |
| 无 range read | 包装流按实际读取计数 |
| `list` 跳过悬空链接 | 额外用 JDK 目录项补盲区：物理目录里有而后端没返回的条目一律拒绝 |
| Operator 关闭后使用会 SIGSEGV | 每次触碰 native 持 `NativeLifetime` 读锁，`close` 拿写锁，两者互斥 |

两条被后端事实推翻的初始假设：`write` 不会补父目录、`move` 不会补目标父目录——两者都需要预检才能满足 Port。

## 5. 平台范围与未验证事项

| 平台 | 状态 |
| --- | --- |
| **macOS arm64** | **已实跑**：native 加载、真实文件读写、符号链接拒绝、权限类 effect 用例全部执行 |
| Linux x64 | **未验证**：依赖 classifier 可解析、CI 已有 `ubuntu-latest` 配置，但需 CI 实跑后才能声明通过 |

| macOS x86_64 / Windows | **未验证**，不在工具链支持范围 |

其他未验证 / 未承诺事项：

1. **SIGSEGV 本身没有复现过**。`NativeLifetime` 的读写锁让「Operator 关闭后触碰 native」的窗口不可达，并有测试证明关闭会等在进行的操作收尾，但**没有真的崩过一次**来证明崩溃路径已被封死。
2. **Linux x64 未实跑**（见上表）；本模块的 native 加载与全部行为结论只在 macOS arm64 上成立。
3. 构造中途释放 Operator 只有代码审查，没有可确定性触发的运行时用例。
4. 「检查后被外部进程替换路径」的竞争、硬链接与 bind mount 别名不做防护（已知限制）。
5. **阻塞 native 调用不能被协程取消即时中断**：`CancellationException` 的原样传播是单元级验证，不是「调用真的停了」的证据。
6. `close()` 会等在途读取收尾，**可能等很久**；停机限时策略属 T18 / T27，本轮未实现。
7. 不做补偿与恢复（E04），不做可靠事件投递（E05）。
8. `Operator.duplicate()` 在 API 表面存在但本轮未使用，也未单独实测其生命周期语义。

### 本轮方法论边界

- **并发与取消是确定性编排，不是压力测试**：关闭竞争用双向闩锁暂停在途操作，线程归属用实例注入的 `onNativeCall` 捕获线程名。没有用重试或高并发压测碰运气，也没有赌 native 崩溃。四个涉及竞争 / 取消的测试类配置了 `@Timeout(60)`，用于超时告警；不保证能强制中断不可中断锁或 native 调用。
- **权限类用例在 root 环境下会被 `assumeTrue` 显式跳过**，跳过原因写在用例里，不静默通过。请在非 root 环境复跑一次以覆盖 `UNKNOWN` / `PARTIAL` 两条 effect。
