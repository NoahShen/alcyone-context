## 4. 设计决定

| 决定 | 选择 | 理由 |
| --- | --- | --- |
| 符号链接拒绝的错误码 | `STORAGE_ACCESS_DENIED` | 被拒绝的是「通过链接访问该位置」，既不是类型不符也不是不存在；判断是否越界需要目标信息，会泄露宿主结构，所以指向根内的链接同样拒绝 |
| 物理根不存在 / 不是目录 | `INVALID_ARGUMENT` | 这是配置项取值不合法，不是运行期 I/O 失败；不自动创建目录 |
| 根规范化 | `toRealPath()` | 消解根本身及其祖先的符号链接；根内部链接仍逐级拒绝 |
| 写入模式预检 | `stat` 预检 + CREATE_NEW 附加后端 `if_not_exists` | 预检**不是原子**；实测 `fs` 支持 `if_not_exists`，用它给 CREATE_NEW 补一层原子保证。REPLACE_EXISTING 无条件写可用（`writeWithIfNoneMatch = false`），只靠预检，文档已写明 |
| 写限额 | 默认 16 MiB，写入前判断 | T04 §6 的首版默认值；先判断才不会截断或留下残留 |
| 有界读取 | 包装流按实际读取计数，请求裁到「剩余 + 1」 | 后端不支持 range read；`stat` 大小可能过期，不能作为唯一依据 |
| `skip` | **计费** | 否则「跳过大文件再读 1 字节」可绕过限额；`available()` 同理裁到剩余额度 |
| 流打开次数 | 单次打开 | 避免重复打开带来的「同一流两次独立计数」歧义；需要再读就再次 `readStream` |
| 流与 Adapter 的关闭顺序 | **先关流再关 Adapter**；Adapter 先关时流读取抛 `CLOSED` | 实测 Operator 关闭后触碰 native 会 SIGSEGV；守卫必须在进 native 之前生效 |
| 目录移动 | `UNSUPPORTED_OPERATION`，`nativeDirectoryMove = false` | T04 实测 `IsADirectory`；复制删除回退属 T20～T22 |
| 递归删除 | 先规划后删除（后序） | 遇到符号链接时副作用为 0，可断言「什么都没删」；中途失败才报 `PARTIAL` |
| 非递归删除遇符号链接 | 仍报 `DIRECTORY_NOT_EMPTY` | 只判断是否为空、不进入子项，报「拒绝访问」会误导调用方 |
| `write` / `move` 失败后的 effect | `UNKNOWN` | 无法从失败点区分「没动」和「已部分完成」；不谎报 `NONE` |
| `readOnly` 能力 | 恒为 `false` | 一次权限检查不构成只读承诺；真实写失败会映射为 `STORAGE_ACCESS_DENIED` |
| 预检用 JDK、访问用 OpenDAL | 路径 / 链接 / 类型检查走 `java.nio.file`，文件访问走 Operator | 任务文档第 2.1 节的要求；检查类操作不需要 JNI |

## 5. 与任务文档不一致之处

1. **任务文档第 2.2 节说「列举条目与递归删除中的符号链接拒绝」的策略须在交付中说明**：本轮选择「`list` 出现链接条目则整体失败」「递归删除在规划阶段拒绝」，两者都不产生副作用，已写入使用说明与验收记录。
2. **任务文档未规定 `move` 目标父目录缺失时的行为**：实测后端会**自动创建**目标父目录。为了与 `write` 的「不补父目录」保持一致、并避免 Storage 层出现 VFS 状态不知道的目录，本实现返回 `NOT_FOUND`，补齐留给 T15。此为新增行为，已在本节与使用说明第 5 节写明。
3. **任务文档第 2.4 节把流计数交给 T12 决定**：本轮定为单次打开 + skip 计费 + 先关流后关 Adapter，均已写明并有用例。
4. **A01 的「异常路径清理」没有运行时用例**：`Operator.of` 在合法根上无法确定性失败，只能代码审查；已在验收记录中如实标注为未验证。

## 6. 模块边界

- `vfs/storage` 只依赖 `vfs/core`（`api`）与 OpenDAL，不反向依赖 persistence / Router / Guard / Runtime；`LocalFsModuleBoundaryTest` 用源码扫描与反射佐证。
- 公共签名（`LocalFsStorage`、`LocalFsOptions`、`LocalFsRoots`）不出现 OpenDAL 或 JNI 类型；Operator 全部封装在实现内部。
- Adapter 不生成 Node ID、不写 Event、不访问 SQLite、不维护注册树。
