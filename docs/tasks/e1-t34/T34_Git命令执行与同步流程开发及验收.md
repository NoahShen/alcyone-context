## 1. 目标与输入

实现内部 GitRepository 和 GitProcessRunner/JvmGitProcessRunner，提供可供后续 Worker 调用的单次同步流程，不接入 VFS 或定时器。

阅读 [E1里程碑](../e1-git-backup/E1_Git本地备份里程碑.md)、[设计文档](../../vfs/Git_本地目录备份设计_v0.1.md) 和根 AGENTS.md。既有 VFS 零侵入、可选插件、Cron 本机时间、逐轮日志、无公开状态模型是固定边界。

## 2. 修改范围

`vfs/git-backup` 内 GitRepository、进程执行契约/JDK实现、必要内部结果类型和测试；必要依赖统一 Catalog，不改既有 VFS。

不得修改现有 VFS 生产代码、Runtime 配置/依赖、数据库 Schema；不得为本任务提前添加后续功能或通用框架。保留工作区已存在的设计/计划改动，不混入当前代码提交。

## 3. 实施步骤

1. 用临时普通源仓库与本地 bare remote 建立隔离 Git 配置；不使用真实远端或修改用户全局配置。
2. 实现仓库根/分支/remote/身份与不支持状态校验、全目录 add、按需 commit、显式 refspec push；支持尚无 HEAD 的首次提交。
3. 实现参数数组启动、输出并发排空/限量保存、禁用交互、超时/取消清理；不得依赖 shell 拼接或按名杀进程。
4. 将每轮开始和结果日志放在唯一适合的同步边界，T35 调用时不得再重复输出整套结果；内部结果不变成公开状态 API。
5. 为失败保留现场、无变化补 push、命令挂起与清理建立真实或受控证据。

## 4. 验收标准

| 编号 | 可观察标准 |
| --- | --- |
| A01 | 根必须是所配置的普通工作区；分支/远端/身份/嵌套仓库等不支持条件失败且不破坏文件。 |
| A02 | 新增、修改、删除、忽略文件、首个提交与空初始仓库均覆盖；无差异不创建空提交。 |
| A03 | commit 成功但 push 失败保留本地提交；下次无新修改仍 push，远端提交树内容可核对。 |
| A04 | 不执行 pull、强推、自动合并、reset/clean 或删 Git 锁；错误/超时不冒充无修改成功。 |
| A05 | stdout/stderr 充满管道及超大输出不挂起；每命令超时计时从进程启动覆盖输出等待。 |
| A06 | 取消/超时仅清理自己启动的进程；有实际退出证据，无法确认清理则拒绝进一步命令，不隐瞒边界。 |
| A07 | 每轮开始和成功/无内容/失败/取消日志有 runId、阶段与耗时；测试凭据不会出现在记录中。 |
| A08 | 格式、模块测试与 ./scripts/check 通过，归档源码/XML差额、Git版本和日志；提交 Lead 初验后等待 Architect。 |
