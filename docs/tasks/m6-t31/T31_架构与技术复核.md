## 2. 必须修改

### R1：独立消费工程缺少完整项目工具链隔离（A02）

`run-consumer.sh` 设置 JAVA_HOME/GRADLE_USER_HOME 以及 Gradle JVM 参数，本次实际编译和运行的确使用项目 JDK，没有改变系统 JDK。但独立工程不继承根 gradle.properties 和根构建中的 Kotlin daemon 设置：缺少禁用 JDK 自动发现/下载、Kotlin daemon runFilesPath、受控编译策略等约束，也绕过 scripts/dev 的 JDK 安装清单验证，仅检查 java 文件可执行。

直接证据：强制 clean 编译的 `/tmp/t31-review-fresh-consumer.log` 中执行了 `/usr/libexec/java_home -V`，说明仍扫描系统 JDK；编译使用 DAEMON 策略，独立工程未设置项目内 runFilesPath。本机用户目录 `~/Library/Application Support/kotlin/daemon` 还有 22:17 的 daemon 发现文件；它早于本轮，不据此声称复核方新建了该文件，但当前脚本无法保证发现状态只在项目内。

修复：沿用既有私有工具链入口的校验与隔离规则，或为独立工程补齐等价最小配置；不要复制一个逐渐偏离 scripts/dev 的不完整工具链实现。不要求改公共 API；可采用项目内 daemon 目录或受控进程内编译，明确实际策略。关闭系统工具链自动发现/下载，并确保 Gradle/编译器/运行 JVM 与临时/发现目录都受项目环境控制。

验收：至少一次 clean 编译/运行记录所用 JDK 与编译策略，不再扫描系统 JDK；证明 Kotlin daemon 发现文件/临时状态在项目内，且使用已有安装校验。不要仅以设置 JAVA_HOME 或旧输出 UP-TO-DATE 作为全部证据。

### R2：SDK 仓库排他性与版本单一来源未落实（A03 / A04）

消费 build.gradle.kts 在本地 Maven 仓库内写 `content { includeGroup(...) }`，只限制该仓库接受哪些 group；Maven Central 仍未排除 SDK group。任务要求 SDK 坐标只从专属本地仓库解析，当前缺件时仍可能向 Central 查同名坐标。使用排他仓库配置，或在所有其他仓库排除 SDK group，并同步 SDK 指南示例；不需要增加仓库管理框架。

同文件硬编码 Kotlin 2.2.21、coroutines 1.10.2、slf4j-simple 2.0.17，未遵守 AGENTS 的依赖/插件版本来自 gradle/libs.versions.toml 规则。独立工程可以引用/导入现有版本声明或由验证入口传参生成，读取版本配置不等于引用 SDK 源码或 composite build；无须为了“独立”复制维护第三方版本。

runtime 坐标与 0.1.0-SNAPSHOT 作为显式消费目标可保留；协程是调用方 runBlocking 的直接业务依赖、SLF4J Simple 是消费方绑定，两者本身合理，不应为追求一行依赖把它们塞进 SDK。独立验证记录需说明两者来源，别把“只靠 runtime 即自动提供宿主日志绑定”当结论。

验收：查看有效仓库配置，SDK group 只命中项目仓库，缺失 SDK 时失败且不回退其他仓库；版本来源单一。保留实际 classpath/坐标证据即可，不要求另建 Maven 工程或全新测试框架。

## 3. 建议优化

- ConsumerMain 计算 SHA-256 却不比较结果；已有总量断言足以证明分块执行，但既然保留 digest，建议与期望内容哈希比较。移动通知按单次唯一移动类型等待可接受，可顺手补目标 URI/source-target 断言；本轮不扩完整事件矩阵。
- 消费样例有未使用 import、常量/格式未纳入根 spotless 范围；`./scripts/dev gradle spotlessApply` 不检查这个独立工程，交付不要暗示其已受同一格式检查。清理 deleteRecursively 返回值未检查，作为临时 smoke 的非阻塞改进，不能宣称任何失败都完成清理。
- SDK 使用指南更直白写“Mac 发布产物的 native classifier 固定为 osx-aarch_64，不随消费主机自动切换”；现有“不作通用跨平台保证”方向正确。不要为了这个建议引入平台变体框架。
- 本地发布普通 maven-publish 仍提供 publishToMavenLocal 任务；本轮指定命令没有写 ~/.m2，不需要禁用标准任务，但将文档“绝不会发布到 ~/.m2”收窄为“本任务命令仅发布至项目目录”。
- AGENTS 第 35 条仍 TODO，交付已 IN_REVIEW；回填准确状态、提交号、环境和报告来源。保留当前 IN_REVIEW，不把自测标为独立通过。

## 4. 可以接受的设计取舍

- 六个普通 JAR + POM + Gradle module，版本与发布映射在根构建统一，排除聚合与测试产物；不做 fat JAR、签名、远端仓库或发布插件框架。
- Runtime 对 API/Core 的 api 依赖保留，Storage/Persistence 运行依赖传递正确。Persistence 元数据中的 SQLDelight runtime 编译依赖来自现有生成代码配置，不是本轮新引入公共 Runtime 签名泄漏。
- 消费工程位于仓库 tools 目录、读取项目工具链/本地仓库不影响其 Gradle 工程独立性；消费者自己的 build/classes 合理，必须排除的是生产者 classes。
- 只验 macOS arm64；OpenDAL native 的生产者平台固定策略在本地阶段可接受。未证明 Linux 可消费，也不要求新增 Linux 实跑；方案④不变。
- 本次主源码没有变化，新增消费样例不计入 752 / 43 JUnit 基线。消费方自行绑定日志合理。
