## 2. 复核事项与本轮处理范围

### R1 / P1：消费者的普通异常仍会冒泡

`event/EventDispatcher.kt:46` 只捕获 `RuntimeException`，消费者抛 `IOException` 等普通 `Exception` 时会逃逸并阻止后续消费者执行，与“消费者失败不影响已完成操作”不符。独立复现为 `CONSUMER_ESCAPED=IOException LATER_CALLED=false`。

要求：取消异常继续原样传播，其他普通 Exception 记录后继续分发，不要求吞 JVM Error。补 IOException、RuntimeException、取消三类回归断言，并同步 KDoc 的取消例外。

### R2 / 测试替身限制：不作为接口验收阻塞项

回调异常 / 取消后，测试替身仍允许访问逃逸的事务视图，这一复现结果成立，但不能据此认定事务接口设计不合理。撤回 P2 定级及本轮必须补齐所有退出路径防护测试的要求；接口只需说明事务视图用于回调作用域内，不必现在规定回调外必须抛某个具体异常。

本轮把验收记录中的覆盖结论改准确即可，不需要扩建替身。真实事务的退出、回滚和资源管理在 T11 实现时验证；后续仍使用该替身验证相关行为时，再按测试需要修正它。

### R3 / 接口说明补充：不作为实现缺陷或独立阻塞项

撤回原 P2 定级，以及本轮必须验证读取途中超限、关闭后读取行为的要求。T07 尚无真实流式读取实现，测试替身不能用来认定生产实现有缺陷，也不应为了验收接口而提前实现一套流包装。

本轮仅建议简短说明调用方与实现方需要共同理解的含义：`maxBytes=null` 表示什么、限额约束实际读取内容、返回资源由谁关闭。重复打开、计数方式、异常转换与关闭后的具体行为可在 T12 实现时明确并补测试；不要求新增计数属性、强制包装或本轮流式边界测试。

例：`readStream(path, maxBytes=1024)` 表达读取上限，而如何计数并中止由后续实现与测试保证，接口本身不需要执行这一行为。

### R4 / P2：MountRecord 恢复了可配置只读字段

`repository/RepositoryModels.kt` 的 `MountRecord.readOnly` 表示挂载配置属性，而 T01 第 6.1 节与 AGENTS 均明确首版不增加可配置只读挂载，交付决策也未记录该范围变更。它不应与后端真实只读能力混用。

要求：删除该配置字段及对应示例 / 替身参数，后端只读和拒绝访问继续按真实能力 / 错误处理。若确实需要改变首版范围，应另行提交明确设计变更，不能默认引入。

### R5 / 文档一致性：收敛为接口语义说明

本轮只统一会影响调用方理解的内容：删除后正常查询不再返回该节点、路径可被新节点复用、父路径类型错误的分类，以及 operationId 的诊断用途。T03 已定的状态语义继续保留，但不要求 T07 决定数据库删除字段、索引、清理顺序或后端探测步骤，也不增加字段或接口来强制这些实现细节。

清理文档中已取消的时钟 / ID 注入、旧包路径、固定命名空间和“完全无实现”等过期说法；A06 本轮不适用，A05 只记录替身实际演示的范围。operationId 随事件保存与“不建立独立操作恢复日志”并不冲突，持久化细节留 T11 / T14。
