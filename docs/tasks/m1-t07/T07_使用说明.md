## 1. 用例 → Port 对照表

### 1.1 候选 Port 方法清单

**Storage Port**（绑定单个 Mount，参数是挂载根内已解码的相对路径 `StoragePath`；不生成 Node / Event，不认识 `VfsPath`）

| 编号 | 提案方法 | 用途 | 用例 |
| --- | --- | --- | --- |
| S1 | `read(path, maxBytes: Long): StorageContent` | 有界读取，同时返回可得的属性。Adapter 必须先 stat 取大小做快速判超限（用户 G4），并在超限内容进入内存前中止；B3 补流式 / 分段读取契约 | read；跨 Mount 复制 |
| S2 | `stat(path): StorageAttributes` | 存在性、类型、大小、修改时间 | stat、read 前置判定（见决定 D6）、write、move、delete |
| S3 | `list(path): List<StorageEntry>` | 单层列举，不递归 | list；目录移动复制；非递归删除前判空 |
| S4 | `write(path, content, mode: StorageWriteMode): StorageAttributes` | 三种写入模式 | write；跨 Mount 复制 |
| S5 | `createDirectory(path)` | 补齐父目录；跨 Mount 目录移动需要保留空子目录 | write、move（无公共 API 入口） |
| S6 | `move(source, target): StorageAttributes` | 同一 Storage 内的原生移动 | move（同 Mount） |
| S7 | `delete(path, recursive: Boolean)` | 删除文件 / 目录 | delete；跨 Mount 与目录移动的删除阶段 |
| S8 | `capabilities(): StorageCapabilities` | 只暴露 Core 需要的差异：原生文件移动、原生目录移动、创建目录、有界读 | 全部写操作的能力检查 |

`StorageEntry` = 名称 + 类型 + 可选属性；`StorageAttributes` 对应公共 `StorageStat` 的可空字段。错误一律用 `VfsException`（`VfsErrorCode`），不另设 Storage 异常类型。

**Repository / 状态 Port**（状态类型只含逻辑信息，不含数据库行、Storage 凭据和物理路径）

| 编号 | 提案方法 | 用途 | 用例 |
| --- | --- | --- | --- |
| R1 | `findNodeByPath(path: VfsPath): NodeRecord?` | 按有效路径查 Node | write、stat、list、move、delete |
| R2 | `findNodeById(id: NodeId): NodeRecord?` | 按 ID 查 Node | getNode、getMetadata、setMetadata、move、delete |
| R3 | `registerNode(record): NodeRecord` | 懒注册；有效路径已被占用时返回既有记录（竞争复用） | stat、write、move |
| R4 | `updateNodePath(id, newPath, updatedAt)` | 同一 Node 换逻辑路径 | move |
| R5 | `touchNode(id, updatedAt)` | 内容覆盖后更新逻辑记录时间 | write |
| R6 | `markNodeDeleted(ids, deletedAt)` | 标记删除并释放有效路径 | delete |
| R7 | `findRegisteredSubtree(path): List<NodeRecord>` | 含自身与后代，按段边界，不含 `/a` 的 `/ab` | 目录 move、递归 delete |
| R8 | `findNodesByPaths(paths): List<NodeRecord>` | 批量补 `list` 结果的 Node ID，避免逐项查询 | list |
| R9 | `getMetadata(id): NodeMetadata?` / `putMetadata(id, metadata)` / `deleteMetadata(id)` | Metadata 查询 / 整体替换 / 清理 | getMetadata、setMetadata、delete |
| R10 | `appendEvent(event: EventRecord)` | 与 Node / Metadata 同一事务追加事件 | write、move、delete、setMetadata |
| R11 | `listMounts(): List<MountRecord>` | 启动时载入 Mount 映射；路由算法不在这层 | list、move 的嵌套 Mount 检查（T09 消费） |

**事务与通知 Port**

| 编号 | 提案方法 | 用途 | 用例 |
| --- | --- | --- | --- |
| X1 | `inTransaction(block)`：进入后获得同一事务内的 nodes / metadata / events 视图 | 让 Node、Metadata 与 Event 共用一次提交 | write、move、delete、setMetadata、stat 的懒注册 |
| X2 | `dispatch(events): Unit` | 提交成功后进程内分发 | 同上；Consumer 失败不回滚 |

**时间与 ID**（B1 原提案，**已取消**；保留于此仅为记录 B1 讨论过程）

| 编号 | 原提案内容 | 结论 |
| --- | --- | --- |
| I1 | `java.time.Clock` | **取消**：Core 直接取系统时间，不建可注入时钟 |
| I2 | `IdGenerator.nextNodeId()` / `nextEventId()` | **取消**：直接调用 `common` 的 UUIDv7 工具，不建可注入生成器 |

### 1.3 双向自查

**用例需要的 Port 方法是否都在表里**：九个用例引用的方法为 S1～S8、R1～R11、X1、X2，均已列出（I1 / I2 已取消）。三处需要留意的组合：

- `list` 依赖 R8（批量）与 R11（Mount 派生），二者都不是“直接查 Node”能替代的。
- `delete` 依赖 R7 与 R9 的清理动作，而不只是 R6 标记删除。
- 懒注册（R3）出现在 `stat`、`write`、`move` 三处，但只有 `stat` 是不带事件单独提交的（路径 T03 第 4 节）。

**没有被任何用例使用的 Port 方法（预留）**：

| 方法 | 是否定义 | 理由 |
| --- | --- | --- |
| `R11` 的写入侧（首次启动保存 / 修改 Mount 映射） | **本批不定义** | T03 第 8 节要求首启保存 Mount 映射，但写入发生在 Runtime 组装（T18）与 Schema（T11），B4 只定义读接口；等 T18 确认配置流程后再补，避免 Core 提前承诺初始化顺序 |
| `S-copy`（Storage 侧服务端复制） | **本批不定义** | 跨 Mount 复制用 S1 + S4 即可表达；服务端复制只在需要绕开单文件 16 MiB 内存上限时才有价值，尚未确认 OpenDAL 在两类后端上的等价语义（见缺口 G4） |
| 事件清理 / 消费游标 / 操作日志 | **明确不做** | 分别属 E05 与 E04，首版不引入；T07 不为其预留接口 |
| 条件写（if-absent / if-match） | **本批不定义** | T02 第 9.2 节明确首版只保证同一 Runtime 内一致，不承诺对外部并发写入的条件原子性；S4 的模式语义已足够 |

**已定义但当前无用例直接消费**：`S8.capabilities` 由 T10 及后续写操作消费，不由查询用例消费；它属于 Port 契约的一部分（能力差异的表达方式），不算缺口。

## 2. 边界归属表

| 语义 | Port 契约承诺什么 | 不承诺 / 由谁实现 |
| --- | --- | --- |
| 存储能力差异（S8） | 只表达 Core 需要的四项能力：原生文件移动、原生目录移动、创建目录、有界读；能力不足时以 `UNSUPPORTED_OPERATION` 报告，不静默降级 | **T10** 负责检查与降级编排（读→写→确认→删）；T12 负责把 OpenDAL 能力映射到这四项，不得把 `Capability` 原样透传 |
| Mount 路由与最长前缀（T09） | R11 只提供 `listMounts()`；路径前缀比较、子树推导、嵌套 Mount 覆盖规则 | **T09** 实现路由：最长完整段前缀匹配、后代 Mount 派生、虚拟目录推导。Repository 不做前缀匹配，不做命名空间判断 |
| 懒注册与竞争（T13） | R3 的契约：有效路径唯一；并发注册同一路径时调用方拿到同一个已存在 ID，而不是第二个 ID；注册只提交 Registry | **T13** 决定何时触发（stat 未命中、move 的未注册源）、如何串行化；T03 第 7 节的单把变更锁由 T18 组装 |
| 事务的真实实现（T11） | X1 的契约：一次事务内可见一致的 nodes / metadata / events 视图，提交或整体回滚；取消原样传播 | **T11** 实现真实 SQLite 事务；T07 不提供事务协调器实现，也不假定各 Repository 各自提交 |
| 事件持久化与提交后分发（T14） | R10 在事务内追加；X2 只在提交成功后调用；分发失败不影响已提交状态与已完成的文件操作 | **T14** 实现持久化与进程内分发；T07 不实现总线、不做消费进度与重放（E05） |
| 父目录补齐（T15 / T16） | S5 存在且只在目标所属 Mount 内调用；S4 失败不隐式补目录 | **T15**（write）负责“先完成检查再创建父目录”，**T16**（delete）不创建父目录；T02 6.2 的顺序由 T15 保证 |
| 跨 Mount 复制与删除顺序（T21 / T22） | S3 + S1 + S4 + S2/S3 确认 + S7 足以表达“先完整复制并确认，再删源” | **T21 / T22** 负责编排顺序、目录树逐层遍历、空子目录保留、部分失败如实报告；Port 不提供“原子移动” |
| 读取限额（T18 配置 / T12 执行） | S1 的 `maxBytes` 非空且为有效上限，Adapter 在读入超限内容前中止并报 `LIMIT_EXCEEDED` | **T18** 解析配置与默认值（16 MiB，可配置）；**T15** 取调用方上限与 Runtime 限额的较小值；**T12** 验证有界读 |
| 路径规范化与穿越规则 | `StoragePath` 拒绝绝对路径、`.` / `..`、段内分隔符，不做百分号解码；`VfsPath` 沿用 T06 已实现的校验 | **B2** 定值类型；**T12** 负责物理根边界与符号链接；T09 负责把 `VfsPath` 切成 `StoragePath` |
| 错误码与 effect | Storage / Repository 抛 `VfsException`；不引入基础设施异常类型；effect 由编排层判断 | **T10 / T23** 归类后端错误；**T23** 验证 effect 不被误报 |
| 时间与 ID | **本轮无接口**：Core 直接取系统时间与 `common` 的 UUIDv7 工具 | 无需注入点；若后续确需断言时间戳相对顺序或固定 ID，再按当时用例补 |

一句话概括职责边界：**Port 只表达“能做什么、拿到什么状态、错误怎么带”，所有顺序、路由、能力降级、锁与通知时机都在 Core 业务任务里。**

## 4. 术语约定

| 术语 | 含义 | 落地形态 |
| --- | --- | --- |
| Interface | 接口，声明“需要什么能力”。**按领域自然命名，不强制加后缀** | `interface Storage`、`interface NodeRepository`、`interface UnitOfWork` |
| Impl | 实现接口的具体后端，用 `Impl` 后缀；测试替身用 `FakeImpl` | `OpenDalStorageImpl : Storage`，内部持有 OpenDAL Operator |
| Core | 业务编排层 | 持有 Port 引用，按 T01 / T02 / T03 规则编排操作 |

调用链：`调用方 → Vfs(API) → Core(业务) → Storage 接口 → StorageImpl → 真实文件系统`。事件分发在 Core 内部，不经 StorageImpl。

### 6.1 B2: StoragePath

文件：`vfs/core/src/main/kotlin/alcyone/vfs/core/storage/StoragePath.kt`

```kotlin
package com.github.noahshen.alcyone.context.vfs.core.storage

import com.github.noahshen.alcyone.context.vfs.VfsErrorCode
import com.github.noahshen.alcyone.context.vfs.VfsException

class StoragePath private constructor(
    segments: List<String>,
) {
    val segments: List<String>
    val isRoot: Boolean get()
    val name: String get()
    val parent: StoragePath get()

    fun resolve(child: String): StoragePath
    fun resolveAll(children: List<String>): StoragePath
    fun toRelativeString(): String
    override fun toString(): String
    override fun equals(other: Any?): Boolean
    override fun hashCode(): Int

    companion object {
        val root: StoragePath
        fun parse(text: String): StoragePath
        fun of(segments: List<String>): StoragePath
    }
}
```

- **挂载根**：`segments` 为空列表；规范相对字符串为 `.`，空字符串与 `.` 均解析为挂载根。
- **校验边界**：拒绝绝对路径（以 `/` 开头）、空中间段（`a//b`）、相对段（`.` 与 `..`）、非法字符（`/`、`\`、NUL、C0、DEL、C1 控制字符 0x80..0x9F）、孤立高/低代理字符。非法输入抛 `VfsException(VfsErrorCode.INVALID_URI, ...)`。
- **编码语义**：输入已解码，`parse` 不做百分号解码，`%2e%2e` 作为字面普通文件名处理。
- **不可变性**：入参做防御性拷贝，暴露的 `segments` 包装为 `Collections.unmodifiableList`。

### 6.4 B5: 事务作用域与提交后通知边界

文件：
- `vfs/core/src/main/kotlin/com/github/noahshen/alcyone/context/vfs/core/transaction/UnitOfWork.kt`
- `vfs/core/src/main/kotlin/com/github/noahshen/alcyone/context/vfs/core/event/EventDispatcher.kt`

```kotlin
package com.github.noahshen.alcyone.context.vfs.core.transaction

import com.github.noahshen.alcyone.context.vfs.core.repository.EventRepository
import com.github.noahshen.alcyone.context.vfs.core.repository.MetadataRepository
import com.github.noahshen.alcyone.context.vfs.core.repository.NodeRepository

/** 一次事务内的聚合视图；离开 inTransaction 回调即失效。 */
interface TransactionScope {
    val nodes: NodeRepository
    val metadata: MetadataRepository
    val events: EventRepository
}

/** 事务入口：回调正常返回即提交，抛异常则整体回滚，取消异常原样传播。 */
interface UnitOfWork {
    suspend fun <T> inTransaction(block: suspend (TransactionScope) -> T): T
}
```

```kotlin
package com.github.noahshen.alcyone.context.vfs.core.event

import com.github.noahshen.alcyone.context.vfs.VfsEvent

/** 消费者异常由分发器吞掉，不影响已提交状态。 */
fun interface VfsEventConsumer {
    suspend fun onEvent(event: VfsEvent)
}

/** Core 内部组件，不是 Storage / Repository 接口（X2）。 */
class EventDispatcher {
    fun subscribe(consumer: VfsEventConsumer)
    suspend fun dispatch(events: List<VfsEvent>)
}
```

- **G7 方案 A**：事务边界在代码中可见；视图直接复用 B4 的 Repository 签名，不额外派生事务专用接口。
- **提交与回滚**：正常返回提交；抛异常则回滚，回调内已排队的变更全部不生效。替换 Metadata 后追加事件失败，两者都不提交。
- **不隐退自动提交**：事务对象逃逸到回调外使用时抛 `IllegalStateException`；提交失败后同样失效。
- **取消传播**：`CancellationException` 原样传播，不包装成业务异常。
- **X2 边界**：分发器只接收已提交事件；提交失败时调用方不得分发。消费者抛异常只记日志（SLF4J WARN），不回滚事务、不影响已提交状态、不冒泡给调用方；`CancellationException` 例外，仍传播。
- **真实实现归属**：真实 SQLite 事务属 T11，事件持久化属 T14，可靠消费属 E05；本批只定义契约与可记录顺序的替身，**替身结果不作为真实事务验证**。
