## 1. 目标与依据

在 `vfs/core` 定义后续业务编排需要的 Storage / Repository Port、事务作用域和事件通知边界，并提供可替换的时钟与 ID 生成入口。本任务交付可编译接口、必要的数据类型和测试替身；方法命名、文件拆分等细节由开发 Agent 在实现时明确，不提前铺设通用后端框架。

例：Core 能通过接口表达“写文件 → 同事务保存 Node 与事件 → 提交后通知”，而不需要知道 OpenDAL Operator 或 SQLDelight Driver。

## 2. 开发范围

### 2.1 Storage Port 与相对路径

提供读取、写入、属性查询、单层列举、创建目录、移动和删除所需的最小接口；明确参数、结果、能力不足与失败语义，Storage 不生成 Node / Event。路径使用挂载根内的已解码相对路径类型，明确根的表示，拒绝绝对路径、`.` / `..` 和段内分隔符，不再解码百分号；物理根和符号链接边界留 Adapter 验证。

例：逻辑 `/notes/reports/a.txt` 挂载于 `/notes` 后，Storage 收到 `reports/a.txt`，不是逻辑 URI 或宿主绝对路径；字面 `%2e%2e` 不再次解码。

### 2.2 存储能力与操作语义

仅暴露核心用例实际需要的能力差异，区分文件 / 目录原生移动，不能把 OpenDAL Capability 原样暴露给 Core。接口须能传递有效读取字节上限和写入模式，说明单层 list、目录创建、目标已存在、非空目录删除的处理责任；具体能力检查和降级编排分别留 T10 / 后续业务任务。

例：后端不支持目录 rename 时可以明确报告能力不足，由后续 Core 逐层复制并删除；不能声称一个 `move=true` 就支持所有移动。

### 2.3 Repository Port 与状态类型

按需提供 Mount 映射记录、Node 查询 / 注册 / 更新 / 删除标记、Metadata 查询 / 替换 / 清理、Event 追加所需接口；Node 支持按 ID、有效路径查询，以及目录移动 / 删除涉及的已注册子树查询。方法契约须说明有效路径唯一、注册竞争结果、移动保留 ID、删除释放路径与虚拟目录无物理映射，状态类型不包含数据库行或 Storage 凭据。

例：注册 `/notes/a` 时若已有有效 Node，调用方能够得到已有 ID 或明确的冲突结果；子树查询 `/notes/a` 不包含 `/notes/abc`，不能依赖未经限定的字符串前缀。

### 2.4 事务作用域与事件边界

提供一次事务内访问相关 Repository 的明确方式，使 Node / Metadata 与 Event 追加可以共用同一事务；说明成功提交、异常 / 取消回滚的责任，不能由各 Repository 分别提交来代替。事件持久化与提交后通知分开，Storage 不纳入数据库事务，通知失败不回滚已提交状态；本轮只定义这些接口契约，真实事务与分发分别由 T11 / 后续事件任务实现。

例：替换 Metadata 后追加事件失败，两者都不提交；数据库提交失败不能通知成功事件，也不能宣称此前 Storage 写入已回滚。

### 2.5 时钟、ID 与故障注入

时间直接取 `Clock.systemUTC().instant()`，Node / 事件 ID 直接调用 `common` 的 UUIDv7 工具，不另写算法、不建可注入的时钟或 ID 生成器。**2026-09-29 B1 评审决定**：时间与 ID 入口不列为 Port 也不列为可注入依赖；待出现确需断言相对顺序的用例时再补注入点。**2026-09-30 复核裁定**：本任务没有时间字段与 ID 的填充逻辑，因此**验收项 A06 记为不适用**；Node 生成与时间字段在 T13 验证，事件在 T14 验证。本轮仅需证明接口可表达成功 / 失败，真实业务故障路径在后续实现任务验证。

例：可以用简单调用示例说明事件追加可能失败；本轮没有 Node / 事件生成流程，不必为验收而新增这一实现。

## 3. 交付物与范围边界

| 位置 | 交付内容 |
| --- | --- |
| `vfs/core/src/main/kotlin/` | 建议使用 `com.github.noahshen.alcyone.context.vfs.core` 及必要子包，交付 Port、最小状态 / Storage 路径类型、必要的局部值类型实现 |
| `vfs/core/src/test/kotlin/` | 测试替身、调用示例、已交付局部值类型的测试；不把替身作为正式存储发布 |
| `vfs/core/build.gradle.kts` | 按需调整依赖可见性及测试依赖；复用版本目录，不引入具体 Adapter |
| 本任务目录 | 开发 Agent 补充 `T07_使用说明.md`、`T07_验收记录.md`，记录接口决策、命令、结果与未验证事项 |

Core 可供独立 Adapter 模块实现的 Port 必须具有可访问的 Kotlin 可见性，不能全部声明为模块内 `internal`。Core 签名引用 API 类型时，检查 Gradle 依赖可见性；不因方便测试而把 Core Port 移入 `vfs/api`。

本轮不实现 Mount 路由、Storage Adapter、SQL / Schema、Node Registry 或 `Vfs` 方法体，也不实现生产事务协调器、事件总线、Runtime 配置与生命周期。命名空间保持由后续配置注入，既不恢复 API 白名单，也不增加调用身份、访问权限、操作恢复日志或事件重放机制。

## 4.1 验收批次与审核门

| 批次 | 范围 | 交付物 | 审核门 |
| --- | --- | --- | --- |

| B4 状态 Port | S3 前半 | Repository 接口、Node / Mount / Metadata / Event 记录类型，子树查询 | 状态字段与唯一性、子树边界语义经确认 |
