## 1. 目标与依据

在 `vfs/core` 实现逻辑挂载校验、最长完整路径段匹配及相对 StoragePath 计算，供后续文件操作编排使用。本任务是纯逻辑实现，应对路由算法做真实单元测试；不为未实现的存储行为扩建测试替身。

依据：[T02 路径与文件操作语义](../../vfs/VFS_路径与文件操作语义_v0.1.md) 第 2、3、8 节，[T03 状态与事务](../../vfs/VFS_状态与恢复设计_v0.1.md) 第 8 节，以及已交付的 VfsPath、VfsUri、StoragePath、MountRecord。继续保持自定义命名空间，不恢复 memory / resources 白名单，也不新增身份或访问权限。

例：有 `/notes` 和 `/notes/archive` 两个挂载时，`/notes/archive/a.txt` 选择后者，相对路径是 `a.txt`。

## 2. 开发内容

### 2.1 接收与校验挂载集合

接收已解析的命名空间集合及 MountRecord 集合，建立本次使用期间固定的路由视图；复用 VfsPath 校验与规范化，拒绝重复挂载位置和挂载逻辑根 `/`，挂载首段须属于传入的命名空间。输入类型和类名由开发 Agent 按现有类型简洁实现，不新增配置文件格式、全局注册中心或动态挂载管理。

例：`/notes/a` 与 `/notes/a/` 是重复位置，应拒绝；命名空间由输入配置包含 `notes`，不是由路径解析器内置。配置非法使用既有 INVALID_ARGUMENT / NONE，格式错误沿用路径类型已有错误码。

### 2.2 按最长完整路径段路由

匹配必须按已解码的路径段进行，选中最深的 Mount，结果不受输入挂载顺序影响；返回足够供调用方使用的挂载记录和相对 StoragePath。没有匹配 Mount 时须可明确识别，不查询 Storage 存在性，也不因深层挂载后端不可用而选择父挂载。

例：`/notes/a` 匹配 `/notes/a/report`，不匹配 `/notes/abc`；有父挂载 `/notes` 时，后者选择父挂载。

### 2.3 计算后端相对路径

从 VfsPath 段列表移除已选挂载前缀，以现有 StoragePath 构造结果；恰好访问挂载根时返回 StoragePath.root。不得拼宿主绝对路径或依靠未经段边界检查的字符串截取。解码后的段中不出现字面 `%`（双重编码已在 VfsUri / VfsPath 解析层拒绝，见 T02 第 2.2 节），因此路由和 StoragePath 构造无需处理百分号二次解码的歧义。

例：挂载 `/notes`，URI `alcyone://notes/%252e%252e/a` 在解析时即被拒绝（INVALID_URI）；正常路径 `alcyone://notes/a b/c.txt` 解码后相对路径为 `a b/c.txt`。

### 2.4 配置目录与挂载结构查询

从传入命名空间和挂载集合推导逻辑根、命名空间根、挂载入口及必要祖先，能查询直接可见的配置子目录、是否为挂载根及是否包含后代挂载。只提供后续 stat / list / 移动删除所需的结构信息，不生成 Node、不执行目录合并或文件变更。

例：仅配置 `/notes/team/docs`，导航信息能在 `/notes` 下列出 `team`，在 `/notes/team` 下列出 `docs`；两个挂载共享祖先时同一子目录只出现一次。

### 2.5 区分路由和虚拟目录

配置目录即使没有 Storage 映射也能被识别，避免把逻辑根或深层挂载祖先直接判为 MOUNT_NOT_FOUND；虚拟祖先也可能同时有父挂载映射，两种信息不能互相覆盖。结果形状可用少量方法或轻量类型表达，不要求建立复杂节点分类体系。

例：同时挂载 `/notes` 与 `/notes/team/docs` 时，`/notes/team` 既有父挂载下的相对路径，也有配置子目录 `docs`；后续 list 才负责与真实后端内容合并。既无映射又非配置目录的普通路径按 T02 返回 MOUNT_NOT_FOUND；已匹配挂载内的 NOT_FOUND 由后端判断。

## 3. 交付范围与后续归属

| 本轮交付 | 后续处理 |
| --- | --- |
| Core 路由、逻辑配置校验、StoragePath 计算、配置目录和后代挂载查询 | T10 / 文件操作任务落实操作约束、能力检查及修改拒绝 |
| 从传入集合构建固定路由视图 | T18 提供 Runtime 配置与 Storage 实例组装；本轮不创建 Operator，也不读取配置文件 |
| 使用 MountRecord.path / storageKey 识别路由目标 | T11 / T18 负责首次保存、配置与持久化状态核对 |
| 逻辑段边界及相对路径验证 | T12 负责物理根、符号链接；可识别的后端物理根重叠由有实际映射信息的 T12 / T18 验证 |

`storageKey` 是不透明标识，不能据不同 key 推断物理根一定不重叠；本轮无需为此扩充物理 URL、凭据或文件系统接口。既有类型只在确有必要时做兼容性补充，说明理由，不重写 T06 / T07 已验证的解析器。本轮确有一处必要的兼容性收紧：VfsUri / VfsPath / StoragePath 拒绝解码后含字面 `%` 的段（理由见 T02 第 2.2 节本次修改说明），属于契约收紧而非行为重写。已接到的既有测试调整清单：

| 位置 | 现状 | 调整 |
| --- | --- | --- |
| `vfs/api/.../VfsUriTest.kt` `example 9 double encoding stays a literal file name` | 断言 `%252e%252e` 解析成功 | 改为 `assertInvalidUri` |
| 同文件 `uri round trip is idempotent` | 输入列表含 `alcyone://resources/%252e%252e` | 移除该输入，另补含 `%25` 的拒绝用例 |
| 同文件 `serialization keeps unreserved characters and uses uppercase hex` | 输入 `a%3F...%3D%25` 解码后段尾为 `%` | 同样改为拒绝，序列化正例改用不含 `%` 的输入 |
| `vfs/api/.../VfsPathTest.kt` `segments are taken literally without percent decoding` | 断言字面 `%252e%252e` 段合法 | 改为含 `%` 的段抛 INVALID_PATH |
| `vfs/core/.../StoragePathTest.kt` 第 4 组“字面 `%2e%2e` 当普通文件名” | 断言 `%2e%2e` 段合法 | StoragePath.parse 同步禁 `%`，改为拒绝，保留正常段不解码的正例 |

实现侧对应改动：`VfsUri.percentDecodeOnce` / `VfsPath` 段校验在解码后检查段不含 `%`，StoragePath 同理；`encodeSegment` 不变。其余测试（`%2e%2e` 拒绝、中文、空格、大小写等）不受影响。

源码和单元测试放在 `vfs/core` 现有包路径下，文件拆分按实际需要决定。同目录补齐 `T09_使用说明.md` 与 `T09_验收记录.md`；不改工具链、CI、数据库 Schema 或 Vfs 公共操作签名。

## 5. 验收标准

| 编号 | 必须满足的结果 | 核心场景 / 证据 |
| --- | --- | --- |
| A01 配置校验 | 拒绝规范化后的重复位置、根挂载及未配置命名空间中的挂载；不固定名称 | `/notes/a` 与尾斜线变体冲突；配置 notes / Resources 后均可使用且保留大小写；空挂载集合可构建 |
| A02 最长段匹配 | 父子挂载选最深，完整段边界、大小写和输入顺序行为正确 | `/notes/a/x` 选 `/notes/a`；`/notes/abc` 不误选 `/notes/a`；反转挂载输入顺序结果不变 |
| A03 相对路径 | 返回所选挂载与正确 StoragePath，挂载根返回 root，已有解析规则不被绕过 | 中文 / 空格路径；双重编码（`%252e` 等）在解析层拒绝；逻辑前缀不会出现在相对结果中 |
| A04 配置目录 | 根和配置命名空间可导航；深层挂载祖先及直接子目录去重；与父挂载映射共存 | 空挂载下 `/` 和已配置 `/notes` 仍识别为目录；两个深层挂载共享 `team`；未知 `/other` 不因能解析就成为虚拟目录 |
| A05 结构与无匹配 | 精确挂载根、后代挂载关系按段判断；无映射的普通路径明确为 MOUNT_NOT_FOUND | `/notes/team` 包含 `/notes/team/docs`，不包含 `/notes/teammate`；结果不声称普通文件已存在 |
| A06 纯逻辑与稳定性 | 不调用 Storage / Repository 或创建资源，不暴露具体后端类型；外部修改输入集合不改变既有视图 | 代码审查、输入集合修改测试；只使用必要的测试数据，不要求完整存储替身 |
| A07 构建与交付 | 新增 Core 测试真实执行、原有测试继续通过、格式检查通过；文档和状态准确 | `./scripts/check` 输出、JUnit 数量与失败 / 错误 / 跳过统计、变更清单；远端结果如实记录 |

本轮验证的是逻辑路径无法通过路由变成挂载外相对路径，不代表已抵御真实文件系统的符号链接或外部并发替换。API 解析成功不表示命名空间已配置，选中 Mount 也不表示实际文件存在。
