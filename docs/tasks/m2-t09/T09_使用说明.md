## 1. MountRouter 是干什么的

用户访问 `alcyone://memory/notes/a.txt` 时，VFS 必须知道两件事：**这个文件落在哪个存储上**，以及**在该存储里叫什么相对位置**（`notes/a.txt`，而不是宿主绝对路径）。这就是 MountRouter 干的事：

- 你告诉它「有哪些命名空间、哪些路径挂了存储」；
- 它回答「某个逻辑路径落在哪个挂载点下、在那个存储里的相对位置是什么」，以及「哪些目录是配置推导出来的、能不能浏览」。

它不碰文件、不连存储、不查文件是否存在，所有答案只来自你给的配置。想执行读写的代码（Vfs 的 write / read / list）在拿到这个答案后才去访问后端。

## 2. 贯穿全文的例子：笔记本场景

假设这台笔记本的配置是：

| 命名空间 | 含义 |
| --- | --- |
| `memory` | 智能体长期记忆 |
| `resources` | 长期文件资源 |

| 挂载点 | 落到哪个存储 |
| --- | --- |
| `/memory` | 本地硬盘（`storageKey = "local-disk"`） |
| `/memory/archive` | 另一块存储，比如 WebDAV（`storageKey = "archive-disk"`） |

`storageKey` 是给每个存储实例起的内部名字。路由只把它原样转交，不关心它对应本地硬盘、WebDAV 还是别的后端。

下文每个方法的例子都用这套配置：

```kotlin
val router =
    MountRouter.of(
        namespaces = setOf("memory", "resources"),
        mounts =
            listOf(
                MountRecord(VfsPath.parse("/memory"), "local-disk"),
                MountRecord(VfsPath.parse("/memory/archive"), "archive-disk"),
            ),
    )
```

**注意命名空间和挂载点是两件事**：`resources` 是命名空间（说明存在这个顶层目录），但它下面没挂任何存储。所以 `/resources` 仍然是可以浏览的目录，而 `/resources/x.txt` 路由不到任何存储。

### 2.1 `storageKey` 与 `mountId` 的区别

这两个名字都和挂载有关，但标识的是不同的东西，出现在不同的任务阶段：

| | `storageKey`（现在就有） | `mountId`（T11 持久化时才有） |
| --- | --- | --- |
| 标识什么 | 用哪个存储实例 | 哪一条挂载记录 |
| 回答的问题 | 这个挂载点背后是哪块盘 | 数据库里这行挂载记录是哪条 |
| 唯一性 | 多个挂载点**可以共享**同一个 key | 每条挂载记录唯一（数据库主键） |
| 出现位置 | `MountRecord.storageKey` | SQLite Mount 表的 `id` 字段 |

回到笔记本场景，把例子改成这样：

```kotlin
MountRecord(VfsPath.parse("/memory"),        "local-disk")   // 挂载点 1
MountRecord(VfsPath.parse("/memory/backup"), "local-disk")   // 挂载点 2，同一块盘
MountRecord(VfsPath.parse("/resources"),     "webdav-nas")   // 挂载点 3
```

前两个挂载点**共享** `storageKey = "local-disk"`：表示两个入口通向**同一块本地硬盘**——`/memory/backup` 下的文件和 `/memory` 下的文件实际在同一块盘上。这就是「key 标识存储实例」的含义。

`mountId` 目前代码里**不存在**。当前路由是纯内存逻辑，挂载点的唯一身份就是它的 `path`（创建 router 时已保证不重复），不需要额外 ID。等 T11 把挂载记录存进 SQLite 时，每条记录才会有自己的主键 `mountId`，Node 身份记录（NodeIdentity）通过它关联「我在哪个挂载点下」——那是数据库里的外键关系，路由层用不到。

另一个已知限制：`storageKey` 不透明——两个**不同**的 key 也可能指向同一块物理硬盘（比如两个 key 都配成本地 `/data` 目录）。这种物理根重叠的检查属于 T12 / T18，路由不负责。

## 3. 怎么创建

`MountRouter.of(namespaces, mounts)` 创建，创建完之后它自己不会再变（没有添加 / 删除挂载的方法）；要改配置就重新创建一个。想换配置时直接重新 `of(...)`。

入参会复制一份存起来，之后调用方修改自己那份 `Set` / `List`，已经创建的 router 不受影响。

`namespaces` 里的每个名字是一个路径段：不能为空、不能带 `/`、`\`、控制字符或空格、不能带 `%`（这就是 T09 A 阶段收紧的规则），并且**区分大小写**——`Resources` 和 `resources` 是两个不同的命名空间。

`mounts` 里的每个 `MountRecord` 要求 `path` 已经解析成 `VfsPath`。

`mounts` 可以是空的：这样创建出来也能用，只是任何路径都路由不到存储，只剩配置目录可以浏览。

## 4. 方法说明

### 4.1 `route(path)`：这个路径落在哪个存储的哪个位置

**做什么**：给一个逻辑路径，返回它该走哪个挂载点、在那个存储里的相对位置；匹配规则是「按完整路径段一层层比，取最深的那层」。

**什么时候用**：read / write / stat / list / move / delete 在真正访问后端之前都要先调它。

```kotlin
router.route(VfsPath.parse("/memory/notes/a.txt"))
// → RouteMatch(mount=/memory, relativePath=notes/a.txt)
```

为什么是 `/memory`：`/memory/archive` 也在配置里，但 `notes` 不是 `archive`，深层挂载不命中，所以退回父挂载 `/memory`；相对路径 = 去掉 `/memory` 前缀后的 `notes/a.txt`。

```kotlin
router.route(VfsPath.parse("/memory/archive/2025/q1.md"))
// → RouteMatch(mount=/memory/archive, relativePath=2025/q1.md)
```

这里命中深层挂载：路径段是 `memory`、`archive`、`2025`、`q1.md`，和 `/memory/archive` 完全一致的前缀，取最深的它。

**边界情况**：

- `router.route(VfsPath.parse("/memory/archive"))` → `relativePath` 是 `StoragePath.root`（挂载根本身，相对位置为「存储的根」，`toRelativeString()` 得到 `"."`）。不会返回空字符串，避免后端把空字符串误当成上一级目录。
- `router.route(VfsPath.parse("/resources/x.txt"))` → `null`。`resources` 只是命名空间、下面没挂存储，没有任何挂载点命中。返回 `null` 表示「我不知道该走哪个存储」，由上层判断：它是配置推导出来的目录就按虚拟目录处理，否则按 T02 §3.2 返回 `MOUNT_NOT_FOUND`。`MountRouter` 自己不抛 `MOUNT_NOT_FOUND`。
- 段边界是严格的：`/memory/archive` **不会**命中 `/memory/archiver`。
- 挂载顺序不影响结果：把两个 `MountRecord` 换顺序写，答案一样。

### 4.2 `isConfiguredDirectory(path)`：这个目录是不是配置里推出来的

**做什么**：判断某个路径是不是「配置能证明存在的目录」。这些目录包括逻辑根 `/`、所有命名空间根、所有挂载点，以及挂载点缺掉的中间层。

**什么时候用**：stat / list 之前区分「这是个真实的后端目录」还是「只是个配置里的虚拟目录」。虚拟目录不该报「找不到」。

```kotlin
router.isConfiguredDirectory(VfsPath.root) // true：逻辑根
router.isConfiguredDirectory(VfsPath.parse("/resources")) // true：命名空间根，哪怕下面没挂存储
router.isConfiguredDirectory(VfsPath.parse("/memory/archive")) // true：挂载点
router.isConfiguredDirectory(VfsPath.parse("/memory/notes")) // false：配置里没有这一层
```

为什么 `/resources` 是 `true`：`resources` 在命名空间集合里，逻辑根下必须能看见它，否则没法浏览配置好的命名空间。`/memory/notes` 是 `false`：没有挂载点落在它下面，也没有命名空间叫 `notes`，配置对它一无所知。

**边界情况**：返回 `true` 只说明「配置里说得通」，**不代表后端真有这个目录**。`/memory/archive` 在配置里，但如果 `archive-disk` 上根本没建过 `archive` 目录，真正的 `stat` 仍然会失败——那是后端的事。

### 4.3 `listConfiguredChildren(path)`：这个目录下配置里有哪些子目录

**做什么**：列出某个目录**直接**下一层的、由配置推导出来的子目录名，重名的只出现一次。它不列后端里的真实文件。

**什么时候用**：`list` 时把「配置要求的入口」和「后端返回的内容」合并。深层挂载即使后端离线，它的入口在这一层也必须看得见。

```kotlin
router.listConfiguredChildren(VfsPath.root) // [memory, resources]
router.listConfiguredChildren(VfsPath.parse("/memory")) // [archive]
router.listConfiguredChildren(VfsPath.parse("/memory/archive")) // 空集合
```

为什么 `/memory` 下只有 `archive`：`/memory/archive` 是挂载点，必须能进去，所以它是 `/memory` 下的一个可见入口；`notes` 只是后端里的普通目录，配置不管它，由后端的 list 结果补上。

重名去重：再挂一个 `/memory/archive/2024`，`/memory` 下仍然只有 `archive`。

**边界情况**：路径不是配置目录时返回空集合（不是报错）——比如 `router.listConfiguredChildren(VfsPath.parse("/memory/notes"))` 得到空集合，意思是「配置在这一层没有要求你展示任何子目录」，而不是「这个目录不存在」。

### 4.4 `isMountPoint(path)`：这个路径是不是一个挂载点

**做什么**：判断路径是否**正好**是某个挂载点。

**什么时候用**：变更保护。挂载根不能被 write / move / delete 替换或删除（T02 §8.2）。

```kotlin
router.isMountPoint(VfsPath.parse("/memory")) // true
router.isMountPoint(VfsPath.parse("/memory/archive")) // true
router.isMountPoint(VfsPath.parse("/memory/notes")) // false
router.isMountPoint(VfsPath.parse("/")) // false
```

**边界情况**：祖先目录不算。`/memory/archive` 是子挂载点，但它不会让父目录 `/memory` 也变成挂载点；本例里 `/memory` 自己确实挂了存储，所以 `isMountPoint("/memory")` 是 `true`，而 `/memory/notes` 只是普通目录，是 `false`。

### 4.5 `hasDescendantMounts(path)`：这个目录下面还有没有别的挂载点

**做什么**：判断 `path` 之下是否还挂着**别的**存储（严格更深，按完整路径段算）。

**什么时候用**：整体移动 / 删除一个目录之前。目录里如果包含挂载点，就不能整棵搬走或删掉，否则会动到别的存储里的数据（T02 §8.2）。

```kotlin
router.hasDescendantMounts(VfsPath.parse("/memory")) // true：下面挂着 /memory/archive
router.hasDescendantMounts(VfsPath.parse("/memory/archive")) // false：下面没有更深的挂载
router.hasDescendantMounts(VfsPath.parse("/memory/arch")) // false
```

最后一条是段边界的体现：`archive` 不在 `arch` 下面。

**边界情况**：不算 `path` 自己。如果 `path` 自己就是挂载点，答案只看它下面还有没有更深的——`hasDescendantMounts("/memory/archive")` 为 `false`，并不表示它「不是挂载点」，那件事问 `isMountPoint`。

## 5. 完整走一遍：三个操作

```kotlin
// 1) 读一个文件
router.route(VfsPath.parse("/memory/notes/a.txt"))
// → 挂载 /memory，存储 local-disk，相对位置 notes/a.txt

// 2) 看某个目录能不能浏览、里面有什么配置入口
router.isConfiguredDirectory(VfsPath.parse("/memory")) // true，真实后端目录
router.listConfiguredChildren(VfsPath.parse("/memory")) // [archive]：还有一块独立存储
// 后端 list 的结果（notes 等真实文件）由上层与这一项合并

// 3) 能不能整棵删掉 /memory/notes
router.hasDescendantMounts(VfsPath.parse("/memory/notes")) // false：下面没有别的挂载 → 不因挂载被拒
```

## 6. 挂载位置的选择

最常见的误解是「根目录不能挂载」。准确规则是：**可以挂在命名空间根（`/memory`），只有逻辑根 `/` 不行**。

| 想挂载的目标 | 逻辑路径 | 是否允许 | 写法 |
| --- | --- | --- | --- |
| memory 命名空间整体挂本地硬盘 | `/memory` | 允许 | `MountRecord(VfsPath.parse("/memory"), "local-disk")` |
| memory 下的子目录挂别的存储 | `/memory/archive` | 允许 | `MountRecord(VfsPath.parse("/memory/archive"), "other-disk")` |
| 整个 `alcyone://` 挂一个存储 | `/` | 拒绝 | 命名空间是隔离单位，挂 `/` 会让所有命名空间落到同一个存储 |

`/memory` 是允许的，因为它是命名空间的根，也是最常见的用法：`alcyone://memory` 整个命名空间就是一块本地盘。`/memory/archive` 同理，只是范围更小。

`/` 被拒绝的原因是：它是所有命名空间的父级，挂上之后 `alcyone://memory/...` 和 `alcyone://resources/...` 会落到同一个存储，命名空间之间的隔离就没了。想让所有内容进同一块盘，正确做法是按命名空间分别挂：`MountRecord(VfsPath.parse("/memory"), key)` 和 `MountRecord(VfsPath.parse("/resources"), key)`。

挂载点位置不能重复。同一个位置写两次会被拒绝，因为「同一个逻辑路径该去哪个存储」没有唯一答案：

```kotlin
MountRouter.of(
    namespaces = setOf("memory"),
    mounts = listOf(MountRecord(VfsPath.parse("/memory/archive"), "a"), MountRecord(VfsPath.parse("/memory/archive/"), "b")),
) // 抛 INVALID_ARGUMENT：/memory/archive 与 /memory/archive/ 规范化后是同一个位置
```

挂载点的首段必须在命名空间集合里，否则就是「挂到了没配置的地方」：

```kotlin
MountRouter.of(
    namespaces = setOf("memory"),
    mounts = listOf(MountRecord(VfsPath.parse("/resource/photo"), "local-disk")),
) // 抛 INVALID_ARGUMENT：resource 不是已配置的命名空间
```

## 7. 错误码

`MountRouter` 出错一律抛 `VfsException`。消息里只有逻辑路径和配置名，不含物理路径、连接串或凭据。

| 场景 | code | 触发它的输入 |
| --- | --- | --- |
| 命名空间名为空串 | `INVALID_URI` | `MountRouter.of(setOf(""), emptyList())` |
| 命名空间名含 `/` 或 `\` | `INVALID_URI` | `MountRouter.of(setOf("a/b"), emptyList())`、`setOf("a\\b")` |
| 命名空间名含空格 | `INVALID_URI` | `MountRouter.of(setOf("my notes"), emptyList())` |
| 命名空间名含字面 `%` | `INVALID_URI` | `MountRouter.of(setOf("a%b"), emptyList())` |
| 命名空间名含控制字符 | `INVALID_URI` | `MountRouter.of(setOf("a\u0000b"), emptyList())` |
| 挂载在逻辑根 `/` | `INVALID_ARGUMENT` | `MountRouter.of(setOf("memory"), listOf(mountRecord("/")))` |
| 挂载位置重复 | `INVALID_ARGUMENT` | 挂 `/memory/archive` 与 `/memory/archive/` |
| 挂载首段不是已配置命名空间 | `INVALID_ARGUMENT` | 命名空间只有 `memory`，却挂 `/resource/photo` |

命名空间名是格式错误，所以复用路径的错误码 `INVALID_URI`；挂载集合是配置结构错误，用 `INVALID_ARGUMENT`。

## 8. 它不管的事

- **不碰后端**：不读文件、不列目录、不检查存储是否在线。深层挂载的存储离线时，路由结果不会变，也不会退回父挂载。
- **不判断文件存不存在**：回答的是「按配置该去哪里」，「那里有没有这个文件」由后端回答。
- **不管符号链接和物理路径**：`storageKey` 只是内部名字，路由不解释它。两块逻辑路径是否实际指向同一块硬盘，由后面的任务（T12）检查。
- **不改配置**：没有添加 / 删除挂载的方法；重新配置就重新创建 router（T02 §3.1 要求 Runtime 存活期间挂载固定）。
- **不合并目录内容**：`listConfiguredChildren` 只给配置入口，和后端真实条目的合并由文件操作层（T10 / T15）完成。
- **不抛 `MOUNT_NOT_FOUND`**：路由不到存储时返回 `null`，由上层结合虚拟目录判断后再决定错误码。
