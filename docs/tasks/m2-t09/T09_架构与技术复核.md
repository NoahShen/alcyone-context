## 2. 逐项复核结论

### 2.1 A01～A07 与 T02 语义：符合

- 最长段匹配用段级 `subList` 比较，不做字符串截取；段边界严格（`/notes/abc` 不命中 `/notes/a`）。

- 纯逻辑、入参防御性快照；`MountRecord` / `VfsPath` 本身不可变，快照深度足够（A06 有专门用例）。

### 2.2 百分号收紧：准确且完整

- 三个入口（`VfsUri.percentDecodeOnce`、`VfsPath.validateSegment`、`StoragePath.validateSegment`）一致拒绝解码后含字面 `%` 的段，错误码 `INVALID_URI`。
- 推理验证：解码后字符串中的 `%` 只可能来自 `%25` 转义（UTF-8 续字节 ≥ 0x80，不可能产生 0x25），单点检查即可封死双重编码，无遗漏通道。
- 既有测试调整与任务文档第 3 节清单**一一对应**（5 处全部落实），并额外补充拒绝用例（`example 9b`、`literal percent signs...`、StoragePath 拒绝组）。除 R3 一条外，无未文档化的契约变更。

### 2.3 模块边界与错误码：正确

- `MountRouter` 只依赖 `VfsPath` / `StoragePath` / `MountRecord`（core 内模型）/ `VfsException`，零 I/O、零 Storage / Repository 接口依赖。
- `route` 返回 `null` 而不抛 `MOUNT_NOT_FOUND` 的职责划分正确：T02 §3.2 要求上层先判虚拟目录再定错误码，router 抛错等于替编排层做一半决定。
- `INVALID_URI`（命名空间格式，沿用路径错误码）与 `INVALID_ARGUMENT`（挂载集合结构）的划分符合任务文档 2.1。
