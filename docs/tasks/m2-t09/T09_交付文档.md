## 需求目标

在 `vfs/core` 实现纯逻辑的路径与挂载路由：挂载配置校验、最长完整路径段匹配、挂载内相对 StoragePath 计算，以及配置目录与挂载结构查询，供后续文件操作编排（T10 及以后）使用。同步落实 T02 已确认的编码契约收紧：解码后的路径段不允许出现字面 `%`。

本任务不含 Storage I/O、数据库 Schema、文件操作编排、配置文件读取与动态挂载管理。

## 主要实现

### A 阶段：百分号契约收紧（前置兼容性修改）

| 文件 | 变更 |
| --- | --- |
| `vfs/api/.../VfsUri.kt` | `percentDecodeOnce` 解码后检查段含字面 `%` → 抛 `INVALID_URI`；类注释补规则 |
| `vfs/api/.../VfsPath.kt` | `validateSegment` 拒绝含字面 `%` 的段（`INVALID_URI`），两个解析入口规则一致 |
| `vfs/core/.../storage/StoragePath.kt` | `validateSegment` 同步拒绝（`INVALID_URI`）；Kdoc 删除过期表述 |

理由：下游后端（尤其 WebDAV）可能再次百分号解码，`%2e` 类段会被重新解释为 `.`，VFS 无法在路由层消除该歧义，因此在解析层直接拒绝双重编码。代价是名称含 `%` 的物理文件无法经 VFS 寻址（T02 §2.2 已接受）。

`encodeSegment` 未改动（保持 unreserved + 大写十六进制）。既有测试按任务文档第 3 节清单调整（`example 9` 改拒绝、round trip 移除 `%252e%252e` 等），并补充双重编码拒绝用例。

### B 阶段：Core 路由实现（新增）

`vfs/core/src/main/kotlin/.../core/router/MountRouter.kt`：

- `RouteMatch(mount: MountRecord, relativePath: StoragePath)`：路由命中结果。
- `MountRouter.of(namespaces, mounts)`：
  - 校验并快照入参（外部修改集合不影响已构建视图）；
  - 拒绝挂载逻辑根 `/`、规范化后重复的挂载位置、首段不在命名空间集合中的挂载（`INVALID_ARGUMENT`）；
  - 命名空间名沿用路径段格式校验（空串、`/`、`\`、控制字符、空格、`%`、孤立代理项 → `INVALID_URI`）；
  - 空挂载集合允许构建；
  - **命名空间根本身（如 `/memory`）允许挂载**——这是「整个命名空间挂一块盘」的正常用法；仅逻辑根 `/` 被拒绝。
- `route(path): RouteMatch?`：最长完整段匹配（`subList == prefix` 段级比较），输入顺序无关、大小写敏感；无匹配返回 `null`，不抛 `MOUNT_NOT_FOUND`（由上层结合虚拟目录判断，T02 §3.2）。
- `isConfiguredDirectory` / `listConfiguredChildren`：配置目录 = 逻辑根 + 命名空间根 + 挂载点 + 挂载缺失祖先；直接子目录去重；构建期预计算。
- `isMountPoint` / `hasDescendantMounts`：挂载点精确匹配与后代挂载（严格更深、按完整段）检查，供后续移动 / 删除保护使用。

## 关键设计决策

1. **解析层拒绝而非路由层处理百分号歧义**：双重编码（`%252e`）在 `VfsUri` / `VfsPath` / `StoragePath` 三个入口一致拒绝，路由层不会再收到含 `%` 的段，StoragePath 构造无需考虑二次解码。
2. **无匹配返回 `null` 而不抛 `MOUNT_NOT_FOUND`**：T02 §3.2 要求上层先判断虚拟目录再决定错误码；router 抛错会替上层做一半决定。`MOUNT_NOT_FOUND` 由 T10 / T15 的编排层决定。
3. **路由映射与虚拟目录共存互不覆盖**：同时挂载 `/notes` 与 `/notes/team/docs` 时，`/notes/team` 既有父挂载相对路径，又是含 `docs` 的配置目录；两种信息分别由 `route()` 与 `listConfiguredChildren()` 提供。
4. **不引入 Trie / 缓存 / 可插拔策略**：线性扫描 + 段级 `subList` 比较，配置目录构建期一次算好；当前规模（首版少量挂载）无性能证据支持更复杂结构。
5. **挂载点身份 = path**：当前纯内存路由不需要 mountId；`storageKey` 标识存储实例（可被多个挂载点共享），数据库主键 `mountId` 属 T11 持久化范畴。
6. **入参防御性快照**：构建后不可变，符合 T02 §3.1「Runtime 存活期间挂载固定」。

## 已知问题或限制

1. **纯逻辑验证边界**：本任务验证逻辑路径无法经路由变成挂载外相对路径；不代表已抵御真实文件系统的符号链接、物理根重叠或外部并发替换（T12 / T18）。
2. **不证明资源存在**：路由命中不表示实际文件存在；`isConfiguredDirectory` 为 true 不表示后端有该目录；stat / list 与后端条目合并属 T10 / T15。
3. **`storageKey` 不透明**：不同 key 不代表物理根一定不重叠，同一 key 一定同盘；物理根重叠检查属 T12 / T18。
