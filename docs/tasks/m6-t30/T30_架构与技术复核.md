## 2. 必须修改

### R1：修复不能直接使用的 API 与事件示例（A01 / A02 / A05）

- README §1 的 `NODE_DELETED` 不存在，实际为 `FILE_DELETED` / `DIRECTORY_DELETED`；SDK 使用指南 §4 的 `NodeMetadata.EMPTY` 不存在，清空应传 `NodeMetadata()`。依据 `VfsEvent.kt`、`NodeMetadata.kt`。
- SDK 使用指南 §6 未预置目标，却等 `FILE_WRITTEN`：首次 UPSERT 创建发 `FILE_CREATED`，因此在新目标上 `await()` 可永久等待。改成明确新建或覆盖的完整场景，匹配目标与对应类型，等待加界限并说明通知可能丢弃；`subscribe` 返回 Unit，删除暗示订阅句柄的 `val subscription`。
- 初始化/流/事件代码块应标明 suspend 上下文、已有变量与必要 import；发生实质改写的片段编译或运行一次，保留来源/命令。无需为每个片段新增正式测试，但不能以旧 LocalFsSampleTest 通过证明所有新片段可执行。
- README §3 与 T30 使用说明 §1 将 `[sample]` 称为终端输出不符实跑：默认命令仅打印 Gradle 结果，详细 stdout 在指定 XML 的 `system-out`。同步验收记录，并补其报告目录中遗漏的 `vfs/api`。

验收：消除不存在的符号；事件例子在全新目标上能有界完成，指南与实际输出位置一致。

### R2：对齐配置、列表、移动与 Runtime 机制（A03 / A04 / A05）

- SDK 使用指南 §2 的 storageKey“同配置内唯一”过强：`VfsRuntimeConfig.resolve` 允许同 key 对应同一规范后端并归并，拒绝同 key 指向不同后端。补逻辑路径到挂载相对路径的简例、远端规范目标重叠与重开身份约束；明确本地根不能包含状态库文件，不要扩大为两个目录完全不能相邻/包含状态库的父目录。
- §3 list 当前仅说明单层与可空 ID，缺物理直接子项与配置目录入口合并、同名配置入口优先、不凭历史 Node 行列出已消失物理项、不批量登记。move 补同 Mount 按原生能力选择、跨 Mount 复制确认删除、目录根级事件与复制路径的单文件内存限额；不能让读者误以为公开支持目录 move 就是 Adapter 原生支持。
- 运维说明 `limits.readBytes` 不存在；实际配置为 `VfsLimits.defaultReadMaxBytes/defaultWriteMaxBytes`。使用指南补 ReadOptions 只能收紧、streamTotalLimit 与 maxTotalBytes 取较小值，以及流默认无总量上限。
- §6 不能把 Runtime Consumer 自抛取消统称“向上传播”：EventDispatcher 会重抛，AsyncEventNotifier 在自身仍活跃时记录并继续后续事件，本次事件余下 Consumer 可能不再收到；分发器关闭取消会结束 worker，调用方取消另属调用路径。普通异常隔离与慢 Consumer 延迟后续通知仍保留。
- §7 是 SQLite **单连接**，不是连接池；宽限期等 `inFlight.done`，不等待已交出的遗留流自行读完。等在途清理后主动关闭遗留流，最后释放后端/状态库/锁；没有在途操作时不为遗留流等待 30 秒。保留 close 幂等、失败共享与回调内关闭的限定，不承诺任何 close 返回都已完成全部释放。

依据：`DefaultVfs.listInsideBoundary`、移动编排、`VfsLimits`、`Options.kt`、`VfsStream.kt`、`AsyncEventNotifier`、`AlcyoneVfs.releaseEverything/awaitGracePeriod`。验收以对应源码/已有精确用例为准，不扩建实现或完整测试矩阵。

### R3：纠正失败模型与人工处置建议（A06 / A07）

运维说明 §3.2 不能按错误码将 effect 一律列为 NONE。已存在目录复制后项超限返回 `LIMIT_EXCEEDED + PARTIAL` 的正式用例；确认/删源报错也可保留后端 code 与 UNKNOWN。表格若仅指预检必须明确阶段，其余按实际异常 effect 判断，不把 UNKNOWN 降级，不把取消理解为无提交；`CancellationException` 不应被“统一抛 VfsException”覆盖。

§4.2 的“stat 两端后补做源端删除或重新写入”不足以保护身份：stat 会懒注册目标，而公开 delete 源会废弃原 ID / Metadata，不能视为完成原 move。改为先停相关写入、保留异常与原 ID/逻辑映射、通过后端工具只读核对两端类型和完整内容，再制定人工处置；若用公开 stat 必须说明登记副作用。首次版本没有修复事务/API，不给出可自动保持身份的补删承诺。

六类诊断应覆盖初始化、Storage、状态提交、Consumer、队列丢弃、关闭，而非用六个常见错误码替代。补 STATE_ERROR 的物理已完成/逻辑未提交排查、cause/suppressed、宿主提供 SLF4J 绑定、丢通知不等于删持久事件、关闭失败不得当正常备份前提；不需要新增诊断框架。

### R4：撤回无依据的 WAL 保证，补可复现冷备份记录（A06 / A08）

运维说明 §2 写“SQLite 采用 WAL”“正常 close 确保 checkpoint”，代码却以 `DriverManager.getConnection(url, Properties())` 打开单连接，未设置 journal_mode 或执行 checkpoint。按实际查询到的模式和文件布局写正常关闭离线步骤；遇异常关闭/伴随文件须先确认状态，不将复制主库或 wal/shm 文件写成通用恢复保证，也不要为文档去新增 WAL 机制。

验收 §2 只有流程叙述，没有验证入口、执行命令、输出/报告、实际 journal_mode 和关闭后的文件清单；源码无所述备份用例。另本地 Gradle daemon 日志保留 17:57 的 `BackupRestoreVerificationTest ... FAILED`（VfsException，1 test / 1 failed），这不能证明后来未成功，但当前材料无法把后续 PASS 与该次失败区分。补存可复现探针/样例或明确脚本及执行结果，交代成功版本、实际复制了哪些文件、ID/Metadata/内容断言与隔离清理；不得以 752 例回归替代临时探针成功证据。

正常关闭、原挂载身份路径、临时目录验证的方向可保留。明确本地样例只证明所测冷备份，SQLite 不含文件内容，WebDAV 数据需独立备份且不构成跨后端原子快照；归档配置区分非秘密身份参数与凭据安全提供，不指导将含密码的完整配置无保护归档。
