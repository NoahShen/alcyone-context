## 1. 构建与测试

在 macOS arm64 使用项目内工具链，命令与 T05 相同，不改系统 JDK、Gradle 或 shell 配置：

```sh
./scripts/dev bootstrap                      # 首次或工具链校验失败时执行
./scripts/dev gradle spotlessApply           # 写完代码先格式化
./scripts/dev gradle clean build --console=plain
./scripts/dev gradle :common:test :vfs:api:test --console=plain
./scripts/dev gradle -q javaToolchains       # 确认测试使用项目 JDK 21
```

格式化由 Spotless 7.0.2 + ktlint 1.5.0 承担，规则见根目录 `.editorconfig`（`max_line_length = 140`）。`spotlessCheck` 已挂进 `check`，所以 `build` 会因为格式问题失败。

JDK 与 Gradle 版本、下载地址和 SHA-256 集中在 `gradle/toolchain.versions`（`KEY=VALUE` 纯文本），是唯一来源：`scripts/dev` 和根构建的 JDK 守卫、`tasks.wrapper` 都从它读取。升级 JDK 时同时改安装目录（`scripts/dev` 按 `jdk.version` 拼出 `.local/jdk/jdk-$version`）；`gradle/wrapper/gradle-wrapper.properties` 是 wrapper 任务的生成产物，需与 `toolchain.versions` 一致，可通过 `./scripts/dev gradle wrapper` 重新生成核对。

诊断用命令：

```sh
./scripts/dev gradle :vfs:api:dependencies --configuration runtimeClasspath --console=plain
./scripts/dev gradle :common:test :vfs:api:test --console=plain --info --rerun-tasks
.local/jdk/jdk-21.0.12.1+1/Contents/Home/bin/javap -p -cp vfs/api/build/classes/kotlin/main alcyone.vfs.Vfs
```

原始日志与用例清单位于 `.local/tmp/acceptance/t06/`（`clean-build.log`、`api-test-info.log`、`api-deps.log`、`api-signatures.log`、`test-cases.txt`），该目录被 Git 忽略，不随提交保存。

## 2. 交付内容

包名 `alcyone.vfs`，文件按任务文档第 3 节清单交付：

- 路径：`VfsUri.kt`（解析、规范化序列化）、`VfsPath.kt`（已解码逻辑路径、段校验、段列表与根表示）。
- 身份与结果模型：`NodeId.kt`、`NodeType.kt`、`StorageStat.kt`、`VfsEntry.kt`、`NodeInfo.kt`。
- 契约：`Vfs.kt`（仅签名）、`NodeMetadata.kt`、`Options.kt`、`VfsException.kt`、`VfsEvent.kt`。
- 测试：`VfsUriTest`（29）、`VfsPathTest`（15）、`NodeIdTest`（6）、`PublicContractTest`（12），`vfs/api` 共 62 个用例；另有 `common` 10 个用例，合计 72 个。
- 协议常量：`VfsProtocol.kt` 现仅保留 `SCHEME`。按 R5 已删除 `NAMESPACE_SEGMENTS` 及首段成员检查，命名空间不再由 API 判定，后续由 Runtime 配置注入。`VfsPath.isNamespaceRoot` 只表示单段路径结构，不证明该命名空间已配置。
- `vfs/api/build.gradle.kts` 增加 `api(project(":common"))` 与测试依赖（`kotlin.test`、JUnit BOM、`testRuntimeOnly` engine 与 launcher），写法与 `integration-tests/vfs/build.gradle.kts` 一致。

公共工具库 `common/`（包 `alcyone.common`）不在 `alcyone.vfs` 内，单独交付：

- `common/src/main/kotlin/alcyone/common/Uuid.kt`：`newUuidV7()`、`normalizeUuidV7()`、`isUuidV7()`、`InvalidUuidException`。
- `common/src/test/kotlin/alcyone/common/UuidTest.kt`：7 个用例，覆盖生成格式、唯一性、大小写规范化与各类非法输入。
- `common` 不依赖 `vfs/api`；`vfs/api` 通过 `requireUuidV7()` 把 `InvalidUuidException` 转成 `VfsException(INVALID_ARGUMENT)`。

使用示例：

```kotlin
val uri = VfsUri.parse("alcyone://resources/medical/a%20b.dcm")  // 非法输入抛 VfsException(INVALID_URI)
val path: VfsPath = uri.path                                      // /resources/medical/a b.dcm
val id = NodeId.parse("018f6a3c-9c1e-7b2d-8f3a-4c5d6e7f8091")     // 只校验 UUIDv7 文本，不生成
```

## 3. 实现中明确的细节

以下未在 T01 / T02 单独规定，按已审阅规则取最保守解释；后续任务如需改变，直接改代码并回写文档。

| 事项 | 本次实现 | 依据 |
| --- | --- | --- |
| 原始空格 | URI 输入中出现未编码空格即 `INVALID_URI`；文件名中的空格必须写 `%20` | T02 2.2 规则 4“原始空格要求使用 `%20`” |
| 非首段的 `:` / `@` | 仅拒绝第一段的 `:` 与 `@`（端口、userinfo 位置）；其他段的 `:` 合法，序列化时编码为 `%3A` | T02 2.2 拒绝项只列端口与 userinfo |
| 原始非 ASCII 字符 | 接受并按 UTF-8 逐字节解码，与 `alcyone://resources/报告.md` 例子一致 | T02 2.3 例子 3 |
| 路径类错误的 code | `VfsUri.parse` 与 `VfsPath.parse` / `VfsPath.of` 的格式错误统一为 `INVALID_URI`；`NodeId` / `VfsEventId` 格式错误为 `INVALID_ARGUMENT`；`ReadOptions` 负数等非路径参数为 `INVALID_ARGUMENT` | T01 第 7 节已补充分类：路径格式错误用 `INVALID_URI`，ID、选项等非路径参数用 `INVALID_ARGUMENT`。`VfsPath` 是 `VfsUri` 的解码结果，两者同属路径 |
| `VfsEffect` 默认值 | 构造默认为 `NONE`；存储写入、跨 Mount 移动等操作在实现时必须显式传 `PARTIAL` / `UNKNOWN` | T01 7.1“effect 不能仅由错误码猜测” |
| 异常消息内容 | 只含拒绝原因，不回显原始输入，避免文件名或凭据进入日志 | T01 7.1 诊断信息限制 |
