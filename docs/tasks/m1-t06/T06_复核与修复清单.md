### 2. R1 / P1：路径段集合泄漏，校验可被绕过

`VfsPath.segments` 返回内部实际可变的 List，Java 调用方可直接 set，Kotlin 调用方也可转换为 MutableList 后修改。已构造的 URI 因而可以变成包含 `..` 的非法路径，且 hashCode 随之改变，破坏路径校验及值对象作为集合键的稳定性；位置：`vfs/api/src/main/kotlin/VfsPath.kt:13`。

复现：解析 `alcyone://resources/safe/file`，执行 Java 调用 `uri.getPath().getSegments().set(1, "..")`，输出变为 `alcyone://resources/../file`，`HASH_CHANGED=true`。

修复验收：对外集合不可改变对象内部状态，构造输入也不能反向修改对象；覆盖 Java / Kotlin 集合修改、URI / Path 相等与 hashCode 稳定性。保留直接路径构造时的原有校验。

### 3. R2 / P2：UUIDv7 大小写和字符范围校验不正确

`normalizeUuidV7` 先用只含小写的 `89ab` 检查 variant，导致合法大写 A / B 被拒绝；`digitToIntOrNull(16)` 又接受部分非 ASCII 数字，使非规范 UUID 文本通过。两处同时影响 NodeId、VfsEventId 和 common 工具；位置：`common/src/main/kotlin/alcyone/common/Uuid.kt:42`、`:44`。

复现：`018F6A3C-9C1E-7B2D-AF3A-4C5D6E7F8091` 被拒绝，而首字符是 U+0660 的 `٠18f6a3c-9c1e-7b2d-8f3a-4c5d6e7f8091` 被接受。

修复验收：大小写 ASCII 十六进制均可输入、统一输出小写；拒绝非 ASCII 数字及字母，测试覆盖 variant 8 / 9 / a / b 的大小写，以及两个 VFS ID 类型的异常转换。

### 4. R3 / P2：非法 Unicode 被替换，控制字符拒绝不完整

未配对的 UTF-16 代理字符能进入路径，随后 `toByteArray(UTF_8)` 将它替换为 `?`，产生与原值不同的规范 URI；只检查小于 U+0020 和 U+007F 也漏掉 C1 控制字符。位置：`vfs/api/src/main/kotlin/VfsPath.kt:65`、`VfsUri.kt:57`、`:65`、`:91`。

复现：URI 文件名为单个 U+D800 时序列化为 `%3F`，再次解析后 `equals=false`；`alcyone://resources/%C2%85`（U+0085）被接受。

修复验收：在原始 URI、解码后路径及直接 Path 入口拒绝未配对代理字符和控制字符，编码不能静默替换输入；补充合法 emoji 代理对、截断 / 过长 UTF-8、C1 控制字符及往返相等测试。

### 5. R4 / P2：读取限额缺少本地参数校验

`ReadOptions` 仅保存数值，允许负数进入有效选项，与 T06 原任务“选项检查可本地判断的参数范围”要求不符。位置：`vfs/api/src/main/kotlin/Options.kt:8`；应在 API 边界完成此项，而不是留给未来 Storage 调用处理。

复现：`ReadOptions(-1)` 正常构造，`maxBytes=-1`；未抛领域异常。

修复验收：负数返回 INVALID_ARGUMENT / NONE，构造和 copy 均不能绕过；明确并测试 null、0、正数的语义。Runtime 的 16 MiB 默认值及实际 I/O 限额执行仍留后续任务。
