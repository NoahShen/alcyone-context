## 1. 目标与范围

形成上层 Context System 可以据以接入的首版本地交付记录，并明确剩余限制与后续需求。主要交付是文档，不新增 VFS 功能、重构模块或重新设计已冻结契约；若发现实际阻塞缺陷，记录影响和最小修复需求，不能用文档将其标为完成。

例：记录 `0.1.0-SNAPSHOT` 的六模块本地产物已验证消费，不将它改名为正式发布的 `0.1.0`，也不声称 Maven Central 已可下载。

## 2. 工作内容

### 2.1 首版交付记录

新增 `docs/vfs/首版交付记录.md`，集中列出版本与代码基线、六模块坐标、项目内仓库、接入文档和消费命令。简要列出 Local FS / WebDAV、文件与目录操作、身份与 Metadata、流、事件和生命周期已交付范围，链接已有说明，不复制全部 API 或测试矩阵。

例：主入口为 `com.github.noahshen.alcyone:alcyone-vfs-runtime:0.1.0-SNAPSHOT`；消费验证使用 `./scripts/t31-consumer-check`，从产物而非生产源码调用。

### 2.2 支持边界与已接受限制

明确只有 macOS arm64 已验证支持，Linux x64 / arm64 配置保留但未验证，Mac 本地产物的 OpenDAL classifier 固定；方案④仍不承诺 native 请求或关闭的最大等待时长。区分正常关闭后重开与崩溃恢复、事件持久化与可靠消费、逻辑事务与物理操作，VFS 无身份绑定/ACL，目录访问范围由 Context System 管理。

例：跨后端移动可能留下两端物理内容，报告 PARTIAL / UNKNOWN 不代表自动补偿；引用运维文档的停止写入、保留现场和只读核对说明，不新增底层补删源建议。

### 2.3 验证证据与可复现入口

交付记录给出命令、运行环境、代码提交、实际结果和证据位置，区分开发自测、独立复核、本轮执行与历史沿用。复用 T29 用例/架构索引、T30 使用与冷备探针、T31 产物消费证据；单次正常备份恢复或样例成功不能扩大为任意失败恢复或全 API 兼容保证。

本任务交付前按顺序运行 `./scripts/check`、`./scripts/webdav-check`、`./scripts/t31-consumer-check`，使用项目私有工具链；正式测试分别核对源码/XML、失败/错误/跳过数量，消费 smoke 单列。若环境受阻，记录实际阻塞而非借旧结果声称本轮全绿；纯文档收尾后的独立复核可沿用同一代码基线的有效执行证据。

### 2.4 后续需求清单

新增 `docs/vfs/后续需求清单.md`，复用计划的 E01～E05 编号，分别整理 Git Sync、可靠消费与中断/重启恢复；另列 Linux 验证、跨平台产物、网络等待限制与公开发布等后续候选。每项记录来源、当前边界、用户影响、建议启动条件与可观察的验收目标，不把建议当成已批准的开发任务或必修缺陷。

例：Linux 验证项的完成条件是目标机器上的回归和独立消费证据，不能只以 classifier 能解析为完成；网络等待项应重新评估依赖或方案，不撤销用户已接受的方案④。

### 2.5 工程状态与入口更新

更新 AGENTS 的当前工程状态、模块、常用命令及阶段措辞，修正“发布策略未确定”“后续 Runtime 配置”等已过期的当前指引；检查 README、SDK 文档与计划的入口和状态一致。保留历史复核结论的时间与归属，可将历史区明确标注，但不要为收尾大规模重写设计或删除问题记录。
