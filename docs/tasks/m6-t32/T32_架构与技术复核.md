## 2. 必须修改

### R1：首版能力摘要含不存在的 API 和过强保证

位置：`docs/vfs/首版交付记录.md` §2～§4.1；AGENTS 路径说明同步修正。

| 当前描述 | 代码事实与修正要求 |
| --- | --- |
| `VfsMountConfig`，AGENTS 称命名空间来自该配置 | 该类型不存在。使用 `VfsRuntimeConfig.namespaces` 与 `mounts: List<MountConfig>`；路由为最长**完整路径段**匹配 |
| `openReadStream().use` | 公开入口是 `openStream(uri, options)`；对返回的完整 `VfsStreamResult` 使用 use，而非仅关 result.stream。见 api/Vfs.kt、VfsStream.kt |
| write “保证底层与元数据状态一致” | 物理 I/O 与 SQLite 不在同一事务；改为成功路径更新逻辑状态，失败按 effect 报告，不承诺跨两者原子一致。原文与自身 §3 矛盾 |
| list “混合物理存在与逻辑节点” | 合并物理直接子项和配置目录入口，再关联已登记 ID；不从历史 Node 行恢复已消失条目，也不批量注册。见 DefaultVfs.listInsideBoundary |
| 同 Mount 原生移动的笼统概括 | 同 Mount 按能力选择，当前目录走复制回退，跨 Mount 走复制删除；补单文件读写限额及单条根级 DIRECTORY_MOVED，避免误解为所有同 Mount 移动都原生 |
| Consumer “第三方异常不破坏分发循环” | 普通 Exception 隔离；自抛 CancellationException 可中止本事件余下消费者，活跃 worker 继续后续事件；宿主/分发器取消退出，Error 不捕获。需点明有界队列满会丢通知、持久事件不因此删除，不能概括为保证送达 |
| 删源失败“保留两端物理文件” | UNKNOWN 可以是服务端已删除但响应丢失，目录删除也可部分完成。准确表述应为不主动补偿、逻辑移动不提交，源可能完整/部分/已经删除，保留可观察现场，只读核对；不能保证两端仍完整 |
| `// settings.gradle.kts 或 build.gradle.kts` 后直接写 repositories / dependencies | 该整段应标为消费工程 **build.gradle.kts**；settings 中依赖仓库需 dependencyResolutionManagement，不能放该 dependencies 块 |

关闭要求：逐项与现有 SDK 使用/运维说明及源码对齐，修改后重新核对 A02/A03，不只改总括结论。无需补生产功能。
