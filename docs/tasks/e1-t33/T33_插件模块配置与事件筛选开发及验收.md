## 1. 目标与输入

建立可编译的可选模块，实现配置校验、纯事件筛选及 Cron 解析/下次时间计算基础；不提前构造无法执行同步的公开 Plugin 空壳。

阅读 [E1里程碑](../e1-git-backup/E1_Git本地备份里程碑.md)、[设计文档](../../vfs/Git_本地目录备份设计_v0.1.md) 和根 AGENTS.md。既有 VFS 零侵入、可选插件、Cron 本机时间、逐轮日志、无公开状态模型是固定边界。

## 2. 修改范围

`settings.gradle.kts`（模块登记）、`gradle/libs.versions.toml`（必要依赖）、`vfs/git-backup/build.gradle.kts`、新模块内 GitBackupConfig / internal GitBackupEventFilter / internal CronBackupSchedule 及针对性测试；模块发布登记留 T36。

不得修改现有 VFS 生产代码、Runtime 配置/依赖、数据库 Schema；不得为本任务提前添加后续功能或通用框架。保留工作区已存在的设计/计划改动，不混入当前代码提交。

## 3. 实施步骤

1. 阅读真实 VfsEvent/VfsUri 与构建约束，Lead 给出公开配置签名和内部类型选择，再委派 Worker。
2. 核对 Cron 解析方案的官方说明/源码及许可证；采用五字段、0～6 星期、DOM/DOW 任一满足的既定方言，选库和版本记录依据。不要自造通用 Cron 引擎，必要适配保持小而可测。
3. 配置值、正时长、非空事件根和 Cron 结构/未来匹配的校验为本任务；文件系统/Git 命令校验留 T34。Cron 无匹配判定必须有界，不能逐分钟扫无限未来。
4. 筛选 VFS 变更事件，移动两侧匹配，同实例只命中一次，Metadata 忽略。只比较已解析完整路径段，接受设计规定的子 Mount 保守多触发。
5. 格式化、模块测试与常规回归，提交真实证据等待复核。

## 4. 验收标准

| 编号 | 可观察标准 |
| --- | --- |
| A01 | 新模块只依赖 API、Coroutines、SLF4J API 和经记录的 Cron 依赖，Runtime 不依赖插件；根构建能发现并检查新模块。 |
| A02 | 配置默认静默 60 秒、cron 为 0 3 * * *，无 dailyAt/zoneId/GitBackupStatus；非法参数清晰拒绝，构造不启动进程或定时任务。 |
| A03 | 五字段示例、范围/列表/步长、DOM/DOW 规则与无未来匹配有直接断言；Quartz 字符/六字段/越界拒绝。 |
| A04 | 普通事件、移动源/目标、完整段边界、URI 编码、多个逻辑别名、子 Mount 保守匹配及 Metadata 忽略均验证。 |
| A05 | Cron 依据本机时间，受控 Clock 验证下次触发，不开放时区配置、不专门扩建跨时区策略。 |
| A06 | 既有生产模块和 Runtime 依赖 Diff 为零；无 Worker、Git 执行、空壳插件或状态模型越界实现。 |
| A07 | ./scripts/dev gradle spotlessApply 后模块测试与 ./scripts/check 通过，记录新旧计数和源码/XML对照，当前任务不需重跑 WebDAV/消费。 |
| A08 | 交付含选型证据、文件清单、真实日志路径与命令退出码；Lead 初验后标 IN_REVIEW，不能自行标 DONE。 |
