## 1. 目标与输入

实现 GitBackupPlugin 独立入口与内部 Worker/Consumer，把受控单次同步接上事件、防抖、Cron、启动和手动触发。

阅读 [E1里程碑](../e1-git-backup/E1_Git本地备份里程碑.md)、[设计文档](../../vfs/Git_本地目录备份设计_v0.1.md) 和根 AGENTS.md。既有 VFS 零侵入、可选插件、Cron 本机时间、逐轮日志、无公开状态模型是固定边界。

## 2. 修改范围

`vfs/git-backup` 插件入口、Worker、可断开引用的 EventConsumer、调度与日志接线和测试；不修改 Runtime 源码或依赖。

不得修改现有 VFS 生产代码、Runtime 配置/依赖、数据库 Schema；不得为本任务提前添加后续功能或通用框架。保留工作区已存在的设计/计划改动，不混入当前代码提交。

## 3. 实施步骤

1. 构造不启动任务；start 幂等并异步启动一次完整检查，requestSync 返回 Unit，状态和查询接口不引入。
2. 单仓库串行执行：相关通知重新计满 60 秒，多触发合并，有效保留运行中的新变更；旧计时器不能越过重置。
3. Cron 依本机时间触发，睡眠错过多次只补一次，不等静默期；没有持久化队列或重试定时器。
4. close 断开 Consumer、拒新请求、停止计时并清理在途 Git；只释放自身资源，保持 VFS 可用。
5. 使用受控时间与受控执行交错建立关键判据，不真实等待 60 秒或凌晨。

## 4. 验收标准

| 编号 | 可观察标准 |
| --- | --- |
| A01 | 构造/重复start/关闭/关闭后调用有清晰规则，未启动或关闭后手动触发拒绝；无公开状态模型。 |
| A02 | 0秒与30秒通知：89秒不执行，90秒执行；持续通知重置，已唤醒旧计时器不会提前执行。 |
| A03 | 单仓库最大流程并发1，手动/Cron合并；运行中新通知不会被结束逻辑抹掉。 |
| A04 | 启动、Cron、手动检查无事件也执行；Cron 不受防抖推迟，错过多时刻不积压。 |
| A05 | 订阅回调无IO无等待Git；关闭后残留回调不再持有Worker，已取到旧引用的并发回调也无法重启工作。 |
| A06 | 自身Scope/任务/进程释放可验证，取消不被吞掉，不泄漏到宿主或其他插件；close 不强制补push。 |
| A07 | 实际每轮日志满足既定契约，不重复、不使用结果日志冒充状态持久化；失败后等待下次正常触发。 |
| A08 | 受控交错测试可靠清理；格式、模块测试及 ./scripts/check 通过，Lead 初验后提交 Architect。 |
