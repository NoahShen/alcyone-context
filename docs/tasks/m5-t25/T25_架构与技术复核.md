## 2. 必须修改

### R1：A06「写响应丢失」实际可在 MKCOL 阶段通过，缺少写入和状态事实证据

位置：`T25WebDavFailureReportTest.kt:73–110、384–402`。目标为 `dropped/target.txt`，脚本与用例都没有预建 `dropped/`，Core 会先建父目录；故障服务对 MKCOL 直接断开，因此 UNKNOWN 可来自建目录，根本不必进入 PUT。即使到达 PUT，当前实现只读请求体、不写文件，也没有 PUT 命中计数，不能证明“部分目标已落地”；这是源码路径核对结论，不冒充网络抓包结果。

修复：预建父目录或正常处理 MKCOL，明确记录并断言 PUT 已发生，在临时目标留下可核对的部分内容后丢弃响应；直接断言源删除未调用、残留内容、原 code / cause / UNKNOWN。源先登记并设 Metadata，保存 ID / 路径 / Metadata 和事件快照，失败后用不触发懒注册的查询核对；现有 `vfs.read(source)` 只能证明源内容可读，不能证明原逻辑映射未提交。

确认失败和删源失败代表也补原逻辑状态断言，并将删源用例的 `effect != NONE` 收紧为注入 NONE 时应得到的 PARTIAL；UNKNOWN 保留可复用既有 Core 用例并明确索引。无需重新建设全部故障矩阵。

### R2：共享流丢失 WebDAV 后端参数，既有消息错误，也有错误码错误

位置：`StorageInputStream.kt:110、121`、`ReaderHandle.kt:38`。前者调用 `mapStorageErrors` 未传 backend，默认 `local storage`，因此 WebDAV 专用的 HTTP 401 → STORAGE_ACCESS_DENIED 规则也失效；后者把 CLOSED 消息硬编码为本地存储。

独立组件探针：给带 `webdav storage` lifetime 的 StorageInputStream 注入 `OpenDALException(Unexpected, "status: 401")`，实际输出 `STORAGE_ERROR / local storage read stream failed (STORAGE_ERROR)`；释放 handle 后通过仍持有的包装流读取，输出 `CLOSED / local storage read stream is closed`。这是已编译组件的受控注入证据，不是真实远端 401 实测。

修复：流的读取 / 关闭转换使用正确后端；ReaderHandle 可用中性消息或后端标签，无需新增公共配置。补共享组件的 WebDAV 401、普通 I/O 失败及外层先关后的消息断言，保留 cause、取消原样传播和 Local FS 原行为。**应在本轮修正，不能只改 ReaderHandle 那一句。**

### R3：新故障装置与组装存在资源和目录边界缺口

位置：`T25WebDavFailureReportTest.kt:210–263、329–487`。`respondPropfind` 将解码路径直接 `dataRoot.resolve(relative)`，缺少规范化与根边界拒绝，`/../` 可查询测试根之外的目录；使用 URLDecoder 还会把字面 `+` 改为空格。PUT 用字符 Reader 按 Content-Length 字节数计数，只对当前 ASCII 样本碰巧一致。

`close()` 只关监听 socket、不主动关闭已接纳连接，首个 worker 等待失败就不再尝试其余；每次 `stack.vfs` / `vfsWith` 又新建 AsyncEventNotifier，却从未关闭其分发协程。`withStack` 取得资源在 try 之前，且串行 close 首错会跳过后续释放，失败装置本身不能满足所宣称的清理边界。

修复：优先复用 T24 已处理的服务边界做法，用字节解析请求体、保留 `+`、拒绝根外路径；停接纳后关闭已接纳 socket，再尝试等待全部 worker 并报告失败。Stack 持有并关闭创建的 notifier，初始化 / 清理异常仍尝试释放已取得资源；补根外拒绝及在途连接关闭代表，不需要生产级 HTTP 框架。

### R4：新 Adapter 路径的关键断言仍被上层预检或关闭标志遮住

A03 的目标存在反例走公开 VFS，在 Core 就被拒绝；直接 Storage.move 只有成功与目录拒绝，不能验证本轮新增的源缺失、目标全新、父目录存在检查，也没有 rename 失败 UNKNOWN / rename 成功后 stat 失败 PARTIAL 的直接证据。补少量 Adapter 级代表，明确失败发生在哪一步，避免拿 Core 拦截当 Adapter 的证明。

A07 的遗忘流用例只看同库重开；Adapter 回收用例先 close Adapter、再 close 外层流，仅断言 isClosed。这些断言在 drainReaders 被删掉时仍可能通过：后续 stream.close 可以代为释放，同库锁也不依赖 reader 是否释放。

补至少一条在任何补救 close 之前直接确认底层 reader 已释放、跟踪已移除的 WebDAV 接线证据，并确认重复关闭不重复释放；计数 / 内部检查可沿用已有测试办法，不强求 OS 句柄统计或新通用测试框架。缺失 / 目录开流失败发生于获取 reader 之前，应标为“预检失败”；交接取消、读关互斥可引用 T12 / T18 机制证据与 WebDAV 源码接线，不宣称本轮真实网络并发或取消实测。

### 7.2 必须修改：R3 残留

**解码后的路径仍可逃逸，而且本次增加 PUT / MKCOL 写入后可写到根外。** `T25WebDavFailureReportTest.kt` 中 handle 先检查 rawPath 的 `/../`，然后解码并直接 `dataRoot.resolve`；`/%2e%2e/outside` 绕过第一道判断。独立 `/tmp/T25BoundaryProbe.java` 反射启动本次编译的 DroppedWriteServer，在独立临时根发送该 MKCOL，请求返回 `HTTP/1.1 201 Created`，并确认 `createdOutsideRoot=true`；探针结束已关服务并清理临时文件。

最小修复：统一先解码，再将候选路径相对于规范根 resolve / normalize，按 Path 段检查仍在根内；各方法共用结果，不各写字符串过滤。至少补编码点段拒绝与普通 `+` 路径对照；本轮不要求生产 HTTP 服务器的全部安全能力。

**清理顺序仍有登记窗口。** close 在 join acceptThread 之前遍历 openSockets：接纳线程可能已经通过 running 检查、尚未登记 socket，此时 close 遍历不到它，之后 worker 才开始；读超时限制的是单次读取，不能替代主动关闭连接。应先停止并确认接纳结束，再关闭全部已登记 socket，最后尝试等待全部 worker；当前 `check(!worker.isAlive)` 会在首个失败时提前终止后续等待，需收集失败后统一报告，并补一条在途连接关闭代表。

**测试自身异常清理也要完整。** R4 回收用例的 finally 只删文件，没有兜底关闭 remote，前置断言失败会漏资源；补 finally 关闭（必须放在释放断言之后，不掩盖证据）。withStack 已逐项释放资源，但清理异常会覆盖原测试异常，closeNotifiers 仍吞失败；保留主异常并将清理错误挂 suppressed，无需抽象成新的资源框架。

### 7.3 必须修改：R4 残留

**集合清空不证明底层释放。** 新用例读取 liveReaders 集合后只断言它为空；drainReaders 末尾本来就有 `liveReaders.clear()`。即使错误地跳过每个 handle.release 而保留 clear，这个断言仍会通过，随后 stream.close 又会补救关闭；这是源码与断言推导，本轮未实跑变异。

最小补证：关闭 Adapter 前保存具体 handle / 可计数的底层流，关闭后、任何 stream.close 之前确认 released / 关闭次数和集合移除；重复关闭后次数不增加。可以复用已有机制层计数证据，但 WebDAV 排空接线必须直接证明 release 被执行；不需要 OS 句柄统计、压力测试或扩大公共 API。

**原生 move 的两个失败阶段仍缺直接证据。** 本轮新增的预检测试可以接受，但没有调用 WebDavStorage.move 后让 rename 失败并断言 UNKNOWN，也没有 rename 成功、随后目标 stat 失败并断言 PARTIAL 的用例。原有 FailingStatStorage 包装的是跨后端复制目标确认，不能替代 WebDAV 原生 move 的第三阶段；补两个受控代表并核对相应物理事实、code / cause 即可，不重建全矩阵。
