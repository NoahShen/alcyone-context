## 1. 一句话

在 T24 的「Local FS 与 WebDAV 同实例挂载」之上，WebDAV 现在补齐了**流式读取**和**原生文件移动**，并支持 **Local FS ↔ WebDAV 双向文件 / 目录移动**。调用方依旧只写 `alcyone://...`，看不到 endpoint、密码，也看不到 OpenDAL 类型。

## 2. 怎么配

配置写法与 T24 完全相同，一行没变：

```kotlin
val vfs = AlcyoneVfs.create(
    VfsRuntimeConfig(
        stateDatabase = Path.of("data/state.db"),
        namespaces = setOf("resources"),
        mounts = listOf(
            MountConfig(VfsPath.parse("/resources/local"), "docs", Path.of("/data/docs")),   // 本机盘
            MountConfig(
                VfsPath.parse("/resources/remote"),
                "remote",
                MountBackend.WebDav(
                    endpoint = "http://127.0.0.1:8080",   // 只接受 http:// 或 https://
                    root = "/dav/team",                   // 服务上的共享根
                    username = "alice",
                    password = "…",
                ),
            ),
        ),
    ),
)
```

配置阶段的校验（凭据不进 URL、root 规范化、重叠检查、换 endpoint / root 报 `CONFLICT`）与 [T24 使用说明 §2](../m5-t24/T24_使用说明.md) 完全一致。

## 3. 这一版能做什么

| 操作 | 状态 | 说明 |
| --- | --- | --- |
| 写（`CREATE_NEW` / `REPLACE_EXISTING` / `UPSERT`） | 可用 | 靠提前查判断，不是原子保障；`CREATE_NEW` 遇已有目标报 `ALREADY_EXISTS`，`REPLACE_EXISTING` 遇缺失报 `NOT_FOUND` |
| 读（有界 `read`） | 可用 | 受 16 MiB 默认限额；超限报 `LIMIT_EXCEEDED`，不截断 |
| **`openStream`（流式读取）** | **可用（T25 新增）** | 按实际读出字节计限；`null` 无界；大文件分块读，不整份进内存 |
| `stat` / `list` / 建目录 / 删除 | 可用 | 与 T24 一致 |
| **`move`（同 WebDAV Mount 文件移动）** | **可用（T25 新增）** | 走经验证的原生 `rename`；Adapter 补「目标全新 / 父目录存在」预检 |
| **跨后端移动（Local FS ↔ WebDAV 文件 / 目录）** | **可用（T25 新增）** | 走 Core 复制删除；文件保留 Node ID / Metadata，目录保留已登记子树身份 |
| 原生目录移动 | 不实现 | 能力表 `nativeDirectoryMove = false`；目录移动走 Core 整树复制回退 |
| 远端根是否真的存在 | 打开时不探测 | 第一次真正操作才见分晓 |

能力表（`capabilities()`）就是实情：`nativeFileMove = true`、`nativeDirectoryMove = false`、`createDirectory = true`、`boundedRead = true`、`readOnly = false`。**不要**据此假设所有 WebDAV 服务器都兼容——只对 WsgiDAV 4.3.3 + Cheroot 10.0.1 验过。

### 3.1 流式读取示例

```kotlin
vfs.openStream(VfsUri.parse("alcyone://resources/remote/big.bin")).use { result ->
    val chunk = ByteArray(64 * 1024)
    while (true) {
        val read = result.stream.read(chunk)
        if (read < 0) break
        // 处理 chunk 的前 read 个字节
    }
}
```

- **必须 `close`**：忘记关的话，Runtime 在 `close()` 时会尝试回收（T25 的直接底层释放证据待补，见复核 R4）。
- 想限制这一次读多少：`openStream(uri, VfsStreamOptions(maxTotalBytes = 10 * 1024 * 1024))`，只能**收紧** Runtime 配置上限，不能放宽。
- 超限那一次读取当场报 `LIMIT_EXCEEDED`，**越界的字节不交付**；已经交出的字节不超过上限。

### 3.2 跨后端移动示例

```kotlin
// 本机文件 → 远端
vfs.move(
    VfsUri.parse("alcyone://resources/local/report.txt"),
    VfsUri.parse("alcyone://resources/remote/report.txt"),
)
// 远端目录 → 本机（含空目录与已登记子树）
vfs.move(
    VfsUri.parse("alcyone://resources/remote/notes"),
    VfsUri.parse("alcyone://resources/local/notes"),
)
```

- **文件**：保留原 Node ID / Metadata，旧 ID 指向新路径，源物理消失。
- **目录**：保留已登记后代的 ID / Metadata / `registeredAt`；只发**一条根级** `DIRECTORY_MOVED`，不为复制出的未登记文件批量登记或发事件。
- **目标必须全新**：已有目标报 `ALREADY_EXISTS`，不覆盖。

## 4. 看到错误之后可能留下什么

远端操作和状态库事务不在同一个事务里，所以**抛异常 ≠ 什么都没发生**。T25 新增的移动与流路径：

| 错误 / 阶段 | 已知事实与边界 | 怎么确认 |
| --- | --- | --- |
| `LIMIT_EXCEEDED`（流式 / 有界读超限） | 越界字节未交付，源文件不变 | 直接读更小范围 |
| 目标存在预检报 `ALREADY_EXISTS` + `NONE` | 尚未进入物理移动；若发生在后续阶段须结合 effect 判断 | 核对异常阶段与目标 |
| 移动时报 `NOT_FOUND` | 预检可能尚未变更；移动后确认也可能报此码，不能只按 code 判定 | 结合 effect，核对源 / 目标及状态 |
| 远端写入部分完成后失败（`UNKNOWN`） | **不知道目标写没写进去**，源保持完整、不删源、不提交 | 核对后端内容与原逻辑记录；公开 stat 会懒注册 |
| 复制路径目标确认失败 | 已写目标，尚未进入删源；保留原 UNKNOWN，否则已知变化至少 PARTIAL；逻辑路径尚未迁移 | 核对两边和原 Node ID |
| 原生移动成功后确认失败 | rename 已成功，源可能已消失，逻辑路径尚未提交；已知变化至少 PARTIAL | 核对两边和原 Node ID |
| 删源失败 | 目标已写入；源可能保留、部分删除或已删除但响应丢失。保留 UNKNOWN；已知变化不能报 NONE | 核对两边，不能从异常断定源仍在 |
| 物理成功、状态提交失败（`STATE_ERROR`） | 远端内容变了，状态回滚了 | 读远端、按 Node ID 查状态；不回滚远端 |

**不要做的事**（与 T24 一致）：

- **不要**假定「异常 = 无变更」，尤其 `UNKNOWN` / `PARTIAL`。
- **不要**无条件重试：写入可能已经落地（`CREATE_NEW` 重试会 `ALREADY_EXISTS`），删除可能已经删掉一半。
- **不要**为了「恢复」自己清 `mount` 表或删状态库。
- **不要**用会懒注册的 `stat` 去核对「失败后的待核对状态」，它本身会改状态。

## 5. 网络与超时的已知限制（方案④，未变）

用户已于 2026-10-10 接受方案④：本阶段只验收服务启动等待上限及已验证的快速网络失败，**不承诺 SDK 网络请求或 close 的最长耗时**。这是范围取舍，不是已经实现请求超时。

远端接受连接后若持续不响应，同步 native 请求可能一直等待，受影响实例的后续操作和关闭也可能被阻塞；协程 `withTimeout` / 取消不保证及时返回，也不能证明远端没有完成写入或删除。T25 的移动与流式读取同样受这条边界约束，**没有**因为新增功能而声称已修复超时。

## 6. 自己跑一次真实服务

```bash
./scripts/webdav-check
```

一条命令：装钉死的依赖到 `.local/webdav/venv` → 起一个只听 `127.0.0.1` 的一次性 WsgiDAV（测试凭据、临时根，外加一块**真实只读**共享 `/readonly`）→ 就绪后跑 `:integration-tests:vfs:webdavTest`（34 例）→ 结束关服务、删临时根。

- venv 已存在且依赖未变时复用，不探测 PyPI；只在准备环境时联网。
- 换 Python：`WEBDAV_PYTHON=/path/to/python3 ./scripts/webdav-check`。
- 这批用例**不在** `./scripts/check` 里；没起服务直接失败，不接受「跳过 = 通过」。
