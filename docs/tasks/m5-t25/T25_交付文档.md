## 1. 交付范围

在 T24 已建好的「Local FS 与 WebDAV 同实例挂载」基础上，把 WebDAV Storage 承诺的操作语义补齐，并通过公开 `AlcyoneVfs` 在**真实本机 WebDAV 服务**上验证 Local FS ↔ WebDAV 的文件 / 目录移动、流式读取、能力声明与远端失败事实。

**做到的**：

- **A01 基础契约**：三种写入模式（`CREATE_NEW` / `REPLACE_EXISTING` / `UPSERT`）、文件 / 目录类型冲突、空目录与非递归删除、`%` 拒绝、中文 / 空格 / `+` 名称落点。
- **A02 流式读取**：`WebDavStorage.readStream` 落地，公开 `openStream` 按**实际读出字节**计限，无界读取可超过 ByteArray 默认 16 MiB。
- **A03 / A04 双向移动**：同 WebDAV Mount 原生文件移动；Local FS ↔ WebDAV 文件与目录移动，核对原 ID、Metadata、`registeredAt`、内容、源消失；目录只发一条根级 `DIRECTORY_MOVED`。
- **A05 能力与权限**：能力表符合实测；真实只读共享能读不能写，拒写落到 `STORAGE_ACCESS_DENIED`，不伪装成功。
- **A06 失败事实**：远端写入部分完成后连接断开、目标确认失败、删源失败均不误提交；UNKNOWN 不降级；含一条真实 HTTP 结果丢失证据。
- **A07 资源与取消**：流路径正常 / 失败 / 遗忘回收都清理；关流不取消宿主、不提前关库。
- **A08 回归与交付**：两套检查实际通过，735 / 34 分别统计，源码与 XML 差额为零。

**没做的**（沿用 T24 §5 的边界，明确不承诺）：

- 网络请求 / `close` 的最长耗时保证（方案④，用户已接受，见 §5）。
- 崩溃 / 断电恢复、自动重试 / 补偿、账号管理、广泛并发压力（T26 / T27 / E04 / E05）。
- 只对 WsgiDAV 4.3.3 + Cheroot 10.0.1 验过；不声称兼容所有 WebDAV 服务器。
- 原生目录移动：实测后端 rename 目录返回 `IsADirectory`，能力表诚实报 `false`，目录移动走 Core 整树复制回退。

## 3. 实现要点

### 3.1 流式读取（A02）

`readStream` 与 `LocalFsStorage` 完全同构：先 `stat` 预检（目录报 `TYPE_MISMATCH`），再在后台任务里 `newReader` 打开 `ReaderHandle`，包成 `WebDavStream`。限额由 `StorageInputStream` 数**实际读出字节**，不看 `stat` 长度；`maxBytes = null` 表示无界。文件流登记进 `liveReaders`，关闭存储时 `drainReaders` 逐个回收（一个失败不中断其余），所以 Runtime 遗忘的流也能在 `close()` 时清掉。

### 3.2 原生文件移动与能力声明（A03 / A05）

实测 OpenDAL 0.50.6 webdav `capability.rename == true`，文件 rename 可用；但后端 rename 会**覆盖目标**、会**顺手建父目录**，与 Port 语义不符，所以 Adapter 在 rename 前补两次检查：目标必须不存在（`ALREADY_EXISTS`）、目标父目录必须存在（`NOT_FOUND`）。源不存在报 `NOT_FOUND`；目录报 `UNSUPPORTED_OPERATION`（实测 rename 目录返回 `IsADirectory`）。这些探测是**预检**，不对并发提供原子保障。

能力表：`nativeFileMove = capability.rename && capability.stat`（与 `LocalFsStorage` 同口径：没有 stat 就做不了「目标全新」预检，不能自称原生移动），`nativeDirectoryMove = false`。Core 因此对 WebDAV 同 Mount 文件移动走 `NATIVE_MOVE`，目录与跨 Mount 走复制回退。

### 3.3 跨后端移动（A03 / A04）

跨后端移动**没有新增第二套身份迁移逻辑**，全部走既有 T21 / T22 编排：`DefaultVfs.move` 按源 / 目标是否同 Mount 选策略；跨 Mount 一律「读 → 补父目录 → 写（`CREATE_NEW`）→ 确认目标 → 删源 → 同事务提交」。文件保留 Node ID（旧 ID 指向新路径），目录只发一条根级 `DIRECTORY_MOVED`，不为复制出的未登记后代批量登记或发事件。

### 3.4 失败事实（A06）

| 失败点 | 现象 | effect |
| --- | --- | --- |
| 远端写入（真实 HTTP 结果丢失） | PUT 请求体被服务端读走后不回包直接断开 | `UNKNOWN`（服务端可能已写了一点，不降级） |
| 目标确认失败 | 写入成功但 `stat` 目标抛 `STORAGE_ERROR` | `PARTIAL`（已知目标已写入） |
| 删源失败 | 目标已确认但源 `delete` 抛错 | 至少 `PARTIAL`，源与目标都保留，不提交 |

三条路径都**不删源、不提交事件、不自动清理残留或回移**；后端原始 code / cause 保留。方案④边界：不声称能中断 native。

## 5. 能力边界与已知限制

| 能力 | 当前状态 |
| --- | --- |
| `stat` / `list` / 建目录 / 有界读 / 写（三种模式） / 删除 | 已实现，真实服务验过 |
| `readStream`（流式读取） | **已实现**并经公开 `openStream` 验过；按实际读出字节计限 |
| `move`（原生文件移动） | **已实现**，能力报 `true`；目标全新 / 父目录存在由 Adapter 预检 |
| 原生目录移动 | 不实现，能力报 `false`；目录移动走 Core 复制回退 |
| 跨后端移动（Local FS ↔ WebDAV） | **已验证**双向文件与目录，保持身份 |
| 只读服务拒写 | **已验证**真实只读共享，落到 `STORAGE_ACCESS_DENIED` |
| 远端写入部分完成后失败 / 确认失败 / 删源失败 | **已验证** effect 与残留事实 |

### 明确的已知限制

- **网络等待边界（方案④）**：请求 / `close` 无最长耗时保证。远端静默可能阻塞在途调用、其他操作及关闭，物理结果仍可能未知。本轮不写成「已修复超时」。
- **预检不是原子保障**：三种写模式与 `move` 的「目标全新 / 父目录存在」都靠**提前查**，查完到真正下发之间别的客户端可能改了目标；服务端不保证「不存在才写」时只有这一层检查。
- **只对一种服务器验过**：WsgiDAV 4.3.3 + Cheroot 10.0.1；其他 WebDAV 服务器未验。
- **`nativeDirectoryMove = false` 是实测结论**：OpenDAL 0.50.6 webdav rename 目录返回 `IsADirectory`，不是协议保证；换版本要重新确认。
- **HTTP 401 靠响应行识别**：OpenDAL 0.50.6 把 401 报成 `Unexpected`，`mapStorageErrors` 从 `status: 401` 认出 `STORAGE_ACCESS_DENIED`（限定 webdav 后端）。
