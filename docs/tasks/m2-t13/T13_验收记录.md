## 8. 变异验证

Lead 提出的变异：`StateBoundary.withLock` 改成 `block()`（锁完全失效）。逐项结果：

| 变异 | 结果 |
| --- | --- |
| `includeStorage=false` 也查后端 | 被测试咬住 |
| 挂载根降级成虚拟目录 | 被测试咬住 |
| `register` 返回本地候选 ID | 被测试咬住 |
| `withLock` 变成空操作（锁失效） | **修复前：412 个测试全过（漏网）→ 修复后：被咬住** |

修复后的实际输出（变异版）：

```
NodeRegistryRealStackTest > A04 the registry queues behind an open transaction that shares the boundary() FAILED
> Task :integration-tests:vfs:test FAILED
AssertionFailedError: 事务提交前 Registry 就返回了 —— 共享边界没有生效 ==> expected: <null>
  but was: <NodeInfo(id=018f0000-0000-7000-8000-0000000000ee, ...)>   // 读到了未提交的行
```

还原后 `./scripts/check` 全绿（见第 1 节）。原来的 `assertFalse(pending.isCompleted)` 之所以漏网：协程只是「还没跑到」，赌的是一个瞬间；现在改成「事务未提交却拿到了返回值」这一确定性判据。
