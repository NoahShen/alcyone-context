## 2. 必须修改

### R1 / P1：远端根与身份没有使用一致的位置规范化

位置：`WebDavRoots.kt` 的 normalizeEndpoint / identity / requireNonOverlapping；Runtime resolve 复用该逻辑。

重叠检查只在 endpoint 原字符串相等时比较 root，但 identity 又把 endpoint 与 root 拼接。这使 `http://localhost:8080/dav + /team` 与 `http://localhost:8080 + /dav/team` 得到**完全相同身份串**却通过重叠检查；同主机大小写差异也通过。独立探针确认这两种接受行为，另确认 `http://bad host` 能通过 normalizeEndpoint。

这不是需要 DNS 才知道的服务器别名，而是配置本身可识别的同址 / 非法地址。两块逻辑 Mount 若指向同一资源，会重复登记身份；跨 Mount 移动还可能在别名路径间写入、删除同一资源，违背 T02 与 A04。

修复：用合法 URI 解析与明确的 endpoint/root 规则，身份、重叠检查及实际 OpenDAL 寻址使用同一套规范结果；处理主机大小写、默认端口和 endpoint 路径与 root 的组合，对点段 / 编码歧义明确规范化或拒绝。不要求 DNS 或全世界服务器别名识别；补上述同址反例及 `/a` 与 `/a-old` 正常对照，至少一个非根 endpoint/root 的真实服务定位证据。

### R2 / P1：文件与非递归空目录删除失败可能误报 NONE

位置：`WebDavStorage.kt:278–288`。外层 `call("delete")` 默认 effect=NONE，文件和非递归空目录直接执行 operator.delete；网络异常因此被映射成 NONE，即使服务端已删除、只是响应丢失。

递归分支已单独映射 UNKNOWN / PARTIAL，但前两条分支没有相同的副作用边界。此错误会经 DefaultVfs 删除入口保留，宿主误以为没有发生删除；属于已交付 delete 的正确性问题，不能以“网络完整矩阵在 T25”为由延后。

修复：保留 stat / 非空检查的 NONE，在实际 DELETE 请求边界使用不能确定结果时的保守 effect，保留原 code / cause；已有变更事实不得丢失。补文件、空目录的针对性失败证据，其中至少一条让服务端实际删除后断开响应，核对物理事实和逻辑 / 事件没有成功提交；可用受控服务装置，不需要新增生产通用 failpoint。

### R3 / P1：没有落实任务要求的网络等待上限

位置：`WebDavStorage` 同步 native 调用、`WebDavRealServerTest.A05` 及交付 / 验收的 A06。对未监听端口测得小于 30 秒，只证明连接快速失败；不能证明“连接已接收但一直不响应”有上限。withTimeout 包住 Dispatchers.IO 内的同步调用，也不能保证 30 秒返回：结构化并发会等阻塞调用结束，后续 close 又等待 NativeLifetime 的在途调用。

文档诚实承认依赖限制值得保留，但任务 §2.5 / A06 要求明确网络超时，不能同时把“没有后端请求超时”与“A06 已通过”成立。使用说明 §5 的“withTimeout 只能限制调用方等多久”也仍过强，在这条调用链中连及时返回都不保证。

修复：先核对已锁定依赖能提供的请求 / 读等待限制与可行接入方式，交付有效的有界网络失败路径；不能用多套一层 withTimeout、遗弃阻塞线程或提前关 native 资源代替。补“接受连接但不响应”的受控证据，并证明调用失败和清理顺序；测试装置自身需有独立有限退出保障。若现有依赖确实无法满足，应明确提出依赖或任务范围调整方案供确认，在批准前保持该项未通过，不自行留给 T25。

### R4 / P2：未校验配置打印仍会泄露 URL 内凭据

位置：`VfsRuntimeConfig.kt` 的 `MountBackend.WebDav.toString()`。虽然 resolve 拒绝 URL userinfo，配置对象在 resolve 前已经可以打印；toString 原样拼接 endpoint，`WebDav("http://demo:synthetic-secret@localhost", "/", "", "")` 的打印包含虚构密码，独立探针已确认。

修复：配置打印不要回显未经校验的 endpoint 中的敏感部分，错误配置也不能泄密；同时明确 username 的打印政策，避免文档声称“凭据全部隐藏”却打印用户名。补非法 userinfo 配置在直接 / 嵌套配置打印中的反例；沿用真实认证失败测试，检查 cause / suppressed，而非只验证正确 password 字段被星号替换。

原始 OpenDAL 异常仍挂在 cause 上，当前四条真实测试仅证明对应响应未含测试密码，不能推广所有服务器响应都不会回显凭据；文档应区分已验证范围与保证。

## 3. 建议优化

- **S1 文档与公开范围**：新增的是公开 Runtime 配置类型；“未改 vfs/api 模块”准确，“未新增公共 API”不准确。保留 Path 次构造函数证明构造调用兼容，不等于旧 root 属性 / copy(root=...) / 二进制兼容全部保持。

- **S3 账号与远端边界**：补任务 §2.2 要求的账号决定可见根时的边界说明；密码轮换可接受，但不能声称换用户名永远是同一份数据。“远端没有符号链接”应改成“客户端无法一概识别服务端链接，边界依赖服务端配置”。
- **S4 测试服务**：已有 venv 且依赖未变时仍强制探测 PyPI，离线可复用性较差；建议只在准备环境时联网。后续可将就绪探测从 TCP 握手提升为带认证的 WebDAV 响应，并检查信号中断时的服务清理，不要求本轮建设通用服务框架。
- **S5 共享辅助类**：WebDAV 有界读复用 StorageInputStream，其部分报错仍称 local storage；可顺手使后端标签一致。HTTP 401 消息匹配最好限定 WebDAV 与对应原始错误类型，避免通用映射仅靠消息片段覆盖其他错误码。

## 4. 可以接受的设计取舍

MountBackend 密封类型和 StorageAdapter 小接口足以表达当前两类后端，无需抽象插件注册框架。组装按 key 持有资源、初始化失败逆序关闭、Core 只看 Storage Port，依赖方向合理。

打开 Adapter 不预检网络可接受；连通性由实际操作验证，不能因此宣称远端 root 已确认存在。独立 webdavTest source set、无服务就失败、默认回归与真实服务分开计数可接受，不必硬塞默认 check。

仅支持已验证的 WsgiDAV 组合、流式及原生移动显式拒绝、条件写不足时如实说明预检的竞争窗口，符合阶段范围；不要求重做 Local FS 或提前完成 T25 矩阵。上述 R1～R4 针对已交付配置、delete、接入等待与打印，不扩大任务。

### 6.2 必须修改与补证

**R1 仍未关闭：完整身份查重修好了，完整路径的包含判断没有修好。**

`requireNonOverlapping` 的 distinct identities 现在能拒绝完全相同的拼接结果，主机大小写 / 默认端口也正确收敛。但是 `sameLocation` 只比较 origin，之后仍比较原始 root，漏掉 endpoint 中的路径。

| 独立探针输入（同一 localhost:8080） | 期望 | 当前结果 |
| --- | --- | --- |
| endpoint `/dav` + root `/team`；endpoint 空路径 + root `/dav/team/sub` | 两个完整路径为 `/dav/team` 与 `/dav/team/sub`，必须拒绝 | 接受，漏检 |
| endpoint `/one` + root `/a`；endpoint `/two` + root `/a` | `/one/a` 与 `/two/a` 不重叠 | 拒绝，误判 |

修复应统一为“规范 origin + endpoint 路径与 root 组成的完整路径段”，同时用于身份、相等及包含比较。已有 `/a` 与 `/a-old` 对照保留；新增真实 A03b 只传 `root=/dav/team`，**没有使用带路径 endpoint**，不能作为两种拆分寻址一致的证据，补 endpoint `/dav` + root `/team` 的实际落点对照即可，不扩展全 URL 矩阵。

**R2：生产修复确认，证据尚需收紧。**

文件 / 非递归空目录现在都经 `deleteConservatively`，预检 NONE、实际请求 UNKNOWN 的分界正确；真实 TCP 装置在删除磁盘目标后不发响应即关连接，两条用例独立通过，确实证明物理删除与错误同时发生。这是受控 HTTP 服务加真实磁盘 / OpenDAL，不是 WsgiDAV 自发丢包。

但断言允许 UNKNOWN **或 PARTIAL**，不能钉住这里“结果不明”的具体约定；两条也未核对 Node / Metadata / event。按上一轮 R2 要求，改为直接断 UNKNOWN，至少一条先通过 Runtime 登记源并设置 Metadata，失败后直接查旧记录与事件不变，不用再次 stat 改写状态。原 code / cause 的保留补直接断言即可，复用此前通知机制，不再强求一套重复通知测试。

**R4 仍未关闭：URI 可解析不等于有合法的服务器 authority。**

独立探针 `WebDav("http://demo:synthetic-secret@bad_host", "/", "", "")` 的 toString 仍包含虚构密码。Java URI 在 host 非法时可以保留 registry authority、返回 userInfo=null；safeEndpoint 因此回到 `return endpoint`，绕过遮蔽。

正常主机 userinfo、直接 / 嵌套打印以及 username 字段不打印的现有修复有效。剩余修复：无合法 host / server authority 的地址不回显原文，使用固定占位或只输出验证过的安全字段；补上述非法主机地址的直接与嵌套打印反例。无需进一步复杂化遮蔽正则。

**新增 R5 / P1：SilentDeleteServer 的监听与删除范围超出测试根。**

新增装置用 `ServerSocket(0)`，实际绑定通配地址，而不是任务要求的 loopback；请求路径经 URLDecoder 后直接 `dataRoot.resolve(...)`，未检查规范化结果是否还在测试根内。装置不认证且 DELETE 会实际删除文件 / 递归目录，带 `..` 或额外前导斜杠的请求可能指向根外，不能以“仅测试代码”接受。

最小修复：显式绑定 127.0.0.1，拒绝路径逃逸（含解码后的点段 / 绝对路径），只操作该装置拥有的临时根；补安全的越界拒绝测试，不实际触碰仓库外文件。close 还应关闭已接纳 socket 并等待线程结束、连接读取有有限等待；daemon 线程只是不阻止 JVM 退出，不能等同于资源已释放。此项来自源码审查，未执行破坏性请求。

### 6.3 R3：证据结论与四种方案

**能确认的结论**：本地锁定 Java 0.50.6 的 Webdav 配置无 timeout 字段，Operator 无直接请求超时 API；AsyncOperator 能加 Layer，但实际 jar 只提供 CapabilityOverride / ConcurrentLimit / Retry，没有 TimeoutLayer。故当前调用路径没有已验证可用的超时入口。

**不能据此推出**：“整个 OpenDAL 不支持超时”“新版本必然无法解决”。native 字符串没搜到不是不存在的证明；[上游 Rust TimeoutLayer 文档](https://opendal.apache.org/docs/rust/opendal_layer_timeout/index.html)明确有操作 / I/O deadline，而[Java 层生产指南](https://opendal.apache.org/docs/bindings/java/production/)列出的已暴露 Layer 不包含它。Rust 能力、Java binding 暴露和已发布制品三者必须区分；本轮没有确认一个可直接升级且满足要求的 Java/native 版本。

| 方案 | 独立建议 |
| --- | --- |
| ① 升级 | 只有找到具体发布的 Java/native 制品并验证超时覆盖后才采纳；仅看 WebDAV 配置字段不能排除 Layer 路径。不建议为未证实的能力盲目升级。 |
| ② Java 包装 | 给现有同步调用外套 withTimeout / Future 超时并丢弃线程不可接受；它不停止 native 请求，还可能延迟写入并阻塞 close。若要新增 JNI TimeoutLayer 桥接，那是自维护 native 的新方案，不是简单 Java 包装。 |
| ③ 独立代理 | 可施加部分 HTTP 等待限制，但会引入额外服务、配置、凭据与生命周期负担，也不能自动证明远端没有完成写入；不推荐作为个人嵌入式库的当前默认方案。 |
| ④ 调整阶段范围、接受已知限制 | **建议当前采用，但需用户确认范围变更。** T24 只承诺服务启动等待及已验证的快速网络失败，不承诺 SDK 请求 / close 的最长耗时；远端静默可能阻塞实例内其他操作及关闭，物理结果仍可能未知。 |

建议 ④ 是交付范围决定，不是 R3 技术修复通过，也不是宣称 native 超时永远做不到。若用户要求首版任意远端挂起都必须限时结束，则保留原验收要求，另安排已发布 binding / JNI 接入或 Storage 引擎替换的定向可行性验证，不直接引入代理。

批准前 R3 保持未通过、不擅改任务 A06。三份文档仍有“withTimeout 只能限制调用方等多久”“测试等待设明确上限”等表述，应改为“同步 native 阻塞时协程超时也不保证及时返回”；新的 A06 标题仍写“通过”但行内写 R3 未通过，应统一为“部分满足，网络等待待决策”。

### 7.2 必须修改

**R1：root 为 `/` 时，完整位置仍未收敛。**

独立探针接受了 `http://localhost:8080/dav + /` 与 `http://localhost:8080 + /dav`；fullPath 分别得到 `/dav/` 与 `/dav`。identity 字符串不同，fullPath 相等检查失败，contains 虽 trim 了尾斜杠，但两边段数相等，不满足严格包含，因此同一目录仍能重复挂载。

前轮 A/B、主机大小写、默认端口及 `/a` 与 `/a-old` 已处理正确。修复只需让 identity、相等与包含都基于同一个规范完整目录路径，除 origin 根外统一末尾分隔符；不要继续给不同检查补独立例外。补上述 root=/ 的同址拒绝与身份相等对照；本轮带路径 endpoint 的真实落点测试已补，不需要再扩展矩阵。

**R2：`UNKNOWN` / 物理事实 / Node / Metadata 已证实，事件未提交尚未直接证明。**

三个反例现在直接断 UNKNOWN、STORAGE_ERROR 和 OpenDALException cause，服务端确实删掉目标后断响应；登记场景还用 getNode / getMetadata 证明旧逻辑记录保留，避免再次 stat 改动现场。这些可以确认。

新增登记用例末尾的 `events.map { it.type }` 来自异步订阅，既不是持久 event 表，也没有等待失败之后的有序尾标记，因此立即看不到通知不能证明未追加成功事件。最小修复是直接查询真实 SQLite 的 event 表，比较删除前后持久记录（至少 ID / type / node_id），本轮不要求重复搭建通知矩阵；把当前“事件未提交直接证据”的措辞对应到实际查表断言即可。

**R5：关闭快照可能漏掉 accept 已返回、尚未登记的 socket / worker。**

loopback、解码后拒绝点段 / 多前导斜杠、规范化后限制临时根、soTimeout 均已落实；越界拒绝测试有效。但 close 当前先遍历 openSockets / workers，最后才 join acceptThread：如果 accept 已返回而还没执行 `openSockets += socket`，两个快照都可能为空；随后 acceptThread 登记并启动 worker，close 仅等接纳线程结束就返回，遗漏该连接和处理线程。带超时 join 且吞异常，也不等于确认线程已结束。

最小修复：停止并关闭监听后，先确保接纳线程退出、不会再登记，再关已接纳 socket 并等待全部 worker；或用同一生命周期锁保证登记与关闭互斥。join 超时 / 中断不要吞掉并报成清理成功，保持测试失败原因；补一个受控“接纳与关闭相邻”的清理证据即可，不需要生产锁框架。

同个测试新增 `Files.createTempDirectory` 和根外哨兵未清理，改放 JUnit @TempDir 下两个子路径或 finally 清理，避免每轮留下测试文件。此为测试收尾，不要求扩大远端安全能力。
