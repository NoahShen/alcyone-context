## 1. 目标与范围

让宿主通过 Runtime 配置挂载真实 WebDAV，以相同 VFS 入口完成最小文件读写闭环；配套服务无需个人账号即可重复运行。T24 完成配置、组装、基础 Adapter 与测试环境，T25 承接完整 Storage 契约、目录 / 移动及 Local FS ↔ WebDAV 集成矩阵。

例：把测试服务器中的 `/dav/team/` 挂到 `/resources/remote`，使用 `alcyone://resources/remote/hello.txt` 写入、读取并删除；调用方不创建 OpenDAL Operator。

## 2. 开发内容

### 2.1 扩展配置与 Runtime 组装

当前 `MountConfig.root: Path`、`ResolvedConfig.roots` 和 Runtime 的 LocalFsStorage 集合都只支持本地盘，需要能表达 Local FS 与 WebDAV 两类后端。采用小范围、类型明确的配置扩展，保持既有本地调用可用；Core / API 不接收 endpoint、凭据或 OpenDAL 类型，不增加通用插件注册框架。

例：同一配置中挂 `/resources/local` 和 `/resources/remote`，Runtime 分别创建 Adapter，Core 仍只调用 Storage Port。具体类型和构造函数可在开发中确定，交付说明兼容方式即可。

### 2.2 远端位置、凭据与挂载身份

明确 endpoint 与 root 如何组合，逻辑相对路径只编码一次；本地 Path 规范化不能套到远端 URL 上。复用 T18 的持久挂载身份及冲突检查，对可识别的同一服务、相同或重叠根按完整路径段处理；凭据不写入 mount 表，不出现在配置打印、异常消息或测试日志中。

例：同库重开仍指向原 endpoint/root，Node ID 保留；改到另一 root 应报 CONFLICT，不能替旧身份自动认证。密码更换不应作为物理根变更；若账号决定服务器可见根，应记录其识别边界，不能假定同 URL 一定同数据；这不是引入 VFS 用户或 ACL。

### 2.3 基础 WebDAV Adapter

在 `vfs/storage` 通过项目已锁定的 OpenDAL 接入，实现最小闭环需要的 stat / list / 目录创建 / 有界读写 / 删除，并接通 Runtime；已暴露的实现遵守既有 Port 语义。移动与流式等尚未验证能力必须诚实报告或明确阶段拒绝，不用空实现、假成功或把预检写成原子保证；完整行为验收交 T25。

例：正常写读同一文件核对字节；缺失目标返回 NOT_FOUND，认证拒绝转换为 STORAGE_ACCESS_DENIED。复用可用的错误、reader 所有权及 native 生命周期机制，但不搬用本地符号链接 / JDK 目录枚举逻辑，也不为复用先重写整个 Local FS Adapter。

### 2.4 可复现测试服务

优先复用 `tools/validation/t04` 已验证的 WsgiDAV / Cheroot 方案，整理为正式测试入口；依赖版本固定、Python 环境与数据目录留在项目忽略目录或临时目录，不修改全局环境。服务只监听本机，使用测试凭据和独立临时根，明确启动、就绪探测、端口分配、有限等待、终止与清理方式；进程启动失败也要清理已取得资源。

例：一条项目命令准备服务并运行测试，结束后无遗留监听进程；连续运行两次不依赖上一轮数据。可改用其他服务，但需在交付中说明理由与可复现命令，不依赖个人 WebDAV 或手工常驻服务。

### 2.5 失败、超时与资源释放

补真实错误凭据、缺失文件、服务不可达的代表，按观察到的后端行为转换 VFS 错误；无法判断远端是否写入时保留 UNKNOWN，不把请求失败等同于无副作用。网络调用与服务启动均须有明确超时，协程等待超时不能冒称已经中断 native 请求；Runtime 初始化失败和正常关闭沿用 T18 的资源释放顺序。

例：先创建有效实例再停止测试服务，读取在约定时间内失败；释放实例与服务后，同一个状态库可再次正常打开。这里只补接入相关证据，不重复 T27 的广泛关闭竞争与压力测试。

### 2.6 正式测试入口与证据

WebDAV 测试必须有明确可运行入口；可纳入统一检查，或作为单独的强制验收命令，但不可因服务缺失静默跳过后仍宣称通过。分别记录真实服务器、故障包装和源码审查证据，实际运行平台如实填写；若改 CI，测试服务和日志清理须随任务结束执行。

例：交付同时列 `./scripts/check` 的回归结果与真实 WebDAV 命令的执行结果，若分开执行，测试数量分别统计并避免重复累计。本轮不要求升级 OpenDAL，不把 T04 的历史探针当成当前 SDK 验收。

## 4. 验收标准

| 编号 | 必须满足 | 直接证据 |
| --- | --- | --- |
| A01 配置与边界 | Local FS 原调用无回归；WebDAV 经 Runtime 组装，Core 不依赖具体后端 | 本地基线与公开配置示例；无 Operator 泄漏 |
| A02 服务可复现 | 无个人凭据，一条明确命令启动并测试；就绪、超时、失败清理可解释 | 真实服务启动及重复执行，临时根 / 端口 / 进程清理记录 |
| A03 最小闭环 | 公开 Runtime 在真实服务上建目录、写、读、stat、list、删除 | 字节一致、列表正确、删除后 NOT_FOUND；至少一个中文或空格名称验证编码及 root 映射 |
| A04 身份与根边界 | 同配置重开保留已登记 ID；可识别的冲突 / 重叠根不被误接受 | 真库重开、改变 endpoint/root 的冲突代表；同服务 `/a` 与 `/a-old` 不误判重叠 |
| A05 错误与保密 | 认证失败、缺失文件、不可达均转换为 VFS 异常；不泄露凭据 | 真实服务反例与异常字段，检查公开消息 / 日志 / cause 中的敏感内容；不要求逐 HTTP 状态码矩阵 |
| A06 生命周期 | 初始化失败释放已取得资源；正常关闭后同库可重开；已验证的快速网络失败有等待断言（不承诺 SDK 请求 / close 最长耗时） | 一个确定失败点及后续重开；Adapter / 服务清理顺序，不把协作取消当强杀。**当前：部分满足，网络等待待决策**） |
| A07 能力与分工 | 能力声明与当前实现一致；未完成方法显式拒绝，T25 待验范围可定位 | 当前能力表及 T25 清单；不声称所有 WebDAV 服务器已兼容 |
| A08 回归与交付 | 712 例基线无回归，真实 WebDAV 不被 Fake 或跳过替代 | 项目检查、WebDAV 命令、XML 与源码计数说明、平台与未验证项 |

不要求特定新增测试数量或变异次数。服务不可用应报告阻塞，不将跳过作为通过；本轮只接受已证明的能力，网络部分失败、三种写模式完整矩阵、流式 / 移动 / 跨后端与目录细节在 T25 补齐。
