## 1. 交付范围

宿主用一份配置就能把 **Local FS 与 WebDAV** 挂在同一个实例上，通过公开 `AlcyoneVfs` 完成建目录 / 写 / 读 / stat / list / 删除的最小闭环；测试服务一条命令启动、跑完自清理，不需要个人账号。

**做到的**：配置与挂载身份扩展、Runtime 按后端分叉组装、`vfs/storage` 里的基础 WebDAV Adapter（stat / list / 建目录 / 有界读 / 写 / 删除）、可复现的真实服务、真实闭环与错误 / 生命周期代表。

**没做的**（都是显式拒绝或诚实少报，见 §5）：移动与流式读取、三种写模式的完整矩阵、网络部分失败、跨后端集成与目录细节。

## 3. 配置方案与 T24 / T25 分工

```kotlin
val vfs = AlcyoneVfs.create(
    VfsRuntimeConfig(
        stateDatabase = Path.of("data/state.db"),
        namespaces = setOf("resources"),
        mounts = listOf(
            MountConfig(VfsPath.parse("/resources/docs"), "docs", Path.of("/data/docs")),        // 既有本地写法
            MountConfig(                                                                        // 新增
                VfsPath.parse("/resources/remote"),
                "remote",
                MountBackend.WebDav("http://127.0.0.1:8080", "/dav/team", username, password),
            ),
        ),
    ),
)
```

| 决定 | 理由 |
| --- | --- |
| `MountBackend` 是**密封类型**，不是一个开关字段 | 本地要 `Path`、远端要 `endpoint/root/凭据`，字段全塞进一个 data class 会让「缺一个」变成运行时才发现；子类型让写错在 `resolve()` 就拒（T24 §2.1「类型明确」） |
| 保留 `MountConfig(path, key, root: Path)` 次构造函数 | 30 处既有调用一行都不用改，A01 的「本地原调用无回归」从源头成立 |
| 身份 = `backendType + identity()`，**不含用户名与密码** | 换密码不是换盘（T24 §2.2）；`MountBackend.WebDav.toString()` 不回显 userinfo、不打印 username、密码遮成 `***`（R4 修复） |
| endpoint 的 `user:pass@` 直接拒 | 否则凭据会顺着 URL 落进 `mount` 表和任何打印出来的消息里 |
| 远端根按**完整路径段**查重叠 | `/a` 与 `/a-old` 不是一家人；字符串前缀会误判。识别边界：看不见两台不同 endpoint 背后是不是同一台服务器 |
| **R1 修复**：endpoint 用 `URI` 解析、主机小写、默认端口省略、身份查重 | `http://host/dav` + `/team` 与 `http://host` + `/dav/team` 身份相同，重叠检查拒绝；主机大小写、默认端口差异在规范化后收敛 |
| 打开 Adapter **不联网** | 配置校验、身份核对、失败释放都发生在「还没碰后端」的阶段，A06 的确定失败点也在这里；副作用只来自真正调用的操作 |
| `nativeFileMove` / `nativeDirectoryMove` 报 `false` | rename 这一轮没验收（T04 的历史探针不算当前 SDK 验收）。报 `false` 之后 Core 自己走复制回退，不会调到被拒绝的 `move` |
| `readStream` / `move` 显式 `UNSUPPORTED_OPERATION` | 与 `LocalFsStorage` 里已有的「明确拒绝」同一套口径，不用空实现或假成功 |
| WebDAV 用例放**独立 source set** 而不是 `@EnabledIfEnvironmentVariable` | 标签方案会在默认跑法里留下「已跳过」记录，看着像跑了又没跑；独立任务里没有服务就直接失败 |

## 4. 执行顺序与两条命令

```
./scripts/dev gradle spotlessApply   # 格式
./scripts/check                      # 回归：clean build + spotlessCheck，不含真实 WebDAV
./scripts/webdav-check               # 真实 WebDAV：装依赖 → 起服务 → webdavTest → 关服务
```

`scripts/webdav-check` 的生命周期：

```
1. 挑一个能连 PyPI 的 python3（可用 WEBDAV_PYTHON 覆盖）
2. 依赖哈希没变就复用 .local/webdav/venv，变了就重建（不碰系统环境）
3. mktemp 一次性临时根；绑 0 拿空闲端口；生成只听 127.0.0.1 的配置（simple_dc + basic 认证）
4. 起服务 → 最多 30 秒就绪探测（进程提前退出 / 到点没就绪 → 打日志并失败）
5. 用 T24_WEBDAV_ENDPOINT / USER / PASSWORD 跑 :integration-tests:vfs:webdavTest --rerun-tasks
6. trap EXIT：先 TERM、最多等 10 秒再 KILL，最后删临时根 —— 不留监听进程、不留数据
```

## 5. 能力边界与 T25 承接

| 能力 | 当前状态 |
| --- | --- |
| `stat` / `list` / 建目录 / 有界读 / 写（含 `CREATE_NEW`、`REPLACE_EXISTING`、`UPSERT` 的提前检查） / 删除 | 已实现并在真实服务上验过最小闭环；三种写模式的**完整矩阵**留 T25 |
| `readStream`（流式读取） | **阶段拒绝** `UNSUPPORTED_OPERATION`；能力表不声称 |
| `move`（原生移动） | **阶段拒绝** + 能力报 `false` → Core 走复制回退；rename 的完整验收与 Local FS ↔ WebDAV 移动矩阵留 T25。**S2 说明**：公开 `Vfs.move` 走 Core 复制路径，该路径本轮未验 |
| 跨后端集成（Local FS ↔ WebDAV 移动保持身份） | 未做，T25 |
| 网络部分失败（连接建立后中途断）、只读服务 | 未做，T25 |
| WebDAV 服务器兼容性 | 只对 **WsgiDAV 4.3.3 + Cheroot 10.0.1** 验过；不声称已兼容所有 WebDAV 服务器 |

### 明确的已知限制

- **没有可中断的 native 超时**：OpenDAL 0.50.6 的 `webdav` 服务不暴露请求超时（已核对 `ServiceConfig$Webdav` 无超时字段、`Operator` 无超时 API、native 库无 webdav 超时字符串）；协程 `withTimeout` **不能**中断一个正在跑的阻塞 native 请求，所以本层**不提供**这样的超时，也不声称提供。T24 只把**服务启动等待**（30 秒）与**测试等待**（30 秒）设了明确上限，并用真实用例断言不可达请求在上限内返回。**R3 方案**：① 升级 OpenDAL 到提供超时的版本（目前上游 0.59.x 仍无 webdav 超时配置，升级不能解决）；② Java 层包装（不可行，HTTP 客户端在 Rust native 里）；③ 引入独立 HTTP 代理层（架构变更，超出 T24 范围）；④ 接受现状，把 R3 标记为「依赖限制，待上游支持或任务范围调整」。**批准前保持 R3 未通过**。
- **认证失败靠响应行识别**：OpenDAL 0.50.6 把 HTTP 401 报成 `Unexpected`，`mapStorageErrors` 从错误消息里的 `status: 401` 认出 `STORAGE_ACCESS_DENIED`（**S5 限定 webdav 后端**）。这是按观察到的后端行为写的对照，不是通用 HTTP 语义推断；换 OpenDAL 版本要重新确认。
- **删除语义按观察到的后端行为补检查**：WebDAV 上「删不存在的目标」「删非空目录」「列不存在的目录」后端都可能报成功 / 返回空，所以 Adapter 各自先 `stat` / 先列一层再动。这些是**这一轮观察到的行为**，不是 WebDAV 协议保证。
- **根目录不做存在性探测**：实测对一个不存在的 OpenDAL `root`，`stat("")` 也会报 `DIR`，探测既查不出来、还可能让服务器建目录。所以远端根是否真实存在**不在打开时确认**，第一次真正操作才见分晓。
