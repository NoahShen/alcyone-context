## 1. 一句话

配置里多写一个 `MountBackend.WebDav`，就能把远端 WebDAV 上的一个根挂进**同一个** VFS 实例，用和本地盘完全一样的 `alcyone://...` 入口读写。调用方不创建 OpenDAL Operator，也看不到 endpoint 和密码。

## 2. 怎么配

```kotlin
val vfs = AlcyoneVfs.create(
    VfsRuntimeConfig(
        stateDatabase = Path.of("data/state.db"),
        namespaces = setOf("resources"),
        mounts = listOf(
            // 既有写法照旧：第三个参数还是 Path
            MountConfig(VfsPath.parse("/resources/docs"), "docs", Path.of("/data/docs")),
            // 新增：远端
            MountConfig(
                VfsPath.parse("/resources/remote"),
                "remote",
                MountBackend.WebDav(
                    endpoint = "http://127.0.0.1:8080",   // 只接受 http:// 或 https://，不许写 user:pass@
                    root = "/dav/team",                   // 服务上的共享根
                    username = "alice",
                    password = "…",
                ),
            ),
        ),
    ),
)
try {
    val info = vfs.write(VfsUri.parse("alcyone://resources/remote/报告/a.txt"), bytes)
    val back = vfs.read(VfsUri.parse("alcyone://resources/remote/报告/a.txt"))
} finally {
    vfs.close()
}
```

### 配置阶段就会拒的

| 写法 | 结果 |
| --- | --- |
| `http://alice:hunter2@host/` | `INVALID_ARGUMENT`：凭据走 `username` / `password` 字段，不进 URL（进了 URL 就会跟着身份串落进 `mount` 表） |
| 没有 `http://` / `https://`、带查询串 / 片段、非法 URI（如 `http://bad host`） | `INVALID_ARGUMENT` |
| `root` 不以 `/` 开头、含空段 / `.` / `..` / `%` | `INVALID_ARGUMENT` |
| 同一个服务上 `/a` 与 `/a/b`，或同一个根挂两个 `storageKey` | `INVALID_ARGUMENT`（按**完整路径段**判断，`/a` 与 `/a-old` 不算重叠） |
| **R1 修复**：同址写法（`http://host/dav` + `/team` vs `http://host` + `/dav/team`）、主机大小写、默认端口差异 | `INVALID_ARGUMENT`（身份串相同或完整路径包含，重叠检查拒绝） |
| **R1 残留修复**：endpoint 路径不同的包含 / 误判 | `INVALID_ARGUMENT`（按 endpoint 路径 + root 拼成的完整路径比较，如 `/dav` + `/team` 与 `/dav/team/sub` 互相包含） |

### 换配置时

- **换密码不等于换盘**：`endpoint + root` 不变，同一个状态库直接重开就行。
- **换 endpoint 或 root**：重开时报 `CONFLICT`——旧 Node 指向的是另一份文件，VFS 不会替你偷偷改指向。要换就明确决定旧文件怎么办，再改状态库。
- **S3 账号边界**：如果账号决定服务器可见的根（不同用户看到不同的根），VFS 无法识别两个不同账号的 URL 是否指向同一份数据——身份串只由 endpoint + root 决定，不含用户名。换用户名不一定是同一份数据；换密码也不是换盘。密码轮换可接受，但不能声称换用户名永远是同一份数据。
- `storageKey` 是内部实例标识，重开时也不许变。

## 3. 这一版能做什么、不能做什么

| 操作 | 状态 |
| --- | --- |
| 写（三种模式的提前检查）、读（有界）、`stat`、`list`、`delete` | 可用，已在真实服务上验过 |
| 新目录 | 写入时自动逐级建出来（VFS 没有单独的 `mkdir`） |
| `openStream`（流式读取） | **`UNSUPPORTED_OPERATION`**：这一版没验收流的所有权与半截网络失败 |
| `move`（原生移动） | 能力表报 `false`，Adapter 直接调会 `UNSUPPORTED_OPERATION`；**公开 `Vfs.move` 走 Core 复制回退，该路径本轮未验**（S2 说明）。跨后端移动矩阵在 T25 |
| 远端根是否真的存在 | **打开时不探测**：第一次真正操作才见分晓（探测既查不出来，还可能让服务器建出目录来） |

能力表（`capabilities()`）就是实情：`nativeFileMove = false`、`nativeDirectoryMove = false`、`createDirectory = true`、`boundedRead = true`、`readOnly = false`。**不要**据此假设所有 WebDAV 服务器都兼容——只对 WsgiDAV 4.3.3 + Cheroot 10.0.1 验过。

## 4. 看到错误之后可能留下什么

远端操作和状态库事务不在同一个事务里，所以**抛异常 ≠ 什么都没发生**：

| 错误 | 大概率留下了什么 | 怎么确认 |
| --- | --- | --- |
| `NOT_FOUND`（缺失目标） | 什么都没做 | 直接看那个路径 |
| `STORAGE_ACCESS_DENIED`（密码错 / 没权限） | 什么都没做 | 检查凭据；`cause` 里是后端原文，**不带你的密码** |
| `CONFLICT`（配置阶段） | 什么都没做 | 配置对不上旧身份，按 §2「换配置时」处理 |
| `LIMIT_EXCEEDED` / 写入被拒 | 目标一个字节都没写，但**父目录可能已经建出来了** | `list` 父目录 |
| 写到一半报 `STORAGE_ERROR` | `effect = UNKNOWN`：**不知道写没写进去**，别当成「没写」 | 先 `stat` / `read` 目标，再决定怎么办 |
| 删除报错 | `effect` 是 `UNKNOWN` / `PARTIAL`：可能已经删掉一部分 | 按 `effect` 逐层 `list` 核对 |
| 物理成功、状态提交失败（`STATE_ERROR`） | 远端内容变了，状态回滚了：**磁盘上是新内容，逻辑路径还在旧位置** | 读远端、按 Node ID 查状态；不回滚远端 |
| 关闭之后再用 | `CLOSED` | 重新 `create` 一个实例 |

**不要做的事**

- **不要**假定「异常 = 无变更」，尤其 `UNKNOWN` / `PARTIAL`。
- **不要**无条件重试：写入可能已经落地（`CREATE_NEW` 重试会 `ALREADY_EXISTS`），删除可能已经删掉一半。
- **不要**为了「恢复」自己清 `mount` 表或删状态库——那会丢掉已提交的 Node、Metadata 和事件。
- **不要**用会懒注册的 `stat` 去核对「失败后的待核对状态」，它本身会改状态。

## 5. 网络与超时的已知限制

用户已于 2026-10-10 接受方案④：本阶段验收服务启动等待上限及已验证的快速网络失败，**不承诺 SDK 网络请求或 close 的最长耗时**。这是范围取舍，不是已经实现请求超时。

远端接受连接后若持续不响应，同步 native 请求可能一直等待，受影响实例的后续操作和关闭也可能被阻塞；协程 withTimeout / 取消不保证及时返回，也不能证明远端没有完成写入或删除。正常不可达端口的快速失败测试不代表所有网络故障都有同样时限。

当前不以遗弃阻塞线程或提前释放 native 资源绕过等待；网络超时保留为后续技术债务，具体方案另行安排，不自动纳入 T25。

## 6. 自己跑一次真实服务

```bash
./scripts/webdav-check
```

一条命令：装钉死的依赖到 `.local/webdav/venv` → 起一个只听 `127.0.0.1` 的一次性 WsgiDAV（测试凭据、临时根）→ 就绪后跑 `:integration-tests:vfs:webdavTest` → 结束关服务、删临时根，不留监听进程和数据。

- **S4 修复**：venv 已存在且依赖未变时复用，不探测 PyPI；只在准备环境时联网。
- 换 Python：`WEBDAV_PYTHON=/path/to/python3 ./scripts/webdav-check`。
- 这批用例**不在** `./scripts/check` 里；没起服务直接失败，不接受「跳过 = 通过」。
