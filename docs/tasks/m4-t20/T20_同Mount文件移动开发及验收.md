## 1. 目标与范围

实现公开 `move(source, target)` 的**同一 Mount 普通文件原生移动 / 重命名**，返回新位置 NodeInfo，保留同一个 Node ID 与 Metadata。编排在 Core，复用 Router、OperationGuard、NodeRegistry、EventPipeline、Storage.move 与 Repository.updatePath；Runtime 已有 move 生命周期入口，不另建一套锁或资源跟踪。

本任务先执行 Guard 的 NATIVE_MOVE；COPY_FALLBACK_MOVE 与 CROSS_MOUNT_COPY_MOVE 暂时明确报 UNSUPPORTED_OPERATION，由 T21 一起承接复制、确认、删源流程。目录移动留 T22；这种分阶段拒绝不改写 T02 的最终能力，也不能把后端实际支持的能力伪报为不支持。

例：`/resources/docs/a.txt → /resources/docs/archive/b.txt` 在同一 Mount 内可移动；跨到另一个 Mount 或移动目录仍阶段拒绝。判断是否同 Mount 用路由中的挂载身份，不仅比较 storageKey。

## 2. 开发内容

### 2.1 参数、结构与物理事实预检

沿用 T10 检查顺序与 T02 错误规则，确认源的真实存在性和类型后再决定执行策略；不能只看逻辑 Node 或调用方声明。同路径 INVALID_ARGUMENT、源不存在 NOT_FOUND、已有普通目标 ALREADY_EXISTS、受保护配置目录按既有规则拒绝；目标目录不能被解释为“移入其中”。

例：把 a.txt 移到已有 b.txt 或已有普通目录时均拒绝，不覆盖、不创建父目录；配置根的结构保护优先沿用 Guard。跨 Mount / 目录 / 暂未实现策略也在注册源、建目录或物理移动前拒绝，避免阶段拒绝产生副作用。

### 2.2 身份与目标父目录

完成已知拒绝检查后，已登记源复用原 ID；未登记源按 UC-04 确认物理文件后建立一次身份，再迁移这条记录，不在目标重新生成 ID。自动补父目录沿用 T15：只在目标 Mount 内逐层创建，不批量登记父 Node、不单独发目录创建事件。

例：移动后 getNode(原ID) 指向 archive/b.txt，Metadata 原样保留；旧路径读取 / stat 报 NOT_FOUND，在旧路径另建文件获得新 ID。失败时源懒注册可能已留下记录，但不能产生 FILE_MOVED 或新目标身份；这是正常登记事实，交付中说明，不要求补偿删除登记。

### 2.3 串行边界、提交与事件

从预检、必要注册、补父目录、Storage.move 到状态提交使用同一 StateBoundary，沿用 T15 / T16 的已持锁组合入口，避免再调用自取锁方法。SQLite 事务只包含移动后的路径 / 存储映射更新和 FILE_MOVED 追加，不包住 Storage I/O；提交成功后才通知。

例：移动一份带标签的报告，原 ID、创建时间及 Metadata 保留，路径 / 映射和更新时间按现有模型更新。事件 nodeId 为原 ID、uri 为目标、sourceUri / targetUri 为本次源和目标；一次文件移动只产生一条 FILE_MOVED，不冒充删除加创建。

### 2.4 失败与取消

复用 T15 的已知副作用合并原则：补目录后失败不能报 NONE，后端 UNKNOWN 不能因上层只知道建过目录就被降级；物理 move 成功但状态 / 事件提交失败报 STATE_ERROR + PARTIAL，保留 cause，不回移文件、不发布成功通知。状态事务回滚仍应保留原逻辑映射，暴露可能的物理 / 逻辑不一致，不假装恢复完成。

例：物理文件已到目标，追加事件失败，目标保留、源已消失，库中旧映射仍在；调用失败且没有成功通知。CancellationException 按既有契约原样传播，不能据此声称无副作用；至少验证一个已进入移动流程的可控取消点，不扩展成全部提交窗口矩阵。

### 2.5 真实栈与阶段说明更新

用真实 Runtime + SQLite + 临时 Local FS 验证同 Mount 移动、Metadata / ID / 事件与正常重开，状态库保持在挂载根外；精确失败点用 Core 替身验证，明确两类证据。原生移动不需要把内容读入 ByteArray，不应意外套用 read 的 16 MiB 默认上限，可用一个大文件或“不调用 read/write”证据确认。

更新 T19 反例及使用说明中“所有 move 均不支持”的当前口径：同 Mount 文件已有正例，跨 Mount 或目录仍可作阶段拒绝反例。历史交付记录不抹除；路径别名 / 符号链接保障沿用 T12，不声称可防御外部进程任意并发改写。

## 4. 验收标准

| 编号 | 必须满足 | 核心证据 |
| --- | --- | --- |
| A01 原生移动 | 同 Mount 文件重命名 / 移到另一子目录成功，不覆盖目标；内容完整，返回新位置 | 公开 Runtime + 真盘 / 真库，旧路径消失、目标字节或摘要一致；确认走原生 move |
| A02 身份连续 | 已登记源保留 ID / Metadata；未登记源只建立一个身份；重开仍指向目标 | getNode / stat / Metadata 与真实记录核对；旧路径重建获得不同 ID，不用新目标身份掩盖迁移 |
| A03 预检与阶段边界 | 同路径、缺失源、目标已存在、配置目录保护与父路径为文件按契约拒绝；跨 Mount / 目录仍阶段拒绝 | 少量代表用例检查错误码、无物理副作用与无成功事件；能力策略可复用 T10，不复制完整矩阵 |
| A04 补父目录与事实保留 | 只补目标 Mount 内缺失父目录，不批量注册；目录创建失败或后续移动失败保留已知变化 | 成功真盘用例；替身控制“建过一层后失败”“补目录后 move 失败”，检查 effect 合并含 UNKNOWN 不降级 |
| A05 状态与事件 | 路径更新与 FILE_MOVED 同事务，提交后通知，移动事件四个身份 / 路径字段正确 | 真库事件字段与通知；事件追加或提交失败时旧逻辑映射回滚且无成功通知 |
| A06 失败报告 | 物理成功 / 状态失败为 STATE_ERROR + PARTIAL，原 cause 保留、不补偿 | 明确断言物理源 / 目标、逻辑映射、Metadata、事件和异常；故障可注入，不伪称真实磁盘故障 |
| A07 锁与取消 | 全链单次持锁，不自锁、不与其他状态变更交错；取消原样传播且释放边界 | 最小受控相遇与取消用例，确认已进入被测阶段；协程内捕获实际异常，后续操作可继续，清理门 finally 放行 |
| A08 工程与文档 | 617 例基线无回归，更新阶段性 move 断言；API / 模块边界不扩张 | 项目内完整检查、分模块 XML、公开 move 样例及证据分层；修改既有测试说明原因，不能删掉不利断言过关 |

同一用例可覆盖多个验收项，不按编号堆测试。已有 T10 / T12 / T18 证据可引用；本次新增的是移动编排的顺序、身份及失败事实，不将全部失败验证推迟到 T23，也不要求变异数量或十连跑。
