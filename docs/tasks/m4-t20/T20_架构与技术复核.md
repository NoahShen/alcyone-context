## 2. 必须修改

### R1 / P2：commitMove 不应为测试替身补一次注册

位置：`DefaultVfs.commitMove` 的 `findById(nodeId) ?: scope.nodes.register(...)`。注释直接说明此分支是为事务替身看不到自动提交记录而存在；VfsHarness 中 nodes / uow 是两份独立内存，生产代码因此承担了弥补测试模型差异的职责。

真实同库、同锁流程中，源身份在物理移动前已确认 / 登记；提交阶段发现它不见了应报告状态异常，而不是重建 registeredAt 等字段并继续成功。register 还是按路径复用接口，不能作为“必然拿回指定 ID”的替代，当前分支会掩盖接线错误或状态不一致；本轮不声称真实 Runtime 的正常路径已触发它。

**最小修复与验收：**去掉专供替身的生产兜底，缺失源记录明确失败，由现有外层报告 STATE_ERROR + PARTIAL，不补偿物理移动、不发成功事件。调整移动测试的状态接线，使自动提交登记和事务视图看到同一份状态（也可使用已有真库证据），保留未登记源仅注册一次及已登记源 ID / Metadata / registeredAt 不变的断言；无需新建通用仓库框架。补一个提交视图缺记录的受控反例，证明不会静默重建身份。

### R2 / P2：缺少普通文件跨 Mount 的编排拒绝用例

验收 A03 把“跨 Mount 阶段拒绝”归于 T10 Guard。实际 Guard 对正常跨 Mount 文件返回 CROSS_MOUNT_COPY_MOVE，而非拒绝；本轮真正的阶段拒绝发生在 DefaultVfs 的策略分支，必须验证该接线。

现有多个 Mount 的 Core 用例只覆盖受保护配置目录、跨 Mount 的目录源，以及同 Mount 复制回退；RuntimeMoveTest 也只有一个 Mount。它们都不能证明“普通文件 + 不受保护目标 + 两个 Mount”在源注册 / 建目录前拒绝。

**最小补证：**配置两个 Mount，源盘预置未登记普通文件，目标指向另一 Mount 的缺失父目录下；调用 move，断言 UNSUPPORTED_OPERATION + NONE、未登记源、未创建目标父目录、没有任何移动 / 写入 / 删除和成功事件，源内容保持。Core 替身即可，不要求跨后端或 T21 正例；更新验收表，将 Guard 策略证据与本轮编排拒绝证据分开。

### R3 / P2：A07 挂起并发测试没有断言失败时的放行清理

位置：`DefaultVfsMoveRealStackTest` 的两个 A07 用例及 PausingMoveStorage。并发用例在 releaseMove 前有多条断言，但没有 finally 放行；withStack 只关资源，不释放这个门。PausingMoveStorage 的 finally 仅减计数，只有收到取消的 catch 才 release，不能等同于任务要求的“清理门 finally 放行”。

最小修复是在掌握 pausing 和工作协程的测试作用域中，用 finally 放行并等待 / 取消未完成任务，再释放真实 DB / Storage；取消用例同样保持失败路径可清理。可临时让放行前的断言失败确认测试及时结束并恢复源码，不需强制变异数或压力跑；验收 A07 如实描述实际清理机制。

## 4. 建议优化

- **S1 缩小绝对化表述。** “拒绝全部发生在副作用之前”应限定为纯参数、已知结构 / 阶段等预检。源懒注册可以先于建目录阶段失败，逐层创建后也可能失败；这是既有允许边界，不能用一句“全部”抹掉。
