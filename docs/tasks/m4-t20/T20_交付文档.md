## 4. S1 盘点：执行顺序与复用清单

`moveInsideBoundary`（**整条链只取一次 `boundary.withLock`**，锁不可重入，内部一律用不加锁入口）顺序：

1. `OperationGuard.rejectMoveArgumentConflicts`（同路径 / 目标落进源子树 → `INVALID_ARGUMENT`，T02 §8.2「参数错误优先」）；
2. `requireMovableStructure(source/target)`（受保护配置目录 → `UNSUPPORTED_OPERATION`，先于路由与后端访问）；
3. `router.route(source/target)`（→ `MOUNT_NOT_FOUND`）+ `storageFor`；
4. `storage.stat(source)`（确认源真实存在与**实际类型**，→ `NOT_FOUND`）；
5. `OperationGuard.check(OperationIntent.move(source, target, actualType))` 拿策略；目录 / `COPY_FALLBACK_MOVE` / `CROSS_MOUNT_COPY_MOVE` → `UNSUPPORTED_OPERATION`（**在注册源、建目录、物理移动之前**）；
6. `confirmMoveTargetAbsent`（目标已存在 → `ALREADY_EXISTS`，不覆盖、不建父目录、不当作「放进去」）；
7. `ensureSourceIdentity`（已登记源复用原 ID；未登记源直接复用 `NodeRepository` 的注册语义建立一次身份，不调用 `NodeRegistry`）；
8. `createMissingParents`（复用 T15 私有实现，只在目标 Mount 内逐层补，不批量登记父 Node、不发目录事件）；
9. `storage.move`（同 Mount 原生 rename，**不 read / write 内容**）；
10. `pipeline.commitInsideBoundary { commitMove }`（同一事务：`updatePath` + 一条 `FILE_MOVED`；提交成功后才通知）。

**复用清单**：`MountRouter` / `CapabilitySnapshot` / `OperationGuard` / `NodeRegistry`（懒注册语义）/ `NodeRepository.updatePath` /
`EventFactory.newMove` / `EventPipeline.commitInsideBoundary` / `Storage.move` / `Storage.stat` / T15 的 `createMissingParents` 与 `withKnownChanges`。

## 5. 策略判定怎么走

- **同 Mount 判据**用**路由中的挂载身份**：`OperationGuard.moveStrategy` 比 `source.route.mount == target.route.mount`（`MountRecord` 结构相等，含 `storageKey + backendType + physicalRoot`），不只比 `storageKey`。
- 同 Mount + 源实际类型是**文件** + 能力 `nativeFileMove == true` → `NATIVE_MOVE`（本任务唯一执行分支）。
- 同 Mount + 文件 + `nativeFileMove == false` → `COPY_FALLBACK_MOVE` → **阶段拒绝**。
- 跨挂载（即便两端 `storageKey` 相同）→ `CROSS_MOUNT_COPY_MOVE` → **阶段拒绝**。
- 源实际类型是**目录**，无论策略一律 **阶段拒绝**（T22）。
- 判定用的是 `storage.stat` 得到的**真实类型**，不是调用方声明；`OperationIntent.move` 只装路径与真实类型。

## 6. 失败注入点

| 目标失败 | 注入方式（均为测试包装，非 OS 自发故障） | 断言 |
| --- | --- | --- |
| 补父目录建到一半 | `StorageFakeImpl.failures.onCreateDirectoryAt`；真栈 `FailingDirectoryStorage(failAt=2)` | 原错误码 + `PARTIAL`，已建目录留着；真栈第一层目录真的在盘上 |
| 补完父目录后物理移动失败 | `StorageFakeImpl.failures.onMove`（`NONE`） | 合并已建目录 → `PARTIAL`，源不动 |
| 后端移动结果不明 | `failures.onMove`（`UNKNOWN`） | `UNKNOWN` 保真，不降级 |
| 物理成功但状态 / 事件提交失败 | `FakeStateUnitOfWork.failOnEventAppend`；真栈 `MoveCollidingEventUnitOfWork`（真主键冲突） | `STATE_ERROR` + `PARTIAL`，保留 cause，目标留、旧逻辑映射回滚；真栈另直接订阅确认无成功通知 |
| 提交视图缺源记录 | 真栈 `HidingNodeUnitOfWork` 把源 ID 从 `findById` 藏起来（R1） | `STATE_ERROR` + `PARTIAL`，源记录 ID / `registeredAt` 不变、目标无新记录，不静默重建身份 |
| 普通文件跨 Mount | 两个 Mount + 未登记源 + 目标缺失父目录（R2） | `UNSUPPORTED_OPERATION` + `NONE`，源未登记、父目录未创建、无 move/write/delete 与事件 |
| 受保护目录 / 目录 / 复制回退 | 配置目录路径 / 目录源 / `StorageCapabilities(nativeFileMove=false)` | `UNSUPPORTED_OPERATION` + `NONE`，零副作用 |
| 取消 | `PausingMoveStorage` 在 `Storage.move` 真正 rename 前挂住；取消调用方 Job | `CancellationException` 原样传播、放锁、不提交、不发事件；测试 `finally` 先放门再 `cancelAndJoin` |

## 7. 未验证边界（如实列出）

- **只验证了同 Mount 普通文件**；跨 Mount、目录移动、复制回退是**阶段拒绝**（正例留 T21 / T22），未在本轮实现。
- **原生移动不读内容进 ByteArray** 用两条证据：调用序列断言不含 `read:` / `write:`（替身）；20 MiB（> read 的 16 MiB 上限）文件移动后逐字节一致、且对同一文件 `read` 仍报 `LIMIT_EXCEEDED`（公开入口）。这是「行为上不经过 read」的证据，不是对后端实现源码的证明。
- **取消**只覆盖「已进入移动流程、物理移动前」这一个可控取消点；不扩展为全部提交窗口矩阵（T23）。
- **失败注入**是端口 / 事务包装，不是真实磁盘故障：真文件系统不会自己停在「建了一半」或「丢回包」；断言对着真盘与真库，但「所有后端故障形态」未穷举。
- **重开**只覆盖正常 `close → create`；崩溃恢复（WAL 残留、半提交）不在本轮。
- **不防御外部进程任意并发改写**；路径别名 / 符号链接沿用 T12 口径。
- **未在小写 / 大小写不敏感文件系统**上单独验证大小写语义（沿用 T12 / T16 结论）。
- **预检拒绝**（纯参数、已知结构 / 阶段）在注册源、建目录、物理移动之前；**懒注册**与**补父目录**是真实副作用，它们之后的失败按 T15 的 effect 合并如实上报，不声称「全部零副作用」。
- `ensureSourceIdentity` 的**懒注册**是自动提交写入：物理移动前失败会留下一条源登记记录（正常登记事实，不补偿删除）。测试夹具用 `shareNodeState` 让自动提交与事务视图共享同一份状态；生产代码在提交视图缺源记录时明确报 `STATE_ERROR`，不重建身份（R1）。
- **失败不通知**：真栈 A06 已直接订阅核对（事件日志回滚 + 无成功通知）。替身用例只断事件日志未追加，提交后通知由 T14 机制与本次接线审查支持。
