## 1. 三十秒上手

```kotlin
val vfs = AlcyoneVfs.create(
    VfsRuntimeConfig(
        stateDatabase = Path.of("data/state.db"),          // 状态库在挂载物理根之外
        namespaces = setOf("resources"),
        mounts = listOf(MountConfig(VfsPath.parse("/resources/docs"), "docs", Path.of("/data/docs"))),
    ),
)
try {
    val info = vfs.write(VfsUri.parse("alcyone://resources/docs/note.txt"), "hello".toByteArray())
    vfs.setMetadata(info.id, NodeMetadata(setOf("ct"), "胸部 CT 报告"))

    // 同一 Mount 内重命名 + 移到子目录（缺失的 archive 自动补出来）
    val moved = vfs.move(
        VfsUri.parse("alcyone://resources/docs/note.txt"),
        VfsUri.parse("alcyone://resources/docs/archive/note.txt"),
    )

    moved.id == info.id                                   // true：同一个 Node ID
    vfs.getMetadata(moved.id)                             // NodeMetadata(tags=[ct], description=胸部 CT 报告)
    vfs.read(VfsUri.parse("alcyone://resources/docs/archive/note.txt"))  // hello
} finally {
    vfs.close()
}
```

## 2. 语义要点

- **保留身份**：移动后的 `NodeInfo.id` 与移动前相同；`registeredAt` 不变，只推进 `updatedAt`。
- **Metadata 跟随 ID**：移动不改 Metadata，`getMetadata(id)` 拿到的是同一个对象。
- **不覆盖目标**：目标已存在（普通文件或普通目录都算）→ `ALREADY_EXISTS`；**不把目标目录当成「放进去的容器」**。
- **自动补父目录**：只在目标所属 Mount 内逐层创建；父目录**不登记 Node**、不发单独的目录创建事件（沿用 T15）。
- **一条事件**：一次文件移动只追加一条 `FILE_MOVED`，不冒充「删除 + 创建」。事件字段：`uri` = 目标位置，`sourceUri` / `targetUri` = 本次源与目标，`nodeId` = 原 ID。
- **未登记源**：磁盘上已有、状态库里没有的文件也能移动；移动时建立**一次**身份，目标位置不重新生成 ID。
- **旧路径失效**：移动后旧路径 `read` / `stat` 报 `NOT_FOUND`；在旧路径另建文件会得到**新的** Node ID。
- **原生移动不读内容进内存**：不受 `read` 的 16 MiB 上限影响，大文件照常移动。

## 3. 错误码速查

| 场景 | 错误码 | effect |
| --- | --- | --- |
| 源和目标同路径，或目标落进源子树 | `INVALID_ARGUMENT` | `NONE` |
| 源不存在 | `NOT_FOUND` | `NONE` |
| 目标已存在（文件 / 目录） | `ALREADY_EXISTS` | `NONE` |
| 源或目标是受保护配置目录（逻辑根 / 命名空间根 / 挂载根 / 承载子挂载的祖先） | `UNSUPPORTED_OPERATION` | `NONE` |
| 源的实际类型是**目录**（T22 接续） | `UNSUPPORTED_OPERATION` | `NONE` |
| 同一 Mount 但后端不支持原生 move（复制回退属 T21） | `UNSUPPORTED_OPERATION` | `NONE` |
| 跨 Mount（属 T21） | `UNSUPPORTED_OPERATION` | `NONE` |
| 目标父路径是文件 | `TYPE_MISMATCH` | 视已建目录，`NONE` 或 `PARTIAL` |
| 补目录后物理移动失败 | 后端原错误码 | 至少 `PARTIAL`；后端 `UNKNOWN` 保持 `UNKNOWN` |
| 物理移动成功但状态 / 事件提交失败 | `STATE_ERROR` | `PARTIAL`（目标保留、不回移、无成功通知） |
| 只读后端 | `READ_ONLY` | `NONE` |
| 协程取消 | `CancellationException`（原样传播） | 不承诺回滚 |

**预检拒绝（纯参数、已知结构 / 阶段）在注册源、建目录、物理移动之前发生**，因此这些错误的 effect 都是 `NONE`，调用方可以放心重试或改用别的路径。
源懒注册与补父目录是真实副作用，它们之后的失败按 T15 的 effect 合并如实上报（可能 `PARTIAL` 或保留后端 `UNKNOWN`），不声称「一律零副作用」。

## 4. 阶段边界（本任务只交付哪一块）

| 能力 | 状态 |
| --- | --- |
| 同一 Mount 普通文件原生移动 / 重命名 | **T20 已交付** |
| 同一 Mount 非原生复制回退 | T21（当前 `UNSUPPORTED_OPERATION`） |
| 跨 Mount 文件移动 | T21（当前 `UNSUPPORTED_OPERATION`） |
| 目录移动（同 Mount / 跨 Mount） | T22（当前 `UNSUPPORTED_OPERATION`） |

这种分阶段拒绝**不改写** T02 的最终能力，也不把后端实际支持的能力伪报为不支持：`LocalFs` 原生支持文件 move，
所以同 Mount 文件走的就是原生 `NATIVE_MOVE`；只有后端确实不支持或跨 Mount 时才拒绝。

## 5. 怎么自己跑一遍回归

```bash
# 只跑本次两个模块（快速）
./scripts/dev gradle :vfs:core:test :integration-tests:vfs:test --rerun-tasks --console=plain

# 只跑 T20 的四个类
./scripts/dev gradle :vfs:core:test \
  --tests "*DefaultVfsMoveTest*" \
  --tests "*DefaultVfsStageBoundaryTest*" --console=plain
./scripts/dev gradle :integration-tests:vfs:test \
  --tests "*RuntimeMoveTest*" \
  --tests "*DefaultVfsMoveRealStackTest*" \
  --tests "*RuntimeLazyRegistrationAndFailureTest*" --console=plain

# 全量检查（编译 + 全模块单测 + 格式）
./scripts/check
```

测试读写只在 `@TempDir` 临时工作目录，状态库在挂载物理根之外；不需要清系统环境。
