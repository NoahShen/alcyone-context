## 3. 工具链与 native 选择一致性（S2，A02）

### 3.1 识别逻辑核对
- `scripts/dev`：
  - `Darwin/arm64` -> `mac` / `arm64`
  - `Linux/x86_64` | `Linux/amd64` -> `linux` / `x64`
  - `Linux/aarch64` | `Linux/arm64` -> `linux` / `arm64`
  - 其他 -> 退出码 1，报错 `Unsupported platform: $PLATFORM. Verified targets: macOS arm64, Linux x64, Linux arm64.`
- `gradle/toolchain.versions`：精确包含上述三种组合的 JDK 下载 URL 与 SHA-256。
- `vfs/storage/build.gradle.kts` 历史逻辑：
  ```kotlin
  // 历史有缺陷的逻辑：
  fun opendalNativeClassifier(): String {
      val onMac = System.getProperty("os.name").startsWith("Mac")
      val onArm = System.getProperty("os.arch") in setOf("aarch64", "arm64")
      return when {
          onMac && onArm -> "osx-aarch_64"
          onMac -> "osx-x86_64"
          onArm -> "linux-aarch_64"
          else -> "linux-x86_64" // 缺陷：Windows/amd64 或 FreeBSD 会静默落入 linux-x86_64
      }
  }
  ```

### 3.2 最小修复实施
修复 `vfs/storage/build.gradle.kts` 中的 `opendalNativeClassifier`，明确白名单判定：
```kotlin
fun opendalNativeClassifier(
    osName: String = System.getProperty("os.name"),
    osArch: String = System.getProperty("os.arch"),
): String {
    val isMac = osName.startsWith("Mac")
    val isLinux = osName.startsWith("Linux")
    val isArm = osArch in setOf("aarch64", "arm64")
    val isX64 = osArch in setOf("x86_64", "amd64")
    return when {
        isMac && isArm -> "osx-aarch_64"
        isMac && isX64 -> "osx-x86_64"
        isLinux && isArm -> "linux-aarch_64"
        isLinux && isX64 -> "linux-x86_64"
        else -> error("Unsupported OS/CPU for OpenDAL native: os.name='$osName', os.arch='$osArch'")
    }
}
```

### 3.3 分支选择测试
新增 `vfs/storage/src/test/kotlin/.../opendal/OpendalClassifierSelectionTest.kt`（2 例）：
- `supported platforms map to the exact opendal classifiers`：覆盖 7 种支持组合（Mac arm64/x64、Linux arm64/x64/amd64）。
- `unsupported OS or CPU architecture fails explicitly without silent fallback`：覆盖 Windows 11/10、SunOS、FreeBSD、Linux mips64/riscv64、Mac riscv64，验证全部显式抛出 IllegalStateException，绝不静默兜底。

## 5. 最小诊断上下文核查（A04）

### 5.1 六类诊断入口整理表

| 失败类别 | 诊断入口类型 | 记录/抛出位置 | 上下文辨识能力（操作/后端/Mount/资源） | 保留字段 (code / effect / cause) |
| --- | --- | --- | --- | --- |
| **初始化 / 配置失败** | 异常 (`VfsException`) | `VfsRuntimeConfig.resolve()` / `MountReconciler` / `StateInstanceLock` | 明确标出非法配置字段、重叠的 Mount 路径或已被占用的 SQLite 路径 | `INVALID_ARGUMENT` / `CONFLICT`，cause 保留底层异常（如 IOE） |
| **Storage 失败** | 异常 (`VfsException`) | `StorageErrors.mapStorageErrors` / `LocalFsStorage` / `WebDavStorage` | 消息格式为 `"$backend $operation failed ($code)"`（如 `webdav storage read failed (STORAGE_ACCESS_DENIED)`） | code 精确映射，保留操作上下文与 `effect`（`NONE`/`PARTIAL`/`UNKNOWN`），底层 OpenDALException 挂在 `cause` |
| **状态提交失败** | 异常 (`VfsException`) | `StateCall.kt` / `UnitOfWork` / `DefaultVfs` | 明确标识状态库操作失败及受影响的 Node / 路径 | `STATE_ERROR`，保留 `effect`（例如变更后提交失败带 `PARTIAL`），cause 保留 SQLDelight / SQLite 异常 |
| **Consumer 失败** | 日志 (`logger.warn`) | `EventDispatcher.dispatch` | 日志打印 `"Event consumer failed for event {}"`，含唯一事件 ID | 异常不向外冒泡，完整 Consumer 堆栈通过 SLF4J 记录 |
| **队列丢弃** | 日志 (`logger.warn` / `logger.debug`) | `AsyncEventNotifier.publish` | 队列满打印容量与首次丢弃的事件 ID，关闭打印未投递数；不刷屏 | 通过事件 ID 与已提交的持久 `event` 表对应 |
| **关闭失败** | 异常 (`VfsException`) | `AlcyoneVfs.releaseEverything` | 包含流释放失败或状态释放失败的详细链条 | 抛出 `STATE_ERROR`（`"VFS instance could not be closed cleanly"`），首个失败为 cause，其余失败挂 `addSuppressed` |

### 5.2 真实 SLF4J 日志捕获正向测试
- 测试位置：`vfs/core/src/test/kotlin/.../event/EventDispatcherLogCaptureTest.kt`
- 机制：在测试内通过 SLF4J 2.0 服务绑定机制注入记录型 Logger，调用 `dispatcher.dispatch` 注入失败 Consumer。
- 验证判据：日志记录包含事件 ID（如 `018f...`）、警告级别 `WARN` 以及 Consumer 原始异常上下文。
