## 3. 工具链与 native 选择一致性（S2，A02）

### 3.1 识别逻辑核对
- `scripts/dev`：
  - `Darwin/arm64` -> `mac` / `arm64`
  - `Linux/x86_64` | `Linux/amd64` -> `linux` / `x64`
  - `Linux/aarch64` | `Linux/arm64` -> `linux` / `arm64`
  - 其他（包含 `Darwin/x86_64` macOS Intel、Windows 等） -> 退出码 1，报错 `Unsupported platform: $PLATFORM. Verified targets: macOS arm64, Linux x64, Linux arm64.`
- `gradle/toolchain.versions`：精确包含上述三种组合的 JDK 下载 URL 与 SHA-256。
- `vfs/storage/build.gradle.kts` 严格对齐（R1）：
  ```kotlin
  fun opendalNativeClassifier(
      osName: String = System.getProperty("os.name"),
      osArch: String = System.getProperty("os.arch"),
  ): String {
      val isMac = osName.startsWith("Mac")
      val isLinux = osName.startsWith("Linux")
      val isArm = osArch in setOf("aarch64", "arm64")
      val isX64 = osArch in setOf("x86_64", "amd64")
      return when {
          isMac && isArm -> "osx-aarch_64"
          isLinux && isArm -> "linux-aarch_64"
          isLinux && isX64 -> "linux-x86_64"
          else -> error("Unsupported OS/CPU for OpenDAL native: os.name='$osName', os.arch='$osArch'")
      }
  }
  ```
  macOS x64 不再返回 `osx-x86_64`，而是与 scripts/dev 保持完全一致明确抛错拒绝。

## 5. 最小诊断上下文核查（A04）

### 5.1 六类诊断入口整理表（如实分层，S2）

| 失败类别 | 诊断入口类型 | 记录/抛出位置 | 上下文辨识能力（操作/后端/Mount/资源） | 保留字段 (code / effect / cause) |
| --- | --- | --- | --- | --- |
| **初始化 / 配置失败** | 异常 (`VfsException`) | `VfsRuntimeConfig.resolve()` / `MountReconciler` / `StateInstanceLock` | 明确标出非法配置字段、重叠的 Mount 路径或已被占用的 SQLite 路径 | `INVALID_ARGUMENT` / `CONFLICT`，cause 保留底层异常（如 IOE） |
| **Storage 失败** | 异常 (`VfsException`) | `StorageErrors.mapStorageErrors` / `LocalFsStorage` / `WebDavStorage` | 消息格式为 `"$backend $operation failed ($code)"`（如 `webdav storage read failed (STORAGE_ACCESS_DENIED)`） | code 精确映射，保留操作上下文与 `effect`（`NONE`/`PARTIAL`/`UNKNOWN`），底层 OpenDALException 挂在 `cause` |
| **状态提交失败** | 异常 (`VfsException`) | `StateCall.kt` / `UnitOfWork` / `DefaultVfs` | 通用 StateCall 仅携带 operation failed 描述及底层 cause；外层 Core 写/移动操作包装时才补充逻辑 URI | `STATE_ERROR`，保留 `effect`（例如变更后提交失败带 `PARTIAL`），cause 保留底层 SQLDelight / SQLite 异常 |
| **Consumer 失败** | 日志 (`logger.warn`) | `EventDispatcher.dispatch` | 日志打印 `"Event consumer failed for event {}"`，含唯一事件 ID | 异常不向外冒泡，WARN 级别及完整 Consumer 堆栈通过 SLF4J 记录 |
| **队列丢弃** | 日志 (`logger.warn` / `logger.debug`) | `AsyncEventNotifier.publish` | 队列满打印容量与首次丢弃的事件 ID，关闭打印未投递数；不刷屏 | 通过事件 ID 与已提交的持久 `event` 表对应 |
| **关闭失败** | 异常 (`VfsException`) | `AlcyoneVfs.releaseEverything` | 包含流释放失败或状态释放失败的详细链条 | 抛出 `STATE_ERROR`（`"VFS instance could not be closed cleanly"`），首个失败为 cause，其余失败挂 `addSuppressed` |
