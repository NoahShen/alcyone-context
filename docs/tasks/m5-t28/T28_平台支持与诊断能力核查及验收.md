## 1. 目标与范围

当前验收范围以 2026-10-13 用户决定为准：仅 macOS arm64 承诺已验证支持；下文原 Linux 实跑安排保留作后续工作，不再是本阶段必过项。Linux 配置不删除，状态仍是未验证。

明确当前版本在哪些 OS / CPU 上实际跑通、在哪些平台只配置了依赖；同时核查错误和日志是否能帮助定位问题、是否泄露 VFS 管理的凭据。优先复用既有脚本、CI 与测试，发现缺口再最小修复，不新建诊断框架、不扩展公共 API。

例：Linux arm64 配有 JDK URL 和 native classifier，只说明有配置；必须实际执行加载和文件操作，才能写“已实测”。Consumer 日志包含事件 ID 可用于关联持久事件，不要求再生成另一套全局追踪 ID。

方案④保持：不承诺 WebDAV native 请求或 close 的最长等待时间，CI / 测试超时仅防止验证任务无限占用资源。崩溃恢复、可靠消费、性能基准、Windows / macOS Intel 新增支持均不在本轮范围。

## 2. 开发与核查内容

### 2.1 建立当前版本平台矩阵

区分工具链配置、native 依赖解析、真实运行、常规回归、真实 WebDAV 五类证据，逐项记录提交 SHA、OS / CPU、JDK / Gradle / OpenDAL 版本和结果。历史 T08 Linux x64 CI 可作为历史证据，不能代替当前 Adapter / Runtime 的平台实跑；Linux 记录发行环境，不把某个 Ubuntu 结果推广到所有 libc / 发行版。

| 平台 | 当前仓库线索 | 本轮安排 |
| --- | --- | --- |
| macOS arm64 | 持续本地两套实跑，T27 748 / 42 | 当前交付版本跑两套检查，保留真实 native 与 WebDAV 证据 |
| Linux x64 | 已有 ubuntu-latest 工作流；T08 历史 CI | 用现有 CI 或真实等价环境跑当前版本常规检查与真实 WebDAV；必要时最小补充工作流步骤及报告上传 |
| Linux arm64 | scripts/dev 与 JDK 清单已配置，T08 仅静态验证 | 有可用真实 ARM 环境则执行同样检查；不可用列明未验证与缺少的条件，不伪造通过 |
| macOS x64 / Windows / 其他 | scripts/dev 明确拒绝 | 保持不支持，检查选择逻辑不静默落到 Linux x64；不新增下载配置 |

应推进三种已配置目标的实际验证；机器、网络或远端执行条件不足时，先完成其他独立工作并交付明确缺口。未验证平台不得宣称受支持或将 A03 / M5 自动标通过；若要缩小首版支持范围，单列决定交用户确认，不由开发方自行降级。

### 2.2 工具链与 native 选择一致

核对 scripts/dev、JDK 清单和 OpenDAL classifier 对平台的识别结果，特别注意 Gradle 选择逻辑当前把“非 Mac”落入 Linux 分支，不能仅靠常用脚本拒绝就声称所有入口都识别正确。若存在未知 OS / CPU 被静默映射的路径，做明确拒绝的最小修复；不扩展支持范围，不升级依赖来替代定位。

例：当前 `os.arch=aarch64` 的 Linux 应选择 linux-aarch_64；未知架构应报清楚错误，不能默认下载 x64 库。模拟属性只能验证选择分支，不能冒充真实目标机加载成功。

### 2.3 真实加载与闭环证据

复用真实 Local FS / SQLite / Runtime 用例证明 native 能执行操作，不以 Gradle 成功解析依赖或构造配置代替加载成功。每个已实测目标用真实 WebDAV 脚本验证网络后端，记录服务版本、命令与退出码；无需重建 T24～T27 的业务矩阵。

例：实际写读文件、打开流并关闭、关库重开可由已有测试组合证明；WebDAV 服务没起来应记失败或阻塞，不能用跳过用例凑全绿。日志与 XML 分开保存，后续 clean 不应删除先前证据。

### 2.4 最小诊断上下文

整理初始化 / 配置失败、Storage 失败、状态提交失败、Consumer 失败、队列丢弃和关闭失败的诊断入口，标明来自异常还是日志。操作失败至少能从同一诊断记录或关联记录辨认操作与相关后端 / Mount / 资源之一，并保留 code / effect / cause；事件通知失败可用事件 ID 关联，不要求每条日志都带全部字段。

例：读 WebDAV 失败能看出 read、WebDAV 和领域错误；Consumer 失败日志带事件 ID；状态提交失败保留 STATE_ERROR、实际 effect 与原因。只补缺失上下文，不给每个成功操作加日志、不同时在每层重复打印同一异常；取消继续原样传播。

### 2.5 凭据与错误链

复用 T24 / T25 的配置直接 / 嵌套打印、非法 endpoint 与真实认证失败反例，检查 VFS 管理的 username / password、URL userinfo 和认证信息不进入配置输出、身份串、持久表或诊断输出。用专用测试标记凭据核对完整异常文本（含 cause / suppressed / 堆栈）及实际捕获日志；只检查顶层 message 或无日志绑定导致的空输出不能证明安全。

例：测试密码为唯一标记，认证失败后格式化异常并捕获一次对应诊断，确认标记未出现且错误码仍正确。需要测试日志绑定时只放测试依赖，生产仍只依赖 SLF4J API；宿主自己写入的任意 Consumer 异常内容不自动成为 VFS 全局脱敏承诺，证据要说明来源范围。

### 2.6 排障说明与证据归档

使用说明给出工具链未准备、平台不支持、native 加载失败、WebDAV 认证 / 连接失败、状态库占用及通知丢弃的简短排查步骤，区分配置问题、后端问题与已知等待限制。附真实执行证据入口和未验证平台，不将脚本的“Verified targets”文字当作实跑依据，也不抹除旧文档的历史结论。

例：native 加载失败先对照实际 OS / CPU、JDK 架构与 classifier，再查原始加载错误；不要建议切换系统默认 JDK 或跳过校验。上传报告限定测试日志 / XML，不归档凭据、真实用户数据或整个项目本地工具目录。

## 4. 验收标准

| 编号 | 必须满足 | 证据要求 |
| --- | --- | --- |
| A01 平台矩阵 | 三种已配置目标与不支持平台分列，历史 / 当前 / 未测明确 | OS / CPU / 版本 / 提交 / 命令 / 结果 / 证据位置完整，不能用历史 T08 推定当前通过 |
| A02 选择一致 | 工具链与 native 架构匹配，未知 OS / CPU 不静默兜底 | 当前真实环境解析结果 + 必要分支反例；模拟只验证映射，不算目标机实跑 |
| A03 目标实跑 | 按用户批准方案二验证 macOS arm64；Linux x64 / arm64 保留配置、未验证，后续按需验证 | macOS 两套检查日志 / XML；范围调整已获用户确认，不将 Linux 标为实测通过 |
| A04 诊断定位 | 失败可辨认操作与相关上下文，事件失败可按 ID 关联；code / effect / cause 不丢 | 诊断索引 + 一条实际日志捕获的正向代表，其他异常 / 日志可复用；无需公共 trace API |
| A05 不泄露凭据 | VFS 配置、身份与自身失败输出不回显所管理的凭据 | 独特测试标记、直接 / 嵌套配置、完整异常链及真实日志；无日志绑定的空结果不能算通过 |
| A06 模块与语义 | 不绑定宿主日志实现，不包装取消，不改变错误与生命周期契约 | 生产依赖 / 代码 diff 审查，针对修复验证；方案④保持，不以测试超时声称请求超时已解决 |
| A07 可复现诊断 | 使用说明能按平台与失败类别排查，CI 日志 / XML 可定位 | 实际命令、提交 SHA / Run ID 或等价执行记录；失败时保留报告、服务与临时资源有清理 |
| A08 回归与交付 | 测试计数与文档一致，未测 / 受阻如实，M5 不自动收口 | 两套命令分别统计源码 @Test / XML / 失败 / 错误 / 跳过；差额解释，独立复核后决定 DONE / M5 状态 |

不限定新增测试数或变异次数，不以建设通用日志过滤器、遥测平台或新 CI 框架作为验收目标。平台分支、日志捕获与真实运行各证明各自范围，不互相替代。
