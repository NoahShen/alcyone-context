## 3. 实现要点

### 3.1 A 阶段（结构与参数）

- **检查顺序**（T02 §8.2）：纯参数与路径冲突 → 结构保护 → 路由判定。结构与路由是两个独立循环，源与目标各自执行，不交叉。
- **结构保护只用一次 `MountRouter.isConfiguredDirectory`**：T09 已把挂载点自身与全部祖先放进 `configuredDirectories`，因此逻辑根、命名空间根、挂载根、配置推导目录、含后代挂载的目录都落在同一查询上；`isMountPoint` / `hasDescendantMounts` 是它的子集，无双重拒绝也无漏拒绝。**未修改 MountRouter。**
- **每种操作需要路由的路径**：write → target，move → source + target，delete → source；已过结构层的路径必然不是配置目录，`route() == null` 即 `MOUNT_NOT_FOUND`，配置目录不会走到这一层。
- 参数冲突：规范化后源 = 目标、目标段列表以源段列表为前缀且更长 → `INVALID_ARGUMENT`（早于结构检查）。
- 错误信息只含逻辑路径与操作名 / 角色（source、target），不含物理路径或 `storageKey`；`effect` 用默认 `NONE`。

### 3.2 B 阶段（只读、能力与策略）

- **只读**（位于路由之后、能力组合之前）：write 看目标侧、delete 看源侧、move 任一侧只读即 `READ_ONLY`。
- **能力快照不完整 → `INVALID_ARGUMENT`**（本阶段确定的决策，已独立验收确认）：路由命中的 `storageKey` 在快照中查不到时预检无法判定只读与能力组合，抛 `INVALID_ARGUMENT` 并在消息中说明缺哪一侧的存储；不静默假设能力齐全，避免不受支持的变更漏到执行期。决策同时写入 `check` 的 Kdoc、`Side` 的 Kdoc 与 [使用说明](T10_使用说明.md) 第 7 节。
- **能力组合**（`UNSUPPORTED_OPERATION`）：同挂载点 move 按 `entryType` 选 `nativeDirectoryMove` / `nativeFileMove`，原生 → `NATIVE_MOVE`，缺失 → 复制回退（目录回退要求目标 `createDirectory`，文件回退无要求）；跨挂载点一律 `CROSS_MOUNT_COPY_MOVE`，目录要求目标 `createDirectory`，文件无额外要求。**不因两侧 `storageKey` 相同改用原生 move**——该取舍在 Kdoc 与使用说明中注明「等 T12 / T18 掌握真实物理映射后重估」。
- write / delete 除只读外无组合能力要求，输出 `DIRECT_WRITE` / `DIRECT_DELETE`。
- 顺序校验：只读先于能力组合（源只读 + 目标缺 `createDirectory` → `READ_ONLY`）。

## 8. 证据边界与未验证事项

- **纯逻辑验证不涵盖真实后端**：A04 / A05 用的是假能力数据。真实 Local FS / WebDAV 的 `readOnly` 探测、OpenDAL 原生能力的实际取值与错误转换属 T12；集成验证属 T19 / 纵向集成。
- **`readOnly` 只反映打开后端时已知的信息**：运行中权限变化、盘满、后端中途拒绝，按执行期错误处理，预检不负责。
- **跨挂载点一律复制的取舍未在真实后端验证**：`storageKey` 相同不代表物理根重叠或 rename 一定失败；本轮保守按复制语义执行，真实行为与是否可放宽由 T12（后端能力与错误转换）、T18（配置组装与物理映射）重估。
- **物理边界未检查**：逻辑路径无法经路由逃出挂载相对路径，不代表已抵御符号链接或外部并发替换（T12）。
- **存在性 / 类型 / 覆盖冲突不在预检范围**：`NOT_FOUND` / `ALREADY_EXISTS` / `TYPE_MISMATCH` 由执行期判定（T02 §9.1）。
