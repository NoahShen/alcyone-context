## 1. 目标与依据

在 `vfs/core` 实现变更操作（write / move / delete）的预检组件：结合 T09 的 MountRouter 路由视图与各存储的能力快照，在任何存储副作用之前拒绝已知无效或不受支持的变更，并为允许的操作给出执行策略。本任务是纯逻辑实现，用假能力数据做真实单元测试；不执行 I/O、不产生事件、不读写 Node。

依据：[T02 路径与文件操作语义](../../vfs/VFS_路径与文件操作语义_v0.1.md) 第 6～9 节（写入与覆盖、移动、删除与配置边界、能力与错误），T07 交付的 `Storage` / `StorageCapabilities`，T09 交付的 `MountRouter`。预检只拒绝"已知"问题；存在性、类型冲突等执行期事实（NOT_FOUND / ALREADY_EXISTS / TYPE_MISMATCH）不在本任务判定。

例：挂载 `/notes/team/docs` 时，`delete /notes/team`（recursive=true）在触碰任何存储之前即被拒绝。

## 2. 开发内容

### 2.1 变更操作预检入口

提供面向编排层的预检入口：输入操作意图（操作类型、write 模式或 delete 的 recursive、源与目标 `VfsPath`）、一个 `MountRouter` 视图和 `storageKey → StorageCapabilities` 的能力快照，输出允许（含执行策略，见 2.5）或拒绝（抛既有错误码的 `VfsException`）。类名与结果形状由开发 Agent 按现有类型简洁实现；能力快照构建后不可变，外部修改入参不影响已构建视图（同 T09）。

检查顺序固定：先纯参数与路径冲突（INVALID_URI / INVALID_ARGUMENT），再结构保护（2.2），再路由判定（2.3），最后只读与能力（2.4）——对应 T02 §8.2“先拒绝参数错误和已知配置结构冲突，再检查路由 / 存储状态”。

例：同一路径既无挂载又是受保护目录时，先报结构冲突；预检全程不调用 Storage。

### 2.2 结构性变更保护

按 T02 §8.2 拒绝对逻辑根 `/`、命名空间根、Mount 根及配置推导目录的 write / move / delete（UNSUPPORTED_OPERATION）；包含后代挂载的目录整体移动 / 删除拒绝（recursive=true 也不放宽）；move 目标路径会包含已配置挂载时拒绝。结构信息一律复用 T09 的 `isMountPoint` / `hasDescendantMounts` / `isConfiguredDirectory`，不重复推导。

例：挂载 `/notes/team/docs` 时，删除 `/notes/team` 拒绝、删除 `/notes/team/docs/a.txt` 通过结构检查进入后续判定。

### 2.3 参数冲突与路由判定

规范化后源与目标相同的 move、目标位于源路径子树内的 move 返回 INVALID_ARGUMENT；write / move 的目标或 delete 的源路由不到挂载且不是配置推导目录时返回 MOUNT_NOT_FOUND。路由结果（源 / 目标各自命中的挂载与相对 StoragePath）随允许结果一并输出；同挂载点与跨挂载点的区分以路由结果为准。

例：`move /notes/a → /notes/a/b` 拒绝；`write /other/x`（other 未配置命名空间）返回 MOUNT_NOT_FOUND。

### 2.4 只读与能力检查

`StorageCapabilities` 增补 `readOnly: Boolean = false`（T07 类型兼容性补充，理由：只读在打开后端时即可得知——只读挂载的本地目录、服务器声明的 WebDAV——预检据此在副作用前拒绝，正是本任务目标；默认值不改变既有实现与测试）。操作涉及的任一存储实例只读时，write / move / delete 返回 READ_ONLY。

能力检查按操作组合：同挂载点 move 优先原生（`nativeFileMove` / `nativeDirectoryMove`）；缺失原生能力时按复制回退检查——目录复制回退需要 `createDirectory`，缺失返回 UNSUPPORTED_OPERATION。跨挂载点 move 一律按复制语义（read → write → 确认 → delete）检查所需能力，**不因 storageKey 相同推断可用原生 move**；该取舍可在 T12 / T18 掌握真实物理映射后重估。

例：`nativeDirectoryMove=false` 且 `createDirectory=false` 时目录 move 返回 UNSUPPORTED_OPERATION；两个挂载点共享同一 storageKey，move 仍按跨挂载复制语义检查。

### 2.5 执行策略输出

允许的结果携带足够编排使用的执行信息：直接执行（write / delete）、原生 move 或复制回退，以及源 / 目标命中的挂载记录与相对 StoragePath。策略只描述"该怎么做"，不执行任何 I/O；T15 / T16 / T20 / T21 据此编排实际操作、状态更新与失败 effect 报告。

例：同挂载点文件 move 在 `nativeFileMove=true` 时输出原生策略与目标相对路径，编排层据此调用 `Storage.move`。

## 5. 验收标准

| 编号 | 必须满足的结果 | 核心场景 / 证据 |
| --- | --- | --- |
| A01 结构保护 | 根 / 命名空间根 / Mount 根 / 配置推导目录的变更被拒；复用 T09 结构查询 | write / move / delete 对各受保护路径返回 UNSUPPORTED_OPERATION；不触发存储调用 |
| A02 嵌套挂载 | 含后代挂载的目录整体移动 / 删除拒绝，recursive=true 不放宽；move 目标包含已配置挂载拒绝；子挂载内普通条目不受影响 | 挂 `/notes/team/docs`：拒删 `/notes/team`，允许检查 `/notes/team/docs/a.txt` |
| A03 参数与路由 | 同路径 move、目标入源子树返回 INVALID_ARGUMENT；无挂载且非配置目录返回 MOUNT_NOT_FOUND | `move /notes/a → /notes/a/b`；`write /other/x`；检查顺序先参数后结构后路由 |
| A04 只读预检 | 涉及只读存储的 write / move / delete 在副作用前返回 READ_ONLY；`readOnly` 默认 false 不影响既有测试 | 跨 Mount move 源盘只读即拒绝；T07 既有测试全部继续通过 |
| A05 能力与策略 | 同挂载点优先原生，缺失按复制回退检查；目录回退缺 `createDirectory` 返回 UNSUPPORTED_OPERATION；跨挂载点一律复制语义 | `nativeDirectoryMove=false` + `createDirectory=false` 拒绝；同 storageKey 两挂载点仍按复制检查；允许结果含挂载与相对 StoragePath |
| A06 纯逻辑与稳定性 | 不调用 Storage / Repository / 事件，不创建资源；入参快照不可变；检查顺序确定 | 代码审查、修改入参集合测试；无任何 I/O 依赖 |
| A07 构建与交付 | 新增测试真实执行、原有测试继续通过、格式检查通过；文档和状态准确 | `./scripts/check` 输出、JUnit 数量与失败 / 错误 / 跳过统计、变更清单；远端结果如实记录 |

预检通过不代表操作会成功：存在性、类型、覆盖冲突与真实 I/O 错误由执行期判定（T02 §9.1）；`readOnly` 只反映打开后端时已知的信息，运行中新出现的拒绝按执行期错误处理。
