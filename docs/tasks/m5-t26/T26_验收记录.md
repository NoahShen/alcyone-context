## 5. 时序、清理与证据强度口径

- **先订阅再触发**：两条代表都在操作之前 `vfs.subscribe`；等待键是「目标 Node ID + 类型」（本装置每个组合唯一），不共享一次性信号。
- **否定通知分三种机制，不能笼统说「都靠末尾标记」**：
  - **提交前无通知**：受控事务门——事务开着时闩锁停在 `commit` 块里，断言 0 行、Consumer 一条未收；放行后才收到（`EventPipelineRealStackTest :: A03 no consumer hears anything before the transaction commits`）。
  - **回滚 / 失败无成功通知**：先发**末尾标记**、等到标记被分发（同一条 FIFO 链），再断言目标事件不在收到的列表里（`A03 a real commit failure publishes nothing`、`EventPipelineTest :: A03`、包装用例）。
  - **满队列丢弃**：挂起 Consumer + 容量 1——分发协程取走第一条后堵在 Consumer 上，第二、三条入队遇满被丢，断言 `droppedEvents == 1` 且真实库三条记录都在（`A05 a full buffer drops the in-process event ...`）；这不是「另发末尾标记」。
- **挂起用例的清理不都是一套写法**：
  - 机制层挂起 Consumer 的用例由 `EventPipelineRealStackTest` 的 `withStack` 在 `finally` 里关 notifier、等分发收尾后再关库。
  - 目录提交取消用例（`DefaultVfsDirectoryMoveRealStackTest :: A06`）复用 T23 R1 的托管写法：`try/finally` + `withContext(NonCancellable)` 里 `cancel + join`。
