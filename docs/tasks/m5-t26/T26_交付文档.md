## 4. 补的两条代表（S2）

1. `RuntimeEventNotificationTest :: one failing consumer does not stop the other one nor later committed events`
   - 公开 `vfs.subscribe` 注册两个 Consumer（抛 `IllegalStateException` 的在前，记录的在后），**先订阅再触发**。
   - `write` → 记录者按事件 ID 等到 `FILE_CREATED`；`setMetadata` → 等到 `METADATA_UPDATED`；再 `write` → 等到后续 `FILE_CREATED`。
   - 断言：抛错 Consumer 确实被调用过；健康 Consumer 三次都收到；文件内容 / Metadata 状态照旧；真实 event 表三行与业务操作一一对应。等待按事件 ID（同一条 FIFO 链），不 sleep。
2. `RuntimeEventNotificationTest :: a normal reopen keeps the log but a new subscription is not replayed the old events`
   - 第一段 Runtime：写两个文件（两条旧事件），正常 `close`；保存旧事件 `event_id / event_type / node_id / uri` 四项快照。
   - 第二段：重开同一库，**先订阅**再写一个新文件；按新事件的 Node ID 等到它送达。
   - 断言：新订阅收到的新事件就是这一条；**收到过的所有事件**里没有旧日志的 Node（`received()` 不过滤）；旧事件四项快照重开后逐字不变；新事件追加在旧记录之后。用新标记事件证明监听器确实接上了，避免把「监听器没接上」误当不重放证明。

无生产代码改动；两条均为**真实 SQLite + 真本机目录 + 真 Runtime 组装 + 真进程内通知**。

- **不新增可靠投递**：无 ACK、消费游标、自动重试、去重、重启补发、外部消息队列、事件查询公共 API（E05/后续）。
