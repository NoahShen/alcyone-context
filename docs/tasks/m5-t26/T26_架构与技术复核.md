## 2. 必须修改

### R1：补齐 A01 / A03 的公开接线断言

`RuntimeEventNotificationTest.kt:73–105` 的健康 Consumer 按 **Node ID + 类型** 等待；数据库只查类型与 URI，没有将通知 `event.id` 与持久 `event_id` 对照。抛错 Consumer 仅断言 `isNotEmpty()`，无法直接证明它与健康 Consumer 收到的是同一批事件；`EventFactoryTest` 的转换测试以及真库机制测试不能替代任务 A01 指定的一个公开代表。

A03 所引 `RuntimePublicEntryTest` 的 Consumer 只把事件放进列表，`stat / getNode / getMetadata` 均在主测试协程执行。新增 Consumer 同样只记录事件；因此验收 §3「公开代表避免查询自锁」没有直接依据，既有回调 close 测试也不能代替公开查询接线。

**验收要求：**可在现有 Consumer 隔离用例中同时补齐：

- 保存两个 Consumer 收到的事件，在健康 Consumer 确认处理完成后，与真实 `event` 表按 **事件 ID** 比较；至少核对类型、Node ID、URI、毫秒时间，非移动事件的 source / target 为空，并直接比较两个 Consumer 的事件身份。
- 至少一个回调通过公开 `getNode` 或 `getMetadata` 查询已提交状态，将查询结果或异常交给测试协程直接断言；在查询完成前不做会改变该状态的下一步操作。等待应有界，回调中的断言不能只被通知器当普通异常吞掉。
- 不要求新增一整组测试或极窄取消注入点。完成后再把 A01 / A03 标为达成。
