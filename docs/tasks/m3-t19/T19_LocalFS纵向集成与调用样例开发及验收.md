## 1. 目标与范围

让调用方只提供配置，通过 AlcyoneVfs 完成一条可演示、可回归的本地文件使用流程，并证明正常关闭后数据与身份仍在。主要修改 `integration-tests/vfs` 和配套文档；复用真实 SQLite、临时 Local FS 与 OpenDAL，不重新组装 Core / Repository 充当 SDK 入口。

已有 `RuntimePublicEntryTest`、`MountConfigurationTest` 以及 T18 的 Runtime 测试可复用或补强，不按任务号复制同一批用例。若发现实现缺陷，做最小修复并单独说明原因；不提前实现 move、WebDAV、ACL、只读挂载配置、事件重放或崩溃恢复，也不扩展到 T27 的压力 / 并发矩阵。

## 2. 开发内容

### 2.1 从公开入口贯通真实操作

使用 `AlcyoneVfs.create(config)` 贯通 write / read / list / stat / getNode / Metadata / delete，核对文件内容、Node ID 与事件中的对象对应；涉及目录列表时按路径比较，不假设返回排序。用一个直接写入临时磁盘的未登记文件验证 read / list 不注册、stat 后出现稳定 Node ID，沿用 T13 的懒注册语义。

例：挂 `/resources/docs` 到临时 docs 目录，写 `note.txt`、整体替换 Metadata，再读取并列出；另放 `external.txt`，list 时 nodeId 为空，stat 后可按 ID 查询。

### 2.2 正常关闭后重开

在同一配置和同一状态库上完成“写入与 Metadata → close → create → 校验 → 删除 → close → create”的连续流程，保留第一次的 Node ID 比对。确认内容、有效 Node、Metadata 与历史事件在正常重开后保持；删除后的旧 ID / Metadata 查询返回 NOT_FOUND，同路径重建得到新 ID。

例：note.txt 重开仍是原 ID 与标签；删除后再次重开不能查到旧 ID，重新写同一路径是新文件。这是正常持久化验证，不等于异常中断恢复；不得删库或清 Mount 行来使测试通过。

### 2.3 区分持久化事件与实时通知

用公开 subscribe 接收事件，明确订阅先于操作，以目标 Node ID / 事件类型等待完成，不靠固定 sleep 宣称“没有事件”。测试侧允许只读检查 SQLite 的 Event Log，优先在 Runtime 关闭后核对提交记录及重开前后已有事件 ID / 内容不变；不增加公共事件查询 API，不要求重放旧通知。

例：写入与更新 Metadata 各留下对应事件，删除再追加删除事件；重开仍保留旧记录。列表、读取和流式读取不产生变更事件，可在关闭后的日志中比较操作前后的持久化事实；测试 SQL 只作断言，不替 SDK 写数据。

### 2.4 流式入口与资源释放

通过公开入口验证超过 ByteArray 默认限额的文件可分块读取，流总量上限按 Runtime 配置与调用选项取更严格值；关闭结果对象用 result.use，关闭 Runtime 用协程内 try/finally。验证一次遗忘流被 Runtime 回收、关闭后读失败、同库可重开；交接取消、原异常与清理等待沿用 T18 专项证据，不复制反射替身测试。

例：临时生成大于 16 MiB 的文件，read 默认报 LIMIT_EXCEEDED，openStream 分块计算字节数或摘要与原文件一致。样例不要用 readBytes 把大文件重新整体读入内存。

### 2.5 拒绝操作与可运行样例

选少量公开入口反例：缺失文件 NOT_FOUND、已存在文件的 CREATE_NEW 冲突、受保护挂载目录的变更拒绝，以及 move 明确 UNSUPPORTED_OPERATION；错误码和 effect 沿用既有契约，核对失败前后内容及有效状态不被意外改变。能力预检细目复用 T10 / T12 的证据，不用操作系统 chmod 模拟尚未支持的只读配置。

提供一个可复制并实际运行的 Kotlin 最小样例，包含配置、文件操作、Metadata、订阅、流式读取与 finally close，并给出准确运行命令及预期结果。可直接把集成模块里的一个可执行 JUnit 样例作为入口，无需新建样例模块、CLI、发布或安装流程；示例只使用 API / Runtime，SQL 检查留在测试辅助代码中。

## 4. 验收标准

允许多个验收项共享同一条完整场景，不要求每项新建测试类。复用用例写明位置与断言；不以测试数量、强制变异数量或重复执行次数代替证据。

| 编号 | 必须满足 | 核心证据 |
| --- | --- | --- |
| A01 公开入口 | 宿主仅配置 Runtime，完成文件基础操作和 Metadata 整体替换 | 真 Local FS + SQLite；检查实际字节、同一 Node ID、列表结果与删除结果 |
| A02 懒注册 | 物理预置文件 read / list 不注册，stat 后可按 ID 查询；读取不产生变更事件 | 公共入口结果与只读状态核对；与 T13 / T18 用例区分新增闭环证据 |
| A03 重开与身份 | 正常重开保留文件、Node ID、Metadata；删除重开后旧 ID 无效，同路径重建为新 ID | 同一库连续 create / close，禁止删库重建规避问题 |
| A04 事件 | 对应变更记录持久化，正常重开保留旧事件；实时订阅按目标确认 | 事件类型 / 对象 / ID 核对，不把通知可靠投递或重放当保证 |
| A05 流与关闭 | 大文件分块读取、有效上限、遗漏流回收、关闭后失败及同库重开 | 公开 Runtime 真流验证；取消与 native 内部细目引用 T18 / T12 已确认测试 |
| A06 失败与阶段边界 | 少量参数 / 结构 / 存储反例按契约拒绝，无意外物理或逻辑变更；move 阶段拒绝 | 精确错误码、适用的 effect 及前后事实；不新增只读配置或后端能力 |
| A07 样例可运行 | 文档有完整调用、配置与关闭流程，运行入口真实存在且执行成功 | 项目内命令、关键预期结果、临时目录清理；样例不手工组装 Repository / Operator |
| A08 工程与交付 | 原 609 例基线无回归，模块边界不扩大，证据归属和未验证项准确 | `./scripts/check`、分模块 XML；新增 @Test 确实进入报告，若迁移测试解释计数变化 |

测试读写仅在临时工作目录，状态库置于挂载物理根之外。公共操作断言优先；只读 SQL 可确认持久化事实，但不得用写 SQL 或内部替身替代被测操作。
