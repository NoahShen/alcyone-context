## 2. 必须修改

### R1 / P2：A04 缺旧事件目标重开后的比较

位置：`RuntimeReopenIdentityTest.kt:149–167`。重开前检查旧事件的 node_id，重开后只比较旧 ID、类型，并检查新事件的目标；没有比较重开后的旧事件目标，无法支撑用例标题和交付文档所称“旧事件 ID / 类型 / 目标不变”。

最小修复：保存重开前旧事件的目标信息，重开后比较同一批记录；建议以 `event_id / event_type / node_id / uri` 的小快照一次比较，既明确对象也明确路径。不要求新增事件 API、故障注入或重写测试；若仍宣称完整“内容逐字不变”，应比较相应字段，否则把说明限定为实际比较的字段。

这是本任务 A04 明确要求的纵向证据缺口，不是发现数据库真的改写了事件。其余事件持久化、订阅先于操作及按目标 / 类型等待的断言有效。

### R2 / P2：使用说明把缺失文件的写入一概写成 NOT_FOUND

位置：`T19_使用说明.md` §7 的“读写缺失文件 / 删除缺失目标”。公共 `WriteOptions` 默认 UPSERT，目标缺失且其他前提满足时允许创建；CREATE_NEW 同样允许创建，REPLACE_EXISTING 才要求目标已存在。当前说明会误导宿主使用 SDK。

将读取 / 删除缺失目标与不同写入模式分开，或只列本轮实际验证的 read / delete 反例；不因此强制新增 REPLACE_EXISTING 测试矩阵。同步订正反例用例注释中的“read / delete / stat 都检查”及验收记录 effect 表述：当前只调用 read / delete，effect 直接断言仅覆盖 missingDelete 和 deleteRoot。
