## 2. 样例做了什么（逐段对应源码注释）

1. 准备一块真的本机目录，和**挂在根之外**的状态库路径；额外放一个未登记的外部文件；
2. 把 `VfsRuntimeConfig`（命名空间 + 挂载）交给 `AlcyoneVfs.create`；
3. `subscribe` 订阅事件——**订阅先于操作**；这个样例只有一个文件，所以按事件**类型**等待（多文件场景应再加目标 Node ID 一起作判据）；
4. `write` 写文件，`setMetadata` 整体替换 Metadata，等到 `METADATA_UPDATED`；
5. `read` 读回字节，`stat` 确认同一 Node ID，`getMetadata` 读标签；
6. `list` 列目录（**按路径比较，不假设排序**；未登记项 `nodeId == null`）；
7. `openStream` 分块读取并算 SHA-256——**不把整份读进内存**；
8. `finally { vfs.close() }`（`close()` 是挂起函数，用 `try/finally` 而不是 `use`）。

## 3. 重开与身份（A03）

在**同一个状态库**上连续 `create → 用 → close`：内容、有效 Node、Metadata、Node ID 正常重开后原样保留；
删除重开后旧 ID / 旧 Metadata 都 `NOT_FOUND`，同路径重建得到**新 ID**。

```kotlin
// 第一段：写入并正常关闭。
val info = run {
    val vfs = AlcyoneVfs.create(config)
    try {
        vfs.write(VfsUri.parse("alcyone://resources/docs/note.txt"), bytes)
    } finally {
        vfs.close()
    }
}
// 重开校验：内容与身份都还在。
val vfs = AlcyoneVfs.create(config)
try {
    check(vfs.read(VfsUri.parse("alcyone://resources/docs/note.txt")).contentEquals(bytes)) // 内容还在
    check(vfs.getNode(info.id).id == info.id)                                                // 身份还是它
} finally {
    vfs.close()
}
```

`close()` **正常关闭**不等于异常中断恢复：这是正常持久化验证。**不要**删库或清 `mount` 行来让测试通过。

## 4. 懒注册（A02）

物理预置、未经 VFS 登记的文件：

- `read` 只读内容，**不登记**；
- `list` 把它列为 `nodeId == null` 的条目，**不登记**；
- `stat` 才懒注册，给出**稳定** Node ID，此后可按 ID `getNode` 查询；
- 以上读取 / 懒注册**都不产生变更事件**。

## 5. 事件（A04）

- 变更事件的类型与对象持久化在事件日志里，随正常重开保留；**重开前后已有事件的 ID / 内容不变**，新事件追加在后面；
- 实时 `subscribe` **先于操作**注册，按目标 Node ID / 事件类型等待；
- 通知是 T14 的**有界进程内通知**：不保证回放与可靠投递。要确认「某操作没发事件」，
  看的是**同步提交的事件日志**，不是靠 sleep 猜通知。

## 6. 大文件流式（A05）

- 超过 `read` 默认限额（16 MiB）的文件用 `openStream` 分块读，**不要** `readBytes()` 整体拉全；
- 实际上限取 `min(streamTotalLimit, options.maxTotalBytes)`，超限报 `LIMIT_EXCEEDED`；调用级只能**收紧**；
- 流**拿到就 close**（`result.use { }`）：调用方忘了关，Runtime 在 `close()` 时替你收回；关闭后读失败；
- 关闭 Runtime 后，**同一个状态库可以重开**。

```kotlin
val digest = MessageDigest.getInstance("SHA-256")
var total = 0L
vfs.openStream(uri("/big.bin")).use { result ->
    val buffer = ByteArray(64 * 1024)
    while (true) {
        val read = result.stream.read(buffer)
        if (read < 0) break
        digest.update(buffer, 0, read); total += read
    }
}
```

## 7. 公开入口反例（A06）

| 场景 | 错误码 |
| --- | --- |
| **读取 / 删除**缺失目标（本轮验证的入口） | `NOT_FOUND`；`delete` 的 effect 为 `NONE`（没删任何东西） |
| 对已存在文件用 `WriteMode.CREATE_NEW` | `ALREADY_EXISTS`（内容不被改写） |
| 变更受保护的挂载目录（挂载根 / 命名空间根 / 逻辑根 / 承载后代挂载的祖先） | `UNSUPPORTED_OPERATION`（effect `NONE`） |
| `move` **目录**（同 / 跨 Mount，**T22 接续**） | `UNSUPPORTED_OPERATION`（源 / 目标都不动） |
| `move` 同一 Mount 普通文件（**T20 已交付**） | 成功：保留原 Node ID / Metadata，旧路径消失、目标生效，一条 `FILE_MOVED` |
| `move` 同 Mount 复制回退（后端无原生 move）或**跨 Mount** 普通文件（**T21 已交付**） | 成功：同样保留原 Node ID / Metadata + 一条 `FILE_MOVED`；区别是走「读源 → 写目标 → 确认 → 删源」，因此**受 16 MiB 读写限额约束**，超限报 `LIMIT_EXCEEDED` 且源保留 |

这些失败**不改变**内容与有效状态：有效 Node、Metadata、事件日志、磁盘文件集合在失败前后一致。

> **写入缺失目标不等于「一定失败」**：写入由 `WriteOptions.mode` 决定——默认 `UPSERT` 在目标缺失且其他前提满足时**允许创建**，
> `CREATE_NEW` 也允许创建（只在目标已存在时报 `ALREADY_EXISTS`），**只有 `REPLACE_EXISTING` 才要求目标已存在**
> （缺失时报 `NOT_FOUND`）。本轮只验证了 read / delete 的缺失反例，没有为 `REPLACE_EXISTING` 单独建矩阵。

## 8. 怎么自己跑一遍回归

```bash
# 只跑集成模块（含本任务的 4 个类）
./scripts/dev gradle :integration-tests:vfs:test --rerun-tasks --console=plain

# 只跑本任务的类
./scripts/dev gradle :integration-tests:vfs:test \
  --tests "*RuntimeReopenIdentityTest*" \
  --tests "*RuntimeLazyRegistrationAndFailureTest*" \
  --tests "*RuntimeStreamingVerticalTest*" \
  --tests "*LocalFsSampleTest*" --console=plain

# 全量检查（编译 + 全模块单测 + 格式）
./scripts/check
```

测试读写只在 `@TempDir` 临时工作目录，状态库在挂载物理根之外；不需要清系统环境。
