## 3. 复用清单与缺口（S1 盘点固化）

`integration-tests/vfs` 原有 55 例，复用于 A01～A08 的如下：

| 已有用例 | 位置 | 复用于 |
| --- | --- | --- |
| `a host that only submits configuration gets the whole file lifecycle` | `RuntimePublicEntryTest` | A01 主流程（write→read→stat→list→Metadata→delete，含事件顺序与三边一致） |
| `an invalid configuration is refused before any service is opened` | `RuntimePublicEntryTest` | A01 非法配置不开放服务 |
| 6 例 | `MountConfigurationTest` | A03 单次重开保留身份 / Metadata；A04 Mount 身份持久化 |
| 26 例 | `vfs/DefaultVfsRealStackTest` | 底层真实栈（Core + 真 SQLite + 真 Local FS） |
| 12 例 | `registry/NodeRegistryRealStackTest` | 懒注册 / 路由 / 状态库语义（A02 的**底层**证据） |
| 9 例 | `event/EventPipelineRealStackTest` | 事件提交 / 回滚 / 重开（A04 的**底层**证据，含反射替身） |

**本轮补的缺口**（不按任务号复制同一批用例，全部走公开 `AlcyoneVfs` 入口）：

1. **A03**：`MountConfigurationTest` 只覆盖**单次**重开保留；本轮补「写 + Metadata → close → 校验 → 删除 →
   close → 校验 → 重建」，并确认删除后旧 ID `NOT_FOUND`、同路径重建得到**新 ID**。
2. **A02**：Registry 层（T13）/ Core 层（T15）已有懒注册证据；本轮补**公开入口**上的独立闭环
   （物理预置文件 read/list 不注册、stat 后按 ID 查询、读不产生变更事件）。
3. **A04**：`EventPipelineRealStackTest` 在事件管道层证「关库重开日志还在」；本轮补公开入口上
   **重开前后已有事件的 `event_id / event_type / node_id / uri` 四项不变** + 实时订阅**先于操作、按目标 ID / 类型等待**。
4. **A05**：T18 `RuntimeStreamTest` 已覆盖分块 / 限额 / 交接取消；本轮补公开入口的**纵向闭环**：
   >16 MiB 文件 `read` 报 `LIMIT_EXCEEDED`、`openStream` 分块**摘要**与原文件一致、遗忘流被回收、
   关闭后读失败、同库可重开。**不复制** T18 的反射替身与交接取消用例。
5. **A06**：公开入口反例（缺失 `NOT_FOUND`、`CREATE_NEW` 冲突 `ALREADY_EXISTS`、受保护挂载目录变更
   `UNSUPPORTED_OPERATION`、`move` `UNSUPPORTED_OPERATION`），并核对失败前后事实不变。
6. **A07**：可运行 JUnit 样例，文档给出真实运行命令与预期结果。

## 4. 决定与理由

| 决定 | 理由 |
| --- | --- |
| 全部走 `AlcyoneVfs` 公开入口 | 本任务是**纵向集成**：宿主只提交配置，不手工组装 Repository / Operator |
| 状态库放在挂载物理根**之外** | 配置层已强制（`requireOutsideMounts`）；读写只在 `@TempDir` |
| 只用**只读** SQL 确认持久化事实 | 确认 Node / Metadata / Event 真的落库；不用写 SQL 或内部替身替代被测操作 |
| 列表按路径比较（`.sortedBy` / 集合） | `list` 不保证排序 |
| 事件等待用目标 Node ID / 类型，不用固定 sleep | 不靠 sleep 宣称「没有事件」；同步提交的**事件日志**直接比行数 |
| 大文件样例不 `readBytes()` 整体读入 | 分块 `InputStream.read` 累加 + 分块 `MessageDigest`，与原文件摘要比对 |
| 复用 T18 的取消 / native 细目证据 | 交接取消与反射替身属 T18 / T12 专项，不复制 |
| 不新增只读挂载配置、不实现 move | 阶段边界：只读属后续、move 属 T20～T22 |
| 新增文件不合并进既有类 | 既有类各自有明确任务号；新增用例归 T19，避免混淆归属 |

## 5. 可运行样例（A07）

样例入口：`integration-tests/vfs/src/test/kotlin/.../runtime/LocalFsSampleTest.kt`。
它演示宿主视角的完整用法：**只提交配置** `AlcyoneVfs.create(config)`，然后
write → read → stat → setMetadata/getMetadata → list → subscribe（等到事件）→ openStream（分块）→ `finally close`。
不新建样例模块、不做 CLI、不发布；SQL 检查留在测试辅助代码里，样例只用 API / Runtime。

运行命令与预期结果见[使用说明 §1](T19_使用说明.md)。

## 6. 契约范围

本轮**无契约回写**：只用 T18 已固化的公开能力（`AlcyoneVfs.create` / `subscribe` / `openStream` /
`suspend close`），未扩展 API，未新增错误码。

## 7. 证据边界（未验证项）

- 事件是**有界进程内通知**：不保证回放与可靠投递；本轮不把「通知送达」当保证，只核对**已提交事件日志**。
- `move`、WebDAV、ACL、只读挂载配置、事件重放、崩溃恢复都**未实现**，本轮不触碰。
- 流式 native 内部细目（交接取消、关流失败 suppressed）引用 T18 `RuntimeStreamTest`，本轮不重复验证。
- 大文件场景用确定性字节序列 + SHA-256 比对，验证「分块读内容无损」；不覆盖极大文件（> GiB）与磁盘满。
- 反例只覆盖少量参数 / 结构边界（A06 列出的四类），不扩到 T27 的压力 / 并发矩阵。
