### 2.3 源码 `@Test` 注解与 XML 报告对账命令

可在根目录下执行以下快速脚本核对源码用例与 XML 结果严格一致：
```bash
python3 -c "
import glob, re, xml.etree.ElementTree as ET

def count_src(pattern):
    cnt = 0
    for p in glob.glob(pattern, recursive=True):
        if '/build/' in p: continue
        with open(p, 'r', errors='ignore') as f:
            cnt += len(re.findall(r'@Test\b', f.read()))
    return cnt

def count_xml(pattern):
    cnt = 0
    for p in glob.glob(pattern, recursive=True):
        cnt += int(ET.parse(p).getroot().attrib.get('tests', 0))
    return cnt

reg_src = count_src('**/src/test/kotlin/**/*.kt')
reg_xml = count_xml('**/build/test-results/test/*.xml')
wd_src = count_src('**/src/webdavTest/kotlin/**/*.kt')
wd_xml = count_xml('**/build/test-results/webdavTest/*.xml')

print(f'Regular: src={reg_src}, xml={reg_xml}, diff={reg_src - reg_xml}')
print(f'WebDAV:  src={wd_src}, xml={wd_xml}, diff={wd_src - wd_xml}')
"
```
预期输出：
```text
Regular: src=752, xml=752, diff=0
WebDAV:  src=43, xml=43, diff=0
```

## 3. 架构审查核验方法

### 3.1 模块依赖无反向与无越级检查
核对各子模块 `build.gradle.kts`：
- `vfs/api` 仅包含 `common` 项目依赖；
- `vfs/core` 仅包含 `common` 与 `vfs:api` 项目依赖；
- `vfs/storage` 与 `vfs/persistence` 分别依赖 `vfs:core`；
- 检查命令：
  ```bash
  ./scripts/dev gradle :vfs:api:dependencies --configuration runtimeClasspath
  ./scripts/dev gradle :vfs:core:dependencies --configuration runtimeClasspath
  ```
  确认无任何 OpenDAL、SQLite、SQLDelight 依赖。

### 3.2 生产日志无实现绑定检查
检查生产代码日志依赖仅为 `org.slf4j:slf4j-api`：
```bash
git grep -in "org.slf4j.impl\|ch.qos.logback\|org.apache.logging" "*/src/main/kotlin"
```
预期输出为空。

## 4. 常见问题排查与边界

1. **WebDAV 测试端口冲突或启动失败**：
   - 检查本次脚本日志与失败信息：`./scripts/webdav-check` 启动异常时会输出临时目录下的 `$LOG` 内容。
   - 检查本次服务是否有遗留进程：测试脚本基于 trap 和 `$SERVER_PID` 自主清理。如果非正常中断导致残留，应先定位本次脚本打印的端口与临时配置路径（如 `/tmp/t24-webdav-*/server.log`），确认该 PID 确实属于本项目单次测试后针对性清理（如 `kill <PID>`）；**切勿**执行全局按名称杀进程（如全局 `pkill -f wsgidav`），以免误杀宿主其他工作进程。
   - 依赖与隔离：项目受管依赖位于 `.local/webdav/venv`，严格由项目管理，切勿向系统 Python 全局安装依赖。
2. **工具链报错 Unsupported Platform**：
   - 当前实跑与验收仅支持 macOS arm64；Linux x64/arm64 虽保留配置但本阶段未承诺实跑。
3. **网络超时假死防护（方案④）**：
   - 底层 native 网络请求无强制超时中断机制；如偶发网络悬挂，应在宿主端排查外部链路。
