## 2. 核心用例（UC-01～UC-07 与目录 list）证据索引

### 2.1 UC-01 读取操作
- **契约要求**：支持有界整读 (`read`) 与流式读取 (`openStream`)；按实际读出字节计限；读不登记 Node、不修改 Metadata、不发事件；资源幂等释放。
- **实现入口**：`DefaultVfs.read`, `DefaultVfs.openStream`, `DefaultVfs.stat`, `WebDavStorage.open`, `LocalFsStorage.open`
- **关键测试与断言**：
  1. `DefaultVfsReadTest.A01 an unregistered file can be read and reading it registers nothing`：
     - 断言：读出字节正确；`nodes.findByPath` 为 null；`committedNodes` 为空；`committedEvents` 为空。
     - 层级：Core + Storage 替身。
  2. `DefaultVfsReadTest.A01 the effective read limit is the smaller of the configured one and the per call one`：
     - 断言：恰好等于上限成功读取，超过上限报 `LIMIT_EXCEEDED`；按配置与调用级较小者生效。
     - 层级：Core + Storage 替身。
  3. `RuntimeStreamingVerticalTest.a file over the byte array default streams in chunks and matches the original digest`：
     - 断言：17 MiB 大文件触发 `read` 的 `LIMIT_EXCEEDED` 拒绝；通过 `openStream` 分块读取且逐块计算 SHA-256 与原文件一致；读完后 activeNodes 计数为 0，event 计数为 0。
     - 层级：公开 Runtime + 真实 Local FS + 真实 SQLite。
  4. `T25WebDavContractTest.A02 a file over the byte array limit streams in full via the public openStream`：
     - 断言：WebDAV 20 MiB 文件 `read` 报 `LIMIT_EXCEEDED`；`openStream` 完整读完并校验 SHA-256。
     - 层级：公开 Runtime + 真实 WebDAV 服务 + 真实 SQLite。
  5. `RuntimeStreamingVerticalTest.an unclosed stream is reclaimed by close and the same database can be reopened`：
     - 断言：遗忘未关的流在 Runtime `close()` 时自动回收；后续读取流抛出 `IOException` 或 `VfsException`；同一状态库可正常重开。
     - 层级：公开 Runtime + 真实 Local FS + 真实 SQLite。

### 2.2 UC-02 写入操作
- **契约要求**：支持 `CREATE_NEW`, `REPLACE_EXISTING`, `UPSERT` 三种写入模式；自动创建缺失的逻辑父目录；覆盖写入保留原有 Node ID、Metadata 与 `registeredAt`；写失败如实反映 `VfsEffect`。
- **实现入口**：`DefaultVfs.write`, `DefaultVfs.createMissingParents`, `WebDavStorage.write`, `LocalFsStorage.write`
- **关键测试与断言**：
  1. `DefaultVfsWriteTest.A01 create-new succeeds when missing and fails when present without touching backend or store`：
     - 断言：新文件写入分配新 Node ID 并落库；目标已存在时抛出 `ALREADY_EXISTS`，Storage 不调用写入，状态库与事件无变化。
     - 层级：Core + Storage 替身。
  2. `DefaultVfsWriteTest.A01 replace-existing overwrites an existing file preserving identity and tags`：
     - 断言：覆盖已有文件，Node ID 与 Metadata 保持不变，`registeredAt` 保持不变，仅更新大小并提交 `FILE_MODIFIED` 事件；目标不存在报 `NOT_FOUND`。
     - 层级：Core + Storage 替身。
  3. `DefaultVfsWriteTest.A01 upsert creates missing and replaces existing with identity preserved`：
     - 断言：目标缺失时等同于新建；目标存在时等同于覆盖并保留身份。
     - 层级：Core + Storage 替身。
  4. `DefaultVfsWriteTest.A01 write auto-creates missing parent directories along the path`：
     - 断言：多级缺失父目录被自动创建，生成 `DIRECTORY_CREATED` 事件，子文件成功落盘。
     - 层级：Core + Storage 替身。
  5. `T25WebDavContractTest.A01 the three write modes behave per the port on the real service`：
     - 断言：真实 WebDAV 上验证三种写模式矩阵，校验 HTTP PUT、服务端内容落盘与 Node ID 保持。
     - 层级：公开 Runtime + 真实 WebDAV 服务 + 真实 SQLite。
  6. `DefaultVfsStateWriteFailureRealStackTest.A06 storage write succeeded but state commit failed marks effect PARTIAL without rollback fake`：
     - 断言：Storage 写入成功但 SQLite 事务提交失败（如只读数据库），抛出异常附带 `VfsEffect.PARTIAL`，源与已写内容不被伪造回滚。
     - 层级：真实 Local FS + 受控 SQLite 注入。

### 2.3 UC-03 Node 查询与懒注册
- **契约要求**：`stat` 首次访问懒注册身份，后继访问复用；并发 `stat` 安全复用同一 ID；`includeStorage=false` 纯逻辑查询不触碰底层后端；`getNode` 纯逻辑按 ID 查询，不存在报 `NOT_FOUND`；虚拟目录不向底层请求属性。
- **实现入口**：`DefaultVfs.stat`, `DefaultVfs.getNode`, `NodeRegistryImpl.stat`
- **关键测试与断言**：
  1. `DefaultVfsReadTest.A01 stat is the first thing that hands out an identity and later stats reuse it`：
     - 断言：首次 `stat` 分配 Node ID 并查询 storage 属性；再次 `stat` 拿到同一个 Node ID。`getNode` 不包含 storage 属性（纯逻辑）。
     - 层级：Core + Storage 替身。
  2. `DefaultVfsReadTest.A01 stat with includeStorage false answers an existing node without asking the backend`：
     - 断言：`includeStorage=false` 直接返回已登记 Node，底层 Storage 调用记录为空（0 次交互）。
     - 层级：Core + Storage 替身。
  3. `NodeRegistryRealStackTest.concurrent stat on same path returns identical nodeId and single row`：
     - 断言：多协程并发对同一未登记路径执行 `stat`，返回完全相同的 `NodeId`，SQLite `node` 表仅有唯一记录行。
     - 层级：真实 SQLite + 机制层并发。
  4. `NodeRegistryBoundaryTest.unregistered query returns NOT_FOUND`：
     - 断言：查询未登记的 Node ID 抛出 `VfsException(NOT_FOUND)`。
     - 层级：Core 纯逻辑。

### 2.4 UC-04 文件与目录移动
- **契约要求**：同 Mount 支持原生移动（若后端支持）；跨 Mount 或后端不支持时回退为复制+校验+删源；保持 Node ID、Metadata 与 `registeredAt` 连续；子树移动后未登记后代不被提前物化登记；目录移动只发一条根级 `DIRECTORY_MOVED` 事件；目标存在报错且不覆盖。
- **实现入口**：`DefaultVfs.move`, `DefaultVfs.moveDirectoryByCopy`, `WebDavStorage.move`, `LocalFsStorage.move`
- **关键测试与断言**：
  1. `T25WebDavMoveTest.A03 a file moves natively within the webdav mount and across backends in both directions`：
     - 断言：WebDAV 内部移动走原生 rename，目标存在、源消失；Local FS 与 WebDAV 双向跨 Mount 移动，Node ID、Metadata、registeredAt 保留，目标已存在报 `ALREADY_EXISTS`。
     - 层级：公开 Runtime + 真实 WebDAV + 真实 Local FS + 真实 SQLite。
  2. `RuntimeDirectoryMoveTest.a directory moves from local to webdav keeping its tree and emitting one root event`：
     - 断言：跨后端移动目录整树；已登记子文件 ID/Metadata 保留并更新路径前缀；未登记子文件不新增 Node 行；SQLite `event` 表恰好产生一条 `DIRECTORY_MOVED` 根事件。
     - 层级：公开 Runtime + 真实 WebDAV + 真实 Local FS + 真实 SQLite。
  3. `DefaultVfsDirectoryMoveRealStackTest.directory move target exists refuses before copy`：
     - 断言：目标目录已存在时提前拒绝，不执行任何底层拷贝或删除。
     - 层级：Core + 真实 Local FS + 真实 SQLite。
  4. `T25WebDavFailureReportTest.A06 a target confirmation failure refuses to delete the source and keeps the effect partial`：
     - 断言：跨后端复制后，目标确认失败则拒绝删除源文件，抛出异常且 `effect` 为 `PARTIAL`。
     - 层级：公开 Runtime + WebDAV 故障装置 + 真实 SQLite。

### 2.5 UC-05 删除操作
- **契约要求**：支持非递归删除与递归删除；非空目录非递归删除报错 `DIRECTORY_NOT_EMPTY` 且物理与逻辑均保留；递归删除清理整棵子树及其所有已登记后代的 Metadata；删除边界严格按段匹配（`a` 不影响 `a-old`）；未登记的物理目录可被递归删除。
- **实现入口**：`DefaultVfs.delete`, `WebDavStorage.delete`, `LocalFsStorage.delete`
- **关键测试与断言**：
  1. `DefaultVfsDeleteTest.A01 non recursive delete on non-empty directory fails and leaves tree untouched`：
     - 断言：非空目录非递归删除抛出 `DIRECTORY_NOT_EMPTY`，底层文件与 Node 均不动。
     - 层级：Core + Storage 替身。
  2. `DefaultVfsDeleteTest.A01 recursive delete removes all descendant nodes and cleans up metadata`：
     - 断言：递归删除目录下所有文件，父目录与子项 Node 状态全部标记为 retired，子项 Metadata 全部清空，生成对应删除事件。
     - 层级：Core + Storage 替身。
  3. `LocalFsPathBoundaryTest.segment boundary ensures a does not delete a-old`：
     - 断言：删除 `/resources/a` 绝不触碰 `/resources/a-old` 或其子项。
     - 层级：Storage 本地路径段匹配测试。
  4. `T25WebDavContractTest.A01 empty directories delete non recursively and non empty ones refuse then succeed recursively`：
     - 断言：真实 WebDAV 上空目录非递归删除成功；非空目录非递归被拒，递归删除整树消失。
     - 层级：公开 Runtime + 真实 WebDAV 服务。

### 2.6 UC-06 Metadata 操作
- **契约要求**：支持基于 `NodeId` 的查询与整体替换；空对象清空 Metadata；未登记或已退役 ID 报 `NOT_FOUND` 并附带 `VfsEffect.NONE`；纯逻辑操作，零触碰底层 Storage；只读后端仍可读写 Metadata；同值更新仍递增版本并发送 `METADATA_UPDATED` 事件。
- **实现入口**：`DefaultVfs.getMetadata`, `DefaultVfs.setMetadata`, `NodeRepositorySqlite`
- **关键测试与断言**：
  1. `DefaultVfsMetadataTest.A01 a valid node without metadata reads empty while unknown and retired ids are NOT_FOUND`：
     - 断言：有效无标签 Node 返回空 `NodeMetadata()`；未知 ID 与已删除 ID 均报 `NOT_FOUND`，`effect` 为 `NONE`，底层 Storage 调用数为 0。
     - 层级：Core + Storage 替身。
  2. `DefaultVfsMetadataTest.A02 a set replaces the whole object and an empty object clears it`：
     - 断言：整体替换而非合并；空对象彻底清除数据行。
     - 层级：Core + 内存状态库。
  3. `DefaultVfsMetadataTest.A03 both operations stay in the state store on a read-only backend`：
     - 断言：在只读后端挂载下，Metadata 读写依然成功（状态库独立于物理盘）。
     - 层级：Core + 只读 Storage 替身。
  4. `RuntimeReopenIdentityTest.a file keeps its identity and metadata across two normal reopens and a rebuild gets a new id`：
     - 断言：写入 Metadata 后正常关闭，多次重开同一 SQLite 库，Metadata 原样读出；删除重开后旧 ID 报 `NOT_FOUND`。
     - 层级：公开 Runtime + 真实 Local FS + 真实 SQLite。

### 2.7 UC-07 事件通知
- **契约要求**：状态提交与事件落库在同一 SQLite 事务原子完成；事务提交后方触发通知；Consumer 之间相互隔离，抛错被静默/打日志丢弃，不阻塞其他 Consumer，不影响后续事件；正常重开不自动重放历史事件；首版尽力而为，不自动重试。
- **实现入口**：`AsyncEventNotifier`, `DefaultVfs.subscribe`, `EventDispatcherLogCaptureTest`, `TransactionAndDispatchTest`
- **关键测试与断言**：
  1. `EventPipelineRealStackTest.A01 event committed atomically with node state in single transaction`：
     - 断言：SQLite 事务回滚时，`node` 与 `event` 同步回滚；提交时二者同步落库。
     - 层级：Core + 真实 SQLite。
  2. `RuntimeEventNotificationTest.one failing consumer does not stop the other one nor later committed events`：
     - 断言：前置 Consumer 抛异常，后续健康 Consumer 仍收到同一个 `FILE_CREATED` 事件；后续操作与事件（如 `METADATA_UPDATED`）正常分发；Consumer 回调内通过公开 `getNode` 能立刻查到刚提交的状态。
     - 层级：公开 Runtime + 真实 Local FS + 真实 SQLite。
  3. `RuntimeEventNotificationTest.A06 normal reopen does not replay historical events`：
     - 断言：保留旧事件快照重开实例，新实例注册订阅后不收到旧事件；重开后新触发操作能正常收到新事件（证明非订阅故障）。
     - 层级：公开 Runtime + 真实 SQLite。
  4. `EventDispatcherLogCaptureTest.failing consumer logs warning without throwing out`：
     - 断言：Consumer 异常被分发器捕获并记录 WARN 日志，包含事件 ID，异常不外抛。
     - 层级：Core 日志捕获测试。

## 3. A01～A08 逐项核对与验收结论

### A01 用例覆盖 —— 通过
- UC-01～UC-07 与目录 list 的契约条款已全量映射到具体实现与测试入口（详见 §2）。
- 区分了公开 Runtime、Core + 真实 SQLite、真实 Adapter 及替身层级；关键断言包含正常路径与失败路径。
- 关键契约无遗漏。

### A02 公共入口与后端覆盖 —— 通过
- 公开门面 `AlcyoneVfs` 覆盖核心读写、流式读取、stat、元数据、删除、移动与事件监听。
- 本地文件系统 (Local FS) 与真实网络 WebDAV 均有全栈集成测试；涵盖同后端与跨后端移动。
- 明确了 Adapter 能力与 Core 回退的界限：WebDAV 原生移动文件，目录移动通过 Core 递归复制后删源回退。

### A03 模块边界与架构分层 —— 通过
- **构建依赖方向**：
  - `common`：仅基础工具与注解。
  - `vfs:api`：仅依赖 `common`，对外导出接口与值对象。
  - `vfs:core`：仅依赖 `common` 与 `vfs:api`，定义 Port 接口与编排逻辑。
  - `vfs:storage`：依赖 `common`、`vfs:api`、`vfs:core`，实现 Storage Port，内部封装 OpenDAL。
  - `vfs:persistence`：依赖 `common`、`vfs:api`、`vfs:core`，实现 Persistence Port，内部封装 SQLDelight/SQLite。
  - `vfs:runtime`：组合上述模块，提供装配门面。
  - `integration-tests`：测试范围依赖全部模块。
- **抽象泄漏排查**：
  - `vfs:api` 与 `vfs:core` 中不存在任何 `org.apache.opendal`、`app.cash.sqldelight` 或 `java.sql` 类型。
- **日志依赖排查**：
  - 生产代码仅依赖 `org.slf4j:slf4j-api`，无任何具体 Logback / Log4j 生产实现依赖。

### A04 路径、路由与身份连续性 —— 通过
- 路径段边界验证：路径隔离以 `/` 为段边界（`a` 不影响 `a-old`）；祖先包含子 Mount 得到保护。
- 嵌套挂载：同名时挂载入口遮蔽底层物理入口；深层挂载仅逐段暴露。
- 身份与状态连续性：写覆盖、同 Mount 原生移动、跨 Mount 移动均保留 Node ID、Metadata 与 `registeredAt`。
- 删除重建：删除后原 ID 彻底失效（`NOT_FOUND`），同路径重建赋予全新 ID。正常关闭重开同一库持久保留状态。

### A05 状态提交与事件事务 —— 通过
- Storage I/O 在 SQLite 事务之外执行，避免外设/网络 I/O 阻塞数据库事务。
- 状态更新与事件插入在同一 SQLite 事务原子提交，提交成功后方触发分发。
- 事件粒度精确：目录移动产生且仅产生一条根级 `DIRECTORY_MOVED` 事件，不向后代文件爆破多余事件。
- 故障隔离：单 Consumer 异常被捕获丢弃，不阻塞并发与后继事件，也不外抛污染事务提交。

### A06 失败事实、取消与生命周期 —— 通过
- 失败语义：写丢失抛 `UNKNOWN` 不降级；目标确认失败或删源失败抛出异常附带 `PARTIAL`，不伪装回滚。
- 流所有权：流生命周期受管，超限即止；Runtime 实例关闭时回收遗忘流，释放底层句柄，避免资源泄漏。
- 关闭顺序与幂等：Runtime 关闭按停接新请求 → 停在途 → 关流 → 关 Adapter → 关状态库顺序收尾，多次调用幂等。

## 5. 未验证边界与已接受限制

1. **平台范围**：本阶段承诺且仅承诺 macOS arm64；Linux x64 / arm64 配置保留、未验证，后续按需安排。

3. **首版事件消费语义**：首版事件分发为进程内尽力而为分发，故障隔离丢弃；不提供跨进程消费、可靠重试、重放或 ACK 机制。
4. **并发原子性边界**：写入与原生移动的“目标不存在/父目录存在”为应用层预检，不对外部并发修改提供跨进程/底层存储强原子保证。
