### 2.1 UC-01 读取操作
- **契约要求**：支持有界整读 (`read`) 与流式读取 (`openStream`)；按实际读出字节计限；读不登记 Node、不修改 Metadata、不发事件；资源幂等释放。
- **实现入口**：`DefaultVfs.read`, `DefaultVfs.openStream`, `DefaultVfs.stat`, `WebDavStorage.read`, `WebDavStorage.readStream`, `LocalFsStorage.read`, `LocalFsStorage.readStream`
- **关键测试与断言**：
  1. `DefaultVfsReadTest.A01 an unregistered file can be read and reading it registers nothing`：
     - 断言：读出字节正确；`nodes.findByPath` 为 null；`committedNodes` 为空；`committedEvents` 为空。
     - 层级：Core + Storage 替身。
  2. `DefaultVfsReadTest.A01 the effective read limit is the smaller of the configured one and the per call one`：
     - 断言：恰好等于上限成功读取，超过上限报 `LIMIT_EXCEEDED`；按配置与调用级较小者生效。
     - 层级：Core + Storage 替身。
  3. `RuntimeStreamingVerticalTest.a file over the byte array default streams in chunks and matches the original digest`：
     - 断言：17 MiB 大文件触发 `read` 的 `LIMIT_EXCEEDED` 拒绝；通过 `openStream` 分块读取且逐块计算 SHA-256 与原文件一致；读完后 activeNodes 计数为 0，event 计数为 0。
     - 层级：公开 Runtime + 真实 Local FS + 真实 SQLite。
  4. `T25WebDavContractTest.A02 a file over the byte array limit streams in full via the public openStream`：
     - 断言：WebDAV 20 MiB 文件 `read` 报 `LIMIT_EXCEEDED`；`openStream` 完整读完并校验 SHA-256。
     - 层级：公开 Runtime + 真实 WebDAV 服务 + 真实 SQLite。
  5. `RuntimeStreamingVerticalTest.an unclosed stream is reclaimed by close and the same database can be reopened`：
     - 断言：遗忘未关的流在 Runtime `close()` 时自动回收；后续读取流抛出 `IOException` 或 `VfsException`；同一状态库可正常重开。
     - 层级：公开 Runtime + 真实 Local FS + 真实 SQLite。

- **实现入口**：`DefaultVfs.write`, `DefaultVfs.createMissingParents`, `WebDavStorage.write`, `LocalFsStorage.write`
- **关键测试与断言**：
  1. `DefaultVfsWriteTest.A02 a new file registers the node and appends FILE_CREATED in one commit` 与 `DefaultVfsWriteTest.A02 the mode matrix is enforced on the real existence of the target`：

  3. `LocalFsFileOperationTest.UPSERT both creates and replaces`：
     - 断言：目标缺失时 `UPSERT` 成功创建文件；目标已存在时 `UPSERT` 成功替换原有内容。

     - 层级：Core + Storage 替身。
  2. `DefaultVfsReadTest.A01 stat with includeStorage false answers an existing node without asking the backend` 与 `NodeRegistryQueryTest.A02 includeStorage false still confirms an unregistered resource`：

     - 路径：`vfs/core/src/test/kotlin/com/github/noahshen/alcyone/context/vfs/core/DefaultVfsReadTest.kt` 及 `vfs/core/src/test/kotlin/com/github/noahshen/alcyone/context/vfs/core/registry/NodeRegistryQueryTest.kt`。

  3. `NodeRegistryRealStackTest.A04 concurrent stats of one path leave exactly one node in a real database` 与 `RuntimeConcurrencyLifecycleTest.concurrent stats of one path hand out a single identity and register no event`：

  4. `NodeRegistryQueryTest.A02 an unknown or deleted id is NOT_FOUND`：
     - 断言：查询未登记的 Node ID 或已删除退役的 Node ID 均抛出 `VfsException(NOT_FOUND)`，effect 为 `NONE`。

     - 路径：`integration-tests/vfs/src/webdavTest/kotlin/com/github/noahshen/alcyone/context/vfs/integration/webdav/T25WebDavMoveTest.kt`。

  2. `T25WebDavMoveTest.A04 a directory moves from local to webdav keeping its tree and emitting one root event` 与 `T25WebDavMoveTest.A04 a directory moves from webdav to local with its empty subtree and source removal`：

  3. `DefaultVfsDirectoryMoveTest.A03 an existing target is refused and the source tree stays`：
     - 断言：目标目录已存在时抛出 `ALREADY_EXISTS`，在任何底层文件复制或删除前提前拒绝，源树内容完好，事件表为空。

### A02 公共入口与后端覆盖 —— 通过
- 公开门面 `AlcyoneVfs` 覆盖核心读写、流式读取、stat、元数据、删除、移动与事件监听。

  - `vfs:api`：直接项目依赖仅 `common`；第三方依赖仅协程与 kotlinx-serialization。对外导出接口与值对象。
  - `vfs:core`：直接项目依赖仅 `vfs:api`（`common` 经 api 传递依赖）；第三方库使用 `uuid-creator`；日志门面仅依赖 `org.slf4j:slf4j-api`。定义 Port 接口与编排逻辑。
  - `vfs:storage`：依赖 `vfs:core`；实现 Storage Port，内部封装 OpenDAL。
  - `vfs:persistence`：依赖 `vfs:core`；实现 Persistence Port，内部封装 SQLDelight/SQLite。
  - `vfs:runtime`：组合上述模块，提供装配门面。
  - `integration-tests`：测试范围依赖全部模块。
- **公共抽象泄漏排查**：
  - SDK 边界审查：`vfs:api`、`vfs:core` Port 接口及 `vfs:runtime` 门面中不存在任何 `org.apache.opendal`、`app.cash.sqldelight` 或 `java.sql` 类型暴露（底层模块内部实现类的 public 修饰符不外溢为 SDK 泄漏）。
- **生产日志绑定排查**：
  - 生产代码仅依赖 `org.slf4j:slf4j-api` 为日志门面，未打包任何 Logback / Log4j 具体实现。

### A04 路径、路由与身份连续性 —— 通过
- 路径段边界验证：路径隔离以 `/` 为段边界（`StateRepositorySemanticsSqliteTest` 验证 `findSubtree` 中 `/notes/a` 不误匹配 `/notes/abc`；`DefaultVfsRealStackTest` 的 `A03 the real database retires the whole registered subtree and a rebuild gets a new id` 验证 `/a` 删除不影响 `/a-old`）；祖先包含子 Mount 得到保护。
- 嵌套挂载：同名时挂载入口遮蔽底层物理入口；深层挂载仅逐段暴露。
- 身份与状态连续性：写覆盖、同 Mount 原生移动、跨 Mount 移动均保留 Node ID、Metadata 与 `registeredAt`。
- 删除重建：删除后原 ID 彻底失效（`NOT_FOUND`），同路径重建赋予全新 ID。正常关闭重开同一库持久保留状态。

### A05 状态提交与事件事务 —— 通过
- Storage I/O 在 SQLite 事务之外执行，避免外设/网络 I/O 阻塞数据库事务。
- 状态更新与事件插入在同一 SQLite 事务原子提交，提交成功后方触发分发；提交失败整事务回滚，事件与状态均不落库（append 冲突回滚见 `EventPipelineRealStackTest.A02 a rejected event id rolls back the node registered in the same transaction`；真实 COMMIT 失败见 `EventPipelineRealStackTest.A03 a real commit failure publishes nothing`）。
- 事件粒度精确：覆盖产生 `FILE_WRITTEN`；补父目录在 Mount 内完成且不单发事件；目录移动产生且仅产生一条根级 `DIRECTORY_MOVED` 事件，不向后代文件爆破多余事件。
- 故障与并发隔离：普通 Consumer 异常被捕获记录 WARN，`CancellationException` 原样传播，Error 不捕获；异步有界队列（默认 256）保护已提交操作不被分发阻塞；同一分发循环内慢 Consumer 会延迟后续通知。普通异常与事件上下文记录见 `EventDispatcherLogCaptureTest`；受管凭据保护闭环见 `WebDavRealServerTest.A05`。

### A06 失败事实、取消与生命周期 —— 通过
- 失败语义：已知目标变化下仅将 NONE 升为 PARTIAL，既有 UNKNOWN / PARTIAL、code 与 cause 如实保留；这是目标已发生物理变化后的阶段，不推广到源侧预检。Core 的 `withKnownTargetWrite` 规则确保目标确认或删源发生 UNKNOWN 时绝不降级（`DefaultVfsCopyMoveTest.A04 / A05`）。
- 取消阶段证据入口（复用 T18/T23/T27）：
  - **入口等锁取消**：`NodeRegistryBoundaryTest.A04 a waiter that gets cancelled sees a CancellationException` 与 `NodeRegistryBoundaryTest.A04 cancelling a waiter does not leave the lock held`（在边界等待锁阶段协程被取消，原样传播 `CancellationException` 且不遗留锁占用，安全退出；层级：组件替身）。
  - **Storage I/O 阶段取消**：`DefaultVfsRealStackTest.A06 a write cancelled at the DefaultVfs entry propagates, releases the lock and commits nothing` 及 `a delete cancelled at the DefaultVfs entry propagates...`（在 PausingStorage 的 I/O 挂起阶段到达后被取消，向外原样传播 `CancellationException`，锁正常释放，底层与状态零变更；层级：真栈）；以及 `DefaultVfsDirectoryMoveTest.A07 a cancellation during the tree copy stops before deleting the source and leaves the boundary usable`（目录复制中途取消，源树完整保留不删，边界锁正常释放可复用；层级：Core 替身）。

## 5. 未验证边界与已接受限制

1. **平台范围**：本阶段承诺且仅承诺 macOS arm64；Linux x64 / arm64 配置保留、未验证，后续按需安排。
2. **网络超时边界（方案④）**：SDK 对底层 native 网络调用不承诺全局超时强杀，服务器长时间静默挂起可能持续占用线程。
3. **首版事件消费语义**：首版事件分发为进程内尽力而为分发，普通异常隔离记录 WARN，CancellationException 原样传播，Error 不捕获；满队列丢弃；不提供跨进程消费、可靠重试、重放或 ACK 机制。
4. **并发原子性边界**：写入与原生移动的“目标不存在/父目录存在”为应用层预检，不对外部并发修改提供跨进程/底层存储强原子保证。
5. **范围与结论收窄**：审查结论限定于已核对条款与剩余边界，不作无限制的绝对化断言。
