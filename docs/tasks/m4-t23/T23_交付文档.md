## 3. 本轮补的四个缺口

1. **状态写入失败的业务层接线**：`FakeStateUnitOfWork.failOnStateWrite` 原来只在内存替身事务测试里用过，没有「经 `DefaultVfs` 走到真正提交事务时状态写失败」的用例。新增四类各一条，层级是**真实 SQLite + 真盘 + 状态写失败包装**。
2. **目录移动后项超限的整树 effect**：第一份已复制、目标根已建，第二个文件超限 → `PARTIAL`（不能照搬单文件读失败的 `NONE`）。
3. **T22 遗留的两种长度事实**：①源**真的**从 3 字节增长到 5 字节（真写内容，不是改 `sizeBytes` 数字）→ 复查拦住、不删源，直接断言源 5 / 目标 3 / 原 ID / Metadata / 无成功事件；②复查时当前长度仍为 `null` → 不阻碍。
4. **目录移动「物理完成、COMMIT 前」的取消窗口**：捕获取消内真正传播的异常，断物理与未提交逻辑分别的事实、后续可用。
