## 2. 必须修改

### R1：取消用例在异常退出时没有先结束子协程（A06）

位置：`integration-tests/vfs/src/test/kotlin/com/github/noahshen/alcyone/context/vfs/integration/vfs/DefaultVfsDirectoryMoveRealStackTest.kt:164–176`。创建 `async` 后，等待挂起点、cancel 和 join 只在正常路径执行，没有包在 `try/finally` 中；`withStack` 的 finally 只负责关闭通知器、数据库和 Storage。

若等待挂起点超时或测试线程被中断，调用会先退出 block 并关闭资源，而正在执行或回滚的子协程尚未被显式取消并等待。外层 runBlocking 的结构化取消发生得更晚，不能替代“结束在途工作后再关库”的顺序；这与任务 §2.5 明确要求不符。此项来自源码检查，不声称本轮正常运行发生了挂死。

修复：从启动 job 后开始用 try/finally 管理，finally 在必要的 NonCancellable 上下文中 cancel 并 join，完成后才退出 withStack。不需要新增生产代码或多轮稳定性测试；保留当前确定窗口及事实断言，验收记录 A06 的“finally 收尾”须与实际代码一致。

### R2：失败使用说明把有条件的事实写成了通用保证（A07）

位置：`T23_使用说明.md` §2、§3、§5；连带 `T23_验收记录.md` §3。

- **NONE**：不能据此断言“没有任何逻辑变化”。任务 §2.3 已明确不能排除失败前的源懒注册；例如复制读取失败前可能已完成源身份登记。请补充这个例外，避免使用说明与当前编排事实冲突。
- **错误保留**：`UNKNOWN` 是 effect，不是错误码。后端错误保留仅适用于对应 Storage 失败合并路径；物理完成后的状态失败仍包装成 `STATE_ERROR + PARTIAL`，cause 指向原失败，不能通称“code 按后端原样保留”。同理，cause / suppressed 不是每个异常都必有的字段。
- **残留事实**：“删源失败 → 两份都在”应为目标已写、源可能仍在 / 部分删除 / 结果未知；“复查发现矛盾 → 源完整”只能保证本次尚未进入删源，不能保证被外部修改后的源仍完整。预检的零副作用结论须限定在身份登记及物理修改之前的拒绝。
- **后续可用**：“失败不会把实例或锁留坏”应收窄为已验证的受控失败及回滚成功场景。复用的 COMMIT 失败测试主动关闭了状态库，本身不支持“任意失败后实例仍可用”。正常重开也不等于修复物理与逻辑的不一致。
- 验收 §3 的“Node / Metadata / 事件一起丢失”改为“本事务修改回滚，旧记录 / Metadata 保留，失败操作的成功事件未提交”。现有断言证明的是后者，不是丢失旧数据。

修复以文字订正为主，不为过强描述扩展实现或新建异常矩阵。T01 §7.1 原表也有简写，但紧接着已提醒懒注册可能改变状态；本轮使用说明至少应保留并解释该边界，而不能省去限制。
