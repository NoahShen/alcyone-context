## 1. 目标与范围

对已实现的写入、删除、文件与目录移动做统一失败验证，证明失败报告与物理文件、逻辑状态、事件事实一致；复用已有测试，只补没有直接证据的关键分支。允许修复测试暴露的实现缺陷，但不借此新增公共 API、补偿 / 自动重试、恢复日志或通用故障注入框架。

例：文件已写入而 SQLite 提交失败，目标内容仍在、数据库回滚、没有成功通知，异常应是 STATE_ERROR + PARTIAL。T23 验证和说明这个边界，不把物理文件自动恢复为旧内容；通过后才可由复核方收口 M4。

## 2. 验证内容

### 2.1 先建立证据索引

在验收记录按“操作 × 失败阶段”列出已有用例、实际断言和剩余缺口，区分真实 SQLite / Local FS、真实组件加故障包装、内存替身和源码审查。同一机制只需有效代表，不做所有操作、阶段、错误码的笛卡尔积；历史文档所称“全矩阵留 T23”在此收敛为下述关键组合，并明确未验证边界。

例：目录事件冲突已验证根与子路径一起回滚，直接引用 T22 真栈用例；不能为了增加测试数量复制一份改名。引用必须定位文件与用例，且不能把“事件表行数不变”写成已直接观测通知。

### 2.2 物理成功与状态失败

写入、删除、原生文件移动、复制文件移动、目录移动都需有“物理成功 / 状态失败”的对应证据，核对实际文件、Node 路径 / 有效状态、Metadata 和事件；状态写入与事件追加失败都要有代表。至少一条真实 SQLite COMMIT 拒绝的机制证据可复用既有 EventPipeline / Persistence 测试，与业务调用接线审查组合，不把回调抛错或事件主键冲突冒称为 COMMIT 本身失败。

例：目录多个 Node 更新后事件追加失败，全部路径回滚，物理树不回移；删除后提交失败，文件不会复活，旧逻辑 Node / Metadata 可能仍在。不要在失败后的事实核查里调用会懒注册的 stat 来改变待核对状态。

### 2.3 部分物理完成与 effect

补目录、部分写入、复制成功后确认失败、部分删源等阶段保留已知变化，后端 UNKNOWN 不被降成 NONE / PARTIAL，错误码和原因按既定规则保留。NONE 只按既定物理 effect 口径解释，不能推导“连源懒注册都没发生”；保留原 ID / Metadata，不生成临时目标身份或成功事件来掩盖失败。

例：第二个文件超限时，第一份目标已复制且目标根已建，不能像单文件读失败一样报 NONE。用例应先证明第一份确实成功，再触发后项失败；缺口可用路径 / 次数受控包装补齐，无须制造真实磁盘损坏。

### 2.4 通知与提交边界

确认未提交的状态失败不产生成功日志或成功通知，事务成功后才通知；订阅必须在被测操作前建立，并用有序末尾标记等确定性判据排除“还没收到”的竞争。Consumer 失败不回滚已提交操作可引用 T14；消费者投递、关闭竞争和压力测试的扩展仍属 T26 / T27。

例：写入返回失败、事件行数未增加，再等待同队列的末尾事件，确认没有该操作的成功通知。COMMIT 已成功后的取消或通知丢失不能倒推数据库回滚，不能用统一“异常即无事件”断言覆盖所有阶段。

### 2.5 有限的取消窗口与后续可用性

保留已验证的复制中取消，再核对一个“物理已完成、事务提交前”的确定窗口，捕获调用内真正传播的 CancellationException，按该窗口断物理 / 逻辑 / 事件事实；既有 T16 用例若满足可直接复用。失败后选一次后续操作证明边界和事务未残留，所有受控门和协程在 finally 中放行 / 取消并等待收尾后再关资源。

例：源文件已删除但事件事务尚未提交时取消，磁盘事实不能因抛取消而被写成“无变更”。不要求覆盖每条指令间的取消，不强杀进程，不把正常重开读库当成恢复中断操作。

### 2.6 T22 遗留证据强度与使用说明

T22 最后两个长度用例已支持分支判断，但“源真的从 3 字节变 5 字节”“复查仍未知”未直接验证；T23 用同一小装置补齐这两种事实，并直接比较源 / 目标、原身份 / Metadata 与事件。其他历史证据若只是描述过强，先收窄措辞；不要为文档声称补造结果或把交付方变异标成独立复核实跑。

例：第一份源文件复制后真的追加内容，最终源枚举报告新长度，应拒绝删源；对照让最终长度仍为 null，不能把未知当 0 或一概拒绝。使用说明以“看到错误后可能留下什么”为主，提醒按事实检查，不能建议无条件重试或自行清库来恢复。

## 3. 既有证据入口与关键组合

| 入口 | 优先复用的内容 |
| --- | --- |
| `DefaultVfsRealStackTest`（integration-tests/vfs） | 写入物理成功 / 事件失败、补父目录失败、删除与状态回滚、提交前取消 |
| `DefaultVfsMoveRealStackTest` / `DefaultVfsCopyMoveRealStackTest` | 原生 / 复制移动、身份保持、事件冲突、复制 / 删源阶段失败 |
| `DefaultVfsDirectoryMoveRealStackTest` / `RuntimeDirectoryMoveTest` | 多路径真实事务回滚、失败无通知、成功目录事件与重开身份 |
| `EventPipelineRealStackTest` / Persistence 事务测试 | 提交前不通知、真实 COMMIT 失败、取消与事务清理；注明机制证据与业务接线证据的区别 |
| Core 的 write / delete / move / directory 测试 | 后端错误码、UNKNOWN、部分完成、调用顺序和受控并发；不能替代真库回滚 |

| 关键组合 | 期望事实与补证方向 |
| --- | --- |
| 已知拒绝 / 存储未变更 | 不产生成功事件；已有预检代表可复用，不重建完整参数矩阵 |
| 已建目录或已写部分内容后失败 | 残留如实可见、NONE 升 PARTIAL，UNKNOWN 保留 |
| 复制目标成功、确认或源删除失败 | 原逻辑映射保持，源 / 目标按实际状态断言，不补偿、不报整体成功 |
| 物理完成、Node / Metadata 事务更新失败 | 真库回滚已执行的状态更新，物理不回滚；原 cause 保留 |
| 状态更新后、事件追加失败 | 状态和事件同事务回滚；无成功通知；可引用已有真实主键冲突 |
| SQLite COMMIT 本身失败 | 用已有真实失败机制证明没有成功提交 / 通知，不与追加失败混称；无需对每种业务重复注入 |
| 物理完成、COMMIT 前取消 | 取消原样传播，物理变化与未提交逻辑分别断言，后续操作仍可用 |

若盘点发现某项已有等强度直接证据，记录引用即可。必要修复限于真实缺口，测试装置优先复用现有包装，不新增生产环境的通用 failpoint。

## 5. 验收标准

| 编号 | 必须满足 | 核心证据 |
| --- | --- | --- |
| A01 覆盖索引 | 写入、删除、原生文件移动、复制文件移动、目录移动均可定位失败证据 | 按阶段列用例 / 层级 / 直接断言；复用与新增分开，不写“全绿所以覆盖” |
| A02 状态与事件原子性 | 物理成功后的状态写入失败、事件追加失败、COMMIT 失败机制均有证据 | 真 SQLite 回滚与日志核对；多路径或含 Metadata 的代表；业务种类可复用现有真栈，不要求各阶段全部交叉 |
| A03 物理事实与异常 | 所列代表场景核对物理、逻辑、Metadata、事件、异常 code / effect / cause，不补偿 | 至少覆盖部分内容 / 后项失败、确认失败、部分删源；T21 / T22 既有用例可引用，后项超限的整树 effect 缺口应补 |
| A04 UNKNOWN 与原始错误 | 已知变化不被抹去，UNKNOWN 不降级，原错误可追溯 | 按各个实际异常合并分支核对；共用 helper 单测加接线证据可复用，不复制全码值矩阵 |
| A05 提交与通知 | 未提交的代表失败直接证明无成功通知，提交前不通知；已提交成功不因 Consumer 失败回滚 | 操作前订阅、按标记等待；T14 机制复用说明；区分日志断言与消费断言 |
| A06 取消与清理 | 一个物理完成 / COMMIT 前确定窗口原样传播取消，事实与阶段一致，后续可用 | 既有满足条件的用例可复用，直接捕获调用内异常；finally 收尾；不声称覆盖 COMMIT 后取消或崩溃恢复 |
| A07 证据与使用说明 | 补齐 T22 两种长度场景的直接事实证据；错误后的残留状态对宿主可理解 | 本任务补真实内容增长与当前长度未知对照；盘上内容、身份 / Metadata 与事件直接断言，故障包装如实归属 |

测试数量不限，不要求变异数量或十连跑；需要变异验证时记录具体改动、命中的断言与执行人，保留源码恢复后的完整检查结果。T23 不负责 WebDAV（T24 / T25）、可靠消费扩展（T26）、广泛并发 / 生命周期验证（T27）或跨平台实跑（T28）。
