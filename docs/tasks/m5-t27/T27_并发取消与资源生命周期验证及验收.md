## 1. 目标与边界

验证同一 Runtime 内的并发调用符合既定串行边界，取消按实际阶段报告，关闭在操作与流收尾后释放资源。先整理已有证据，只补真实缺口；发现实现缺陷才做最小修复，不为了测试重写锁、事务或生命周期机制。

例：两个调用同时对同一路径 CREATE_NEW，只有一个创建成功，另一调用得到 ALREADY_EXISTS；最终文件、有效 Node 和成功事件应对应获胜调用，不能留下两个有效身份。

本轮不承诺 read / list / 流具有文件快照、不规定协程启动顺序就是提交顺序，也不保证外部程序同时改文件时的隔离。崩溃恢复、断点续做、可靠消费仍延后；方案④保持：协作取消不等于能中断 native 阻塞，closeGracePeriod 不是 close 的最长耗时，不要求增加网络超时或强杀机制。

## 2. 验证内容

### 2.1 并发登记与同路径变更

核对并发 stat 懒注册返回同一个 Node ID，真库中同一路径只有一个有效记录且无注册事件；read / list 不变成登记操作。再用公开 Runtime 的同路径 CREATE_NEW 竞争作代表，比较每次调用结果、实际内容、有效记录和持久事件；其他写 / 删 / 移动串行化沿用已有受控用例。

例：调用甲写 A、乙写 B，不预设谁先成功；若甲获胜，最终读回 A，只记录甲的成功创建事件。两者都完成才查结果，单纯看到“最后只有一个文件”不足以证明并发规则。

### 2.2 Metadata 与文件操作交错

补或复用一个 Metadata 更新与移动（或删除）共用 StateBoundary 的受控代表，按实际串行次序核对身份、Metadata、路径和持久事件。至少将其中一个操作停在确定阶段、确认另一个已开始尝试但未进入受保护工作，再放行；允许使用真实 SQLite 配合受控 Storage / Repository 包装，不要求为公开 Runtime 增加注入 API。

例：移动先完成，按旧 Node ID 更新 Metadata 仍定位到新路径，其 METADATA_UPDATED 的 URI 应为新路径；若选择删除代表，删除后的旧 ID 更新应报 NOT_FOUND，不能复活记录。选一种代表即可，不做所有操作两两排列。

### 2.3 取消阶段与事实

复用入口等待、Storage 阶段、事务内 COMMIT 前和流交接的取消证据，分别写清物理内容、逻辑记录、持久事件及异常观察；确认事务回滚才断言没有成功逻辑事件。原异常身份需在调用协程内捕获直接比较，不能拿外层 await 的取消包装或 isCancelled 代替；不强制制造 COMMIT 后极窄窗口。

例：目录已搬完、事务在提交前取消，路径更新回滚，但磁盘变化不会自动恢复；单凭 CancellationException 不能断言“什么都没发生”。“取消后实例仍可用”只指已验证场景，不推广到任意失败。

### 2.4 关闭与在途工作

验证进入 closing 后拒绝新操作、已接纳操作可在等待期内完成、到点取消实际工作但等其收尾后才关库放锁。并发 close、回调 close、初始化失败与清理异常沿用 T18 的受控证据；核对 work / done 分工和取消登记原子性，不另建停机框架。

例：操作正在清理时 close 已进入等待阶段，此时同库重开仍应 CONFLICT；清理放行且 close 完成后才可重开。测试超时只用于防挂死，不能作为 native 请求有超时保障的证据。

### 2.5 流与反复创建 / 关闭

复用 T12 / T18 / T25 的 reader 所有权、读与关互斥、交接取消、遗漏流回收及重复关闭证据；“集合已清空”不能单独证明底层 handle 已释放。补或复用公开 Runtime 的有限轮次创建 / 关闭代表，每轮使用真实资源、交替显式关闭与遗漏流回收，确认旧流不可读且同库能再次打开；轮数由开发方选择并记录。

例：创建实例 → 写入并打开流 → 主动关 result 或交给 Runtime 回收 → close → 同库重开核对身份。结论限定为所测轮次与可观测资源，无需平台相关 FD 基准、强制 GC 或以瞬时堆内存断言“绝对无泄漏”。

### 2.6 时序与测试清理

并发代表要说明“谁到达哪个阶段、谁在等待、放行后哪个调用返回什么”，不以 sleep、重复跑绿或任务尚未完成作为唯一判据；无法控制先后时，接受并直接核对合法结果集合。测试用 finally 放行或在 NonCancellable 中取消并等待自己启动的任务，再关闭 Runtime / 数据库；叠加清理失败时保留主异常。

例：Metadata 的第二次调用返回值要直接保存并断言，不能另查一次后把那个结果当成并发调用的返回。允许复用既有 internal 接缝，不为测试新增公共诊断接口或反复引入独立作用域。

## 4. 验收标准

| 编号 | 必须满足 | 证据要求 |
| --- | --- | --- |
| A01 并发登记 | 同路径 stat 复用唯一有效身份，不产生登记事件，read / list 不登记 | 真 SQLite 并发代表，比较所有调用返回 ID 与有效行数；可复用 NodeRegistry 证据 |
| A02 同路径变更 | 公开 Runtime 同路径 CREATE_NEW 一成功一 ALREADY_EXISTS，内容 / 身份 / 成功事件对应获胜调用 | 两个调用通过同一启动门发起，收集全部结果；真库与内容直接核对。启动门不冒充已经同时进入临界区，串行机制另复用受控用例 |
| A03 Metadata 交错 | Metadata 与移动或删除共用串行边界，结果符合受控次序，身份和事件 URI 正确 | 一个受控交错代表，真实 SQLite 可加故障包装；记录第二调用实际结果，不能只断言事后再查询 |
| A04 取消事实 | 原取消语义保持，阶段明确、事实与事务结果一致，UNKNOWN 不被无依据降级 | 复用 T18 / T23 / T25，区分入口等待 / I/O / 事务 / 交接；直接异常比较与 isCancelled 证据分别标明，不要求 COMMIT 后注入 |
| A05 安全关闭 | 停接纳、等待、协作取消、等清理后释放顺序成立；并发 close 共享结果，宿主父 Job 不受误取消 | 复用真实 Runtime + 受控门的 T18 用例，直接确认 close 已等待及锁未提前释放；初始化 / 异常清理可复用 |
| A06 流所有权 | 交接失败不泄漏、读关互斥、遗忘流回收、重复关闭不重复释放 | 公开 Runtime 与 Adapter 分层组合；底层释放需已有计数 / handle 证据，不能只凭集合大小；两后端不复制整套矩阵 |
| A07 反复生命周期 | 有限轮次真实创建 / 关闭后可重开同库，已提交身份保留、旧流已关闭，无所测资源残留迹象 | 公开 Runtime 代表，记录轮数、资源观测与限制；主动 / 遗忘流关闭均涉及，native 内存 / 全局线程无泄漏不作未测推断 |
| A08 回归与边界 | 文档索引、实现和计数一致，无公共诊断或新并发模型，方案④保持 | 分别运行 scripts/check 与 scripts/webdav-check；记录平台 / 提交 / XML 与源码计数，服务不可用记阻塞而非通过 |

没有固定新增测试数、压力规模或变异次数。需要验证关键判据时可做局部变异，但如实记录执行人、改动、报警用例，不能把历史变异或重复跑绿当成本轮确定时序证据。
