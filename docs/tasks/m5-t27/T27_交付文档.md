## 1. 交付范围

复用 T13 / T15 / T18 / T23 / T25 / T26 的并发、取消与生命周期实现与测试，按 A01～A08 建立证据索引（见验收记录 §2），只补公开 Runtime / 受控交错上**确属缺口**的五条代表：

1. **A01 并发登记（公开代表）**：同启动门发起 8 次公开 `stat` 同一未登记路径，收集全部返回 ID，核对唯一身份、真库单条有效记录、无登记事件；`read` / `list` 之后仍未登记。Registry 层的唯一身份证据（`NodeRegistryRealStackTest`）继续复用。
2. **A02 同路径变更（公开代表）**：两个调用经同一启动门对同一路径 `CREATE_NEW`，收集全部结果；一成功一 `ALREADY_EXISTS`，磁盘内容 / 有效记录 / 唯一成功事件都对应获胜调用。
3. **A03 Metadata 交错（受控代表）**：移动停在真正 rename 前（持共享边界），第二调用按旧 Node ID 更新 Metadata 排队在边界后、放行前未进受保护工作；放行后移动提交完，更新才落库，Metadata 在新路径、`METADATA_UPDATED` URI 是新路径。第二调用的返回值直接保存后断言。
4. **A03 Metadata 交错（公开入口配套）**：移动先完成后按旧 ID 更新（无注入 API，纯真实资源），核对身份 / 路径 / 事件 URI。
5. **A07 反复生命周期（公开代表）**：3 轮真实创建 / 关闭，交替「显式关流」与「交给 Runtime 回收」，每轮确认旧流不可读、同库可重开、已提交身份保留。

**未新增**崩溃恢复、断点续做、可靠消费、网络超时或强杀机制；未新增公共诊断接口；未改模块边界；未修实现缺陷（本轮未暴露新的生产行为问题）。

## 4. 补的五条代表（S2）

1. `RuntimeConcurrencyLifecycleTest :: concurrent stats of one path hand out a single identity and register no event`（A01）
   - 真 SQLite + 真本机目录 + 公开 `AlcyoneVfs`。先写种子文件证明事件通路，再核对 `read` / `list` 后仍未登记、无事件。
   - 同一 `CompletableDeferred` 门：8 个 `async` 建好后一次性 `complete`，收集全部返回 ID。
   - 断言：ID 唯一；同路径有效记录 1 条；同路径多有效身份 0 组；有效记录就是返回的身份；`event` 行数与种子后一致（懒注册不发事件）。
2. `RuntimeConcurrencyLifecycleTest :: a same path CREATE_NEW race leaves one winner and the loser sees ALREADY_EXISTS`（A02）
   - 甲写 A、乙写 B，同一启动门同时发起，`runCatching` 收集「结果或异常」两边都存。
   - 断言：恰好 1 成功 1 失败；失败方**自身的**异常是 `ALREADY_EXISTS`；磁盘内容、读回内容、有效记录都对应获胜调用；唯一 `FILE_CREATED` 的 `node_id` 是获胜身份。
3. `DefaultVfsRealStackTest :: A03 a metadata update by the old id queues behind a move at the shared boundary`（A03 受控）
   - 真实 SQLite + 真本地磁盘 + 真 `DefaultVfs`，包一层 `PausingMetadataMoveStorage` 把 `Storage.move` 停在 rename 前（此刻整条移动链持共享边界）。
   - 第二调用用**旧 ID** `setMetadata`：`start = UNDISPATCHED` 跑到第一个挂起点（取边界）即停在门上；放行前直接查库断言事件数 / Metadata 未变。
   - 放行后：第二调用自身返回成功（`Result` 保存后断言）；`FILE_CREATED → FILE_MOVED → METADATA_UPDATED` 顺序；Metadata 落在已移动身份、新路径有效、旧路径无有效记录；`METADATA_UPDATED.uri` 是新路径。
4. `RuntimeConcurrencyLifecycleTest :: a metadata update by the old id after a move lands on the new path with the new uri`（A03 公开）
   - 公开入口、无注入 API：移动先返回（目标路径），再按旧 ID `setMetadata`；第二调用返回 / 异常直接 `runCatching` 保存后断言。
   - 断言：旧 ID 仍有效且指向新路径；Metadata 落该身份；事件序列与 `METADATA_UPDATED.uri` 为新路径。
5. `RuntimeConcurrencyLifecycleTest :: three rounds of create and close alternate explicit and reclaimed streams and always reopen`（A07）
   - 3 轮，每轮新建真 Runtime；写同一路径（复用同一身份）、`openStream` 真读；偶数轮调用方显式 `close`，奇数轮故意不关留给 Runtime 回收。
   - 每轮 `close()` 后：本轮所有打开过的流都不可读（`IOException` 或 `VfsException`）；同库重开成功、已提交身份与内容还在。
   - 结论限定为 3 轮与可观测资源，不作堆内存 / 无泄漏推断。

## 6. 未验证边界

- **崩溃恢复 / 断点续做 / 可靠消费仍延后**：本轮只覆盖进程内串行边界与正常关闭重开，不验证崩溃一致性，也不承诺可靠投递（E05）。
- **不做无泄漏推断**：A07 只记录 3 轮与可观测资源（旧流不可读 + 重开成功），不测平台 FD、不强制 GC、不以瞬时堆内存断言「绝对无泄漏」。
- **外部并发不保证**：不保证外部程序同时改同一文件时的隔离。
- **方案④保持**：协作取消 ≠ 中断 native 阻塞；`closeGracePeriod` 不是 `close` 的最长耗时；不新增网络超时或强杀。测试超时只用于防挂死。
- **取消事实不笼统**：不把 `CancellationException` 当「什么都没发生」；物理已完成、逻辑回滚分列；不构造 COMMIT 后极窄窗口。
- **本轮未做变异**：关键判据复用既有受控证据已足，未做局部变异；如后续补变异，按任务文档要求如实记录执行人 / 改动 / 报警用例。
