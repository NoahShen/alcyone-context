### 1. 目标与范围

建立可构建的 Kotlin 多模块骨架，以及仅对本项目生效的 Java / Gradle 开发入口。沿用 [AGENTS](../../../AGENTS.md)、[工程结构](<../../Alcyone Context 项目搭建说明 v0.1.md>) 和 [T04 已验证版本](../../vfs/VFS_依赖与能力验证_v0.1.md)，不提前实现 T06 公共 API、T07 Port、T08 CI 或 T11 数据库 Schema。

例：本次应能构建 `vfs/core`，但不需要实现 `Vfs.write()` 或创建 Node 表。

### 2. 项目内开发环境

提供 `./scripts/dev bootstrap` 和 `./scripts/dev gradle <参数>` 两个入口：前者准备项目内环境，后者在子进程中设置 Java 与 Gradle 环境后调用仓库 Wrapper。启动 JVM、Gradle Daemon、Kotlin / Java 编译及后续测试均须使用项目内 JDK 21，不能只设置编译目标版本或依赖系统已安装 JDK。

例：终端原本使用 Java 11，执行项目构建时使用 JDK 21，命令结束后同一终端仍使用 Java 11。

| 内容 | 约定位置或行为 |
| --- | --- |
| JDK | `.local/jdk/`；解压 Temurin 21.0.12.1+1，记录来源和 SHA-256 |
| Gradle 发行包、缓存及 Daemon 状态 | `.local/gradle-user-home/`，通过进程级 `GRADLE_USER_HOME` 指定 |
| 项目缓存与编译产物 | 仓库内 `.gradle/`、`.kotlin/` 和各模块 `build/` |
| 下载暂存与可配置的构建临时目录 | `.local/tmp/`；不依赖 T04 遗留的 `/tmp/alcyone-t04/` |
| 仓库提交内容 | 环境准备入口、版本 / 校验信息、Wrapper、构建配置及说明；不提交 JDK、缓存或生成产物 |

入口自行定位仓库根目录，设置 `JAVA_HOME` 及必要的进程级路径，明确指定项目 JDK 为 toolchain，避免自动选中系统其他 JDK；不得修改 shell 启动文件、系统 Java 链接、全局 PATH 或用户级 Gradle 配置。首次准备允许联网下载并校验，重复执行应复用正确版本，缺失或损坏时明确失败或重新准备，不能回退到系统工具。

例：在父目录调用该入口也能定位项目；无系统 Gradle 时仍能通过 Wrapper 构建。Gradle 的环境配置与 toolchain 是两个独立配置点，依据 [环境配置文档](https://docs.gradle.org/current/userguide/build_environment.html) 和 [toolchain 文档](https://docs.gradle.org/current/userguide/toolchains.html)，开发时核对 8.14.3 的实际行为。

### 3. Wrapper 与依赖版本

使用 Gradle 8.14.3、Kotlin 2.2.21 和 JVM 21，其他依赖沿用 T04，并在版本目录或等效的单一位置集中声明，禁止动态版本。提交标准 Wrapper 文件和发行包 SHA-256，保留生成的 Wrapper 脚本，将项目环境逻辑放在开发入口；首次生成 Wrapper 所需的 Gradle 也只能在项目内准备。

例：现有 `.gitignore` 忽略 `*.jar`，开发 Agent 需为 `gradle/wrapper/gradle-wrapper.jar` 增加精确例外，不能遗漏 Wrapper JAR。应提交的 Wrapper 文件和校验方式见 [官方 Wrapper 文档](https://docs.gradle.org/current/userguide/gradle_wrapper.html)。

### 4. 模块与依赖方向

根工程包含以下六个功能模块；Gradle 自动产生的分组父项目可以保留，但不作为额外业务模块。依赖只按职责配置，正式库不附带日志实现，T04 独立验证工程不并入根构建或生产产物。

| 模块 | 项目依赖与基础设施边界 |
| --- | --- |
| `:vfs:api` | 无内部模块依赖；不引入 OpenDAL、SQLDelight 或 JDBC |
| `:vfs:core` | 依赖 api；不依赖具体 Adapter |
| `:vfs:storage-opendal` | 依赖 core；按类型引用需要依赖 api，封装 OpenDAL 及匹配版本的 native 包 |
| `:vfs:persistence-sqldelight` | 依赖 core；按类型引用需要依赖 api，配置 SQLDelight 插件及 SQLite Driver |
| `:vfs:runtime` | 依赖 api、core 和两个基础设施模块，负责后续组装 |
| `:integration-tests:vfs` | 依赖 runtime；按测试需要依赖 api 等模块，不被生产模块反向依赖 |

例：`api` 的编译依赖图中不应出现 OpenDAL；native 包按已确认的 macOS arm64 配置，其他平台给出明确范围提示，不自动声称支持。

### 5. 骨架与构建验证

配置各模块 Kotlin/JVM 源集、JVM 21 toolchain 和必要插件，`clean build` 可运行；正式 SQL、业务类和用例测试按后续任务实现。空模块的 `NO-SOURCE` 不算编译器验证，需用临时最小 Kotlin 样例证明六个模块的编译任务实际可执行，移除样例后重新清理构建，最终产物不保留探针。

例：临时样例只含简单 Kotlin 声明，不复制 T04 的数据库或存储测试，也不编造尚未实现的业务测试。

### 6. 验收标准

以下各项都需要实际证据；只完成目录和配置文件不能认定 T05 通过。具体诊断任务可由开发 Agent 选择，但证据必须区分启动 JVM、Daemon 与编译 toolchain，而不只是打印一个 `JAVA_HOME`。

| 编号 | 必须满足的结果 | 提交的证据 |
| --- | --- | --- |
| A01 环境准备 | macOS arm64 可从没有项目工具缓存的干净副本准备环境，不依赖全局 Gradle 或 T04 临时目录 | 准备命令、工具来源 / 校验、实际安装路径；使用独立副本避免清理用户现有缓存 |
| A02 环境隔离 | JDK、Gradle 发行包和依赖缓存位于项目内；父 shell 和系统默认 Java 保持原样 | 执行前后 `command -v java`、`java -version`、JAVA_HOME / PATH 对比，以及入口的环境设置审查 |
| A03 工具选择 | 启动、Daemon 和编译均指向项目 JDK 21，Gradle 为 8.14.3、Kotlin 为 2.2.21 | Wrapper 版本输出、JVM / toolchain 路径与编译诊断；检查后续 Test 任务的 JDK 配置，无测试时如实注明 |
| A04 模块关系 | 六个功能模块均被根工程识别，依赖方向符合第 4 项 | `projects` 输出、各模块依赖报告与构建文件检查 |
| A05 编译与构建 | 六个模块实际完成最小 Kotlin 编译，移除临时样例后 `clean build` 成功 | 非 NO-SOURCE 的编译记录及最终构建结果；空测试不算业务测试通过 |
| A06 版本与基础依赖 | T04 版本固定，相关编译 / 运行依赖可解析，OpenDAL Java 与 native 版本匹配 | 版本配置、相关模块的 compile / runtime classpath 解析结果；本轮不重复验收存储行为 |
| A07 可重复与可提交 | 环境准备可重复执行，构建路径不绑定开发者绝对目录，Wrapper 完整可交付 | 二次准备结果、独立副本构建记录、Git 忽略检查和文件清单 |
| A08 范围与说明 | 无越界业务实现，环境及构建说明可执行，不改用户无关文件 | 变更清单、简短使用说明及剩余限制；修改文档均有前部“本次修改” |

例：`build` 成功但实际使用系统 JDK，A02 / A03 仍不通过；`test NO-SOURCE` 可以符合骨架阶段，但不能写成“所有 SDK 测试通过”。

### 7. 交付与验收流程

开发 Agent 开始时将 T05 改为 `IN_PROGRESS` 并填写负责人；完成自测后提交验收记录，改为 `IN_REVIEW`，不自行标记 `DONE` 或进入 T06。用户将结果交回当前对话后，由验收 Agent 审查变更并运行必要检查，通过后记录 DONE；发现问题则交回开发 Agent 修复，验收 Agent 不改实现代码。

例：验收记录逐项填写 A01～A08 的结果、命令、日志位置和未验证内容；发现 Wrapper JAR 遗漏时退回补齐，而不是在验收时替开发 Agent 修改代码。
