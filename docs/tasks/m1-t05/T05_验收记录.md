## 3. JVM 与真实编译证据

启动 JVM 的 `java.home` 由 Wrapper 进程的 `-XshowSettings:properties` 输出，Gradle Daemon 的 `System.getProperty("java.home")` 由临时诊断任务输出，两者均为上述项目 JDK。`probe-build.log` 中 Kotlin Daemon 启动命令指向同一 `bin/java`，六次 `[KOTLIN] Kotlin compilation 'jdkHome' argument` 也指向同一目录；Kotlin Daemon 的 `--daemon-runFilesPath` 已落实到 `.local/tmp/kotlin-daemon`。

项目使用 Kotlin 编译器 `2.2.21`：版本目录、诊断输出和实际 `kotlin-compiler-embeddable/2.2.21` 启动 classpath 相互吻合。Wrapper `--version` 中的 `Kotlin: 2.0.21` 是 Gradle 内置 Kotlin DSL，不能将其误当项目编译器版本。

六模块临时编译日志中实际出现以下任务，均没有 NO-SOURCE 或 UP-TO-DATE 后缀：

```text
> Task :vfs:api:compileKotlin
> Task :vfs:core:compileKotlin
> Task :vfs:persistence-sqldelight:compileKotlin
> Task :vfs:storage-opendal:compileKotlin
> Task :vfs:runtime:compileKotlin
> Task :integration-tests:vfs:compileKotlin
BUILD SUCCESSFUL
```

Test 由根构建的 `tasks.withType<Test>()` 配置 `javaLauncher` 为 JDK 21，六个已解析 launcher 路径见 `diagnostics.log`。集成测试模块使用 kotlin-test-junit5 与固定 JUnit BOM 5.11.4；本轮仅验证依赖和任务配置，无测试源码，也未启动 JUnit 测试进程。

Kotlin Daemon 跟随 Gradle JDK 的行为参考 [Kotlin 官方文档](https://kotlinlang.org/docs/gradle-compilation-and-caches.html)，具体路径以上述本机日志为准；Gradle toolchain 禁用自动发现并使用入口传入的项目路径，依据 [Gradle 8.14.3 文档](https://docs.gradle.org/8.14.3/userguide/toolchains.html)。
