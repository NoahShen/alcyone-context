## 2. 必须修改

### R1 / P2：补父目录中途失败会丢失已经创建目录的事实

位置：`DefaultVfs.createMissingParents` 的 `missing.forEach { storage.createDirectory(it) }`，以及 `writeInsideBoundary` 调用该函数的位置。已有 effect 合并只包住最终 `storage.write`；父目录创建成功一部分后，后续 createDirectory 抛错会直接退出，先前副作用未合并。

独立探针：写 `/resources/a/b/file.txt`，创建 a 成功，创建 a/b 返回 `STORAGE_ACCESS_DENIED/NONE`，最终仍报告 NONE，盘中 a 却已存在。未产生 Node / Event 是正确的，但不能据此宣称整次操作无副作用。

修复：逐步保留父目录创建事实，覆盖“建目录阶段自身失败”和“建完后写文件失败”，仍保留原错误码/cause、后端 UNKNOWN 及取消异常原义；不回删目录或自动补偿。补正式用例：第一层成功、第二层失败报告 PARTIAL；首层无变更失败保持 NONE；后续 UNKNOWN 不降级，成功事件与状态均不提交。

### R2 / P2：A02 / A06 的现有证据不足以支撑全项通过

位置：`DefaultVfsRealStackTest` 的 A02 覆盖用例、A06 串行用例，以及验收记录第 3 节。现有串行用例先 `secondStarted.complete` 再调用 write，随后以 `withTimeoutOrNull(2_000)` 判断尚未完成；第二请求可能还没运行到锁，提前成功的返回值也为 null，与超时混同，不能把该检查描述为确定的锁等待证据（后续 ALREADY_EXISTS / writeCalls 断言仍有价值）。

最小补证据：用可控启动/调度确保第二请求运行到挂起点再放开第一写，验证第二次物理变更未越过边界、一成一败；不增加生产测试接缝或调度框架。另补一次 DefaultVfs 写链上的受控取消，确认 CancellationException 原样传播、锁释放且未产生成功事件；T14 取消回归只能证明组件路径，不能替代新编排入口。

A02 已验证 ID / registeredAt 与事件类型，未预置非空 Metadata 后再覆盖；在现有真实栈覆盖用例里增加一次 Metadata 写入和读回比较即可。无需调用尚未交付的 setMetadata API，可用测试已有 Repository；上述均是原 A02 / A06 要求，不是追加 T27 的完整并发矩阵。

## 3. 用户关注的设计边界

### 3.1 write 全链持锁：接受

参数限额在锁外完成，其余预检、Storage stat、补父目录、write、状态事务和非阻塞事件交接均在同一个 StateBoundary 内。对于首版单状态库、单 Runtime 的串行策略，这是必要且简单的保证，能避免 CREATE_NEW 在物理层已竞争完才排队提交状态。

代价是慢 Storage I/O 会阻塞其他写和当前同样持锁的 read/list/stat；首版可以接受，不要求细粒度路径锁或把 I/O 移到锁外。真实 Runtime 停机和超时仍留 T18 / T27，当前代码不承诺锁等待时限。

### 3.2 commitInsideBoundary：没有发现公开路径误用

生产调用只有两处：EventPipeline 公开 commit 在 boundary.withLock 内调用，DefaultVfs 在 write 的同一外层锁内调用。方法为 internal，数据库事务仍在 Storage 成功后才开启；T14 公开入口的锁与提交后通知行为保留，回归通过。

它仍依赖组装时注入同一个 boundary，属于既有内部约定，不要求新增锁所有权检查或 DI 框架。DefaultVfs 不会在写入前用 Registry 自提交注册，Node 与 Event 留在最后同一事务中。

## 4. 建议优化与可接受取舍

- **建议 S1**：状态提交后的 `catch (Throwable)` 会把 JVM Error 也包装成普通 STATE_ERROR。可收窄为非取消的 Exception，保留因果；不要求为此模拟 OOM 或重构异常体系。

### 7.1 R1：补父目录逐层保留事实

`createMissingParents` 由返回 `Boolean` 改为返回**已建目录列表**；逐层建，每建成一个就记一个，某层失败时把「已经建了什么」通过 `withCreatedParents` 合并进 effect（`NONE` → `PARTIAL`，`UNKNOWN` / `PARTIAL` 原样带走，不前后不一致），原错误码与 cause 保留，取消异常原样传播，不回删目录。`vfs/api` 新增 `VfsException.withEffect` 供编排层换 effect 重抛（`code` / `message` / `uri` / `operationId` 原样带上，`initCause` 回原异常）。

用例：core 3 例（第一层成功第二层失败 → PARTIAL 且 `a` 在盘上；首层失败 → NONE；建目录阶段 UNKNOWN 不降级）、真实 Local FS 1 例（第 2 次 `createDirectory` 注入失败 → PARTIAL，真盘上 `a/b` 确实留着 `a`）。真实栈的失败注入在 Storage 端口上（真文件系统无法预置这种阻断，第一层由本次调用自己建），建出来的目录与断言仍对着真盘。

变异对照：去掉事实合并（`withCreatedParents` 直接原样返回，保留逐层建目录）→ core 与真实栈各报警 1 例（expected PARTIAL but was NONE）；撤回后全绿。

### 7.2 R2：三条补证

1. **A06 并发确定性**：删掉 `withTimeoutOrNull(2_000)` 判据，改为**事后顺序**——`PausingStorage` 记录每次 `stat` / `write`，断言 `stat → write → stat`，即第二个写对目标的 stat 排在第一个写的物理写完成之后；配合闩锁、`writeCalls == 1`、`ALREADY_EXISTS` 与内容断言，一成一败。未新增生产测试接缝、未引调度框架。`DefaultVfsStageBoundaryTest` 仍只作阶段边界证据。
2. **写链受控取消**：`a write cancelled at the DefaultVfs entry propagates, releases the lock and commits nothing`——在 Storage I/O 挂起点取消写链，断言 `CancellationException` 连原因原样传播（不是 VfsException）、闩锁退出、Node / 事件 / 通知均为零，随后同一边界可再取并完成一次真写入。发现并记录的边界：OpenDAL 的落盘在它自己的执行器上，**取消不保证撤掉已发出的物理写**，所以断言落在状态与通知上（这与「取消 ≠ 全部回滚」的既有口径一致）；测试里被取消的那次写显式丢弃，不再落盘。
3. **A02 Metadata**：真实栈覆盖用例预置非空 `NodeMetadata`（用测试已有 Repository，未调用未交付的 `setMetadata`），覆盖后读回比较未被清空。
