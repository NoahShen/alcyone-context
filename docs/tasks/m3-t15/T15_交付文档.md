## 3. 关键设计决策

1. **唯一持锁者**：写操作整链在共享 `StateBoundary` 的一次取锁内完成；内部只用 Registry / EventPipeline 的无锁入口，**禁止嵌套取锁**（Kotlin Mutex 不可重入）。
2. **write 预检顺序**：参数 / 限额 → T10 Guard → 锁内实际存在性与类型确认（`OperationIntent` 的类型声明不是实际验证）→ 补父目录 → 写入。任何可确认拒绝都在物理变更之前。
3. **effect 合并**：补父目录成功后写失败 ≥ PARTIAL（不降 NONE）；后端 UNKNOWN 保持；状态 / 事件提交失败 → `STATE_ERROR` + PARTIAL（物理保留、无成功通知）；通知入队满 / Consumer 失败不反向影响成功结果。
4. **补父目录**：仅目标 Mount 内缺失祖先；不批量注册、无目录创建事件；缺建目录能力仅在确需补时拒绝。
5. **list 遮蔽**：配置入口优先于物理同名项；被 Mount 遮蔽的父后端内容不混入；子后端离线不影响父层入口可见。
