## 1. 范围与现状

已在方案前落盘且本次允许追溯审查的范围：`AlcyoneContext.runDreaming()`、`DreamingResult/ContextDreamingException`、Factory/Impl、`DreamingRuntime`、`DreamingBinding` 及其测试。`DreamingResult`、异常、配置字段属 CT22 已批准组件；除非新证据证明缺陷，不改 CT22～CT25 生产实现。

本任务不包含 Backup、HTTP Dreaming 端点、StartupRecovery、持久化任务队列、直接写 Organized/Map、真实模型默认启用、CM6 或 Git 写操作。CT26 不自行宣称 CM5 DONE。

## 2. 追溯裁定（R1）

| ID | 裁定 |
| --- | --- |
| D1 | `AlcyoneContext` 增加 `suspend runDreaming(): DreamingResult`；`DreamingResult` 固定六字段。第三方默认实现抛 `ContextDreamingException(UNAVAILABLE)`，**不得**用 `ALREADY_RUNNING` 表示不支持。枚举新增 `UNAVAILABLE`，旧 `ALREADY_RUNNING` 只表示真实并发冲突。 |
| D2 | Runtime 开启条件不是 Cron 是否存在：四 Task `DREAMING_TOPIC/MEMORY_SEARCH/DREAMING_EVIDENCE/DREAMING_REFLECTION` 均存在、Profile 均存在、模式均 JSON_SCHEMA/JSON_OBJECT 才完整。完整绑定即可手动执行，Cron 仅增加调度入口。 |
| D3 | `create()` 保持无副作用；完整四绑定也只在 `start()` 取得资源后创建 Runtime。有 Cron 或**任一部分 Dreaming 绑定**而绑定不完整/模式非法，在打开资源前具名 `INVALID_CONFIG`；只有完全无 Dreaming Task 才保持 ingestion-only。不能 manual 调用时才失败。 |
| D4 | 手动与 Cron 共用 Coordinator 单 Worker；手动重叠抛 `ALREADY_RUNNING`，Cron 重叠跳过；固定 C0/U、逐批 Raw+Pending+CAS 不变。手动入口不套额外重试，不把 CE 包成业务错误。 |
| D5 | 关闭先封闭手动/Cron 准入，再等待手动与 owned run 的实际收尾，最后才释放 LLM/SQLite。手动调用方取消仍归调用方；close owner 在 `NonCancellable` 中取消并 join owned run，同时等待已登记手动 run，不允许“close 返回而 activeRun=true”。关闭后/关闭中调用为 `CLOSED`，重复 close 共享同一清理结果。 |
| D6 | `start()` 启动 Cron 失败必须走既有逆序清理；完整配置无 Cron 不创建 Cron。Factory 公共签名不暴露测试类型，tick/configurator 仅 internal 重载。 |
| D7 | 受控 HTTP 使用现有 KtorLlmClient，不新建平行 Adapter；多 Profile 各自 Key/model 不串用。日志/异常/评测归档不含 Key、原始敏感正文与完整响应。 |
| D8 | 真实模型不是本任务默认验收项。已存在本机 CLI/登录状态也不构成发送数据或收费调用授权；如用户后续明确授权，须单独记录 Profile、脱敏样本版本、调用边界与结果。 |

## 3. 分批与允许修改

### B1 · 接线 R1 与真实集成（Worker，经 Lead 初验）

- 允许：`context/api` 的 Dreaming API/异常及测试；`context/runtime` 的 Factory/Impl、Dreaming Runtime/Coordinator/Binding 及必要测试；`integration-tests/context` 新增真实公共入口集成测试；CT26 文档。
- 修 D1～D6，优先最小改动；不得为隐藏缺陷删测试或放宽断言。手动 run 注册与关闭必须同锁准入/封闭，关闭期间不遗留活动 run。
- 用真实 ContextFactory、SQLite、VFS 与受控 HTTP stub 验证：非空 Conversation → Topic → Evidence（含 Memory Search）→ Reflection → Raw+Pending+Checkpoint；组织通知可观测但不由 Dreaming 直接写 Organized。
- 至少覆盖多批、第二批失败后的 partial/前批保留、重启续跑不重复、manual/Cron 互斥、手动运行与 close 竞态、调用方取消、启动失败清理及四 Task 配置矩阵。

### B2 · 独立验收与固定集（不改生产）

- `./scripts/check` 全绿、Spotless、14 模块 @Test=XML、81 VFS 基线、Schema/VFS/common/Core 依赖边界、CT22～CT25 组件 SHA/差异核对。
- 进程内正常重启必须真实关闭/打开 SQLite；另以独立 JVM 子进程在可控处理器“提交已返回、结果发布前”停止，模拟 COMMIT 后崩溃，下一进程验证前批不重复、后续可继续。不得把同进程 Coordinator 重建写成进程崩溃证明。
- 归档 Dreaming 固定脱敏 JSONL、Prompt/Schema/Profile 版本与 Fake 结果；真实模型结果独立文件，未运行写 `not-run`。

### 可选 B3 · 真实模型评测（默认 LOCKED）

仅在用户明确授权模型、数据发送与费用后派发；不自动选择本机账号/凭证，不把授权 CM5 视为收费评测授权。未获授权不影响 B1/B2 的确定性验收，但不能宣称真实语义质量通过。
