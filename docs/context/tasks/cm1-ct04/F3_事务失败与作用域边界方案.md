RawScopes 当前调用路径：

| Java 方法 | 包装类 | scope 检查时点 | 备注 |
|---|---|---|---|

| `Connection.prepareStatement(String)` | `ScopedPreparedStatement` | `executeQuery`/`executeUpdate` 前 | 返回受控 PreparedStatement |
| `Statement.executeQuery(String)` | `ScopedResultSet` | 前 | 返回受控 ResultSet |
| `Statement.executeUpdate(String)` | int | 前 | 更新计数 |
| `Statement.execute(String)` | boolean | 前 | DDL 等 |
| `Statement.close()` | delegate 正常关闭 | 前 | 释放语句资源，不关连接 |
| `PreparedStatement.executeQuery()` | `ScopedResultSet` | 前 | |
| `PreparedStatement.executeUpdate()` | int | 前 | |
| `PreparedStatement.setXxx(...)` | delegate | 前 | 参数绑定，SQLDelight 绑定所需 |
| `ResultSet.next()`/`getXxx()`/`wasNull()` | 值 | 前 | 结果读取 |
| `ResultSet.close()` | delegate 正常关闭 | 前 | 释放结果集资源 |

### 1.2 被明确阻断的出口（抛具名 `PERSISTENCE_UNAVAILABLE`，不再裸透 delegate）

| Java 方法 | 阻断理由 |
|---|---|
| `Connection.commit()` / `rollback()` / `setAutoCommit(boolean)` | 事务控制权只归执行器，作用域内不允许手动提交/回滚 |
| `Connection.close()` | 连接生命周期由 Slot 管理，借出者不得关闭共享连接 |
| `Connection.createStatement(int, int)` / `prepareStatement(String, int)` 等带参数重载 | 不安全的语句创建重载 |
| `Statement.getConnection()` / `Statement.getResultSet()` | 不得透出底层连接/结果集 |
| `Statement.unwrap(...)` / `Connection.unwrap(...)` | 不得透出 delegate |
| `ResultSet.getStatement()` / `ResultSet.unwrap(...)` | 不得透出语句/连接 |
| 其余未列明的 `Connection`/`Statement`/`PreparedStatement`/`ResultSet` 方法 | 默认拒绝，仅上表显式放行 |

### 1.3 SQLDelight 最小能力（保持复用，不重写库）

- 继续复用 `JdbcDriver` 的 `executeQuery`/`execute`（内部调用 `getConnection()` → 返回 scoped 连接 → 检查 scope → 执行）；
- `SlotConnectionJdbcDriver` 仅为Slot内部实现；对外借出的 `ScopedSlotDriver` 固定持有创建时的ScopeSession，绝不动态读取新currentScope来重新激活旧句柄；
- `SlotConnectionJdbcDriver.close()` **不得**置共享 `slot.driver.disposed`（不得越权关闭/损坏共享 Slot）；仅处理本句柄或明确拒绝；
- `ScopedConnection`/`ScopedStatement`/`ScopedPreparedStatement`/`ScopedResultSet` 均为 `Connection/Statement/PreparedStatement/ResultSet` 代理，方法走 `checkScope` 后委托 delegate；
- `Statement.close()`/`PreparedStatement.close()`/`ResultSet.close()` 委托 delegate 正常释放语句/结果集资源，**不关闭连接**；
- `Connection.commit()`/`rollback()`/`setAutoCommit()`/`close()` 对借出者拒绝。

## 2. 事务状态转移表（write / read / raw）

### 2.1 `ContextSlot.txState` 五态

| 状态 | 含义 | 可复用？ |
|---|---|---|
| `IDLE` | 空闲，可 begin | ✅ |
| `IN_TRANSACTION` | 已 begin，未终结 | ✅（事务中） |
| `COMMITTED` | 已成功提交 | ✅（可恢复 autoCommit 后复用） |
| `ROLLED_BACK` | 已成功回滚 | ✅（可恢复 autoCommit 后复用） |
| `POISONED` | begin/终结/恢复失败，连接状态不可信 | ❌（拒绝所有后续操作） |

### 2.2 阶段状态转移与主异常 / poison / 释放责任

| 阶段 | 入口 | 前置检查 | 成功后状态 | 失败处置 | 主异常 | 释放责任 |
|---|---|---|---|---|---|---|
| begin | `beginTransaction()` | `checkPoison()`、`txState == IDLE` | `IN_TRANSACTION` | `autoCommit=false` 失败 → `POISONED` | 原异常 | 失败时释放 Slot 连接 |
| commit | `commitTransaction()` | `txState == IN_TRANSACTION` | `COMMITTED` | `connection.commit()` 失败 → `POISONED`，**不尝试 rollback**，原异常为主 | 原异常 | 失败时释放 Slot 连接 |
| rollback | `rollbackTransaction()` | `txState == IN_TRANSACTION` | `ROLLED_BACK` | `connection.rollback()` 失败 → `POISONED` | 原异常 | 失败时释放 Slot 连接 |
| 恢复 autoCommit | `restoreAutoCommitIfActive()` | 仅 `COMMITTED`/`ROLLED_BACK` | `IDLE` | 失败 → `POISONED` | 原异常 | 失败时释放 Slot 连接 |
| 业务回调成功 | `write`/`read` block 返回 | — | — | commit → 恢复 autoCommit → IDLE | — | commit/恢复失败时释放连接 |
| 业务回调异常 | `write`/`read` block 抛 | — | — | rollback 一次，失败则 `POISONED`；原业务异常为主 | 原业务异常 | rollback 失败时释放连接 |
| 取消 | `write` block 抛 `CancellationException` | — | — | rollback 一次，失败则 `POISONED`；原 `CancellationException`（带 rollback 失败作为 suppressed）为主 | `CancellationException` | rollback 失败时释放连接 |
| begin 失败 | `beginTransaction()` | — | — | `autoCommit=false` 失败 → `POISONED` | 原异常 | 释放连接 |

### 2.3 互斥与“只收尾一次”规则

- **commit 成功后路径**：`commitTransaction()` → `connection.commit()` 成功 → `txState = COMMITTED` → `restoreAutoCommit()` → `txState = IDLE`。commit 失败 → `txState = POISONED`，**不尝试 rollback**，不恢复 autoCommit。
- **rollback 成功后路径**：`rollbackTransaction()` → `connection.rollback()` 成功 → `txState = ROLLED_BACK` → `restoreAutoCommit()` → `txState = IDLE`。rollback 失败 → `txState = POISONED`，**不尝试 commit**。
- **业务回调异常/取消**：`commitAttempted=false` → 尝试 rollback 一次；rollback 失败 → `poison()`，原业务异常/取消为主（rollback 失败作为 suppressed）；**不再重复 rollback**。
- **commit 失败后**：`txState` 已 `POISONED`，**不再**尝试 rollback，后续实际分配到该Slot的 `write`/`read`/`queryRaw`/`updateRaw` 拒绝；健康Slot不受影响。
- **`restoreAutoCommitIfActive()`**：仅在 `txState == COMMITTED` 或 `ROLLED_BACK` 时执行一次；`IN_TRANSACTION`/`POISONED` 时不恢复；恢复失败 → `POISONED`。
- **写取消不再双 rollback**：取消时只 rollback 一次，失败则 `poison()`，原 `CancellationException` 为主（catch 块不再重复 rollback）。
- **commit 成功但恢复 autoCommit 失败**：报告失败/poison，**不声称已提交内容可回滚**（commit 已落库，不可撤销）。

## 4. 与 rev2 的差异（不再犯的错误）

| 缺陷 | rev2 做法 | rev3 做法 |
|---|---|---|
| `ScopedConnection` 裸委托 delegate，重载泄漏 | 仅覆写少数方法 | **缩窄对外能力**：仅上表允许方法，其余重载抛 `PERSISTENCE_UNAVAILABLE`；`getConnection()` 不再裸返回 |
| read finally 无条件 `commitTransaction()` | 回调失败后 rollback 成功置 IDLE，finally 又 commit，原异常丢失 | **回调失败 → rollback，不再无条件 commit**；`COMMITTED`/`ROLLED_BACK` 才恢复 autoCommit |
| write 取消双 rollback | 取消先 rollback，catch 再 rollback | **取消 rollback 一次**，失败则 `poison()`，原 `CancellationException` 为主（带 rollback 失败作为 suppressed） |
| `internal` 被宣称为安全证据 | — | **撤回**；“internal Java 不可见”不作为安全证据，所有防护靠运行期 `checkScope` |
| `rejectSavepoint` 报告与源码不符 | 报告称扩大注释前缀，实际仅首词 | **报告与源码一致**：首词匹配 `SAVEPOINT`/`RELEASE`，并处理前导注释/空白 |
| 驱动 `getConnection()` 裸返回 | 裸返 `slot.connection` | **返回 `ScopedConnection`**，每次操作前 `checkScope` |

## 5. 与 F2 的衔接（释放责任不破坏 F2）

- Slot 中毒（`POISONED`）仅影响**该 Slot** 的后续请求，**不**导致整个 Executor 关闭；健康读 Slot 继续可用（避免测试误要求一个写 Slot 失败后所有读 Slot 必拒绝）。
- 失败处理在 Slot 自己的单线程上执行，**不直接调用会 await 该线程终止的 `Slot.close()`**；物理连接释放由 `Slot.close()`（在执行器确认在途归零后调用）统一完成，保留 F2 单一关闭完成结果/中断清理。
- 取消路径：`CancellationException` 原样传播，安全收尾失败作为 suppressed，**不改原 cause**。

### 8.1 真实SQLDelight最小消费能力

Architect独立javap核对当前2.1.0产物，证据 `.local/validation/cm1/architect/ct04/f3-plan/jdbc-bytecode.txt`。尤其JdbcPreparedStatement.execute调用的是PreparedStatement.execute()及getUpdateCount()，不能只允许executeUpdate()。

- Connection：允许无参createStatement、prepareStatement(String)，在创建前也检查scope；返回受保护对象。借出者无事务控制/close能力。
- Statement：允许单语句executeQuery(String)、executeUpdate(String)、execute(String)、close；执行前统一SQL控制检查。
- PreparedStatement：允许executeQuery()、executeUpdate()、**execute()、getUpdateCount()**、close；prepare时检查固定SQL。绑定按实际签名显式放行（setNull(int,int)、setBytes、setBoolean、setByte、setShort、setInt、setLong、setFloat、setDouble、setBigDecimal、setString、setDate/Time/Timestamp对应双参签名；如使用setObject，仅允许经验证的标量类型与SQL类型三参签名）。不按set/get前缀泛化放行。
- ResultSet：允许next/wasNull/close和所需标量读取，按签名列明索引/标签版本；SQLDelight常用long/double/boolean/bytes/string及当前需要的标量date/time/decimal等必须可读。任何返回Statement/Connection/LOB/Array/流等未受控资源的方法默认拒绝；getObject不允许透出任意对象。不要为未用扩展类型自行扩大范围。
- 所有未列明重载、unwrap、元数据及反向对象出口默认拒绝；Object自身方法仅安全身份信息，不打印delegate。JdbcDriver内部transaction API不属于允许消费面，借出driver不能通过newTransaction等取得额外事务控制权。
- 每个借出driver/connection/statement/cursor绑定不可重新激活的原ScopeSession，检查session.active、所属线程、slot.currentScope身份与Slot可用性；绝不依赖共享driver的“当前scope”动态授权。close若只是语句/结果集清理，需与执行器结束scope的顺序相容，清理失败安全映射且不覆盖主异常。

### 8.2 SQL与异常统一边界

所有允许执行路径（含SQLDelight driver、raw/预编译、statement）统一跳过前导空白及行/块注释，拒绝BEGIN/COMMIT/END/ROLLBACK/SAVEPOINT/RELEASE及改变执行器事务/连接约束的控制操作；不允许多语句绕过。语句边界检测须识别字符串/标识符中的分号，不能简单误拒普通绑定值或正文。仅做此边界判断，不编写通用SQL引擎。失败采用既有PERSISTENCE_UNAVAILABLE，委托调用的SQLException及反射包装均在边界安全映射，取消原样传播。

### 8.3 事务与资源责任

每个请求取得Slot独占权后检查poison，再begin/操作；raw路径同样覆盖。成功业务commit一次、失败/取消rollback一次，二者互斥；仅COMMITTED/ROLLED_BACK恢复autoCommit，成功转IDLE。保留主业务异常或原取消对象，安全收尾错误只suppressed。成功回滚且恢复成功仍可复用；commit已落库但恢复失败只能报告失败与poison，不能声称撤销提交。

POISONED是该Slot不可复用，不自动关闭健康Slot。失败处理标记poison后，在该次同步JDBC已退出、作用域失效的收尾边界尽力释放该Slot物理连接（不恢复autoCommit，不重试未知事务），记录安全清理失败；不在Slot线程里shutdown并await自身。Executor整体close沿用F2等待所有在途退出再统一停止线程/释放尚存资源，物理连接清理应可重复安全调用。先前表中“失败即释放Slot”均按此解释。
