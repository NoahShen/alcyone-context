## 3. Slot 架构

### 3.1 结构

```text
ContextDatabaseExecutor
  ├─ WriteSlot × 1 ─ 单线程执行器 ─ SlotConnectionJdbcDriver ─ 独占 java.sql.Connection ─ SQLite
  └─ ReadSlot × N  ─ 每 Slot 独立单线程与独占连接（默认 N=2，可配置）
```

### 3.2 复用 SQLDelight JdbcDriver

`SlotConnectionJdbcDriver` **继承** `app.cash.sqldelight.driver.jdbc.JdbcDriver`，只覆盖连接供给语义：

- `getConnection()` 固定返回该 Slot 自持的物理连接；
- `closeConnection(connection)` 为**空操作**，逐语句执行后绝不关闭物理连接；
- 参数绑定、`PreparedStatement` 组装与 `SqlCursor` 游标映射全部复用父类，不从零重写 `SqlDriver`；
- 查询监听器用简单的 key → listener 集合实现，与 VFS 既有 `SingleConnectionJdbcDriver` 同构。

不使用 stock `JdbcSqliteDriver` 的原因（探针 P1 实测）：它对文件库按线程持有连接，非事务语句执行完即关闭该线程连接，`driver.close()` 为空操作，连接级 `PRAGMA` 不能持续。

### 3.3 连接级 PRAGMA（Slot 创建时设置，全程持续）

| Slot | PRAGMA |
| --- | --- |
| WriteSlot | `journal_mode=WAL`、`synchronous=FULL`、`busy_timeout=5000`、`foreign_keys=ON` |
| ReadSlot | `busy_timeout=5000`、`foreign_keys=ON`、`query_only=ON` |

创建时断言 `journal_mode` 实际为 `wal`（读连接与写连接都会读到库级 WAL 设置，读连接不改它）。

### 3.4 执行模型

- 每 Slot 一条单线程 `ExecutorService`；`suspend` 只用于在回调**之外**等待 Slot 空闲，回调本身同步执行、不可挂起。
- 同一 Slot 的并发请求按提交顺序串行（不使用共享连接给多个协程）。
- 写事务：`autoCommit=false` → 回调内全部语句 → `commit()`；异常 → `rollback()` → 恢复 `autoCommit=true`。事务绑定物理连接，不用 `ThreadLocal`。
- 嵌套事务拒绝；`Savepoint` 拒绝；事务上下文不可逃逸出回调；非 Slot 所属线程调用拒绝（具名 `ContextPersistenceException`）。
- 交互式只读事务（`BEGIN`/`COMMIT` 包住整个读回调）用于需要稳定快照的 `read`，保证多次查询同一 WAL 快照。

## 4. 初始化与打开保护

### 4.1 显式初始化 `ContextDatabaseInitializer.initialize(path)`

1. 目标文件已存在（含 0 字节）→ 抛 `ContextPersistenceException(PERSISTENCE_UNAVAILABLE)`，**绝不覆盖、不截断**；
2. 文件不存在 → 打开写连接（`journal_mode=WAL`、`foreign_keys=ON`、`busy_timeout=5000`），在显式事务内执行 `Schema.create` 并写 `PRAGMA user_version = 1`；
3. 关闭连接；失败时删除本次创建的文件与 `-wal` / `-shm`，避免留下半成品。

### 4.2 普通打开 `ContextDatabaseFactory.open(path)`

严格顺序（先只读校验，后开读写连接）：

1. 文件不存在 → `DATABASE_NOT_INITIALIZED`，且**不创建**任何文件；
2. 文件大小为 0 → `DATABASE_NOT_INITIALIZED`；
3. 以 `jdbc:sqlite:file:<abs>?mode=ro` 打开只读连接：
   - `PRAGMA user_version` ≠ 1 → `SCHEMA_VERSION_MISMATCH`（低于或高于都一样），文件字节不变；
   - 六表缺失或不完整 → `PERSISTENCE_UNAVAILABLE`（损坏/非本库）；
   - 打开或查询抛 `SQLException` → `PERSISTENCE_UNAVAILABLE`；
4. 校验通过后按 WriteSlot + ReadSlots 顺序打开连接并设置 PRAGMA；任一失败则逆序关闭已开连接并抛错。

关键约束：校验阶段只做只读访问，**先验证版本再设置任何持久化 PRAGMA**，因此错版文件字节严格不变。

## 5. 生命周期

- `close()` / `closeAsync()` 幂等：并发的多次调用共享同一个完成结果。
- 关闭顺序：置关闭闸门（新请求立即抛 `ContextLifecycleException(CLOSED)`）→ 等待在途阻塞 JDBC 执行真正退出（在途计数归零）→ 逆序关闭 ReadSlots → 关闭 WriteSlot（各自 `connection.close()` 与线程终止）。
- 协程取消**不**抢先关闭底层连接；`CancellationException` 原样向外传播，清理跑在 `NonCancellable` 内。
- 部分初始化失败：逆序释放已获取资源（先 ReadSlots 后 WriteSlot），不泄漏连接与线程。
- 关闭后任何读写请求抛 `ContextLifecycleException(CLOSED)`。
