## 3. 锁定的行为契约

### 3.1 Count Trigger（D7）

- `internal class CountTrigger(threshold, databaseProvider, request: (SessionKey) -> Boolean, reporter)` 实现既有 `IngestionNotifier`（签名不改）。
- `onCreated(sessionKey)`：
  - 通过 `ContextDatabase.read` 调 `countPending(sessionKey)`；
  - `count >= threshold` → `request(sessionKey)`；否则不发 Trigger；
  - **只统计 `pending`**；不新增独立 Turn Counter；
  - 查询失败 → 既有 `IngestionNotificationReporter.reportFailure`，不发 Trigger、不影响已提交 Ingestion；
  - `CancellationException` 原样传播；DUPLICATE 不调用（沿用 CT07 已验收契约，B2 不自建通知）。
- 不把 SessionKey/消息/SQL/异常文本写入日志；reporter 只接收异常对象（既有口径）。

### 3.2 Idle Trigger（D6 + §2.4 边界）

- `internal class IdleTrigger(databaseProvider, idleTimeout, clock, request, ...)`：
  - `internal suspend fun scanOnce(): ScanOutcome`（`TRIGGERED` / `SKIPPED` / `FAILED` 语义可用 internal 枚举/返回表示）；
  - **single-flight**：同一时刻只允许一次扫描；并发/重叠调用返回 skip，不排队；`internal fun skippedForTesting()` 计数；
  - skip 记录 `extraction.idle.skipped` **DEBUG**（固定事件名，无 SessionKey/消息/SQL/异常文本/Throwable）；
  - 截止时间：`idleBefore = clock.now() - idleTimeout`，**直接用 `Instant` 运算**，不得先转毫秒/秒并饱和；极大有限 `Duration` 或 `Instant.MIN/MAX` 导致 `DateTimeException`/`ArithmeticException` 时，**本次扫描失败（`extraction.idle.failed` WARN）且不触发任何 Session**，不得转换成错误的短窗口或绕回未来；下一次自然 tick 仍可正常扫描；
  - 成功：`database.read { findIdleSessions(idleBefore) }`，逐个 `request(sessionKey)`（只提交 SessionKey，不选 Turn）；
  - 查询/扫描的普通失败：`extraction.idle.failed` WARN，隔离后返回；`CancellationException` 原样传播且不记普通失败；`finally` 必须释放 single-flight 标记；
  - 复用既有 `findIdleSessions`（所有状态 `created_at` + 必须 pending），不改 SQL/索引。
- 不新增独立 Session 状态表/水位/重试状态。

### 3.3 Cron（D2/D6）

- `internal class IdleCron(idleTrigger, cron, clock, tickSource...)`：UNIX 五字段（分/时/日/月/周），固定 `Asia/Shanghai`，不提供 timezone 键（配置已在 B1 校验）。
- 每次从当前时刻选择**严格未来**的 tick（`next > now`）；启动**不立即扫描**；不补跑停机或扫描期间错过的 tick；无热更新。
- 运行：每个 tick 触发一次 Idle 扫描；扫描通过 `IdleTrigger` 的 single-flight 执行。**实际重叠必须发生并被跳过**：tick 触发不得用“串行 await 扫描完成再等下一 tick”来规避重叠；需允许 tick 在前一扫描未结束时到达，并记录 skip。
- 停止：`closeAsync()` 先停止 tick 循环，再取消并 join 正在运行的扫描/结构化子任务；不遗留后台 Job；关闭后不再触发。
- tick/clock 可注入以便测试；测试不得真实等待 5 分钟；非法 cron 在 B1 已拒绝，本批不重复解析配置。
- 调度失败/无可用下一 tick：受控失败（`extraction.idle.failed` WARN），不触发，不越期发送；下一次自然 tick 可继续。

## 4. 测试要求（真实 SQLite + 确定性屏障）

### 4.1 `CountTriggerTest`

1. 真实 SQLite：4 条 pending 不触发、5 条触发（阈值 5）；complete/failed 不计入。
2. 跨 Session 不合并；同 Session 计数正确。
3. 查询失败 → reporter 收到异常、0 触发、无 SessionKey/异常文本日志。
4. `CancellationException` 原样传播。
5. 复用 `IngestionService`（真实 DB）：CREATED 触发通知检查；DUPLICATE 不产生第二次通知（沿用 CT07 契约）。

### 4.2 `IdleTriggerTest`（真实 SQLite）

1. 等号边界：所有状态最新 `created_at == now - idleTimeout` 触发；略晚 1ms 不触发。
2. 较新的 complete/failed 阻止旧 pending；`timestamp` 与判定无关（旧 timestamp + 新 created_at 不触发）。
3. 无 pending 不触发；仅 failed 不触发；多 Runtime/Agent/Session 隔离。
4. single-flight：用可控屏障使第一次扫描阻塞；第二次 `scanOnce()` 真实重叠 → SKIPPED、skip 计数 +1、`extraction.idle.skipped` DEBUG；放行后第一次完成。
5. 查询失败 → `extraction.idle.failed` WARN、无触发、无 Throwable/SessionKey；下一次扫描成功。
6. `CancellationException` 原样传播、不记普通失败、single-flight 标记释放。
7. 边界：极大有限 `Duration` / `Instant.MIN` 下 `idleBefore` 溢出 → 受控失败、0 触发、无短窗口触发；随后正常扫描仍可触发。
8. 复用既有 `findIdleSessions`，无 SQL/索引改动。

### 4.3 `IdleCronTest`（注入 clock/tick）

1. `nextAfter(now)` 严格未来；UNIX5/Asia-Shanghai；不启动即扫；不补跑多个错过 tick。
2. 用可控 tick 源制造“扫描未结束时下一 tick 到达” → 真实 skip（skip 计数/DEBUG），不是串行 await 规避。
3. `closeAsync()` 停止循环、取消并 join 在途扫描；关闭后 tick 不再触发。
4. 无下一 tick/调度失败 → 受控失败日志、不触发；下一次可用 tick 继续。
5. 不真实等待 5 分钟（注入 tick/clock 或使用极短测试 tick）。
