## 2. 冻结实现要求

### 2.1 OrganizationConfig / ContextConfig / Loader

- `ContextConfig.organization: OrganizationConfig? = null`；null=禁用、不建 pipeline。
- 出现 `context.organization` 即显式启用；空映射使用默认 Trigger。
- `OrganizationConfig` 建议字段：`immediateEnabled=true`、`periodicEnabled=true`、`cron="*/10 * * * *"`。
- 构造即校验：UNIX 五字段 cron；`immediateEnabled || periodicEnabled` 必须为 true，否则 `INVALID_CONFIG`；periodic disabled 不豁免 cron 校验。
- Loader 严格解析 `triggers.immediate.enabled`、`triggers.periodic.enabled/cron`；逐层拒绝未知键；`timezone` 必须作为 `UNKNOWN_FIELD` 拒绝；cron 支持 ENV 展开；错误消息安全。
- 新增纯配置函数 `validateOrganizationBinding(organization, llm)`（命名可微调）：显式组织必须有 `CANDIDATE_SCANNER` 与 `GOVERNANCE` Task；两个 Profile 存在；两个 jsonMode 均为 `JSON_SCHEMA`/`JSON_OBJECT`；缺失/非法 → `ContextConfigException(INVALID_CONFIG)`。B2 的 Factory 将调用此函数，B1 只测纯函数。

### 2.2 Pending 固定列表

- `OrganizationPendingReadOps` 新增 `fun listAllByRawCreatedAt(): List<String>`；`OrganizationPendingRepository` 新增 suspend 同名方法；TxOps 通过继承自动拥有。
- SQL：`organization_pending p JOIN raw_memory r`，`ORDER BY r.created_at ASC, r.id ASC`，无 limit。
- `ContextOps` Read/Tx 实现、`ContextRepositories` suspend 实现与真实 SQLite 测试必须覆盖顺序、空集合、无静默截断/limit。
- 不改 Schema/索引。

### 2.3 OrganizationSourceGuard

- Runtime internal；接 `ContextDatabase`。
- 先用短 `database.read` 查 `organizedMemories.findOrganizedByRaw(rawId)`。
- 已关联返回 `true`，并用短 `database.write` 再次核验：Source 仍存在时，若 Pending 存在则 `dequeue` 精确 1 行；已无 Pending 为 no-op。
- 未关联返回 `false`；若读写期间状态变化导致不再关联，不得误删 Pending，返回 false 供后续正常链路处理。
- 不改 CT15 API；不调用 LLM；异常安全传播/由 Worker 单条隔离。

### 2.4 OrganizationScheduler

- Internal `OrganizationRoundRunner { suspend fun runRound() }`。
- 状态 NEW/RUNNING/CLOSING/CLOSED；Int `triggerCount` 饱和；单 Worker Job；`start()` 幂等；`request()` 仅 RUNNING 接受。
- 一次 Trigger 对应一轮：Worker 在**轮末**消费一个计数；运行期间新 Trigger 只增计数，不启动第二 Worker。
- Worker 退出与 request 在同一锁协调：新 Trigger 要么在退出判断前增加并阻止退出，要么在 worker 置空后启动新 Worker；不得漏触发或并发两个业务 Worker。
- 单 Worker 在同一轮内只运行一个 full round；普通 round 成功/DB 轮级失败后消费一个 Trigger；若 count>0，按 D9 对 `ContextPersistenceException` 固定 1s 可取消退避后下一轮。
- 单条失败由 Worker 自己隔离，不得升级为 Worker FAILED。
- `beginClosing()` 同步封准入；`closeAsync()` 取消并真实 join Worker、清计数、共享关闭结果；关闭后 request false/no-op。
- 提供 internal 状态/计数/queue 诊断访问器；状态可供 B2 映射 `WorkerStatus`，单条失败保持 IDLE/RUNNING 而非 FAILED。

### 2.5 OrganizationPeriodicCron

- 独立 internal 组件，不复用/修改 CT09 IdleCron。
- UNIX 五字段、固定 `Asia/Shanghai`；严格未来；start 不立即扫描；不补跑；无持久状态。
- 每次 tick 调用 `database.read { pending.hasAnyPending() }`；仅 true 时 `scheduler.request()`。
- 普通查询/调度失败 WARN（固定事件名，不含 Throwable/正文/ID）+ 固定 1s 可取消退避；CE 原样传播；close 取消/join、共享结果。
- tick/clock 可注入，测试不得真实等待。

### 2.6 DefaultOrganizationWorker

- 实现 `OrganizationRoundRunner`；一轮开始时在**单次 `database.read`** 中调用 `listAllByRawCreatedAt()`，得到固定 ID 列表。
- 列表完成后逐条串行处理；本轮新入队不出现在本列表。
- 单条流程：`OrganizationSourceGuard` → 若已关联直接完成（不调 Scanner/Governance）→ 读取 Raw → CandidateRetriever.search → GovernanceDecider.decide → OrganizationCommitter.commit。
- 为测试注入定义 internal `OrganizationGovernanceDecider`/等价 seam；生产可由 `LlmGovernanceService::decide` 适配。候选侧直接使用 Core `OrganizationCandidateRetriever`。
- `Committed` 后调用 `OrganizationMapWakeup.onOrganizedCommitted()`；`AlreadyAssociated` 不调用；Map 普通失败 WARN 后吞掉，CE 传播。
- 单条普通异常（LLM/Governance/Committer/Persistence 等）只记录固定安全事件并继续下一条，Pending 保留；CE 原样传播。
- 轮级 `listAllByRawCreatedAt`/raw list DB 错误向外抛给 Scheduler 进入 D9 退避；不得在轮内重查固定列表。
- `OrganizationMapWakeup` 为 internal `suspend fun` fun interface，默认 no-op；不实现 Map。

### 2.7 OrganizationPipeline

- 组合 Scheduler、PeriodicCron、activation gate、`OrganizationWakeup` 与统一关闭；不接 Factory/Impl。
- `start()` 启动 Scheduler/Cron；业务 Runner 在 `activate()` 前等待。start 前不执行 Round。
- 暴露 internal `OrganizationWakeup`，供 B2 注入 Extraction；Immediate/Periodic 都只调用 Scheduler.request。
- `beginClosing()` 同步封闭准入（Scheduler request 与 activation 后 Runner 双重检查）；`closeAsync()` 先停 PeriodicCron，再取消/join Scheduler，清计数，始终完成 activation 以避免悬挂，并共享/链式暴露关闭失败。
- 提供 internal Worker 状态访问器与测试 seams；不改 public ContextStatus。

## 3. 测试要求（B1 可测 A01～A08）

### A01 配置与绑定门

- organization 缺省 null；空映射默认值；immediate/periodic 覆盖；两个 disabled → INVALID_CONFIG。
- unknown 顶层/嵌套键、错误类型、非法 cron、timezone 键 → 正确错误码，消息安全。
- cron ENV 展开；periodic disabled 仍校验 cron。
- 绑定纯函数：合法双 Task/Profile；缺 llm、缺任一 Task、缺 Profile、任一 PROMPT_ONLY → INVALID_CONFIG；不访问 DB/LLM。

### A02 Pending 固定列表

- 真实 SQLite 空集合、按 raw.created_at,id ASC、跨多条稳定顺序；无 limit。
- 读取列表中不混入后续新入队项；下一次 list 可见。

### A03 Scheduler/Counter

- 单 Trigger 单轮；运行中多 Trigger 累加；一次轮只消费一个；count>0 继续；count=0 退出。
- saturation 到 Int.MAX；退出竞态不漏 request；普通 round failure 1s 可取消退避；关闭立即取消/join、后到 request no-op。
- 确保不存在两个并发 Round。

### A04 SourceGuard/Worker

- Source 已关联 + Pending：只清 Pending，不调 Scanner/Governance，不调 Map。
- Source 已关联无 Pending：no-op。
- Source 未关联：调 Scanner→Governance→Committer；Committed 后 Map 一次。
- 轮中新入队不进入当前 list；下一轮可见。
- 单条 LLM/Governance/Committer 失败继续其他项，Pending 保留；CE 传播。
- Map 成功/普通失败/CE；AlreadyAssociated 不调 Map。

### A05 Periodic Cron

- start 不立即 request；严格未来；不补跑；hasPending=false 不 request；true request；普通失败 1s 可取消退避；close 真实结束。

### A06 Pipeline 生命周期

- start/activate 前不执行 Round；activate 后执行；beginClosing 后新 request/已排队准入 0 新 Round。
- close 顺序 Cron→Scheduler，取消/join 在途 Runner；共享关闭结果；启动前关闭/重复关闭安全。

### A07 Worker 状态

- Scheduler/Pipeline internal 状态：IDLE/RUNNING/STOPPED；单条失败不标 FAILED；仅不可恢复 Worker 终止可 FAILED。B2 才映射 public `ContextStatus.workers`。
