## 2. 生产接线要求

### 2.1 Factory.create 纯配置门

- 在 `AlcyoneContextFactory.build` 中、任何资源打开前调用 B1 `validateOrganizationBinding(contextConfig.organization, ownedLlmConfig)`。
- `context.organization == null`：保持现状，不创建 Organization pipeline；现有 extraction-only/ingestion-only 行为不变。
- 显式 organization 但缺 LLM/Task/Profile、PROMPT_ONLY 或双 Trigger disabled：`ContextConfigException(INVALID_CONFIG)`，不得创建目录/文件/连接/协程/线程。
- `create()` 仍零副作用；B1 config 已在 Loader/构造期校验。

### 2.2 AlcyoneContextImpl 构造/启动

- 新增 `organizationConfig`、测试用 Organization tick/configurator/map wakeup 接缝；保持公共 `AlcyoneContextFactory.create(contextConfig,vfsConfig)` 签名不变。
- start 顺序：DB → VFS → LLM → **OrganizationPipeline** → ExtractionRunner/Pipeline → 两条 pipeline `start()` → 发布 RUNNING → activate。
- OrganizationPipeline 组合实际：
  - `LlmCandidateRetriever(database, llmClient, llmConfig)`
  - `LlmGovernanceService(llmClient, llmConfig)` 适配 `OrganizationGovernanceDecider`
  - `OrganizationCommitter(database, MemoryIdGeneratorImpl(clock), clock)` 适配 `OrganizationCommitOperation`
  - `OrganizationSourceGuard(database)`
  - `DefaultOrganizationWorker(..., OrganizationMapWakeup { })`
  - `OrganizationPipeline(organizationConfig, database, worker, clock, organizationTickSource)`
- Extraction Runner 的 `OrganizationWakeup` 默认必须指向 `OrganizationPipeline.wakeup`；内部测试显式注入的 wakeup 仍可覆盖。无 organization 时保持 no-op/注入行为。
- Organization Pipeline 必须先于 Extraction 构造，避免 wakeup 闭包指向未创建对象。
- RUNNING 发布前不得执行业务 Round；发布后 activate。建议先 activate Organization，再 activate Extraction。

### 2.3 生命周期/关闭

- 在 Context RUNNING→STOPPING 的同一状态锁内同步调用 Extraction 与 Organization 的 `beginClosing()`。
- 关闭顺序：取消/等待 ingestion notifications → Extraction pipeline（停止新 Raw 并 join）→ Organization pipeline（Periodic Cron→Scheduler）→ LLM → VFS → executor。
- start 失败/close 赢竞态：已取得的 Organization 与 Extraction pipeline 都必须在 `NonCancellable` 清理路径中尽力关闭，失败共享/抑制，不遗漏真实资源。
- `releaseResources` 增加 Organization 参数；确保 pipeline close 失败后仍继续释放 LLM/VFS/executor。
- Context close 后 Organization Worker 状态 STOPPED；不保留数据库/LLM 引用。

### 2.4 ContextStatus Worker 映射

- 仅当 `context.organization` 显式配置时，`getStatus().workers` 增加 `"organization"`。
- 使用 B1 已有 internal 状态访问器映射到 public `WorkerStatus`：
  - IDLE→IDLE；RUNNING→RUNNING；STOPPED→STOPPED；FAILED→FAILED。
- 单条/普通轮失败继续运行，不得标 FAILED；只有 B1 Scheduler 的不可恢复状态映射 FAILED。
- 不新增 `ContextStatus`/`WorkerStatus` 字段，不改公开 API；未配置 organization 时 workers 保持原行为（空）。
