## 1. 配置字段与阶段边界（CM1）

### 1.1 CM1 实际生效字段

| YAML 路径 | 默认值 | CM1 用途 |
| --- | --- | --- |
| `context.database.path` | `./data/context.db`（相对 YAML 目录） | Context SQLite 路径；显式初始化/普通打开 |
| `context.lifecycle.shutdownTimeout` | `30s` | 关闭等待在途退出的**观察期限**（非强杀上限；到点不发布 CLOSED、不报告资源已释放，沿用 CT04 drain 等真实 JDBC 退出） |
| `vfs.database.path` | `./data/vfs.db`（相对 YAML 目录） | 构造 `VfsRuntimeConfig.stateDatabase` |
| `vfs.namespaces` | 空集合 | `VfsRuntimeConfig.namespaces` |
| `vfs.mounts` | 空列表 | `List<MountConfig>`：`vfsPath`、`storageKey`、`backend.type=local|webdav`、`root`（local）/`endpoint,root,username,password`（webdav） |
| `vfs.limits.defaultReadMaxBytes` / `defaultWriteMaxBytes` | 16 MiB | `VfsLimits` |
| `vfs.streamTotalLimit` | `null` | `VfsRuntimeConfig.streamTotalLimit` |
| `vfs.eventBufferCapacity` | `256` | `eventBufferCapacity` |
| `vfs.closeGracePeriod` | `30s` | `closeGracePeriod` |

### 1.2 全集蓝图字段的阶段边界（澄清版）

- `server.*`：由 Server 层负责，Context Runtime 完全忽略顶层分区。
- `context.ingestion.*`：**属于 CM1（CT07）范围，CT06 暂不消费**；CT07 接线时必须纳入解析、校验与生效，不得把它当永久忽略项。CT06 B1 仅保证：出现该键不报未知字段、不要求未实现密钥、不生效。
- `context.llm.*`、`context.organization.*`、`context.memoryMap.*`、`context.backup.*`：蓝图已知、后续里程碑实现；CT06 暂不消费、不校验、不要求密钥；不创建 LLM/Worker/Cron。
- 以上仅是对**蓝图已知键**的阶段豁免，**不是**对未知 `context`/`vfs` 字段的全面豁免；真正未知字段仍报 `UNKNOWN_FIELD`。

## 2. 配置解析与校验

1. **YAML 读取**：现有 SnakeYAML，限制 unsafe 类型构造（只允许 Map/List/String/Number/Boolean/null）；解析失败 → `ContextConfigException(INVALID_CONFIG)` 安全映射，不回显原文。
2. **相对路径**：`context.database.path`、`vfs.database.path`、LocalFs `backend.root` 一律以 YAML 文件所在目录解析为绝对路径，不使用 CWD。
3. **ENV 展开**：字符串字段中 `${NAME}` 在读取前展开；未定义或 trim 后为空 → `MISSING_ENV`，消息只含字段路径与环境变量名，不含值。
4. **未知字段**：负责分区（`context`/`vfs`）内未识别键 → `UNKNOWN_FIELD` 并指明路径。
5. **类型/范围**：路径非空、限额 >0、`eventBufferCapacity` ≥1、`streamTotalLimit` null 或 ≥0、`closeGracePeriod`/`shutdownTimeout` ≥0、mount `vfsPath` 合法且不在逻辑根 `/`、`storageKey` 非空且不重复冲突（由 VFS `resolve` 复验）。
6. **脱敏**：WebDav 凭据不进异常/日志/`toString`；配置打印走 VFS 已有 `MountBackend.WebDav.toString` 脱敏；Context 侧错误只带字段路径。

## 3. 数据库路径隔离与挂载范围（路径规范化澄清）

- 路径规范化**不得要求每个父目录/挂载根已存在**：默认 `./data` 与多级尚不存在的目录在配置/create 阶段合法，且 create 必须零创建。
- 规范化算法：取**最近的存在祖先**解析真实路径（`toRealPath()`），再把不存在后缀按字面拼接，得到“计划真实路径”；已有文件时再用 `Files.isSameFile` 兜底判定同文件。
- `context.db` 与 `vfs.db` 不得为同一文件（同路径、符号链接别名、已存在文件的 isSameFile）；两者不得落在任何 LocalFs 挂载根真实路径之内（按路径段边界）。
- 不新增其他父子路径禁令；不改变既有 VFS 在真实启动时对挂载根存在/重叠的检查。
- 必需测试：符号链接祖先 + 不存在的多级父目录均能正确规范化并在 create 阶段零创建；同文件/别名/暴露于挂载根仍拒绝。

## 4. Runtime 生命周期状态 / 资源所有权

### 4.1 状态机

`CREATED → STARTING → RUNNING → STOPPING → CLOSED`；`STARTING` 失败 → `CLOSED`（不得回 CREATED，不得半运行）；`CLOSED` 为终态。

| 状态 | 允许操作 |
| --- | --- |
| CREATED | `start`、`close`、`getStatus` |
| STARTING | 并发 `start` 等待同一结果；`close` 可与 `start` 竞争（见 §4.3） |
| RUNNING | `start` 幂等、`close`、`getStatus`；业务入口（CT07 接线后） |
| STOPPING | 新业务入口与 `start` 明确返回 `CLOSED`；`close` 等待同一结果 |
| CLOSED | `close`/`closeAsync` 仍共享此前唯一完成结果（含失败），不重新清理；`start` 返回 `CLOSED`；业务入口 `CLOSED`；仅 `getStatus` 正常返回 |

### 4.2 资源所有权（Context 持有）

| 资源 | 取得时机 | 所有者 | 释放时机 |
| --- | --- | --- | --- |
| `ContextDatabaseExecutor` | `start` 内经 `ContextDatabaseFactory.open`（不建库） | `AlcyoneContextImpl` | 关闭时等待在途后 `executor.close()`（CT04 协议） |
| `ContextDatabaseImpl` | `start` 内组装 | `AlcyoneContextImpl` | 无常驻资源，随 executor 释放 |
| `AlcyoneVfs` | `start` 内经 `AlcyoneVfs.create(vfsConfig)`（suspend） | `AlcyoneContextImpl` | 关闭时 `vfs.close()`（VFS 自身协议） |
| 关闭协调 | `close`/`closeAsync` 首次调用 | 唯一 `CompletableDeferred` | 所有等待者共享结果 |
| 后台任务/LLM/HTTP/Cron | **CM1 不创建** | — | — |

释放顺序（失败也逐步尝试、失败可见）：停止准入 → 等待在途（含 JDBC 实际退出）→ `vfs.close()` → `executor.close()`；逆序于创建。单个失败不中断后续释放，主异常/取消不被替换，后续失败 `addSuppressed`。

### 4.3 并发与失败/取消处置

| 场景 | 结果 |
| --- | --- |
| 并发 `start` | 共享同一 `CompletableDeferred`；只初始化一次；全部得到同一结果 |
| `RUNNING` 重复 `start` | 幂等成功，不重复创建资源 |
| `start` 失败 | 逆序释放已取得资源；状态 `CLOSED`；该异常对所有等待者可见（同一实例后续 `start` 拒绝） |
| `start` 与 `close` 竞争、`close` 获胜 | `start` 不得发布 `RUNNING`；已取得资源逆序清理；`start` 得到 `CLOSED`/失败；`close` 正常完成 |
| `close` 在 `CREATED`（未启动） | 直接 `CLOSED`，不创建资源 |
| 并发/重复 `close` | 共享唯一清理结果；重复调用等待同一结果，失败不被吞 |
| 等待者取消 | 取消自己的等待不影响共享清理；清理在 `NonCancellable`；`CancellationException` 原样传播 |
| 在途阻塞 JDBC | `close` 先等实际退出再关连接，不因超时/取消抢关（复用 CT04） |
| 启动前（CREATED/未启动）业务入口 | `NOT_STARTED` |
| 关闭后（CLOSED）业务入口/start | `CLOSED`；`close` 仍返回/共享此前完成结果 |

### 4.4 create 与显式初始化

- `AlcyoneContextFactory.create(contextConfig, vfsConfig)`：纯配置接收 + 校验 + 依赖组装，**不打开数据库、不建文件、不连网络、不启协程**；返回 `CREATED`。
- `AlcyoneContextFactory.initializeDatabase(contextConfig)`：显式首次初始化，调用 CT04 `ContextDatabaseInitializer.initialize`。
- 普通 `start`：缺库/0 字节/错版/损坏一律拒绝（`DATABASE_NOT_INITIALIZED`/`SCHEMA_VERSION_MISMATCH`/`PERSISTENCE_UNAVAILABLE`），不自动创建、不迁移。

### 4.5 状态如实（不隐式取得资源）

- `getStatus()` **不得**为判断 `databaseInitialized` 而新开 JDBC/连接/文件探测；不得在 `create` 后使状态查询隐式取得资源。
- `databaseInitialized` 取**缓存的已完成事实**：显式 `initializeDatabase` 成功、或 `start` 中 `ContextDatabaseFactory.open` 校验成功后置为 true；未验证/未启动为 false。语义是“本实例已验证可用”，不是“文件存在”。
- 其他状态字段（lifecycle、workers、storage.databasePath）均取实例内状态与已解析路径；workers 为空 Map（CM1 无 Worker，不伪造 RUNNING）。

### 4.6 关闭超时的可观察语义（B2 前定稿）

- `shutdownTimeout` 是**关闭等待在途退出的观察期限**，不是强杀期限：到点后允许继续等待真实 JDBC 退出（沿用 CT04 drain），不得因到点就发布 `CLOSED`、报告资源已释放或关闭仍在使用的连接。
- **失败终态必须与共享结果一致**：启动/清理失败时状态转为 `CLOSED` 并让共享完成结果携带同一失败（主异常保留、收尾失败 suppressed），不得停留在 `STOPPING`/`STARTING` 等待一个永不完成的结果；后续 `close` 仍共享该失败结果。
- 清理结果唯一：成功才发布 `CLOSED`；失败时共享结果抛失败并保留主异常（收尾失败 `addSuppressed`），不吞清理失败、不伪报成功。
- 不新增与 CT04 冲突的关闭协议；复用执行器 drain、唯一完成结果与 `NonCancellable` 清理；等待者取消不影响共享清理。
