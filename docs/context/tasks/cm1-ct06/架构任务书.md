## 范围与依据

依据CT01实施契约§c/§h、三份Context设计、CM1任务书及既有API状态/异常契约。在context/runtime实现配置加载/校验、已有VFS配置组装、Runtime资源所有权、启动/关闭与真实状态；通过CT04 Factory/Initializer、CT05 ContextDatabaseImpl组装持久化。不重新实现数据库或VFS生命周期，不给VFS增加Loader，不改VFS源码。

## 技术要求

1. 配置：读取context/vfs分区，按CT01默认值支持最小配置与缺省空namespaces/mounts；所有相对路径按YAML文件目录解析。环境变量缺失或空白具名报错且不回显值；负责分区未知字段拒绝、非负责分区忽略。使用现有SnakeYAML并限制不安全类型构造；类型/范围/重复键等解析错误安全映射。先列明CM1实际字段与全集蓝图的阶段边界，不要求未实现LLM密钥/任务，不启动假Worker。
2. 构造既有VfsRuntimeConfig及LocalFs/WebDav挂载配置；凭据不可经配置打印、cause/suppressed/日志泄露。context.db与VFS状态库不得同一文件，也不能落在LocalFs挂载公开范围内；按规范化实际路径校验，考虑已存在符号链接/同文件别名，不能只比较原字符串。不要新增无设计依据的父子路径禁令。
3. create仅纯配置接收、校验及依赖组装，不打开数据库/创建文件/连接网络/启动协程；VFS.create推迟到start。首次数据库创建通过显式初始化API调用CT04能力，普通start缺库/空库/错版/损坏拒绝且不自动创建或迁移。
4. 生命周期沿用CREATED→STARTING→RUNNING→STOPPING→CLOSED契约：并发start共享同一结果，RUNNING重复start幂等；close并发/重复共享一次清理结果。start/close竞争若关闭获胜，启动不得再发布RUNNING，已获得资源逆序清理；失败与取消路径清理责任不丢失。先画清状态/资源所有权表，明确失败启动终态及等待者取消不取消共享清理。
5. 关闭先停止准入/实际已创建任务，等待在途阻塞操作真正退出后释放数据库与其他资源；不能因协程取消或宽限期到期就在JDBC仍运行时关连接。复用CT04在途与关闭保障，收尾失败可见且不中断后续资源释放，主异常/取消不被替换。保持SDK无Ktor Server依赖，不启动HTTP。
6. 状态如实反映实际生命周期与存储初始化，不把未实现Extraction/Organization/Dreaming等Worker标为正常运行。仅组装CM1当前必需资源，不为后续能力创建无用HTTP客户端、Cron或后台任务；CT07业务入口留后续接线，不用TODO/假成功冒充完成。

Lead先落配置字段/默认值/映射、生命周期状态与所有权、失败/取消处置及测试映射方案，再委派Paseo worker，保持单一写入者。可分配置与生命周期等可验收批次，每批初验立即交Architect。

- 配置真实YAML覆盖缺省/最小配置、相对目录、ENV缺失/空白、未知字段、类型/限额、LocalFs/WebDav映射、异常完整链脱敏、同文件与挂载路径隔离；不通过真实远端网络测试泄露凭据。
- create副作用断言、显式初始化及普通start拒绝保护须用真实文件SQLite/VFS本地资源。重复/并发start、close及交错启动失败的资源数/最终状态直接断言，不用sleep证明竞态。
- 真实阻塞JDBC受控屏障确认close等待实际退出；关闭后/启动前访问按API具名拒绝。当前尚无Ingestion时验证已有入口与准入组件，CT07再接业务，不提前扩HTTP。
- 故障注入必须确认注入点和前序阶段、检查真实资源释放；所有辅助线程/目录流都有有界回收及失败可见。正常配置/生命周期与失败路径并重，不只测试异常名称。
- 适当模块和集成测试/格式通过后全工程回归，计数/最终SHA/81基线一致。Runtime对外仅暴露API必要契约，Server编译类路径不泄漏Core/Persistence实现依赖。文档在本目录，临时证据在.local/validation/cm1/。
