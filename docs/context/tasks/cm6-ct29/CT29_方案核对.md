## 2. 请求确认的最小接缝

### D1 离线升级前备份入口

Persistence新增公共 `ContextOfflineBackup`（纯同步、无协程/Runtime/VFS）：

```kotlin
object ContextOfflineBackup {
    fun snapshot(source: Path, target: Path): OfflineBackupResult
}
data class OfflineBackupResult(val path: Path, val sizeBytes: Long)
```

实现仅Persistence/JDBC：源缺/0字节DATABASE_NOT_INITIALIZED；`SqliteUrls.openReadUrl` 读源版本和结构，版本非1按SCHEMA_VERSION_MISMATCH，损坏PERSISTENCE_UNAVAILABLE；目标父目录必须存在，目标用 `CREATE_NEW` 独占认领，拒绝覆盖；在同一源连接调用现有Xerial backup，独立只读打开目标 `PRAGMA quick_check` 恰好ok并验版本/结构，写源库为0。失败只删自有目标，不删源/sidecar；安全异常不携带SQL/cause秘密。

允许小改 `ContextSqliteBackup.kt` 提取共享底层算法，或新增 `ContextOfflineBackup.kt` 调用同模块internal；不得复制两套快照规则。现有在线Backup算法/语义不变。备份不是迁移，v1 no-op也先产生可独立quick_check备份再报告no-op，以满足“有实际升级入口须先备份”。

### D2 CLI契约

建议命令：

```text
alcyone-context init --config /path/alcyone.yaml
alcyone-context upgrade --config /path/alcyone.yaml --backup-dir /path/upgrade-backups
alcyone-context run --config /path/alcyone.yaml
```

- 无参数、未知命令/选项、重复/缺失参数、相对/绝对YAML均可明确处理；不隐式init，不带默认run。`--config`只出现一次，`--backup-dir`仅upgrade需要且禁止用于init/run。
- init：先两个现有Loader纯校验（Context+Server），再 `initializeDatabase`；已存在任何文件失败且字节不变；成功只输出固定 `INITIALIZED` 与路径（路径可含敏感信息，建议只输出 `INITIALIZED`，不带配置正文/Key）。
- upgrade：Loader纯校验→离线版本检查→目标父目录必须预先存在且为目录→生成UTC时间+UUIDv7文件名的 `.sqlite` 备份→独立quick_check/结构验证→v1固定 `NO_OP schema_version=1` 与备份路径（若路径敏感则只输出backup ID；运维需要可取回，待定）；高低版/损坏失败且绝不no-op成功。
- run：只 `ManagedAlcyoneHttpServer.fromYaml(config).start()`，缺库/错版失败，成功后阻塞；shutdown hook幂等触发managed close，主线程等待并传播失败。init/upgrade绝不构造AlcyoneContext/Managed/CIO。
- 退出码建议：0成功/no-op；2命令用法/配置无效；3初始化/版本/备份/持久化失败；4 run启动或关闭失败。stderr只固定code，不打印Throwable/message/stacktrace/YAML/Key。若内部错误日志需要仅类型名，不能含路径/正文。
- `main` 可用 `runBlocking`；B1直接测试可注入command runner，B2用真实 `java -jar`/installDist子进程验证退出码。信号只在B2真实进程测试，不用单元Test假称。
