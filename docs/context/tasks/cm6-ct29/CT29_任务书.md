## 1. 初始化与升级

- 日常 Standalone 缺少数据库必须失败且不创建文件；显式 `init` 才复用既有 `AlcyoneContextFactory.initializeDatabase` 创建最新 Schema。已存在、损坏、user_version 高/低均不得由 init 覆盖或自动迁移。
- `upgrade` 是独立显式命令。当前只有 Schema v1 且没有已批准 `.sqm` 时，目标等于当前版本可明确报 no-op；任何低/高版本均拒绝，禁止伪造升级成功。先产生可独立打开且 quick_check=ok 的升级前备份，再考虑未来迁移；本批没有实际迁移路径就不得宣称已验证回滚迁移。
- 初始化和升级命令不得启动 Worker/Cron/Ktor，不调用普通 managed start 隐式建库；成功/失败退出码稳定，stderr 不泄露 Key、配置正文或任意后端秘密。

## 2. Standalone 与部署样例

- 提供真实 JVM `main`：单一 YAML 路径；`init` / `upgrade` / `run` 命令明确，缺省行为不得隐式授权初始化。`run` 使用 CT28 `ManagedAlcyoneHttpServer.fromYaml`，处理 SIGTERM/SIGINT 关闭钩子并传播退出失败。
- 使用 Gradle application/distribution 或等价最小可执行产物，保持版本集中于 libs.versions/toolchain；systemd/Caddy 只给与本地产物一致的样例和说明，不引入第二套 Server/Runtime。
- 默认 127.0.0.1:8080；systemd 专用低权限用户、只读配置、持久化数据目录、Restart=on-failure、TimeoutStopSec；Caddy 仅 TLS/本机反代，不信任客户端 Forwarded 头，不绕过三类 Key。
