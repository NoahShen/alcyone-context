# CT29 使用说明

- 仅修文档，不改 Loader/生产；Linux systemd/Caddy仍not-run。

## 历史修改（2026-11-11，Standalone 与部署样例）

- 说明真实 `installDist` 的 init/upgrade/run、备份和信号退出；部署文件见根 `deploy/README.md`。
- macOS arm64 进程已验证；Linux systemd/Caddy/真实证书/自动迁移恢复 not-run。

## 1. 构建与初始化

```bash
./scripts/dev gradle :context:server:installDist
cd <持久化工作目录>
<分发目录>/bin/alcyone-context init --config <config.yaml>
```

YAML 同时包含 `context`、`vfs`、`server`，示例见 `deploy/README.md`。YAML 内相对路径以 **YAML 文件所在目录**解析，不以 systemd WorkingDirectory 或进程 CWD 为基准；部署样例因此使用 `/var/lib/alcyone-context/...` 绝对路径。`init` 只初始化 Context v1，不建 VFS、不开端口；已存在、0 字节、损坏或高低版本均拒绝，不覆盖。成功输出 `INITIALIZED`，退出 0。

## 2. 独立升级与备份

```bash
<分发目录>/bin/alcyone-context upgrade --config <config.yaml> --backup-dir <已存在备份目录>
```

命令先离线只读检查源库，使用不覆盖目标备份，校验版本、六表五索引、turn/committed raw 和独立 `quick_check`，再对 v1 输出 `NO_OP schema_version=1 backup_id=<文件名>`。当前没有真实迁移、自动恢复或回滚承诺；保管备份并限制权限。

## 3. 运行与停止

```bash
<分发目录>/bin/alcyone-context run --config <config.yaml>
```

缺库/错版不隐式初始化。默认 `127.0.0.1:8080`；Read/Admin 仍需各自 Key，Caddy 不绕过。SIGTERM/SIGINT 等待在途请求和同一 Managed 关闭：成功退出 0，启动/关闭失败退出 4。参数/配置错误 2，init/upgrade 失败 3。

service/Caddy 文件、低权限用户、持久化目录和静态检查见 `deploy/README.md`。这些文件是未在 Linux 实跑的样例，不代表生产部署通过。
