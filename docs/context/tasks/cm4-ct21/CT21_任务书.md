## 1. 目标

CT21 只做 CM4 集成、取消/清理回归、固定集评测归档与收口证据，不新增生产能力：

```text
Conversation
  → Extraction
  → Raw + Pending
  → Organization
  → Organized + Source + watermark
  → Memory Map 生成/发布
  → Bootstrap
  → Search
  → Get / GetRaw
  → Resource Meta / Read / Stream
```

并证明：

- Map 发布与 Bootstrap 读取只看到完整旧版或完整新版。
- Search 返回的 Memory 可携带 Resource URI，后续 Resource 流取消/关闭会释放真实 VFS stream。
- Map stale 能经既有 wakeup/Cron 规则补偿到 CURRENT。
- Fake 固定集只证明协议与确定性约束；真实模型评测保持 `not-run`。
- CM4 收口证据可独立复现。

## 3. 全景 SDK 链候选

### 3.1 真实栈

- 公共 `AlcyoneContextFactory.create/initializeDatabase/start/close`。
- 真实 Context SQLite + 真实 VFS LocalFs `/memory` 与 `/resources` 双挂载。
- 真实 Ktor LLM client + 本机 JDK HTTP stub；不使用真实模型。
- Extraction、Organization、MemoryMap、Retrieval 全部走生产 Runtime。

### 3.2 链式场景

1. 启动 Runtime；空库 Map 启动检查得到确定性空 Map。
2. Ingest 5 个 Conversation Turn，触发 Extraction。
3. Fake Extraction 返回含 Resource URI 的 Raw Memory。
4. Organization Governance 返回 NEW，生成真实 Organized/Source/watermark。
5. Organization committed 触发 Map；Fake Map 返回 Overview/Navigation/真实 Domain。
6. `bootstrap()` 返回已发布 Map，状态 `STALE|CURRENT`，不新增 LLM。
7. `searchMemory()` 经 Scanner + Rerank 返回该 Organized。
8. `getMemory/getRawMemory` 返回 SQLite 权威对象。
9. 从 Memory 内容取得 `alcyone://resources/...`，执行 Meta/Read/Stream。
10. close 后所有业务入口 CLOSED，后台 worker/stream 无残留。

### 3.3 动态 Fake HTTP 路由

静态顺序响应无法安全匹配 Organization 动态生成的 `O-MEM-*` ID。候选新增测试专用 JDK HTTP stub：

- 按 System Prompt 标记区分 Extraction / Governance / MemoryMap / Search Scanner / Search Rerank。
- 需要动态 ID 时从当前真实 SQLite 只读查询 Organized ID。
- 记录每次请求类型、顺序、body/header；不记录或泄露 Key。
- 测试专用，不进入生产源码或公共测试框架。

## 4. Map 发布/读取交错候选

建议独立集成测试：

1. 预置第一版 Organized，启动 Map Pipeline，等待第一版完整 Map。
2. 直接向 SQLite 预置第二版 Organized（或走真实 Organization），触发 Map wakeup。
3. 动态 HTTP stub 阻塞第二版 Map 响应。
4. 在阻塞窗口反复 `bootstrap()`：只能看到第一版完整 Markdown；不得出现半写、空正文或破损 Front Matter。
5. 释放第二版响应，等待发布完成；新 Map 内容完整、Front Matter 可严格解析。
6. 再执行一次水位检查，状态从 STALE 收敛 CURRENT。
7. 允许使用测试专用 `INVISIBLE_REFERENCE` suppression 调用 internal wakeup/VFS stream 计数接缝；不得改变生产可见性。

## 5. Search → Resource 取消/释放候选

全景链中 Resource URI 来自 Search/Get 返回的真实 Memory，而不是测试直接拼写：

- `loadMeta` 断言 URI/size/modifiedAt。
- `read` 逐字节一致。
- `readStream` 正常完成，64 KiB 分块，合计字节一致。
- collector 收到首块后 `awaitCancellation`，取消后真实 `trackedStreamCount == 0`。
- 再次打开 stream 后调用 `context.closeAsync()`，stream 被回收，close 在超时内返回。
- close 后新 collect 抛 CLOSED。
- 测试不得以固定 sleep 猜测释放，使用 barrier/轮询 tracked count。
