### 2.2 动态 HTTP stub

- 测试专用，不进生产源码或公共测试框架。
- 按 System Prompt 标记路由 Extraction / Governance / MemoryMap / Search Scanner / Search Rerank。

- stub 禁止写库、注入业务状态或伪造 ID 来源。
- 记录请求类型/顺序/header/body 时不得输出或持久化 API Key 原文。

### 2.3 全景链 `Cm4SdkJourneyEndToEndTest`

必须覆盖：

```text
start
  → 5 Conversation Turns
  → Extraction
  → Raw/Pending
  → Governance
  → Organized/Source/watermark
  → Memory Map
  → safeReplace
  → bootstrap
  → Search Scanner + Rerank
  → getMemory/getRawMemory
  → Resource Meta/Read/Stream
  → close
```

附加断言：

- LLM 请求类型序列严格为 `Extraction → Governance → Map → Scanner → Rerank`。
- Organization Candidate Scanner 在空候选下可为 0 请求；若出现请求，必须解释并保持序列规则。
- Search 返回动态真实 `O-MEM-*` ID，不接受 stub 伪造 ID。
- Memory 内容包含真实 `alcyone://resources/...` URI。
- `getMemory/getRawMemory` 不新增 LLM 请求。
- close 后无新增请求，所有业务入口 CLOSED。
- 真实 SQLite + 真实 VFS LocalFs `/memory` + `/resources` + 真实 Ktor client + JDK stub。

### 2.4 Map 交错 `Cm4MapInterleavingEndToEndTest`

- 单测试有界，<60s。
- 第一版 Map 完整。
- 第二版触发优先走真实 Organization 路径。
- 若测试稳定性不可行，才允许“预置第二版 Organized + `organizationMapWakeupForTesting()`”退路；使用 `@Suppress("INVISIBLE_MEMBER", "INVISIBLE_REFERENCE")`，不改变生产可见性。
- 第二版 LLM 响应使用确定性 barrier/gate 阻塞；禁止固定 sleep。
- 阻塞窗口反复 bootstrap：只能看到完整旧版 Markdown，Front Matter 严格解析，无半写/空正文/破损。
- 释放 gate 后新版完整；下一次水位检查从 STALE 收敛 CURRENT。

### 2.5 Search→Resource 取消 `Cm4SearchResourceCancellationEndToEndTest`

- Resource URI 必须来自 Search/Get 返回的真实 Memory 内容。
- 真实 LocalFs 文件至少 >128 KiB，覆盖多个 64 KiB chunk。
- `loadMeta/read/readStream` 验证 URI、大小、字节一致。
- collector 收到首块后挂起并取消；使用 `vfsForTesting().trackedStreamCount` + barrier/轮询断言最终 0，禁止固定 sleep。
- 再次打开 stream 后 `closeAsync()`；stream 回收、close 有界返回。
- close 后新 collect CLOSED。
