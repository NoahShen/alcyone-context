## 1. 目标与现状

在现有 Ktor CIO Server 上完整暴露已交付 SDK 能力。Server 负责认证、参数/DTO/错误转换与传输；不得直接查业务表、重建 Search/Backup/Dreaming 流水线或自行操作 VFS。

现有 `AlcyoneContext` 已有 bootstrap/searchMemory/getMemory/getRawMemory/loadMeta/readStream/runDreaming/backupNow/getStatus；`IngestionHttpApi` 已有 Bearer、Runtime 绑定、请求字节上限、严格 UTF-8 与固定错误体。`getStatus()` 仅缓存 `databaseInitialized` 且包含真实 databasePath，不能直接当 Ready，也不能原样序列化到 HTTP。

## 2. 路由与权限

| 方法/路径 | 唯一 SDK 委派 | 凭据/成功语义 |
| --- | --- | --- |
| POST `/v1/conversations/turns` | ingestConversation | Ingestion；201/200 与冲突语义保持 |
| GET `/v1/context/bootstrap` | bootstrap | Read；200，Map 四态原样 |
| POST `/v1/memories/search` | searchMemory | Read；200 列表，空匹配可空，失败不可伪空 |
| GET `/v1/memories/{id}` | getMemory | Read；200，null 为 404 |
| GET `/v1/raw-memories/{id}` | getRawMemory | Read；200，null 为 404 |
| GET `/v1/resources/meta?uri=...` | loadMeta | Read；200 |
| GET `/v1/resources/content?uri=...` | readStream | Read；200 二进制流，单一路由 |
| GET `/v1/admin/status` | 既有状态 + Runtime 管理快照 | Admin；200 脱敏完整可用状态 |
| POST `/v1/admin/dreaming` | runDreaming | Admin；等待本次结果，不另建后台 Job |
| POST `/v1/admin/backup` | backupNow | Admin；等待发布结果，不接收自定义目标路径 |
| GET `/health/live` | HTTP 基本响应 | 无 Key；200 固定短体 |
| GET `/health/ready` | Runtime 真实数据库健康探测 | 无 Key；可服务 200，否则 503 固定短体 |

三类权限互不继承：Admin 不兼作 Read/Ingestion，Read 不可查看管理状态，Ingestion 仅可写绑定 runtime_id。未知/缺失/畸形 Bearer 为 401；已识别但类别不符或 runtime_id 不符为 403；认证先于读取正文及调用 SDK。

扩展现有 `server.auth.readKey/adminKey`；未配置某类 Key 时该类端点不可访问，保留仅 Ingestion 配置兼容。显式配置的缺失环境变量、空白 Key、三类间或同类内重复 Key、重复 runtimeId 均启动前拒绝；Loader/直接构造/Registry 三入口一致，快照防御性复制，比较使用固定长度摘要与恒定时间比较，错误与 toString 不回显秘密。

这只是可信调用者的静态 HTTP 认证，不实现逐 Agent/Domain/Runtime 的读取 ACL。VFS 现状是路径、挂载、资源命名空间、后端能力及文件安全检查；必须复用这些检查，不能声称已有用户级 VFS ACL。

## 3. 参数、传输和错误

Search JSON 为 `query`（必需字符串）、`domains`（可省略/null/字符串数组）、`limit`（可省略，默认 SDK 10）；空数组与 null 的业务语义交 SDK。严格拒绝未知键、重复键、错误类型、尾随垃圾、非法 UTF-8；不将数字字符串强转，不自行改变 Domain 或全局排序。

新增 `server.limits.maxSearchBodyBytes`（默认 65536，正 Int）、`maxResourceBytes`（可选正 Long，默认不附加流总长上限）、`requestTimeoutMillis`（默认 60000，正 Long）。Search 的 Content-Length 预检和实际流计数均执行；Ingestion 仍取实例 IngestionLimitAware 限额，不用新常量覆盖。计数需防溢出；JSON 管理 POST 接受空 body 或严格 `{}`，其他字段/正文拒绝并按 Search body 上限读取。

Resource 先经 SDK loadMeta 校验与预检，然后 collect readStream；`application/octet-stream`，不将文件整体缓存，不把 URI 拼进 Content-Disposition。若配置 maxResourceBytes，同时检查已知 size 与实际累计字节；未知长度也不可绕过，默认流式策略不继承 ByteArray 的 16 MiB 限额。

响应头提交前的失败映射固定 JSON；首块打开/读取失败应在提交 200 前捕获。流中失败、超限、超时或客户端断开必须取消收集并释放流，终止响应，不能追加 JSON 或正常结束伪完整下载；不得依据可能过时的 stat 宣称精确 Content-Length。测试空文件、首块失败及中途失败，明确 HTTP 已提交后不能改状态码。

| 失败 | HTTP/安全错误 |
| --- | --- |
| 非法 JSON/参数/ID/URI、Resource 类型不符 | 400，固定具名代码 |
| 未认证 / 类别或 Runtime 不符 / Resource 越出范围 | 401 / 403 / 403 |
| Memory null、Resource NOT_FOUND | 404 |
| 请求体或 Resource 限额 | 413（已提交流则中断） |
| Dreaming/Backup ALREADY_RUNNING、既有 Turn 冲突 | 409 |
| 生命周期非 RUNNING、数据库不可用、未配置能力 | 503 |
| Retrieval CONFIGURATION/UNAVAILABLE、LLM/Scanner 失败 | 503 具名依赖故障，不能伪 200 空列表 |
| DreamingRunException、Backup 校验/发布失败 | 500 具名阶段/代码，不能伪成功 |
| Server 自己的请求期限到达 | 504；取消底层工作，不宣称回滚已提交批次 |
| 其他异常 | 500 INTERNAL_ERROR |

复用并抽取 Ingestion 的有界 body/UTF-8/固定错误响应与鉴权基础设施，保留原错误兼容。外部 CancellationException 原样传播；仅明确属于本次 Server 自有 deadline 的超时可转 504。响应、实际日志和异常链不得包含 Key、原始 body/Prompt、数据库绝对路径、后端 URL 或任意 Throwable.message。

## 4. Ready、管理状态与生命周期

批准增加最小 SDK `suspend fun checkReady(): Boolean`，第三方默认 false；Runtime 实现必须通过当前受管 executor 的 ReadContext 执行轻量权威表查询（可复用 checkpoint 读取），查询成功后再确认 RUNNING。不得用缓存 initialized、文件存在、另开 JDBC 连接或只返回常量证明健康；失败/关闭/未知一律 false，外部取消继续传播。它证明本次读能力，不宣称每次探针完成全库完整性扫描。

Ready 不调用 LLM、VFS 网络、Map 生成，不因 Pending、Map STALE/UNKNOWN 或最近 LLM/Dreaming 失败自动降级。短探针限时（默认 2000ms，允许 `server.limits.readyTimeoutMillis` 正 Long 配置）不得转化为“已经强制终止 JDBC”的保证，必须和 executor 关闭协调。

管理状态通过 Runtime 最小只读快照扩展提供现有 lifecycle/workers、Pending 数量、Dreaming checkpoint、Map 四态、LLM usage/调用统计与 Backup 状态；保持现有 getStatus 的无 I/O 契约，新增 `getAdminStatus()` 与安全 DTO 承载需要查库的数据。只接入现有 Repository/统计快照，不新建监控表、不复制业务逻辑；不支持/无法获知字段为 null 或显式 unavailable，禁止用 0/CURRENT 冒充。管理快照数据库读取失败为 503；任意 lastError 只输出受控代码，SDK databasePath 不传 HTTP。

保留现有 `AlcyoneHttpServer.start(config, context)` 的外部 Runtime 所有权与“可先监听、请求返回503、随后宿主 start”的已测行为。另加清晰的 managed 入口供 Standalone：配置/Key 校验→唯一 Runtime.start→CIO 监听；监听或启动失败逆序清理，默认 127.0.0.1:8080。

managed close 先封闭 HTTP 准入、排空或取消在途并确认清理完成，再 closeAsync Runtime；并发/重复 start、close 共享真实结果，不重复开资源或提前释放数据库。外部所有权入口 close 只关 Server，Runtime 由宿主关闭。CT28 交付可测 managed 组合；systemd/Caddy 样例及独立部署冒烟归 CT29，禁止信任客户端自报 Forwarded 头绕过认证。
