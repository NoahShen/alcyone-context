## 3. B1 技术边界

### 3.1 配置与凭据

- 保留 `server.ingestion.clients.<runtimeId>.{runtimeType,apiKey}` 兼容。
- 新增并严格解析 `server.auth.readKey`、`server.auth.adminKey`；未配置表示该类别禁用，显式缺失 ENV、展开为空或字面量空白必须启动前拒绝。
- 新增并严格解析 `server.limits.maxSearchBodyBytes`（Int，默认 `65536`）、`maxResourceBytes`（可选 Long）、`requestTimeoutMillis`（Long，默认 `60000`）；全部要求正数。`readyTimeoutMillis` 属 B2，不在 B1 实现。
- Loader、`ServerConfig` 直接构造、Registry 三入口使用同一校验：空白 Key、Ingestion 同类重复、三类跨类重复均拒绝；错误含字段路径但不含 Key。
- 配置对象防御性快照且 `toString()` 脱敏。凭据比较使用固定长度 SHA-256 摘要与恒定时间比较，不以原始 Key 作为 HashMap 查找键。
- 解析只接受 `Authorization: Bearer <token>`；缺失、未知或畸形为 401。已识别但类别不符为 403。认证必须先于 body/query 读取及 SDK 调用。

### 3.2 Read 路由与 DTO

只实现六条 Read 路由：

| 路由 | SDK 委派 |
| --- | --- |
| `GET /v1/context/bootstrap` | `bootstrap()` |
| `POST /v1/memories/search` | `searchMemory(query, domains, limit)` |
| `GET /v1/memories/{id}` | `getMemory(id)` |
| `GET /v1/raw-memories/{id}` | `getRawMemory(id)` |
| `GET /v1/resources/meta?uri=...` | `loadMeta(uri)` |
| `GET /v1/resources/content?uri=...` | `readStream(uri)` |

- Read Key 只进入六条 Read 路由；返回显式安全 DTO，禁止直接序列化 Domain/内部对象。
- Bootstrap 保持四态与 Map 内容/时间；Memory DTO 字段使用 snake_case，保持 Domain 数组顺序与全部时间值。
- Search body 严格 JSON：未知键、重复键、错误类型、缺 `query`、尾随垃圾、非法 UTF-8 均 400；`domains` 可省略/null/字符串数组，`limit` 可省略且默认 10；不自行 trim、排序或重写 Domain。
- Search 同时执行 Content-Length 预检与实际有界流计数，精确 byte 限额通过、`+1` 拒绝，计数防溢出；不得在检查前完整缓存无限 body。
- `GET /resources/content` 只调用 `loadMeta` 做 SDK 校验/预检，再 collect `readStream`；不得直接访问 VFS/OpenJar。响应 `application/octet-stream`，不得把 URI 回显到 `Content-Disposition`。
- 默认不设流总长限制，不把资源整体载入内存，不继承 `read()` 的 16 MiB ByteArray 限额。配置 `maxResourceBytes` 时同时检查已知 stat size 与实际累计字节，未知长度也执行实际计数。
- 首块成功前错误映射固定 JSON；首块成功后不得再写 JSON。流中途失败、超限、超时或客户端断开时取消 collect 并终止响应，不得正常结束伪装完整下载。不依据可能过时的 stat 写精确 Content-Length。
- 空文件返回 200 且长度为 0。路由使用单一路径 `/v1/resources/content`，不增加 alias。

### 3.3 错误映射

- 认证：未知/缺失/畸形 401 `UNAUTHORIZED`；已识别错类 403 `FORBIDDEN`。
- 参数/URI/资源类型：400，使用固定具名代码并保持现有 Ingestion 兼容。
- Memory null、Resource NOT_FOUND：404。
- Search/Resource 限额：413；响应已提交时只能中断流。
- 生命周期非 RUNNING、Persistence 不可用、Retrieval `UNAVAILABLE`/`CONFIGURATION`、Resource `UNAVAILABLE`：503。
- Server 自有请求期限：504，并取消底层工作；外部 `CancellationException` 原样传播，不包装。
- 其他异常：500 `INTERNAL_ERROR`。
- 响应、日志、异常链不得包含 Key、query、memory 正文、原始 body、数据库绝对路径、VFS/后端 path/URL 或任意 Throwable.message。

### 3.4 组装与兼容

- `AlcyoneHttpServer.start(config, context)` 继续保留外部 Runtime 所有权和“先监听、Context 未 start 时 503、宿主后 start”的既有行为。
- 同一 Application 同时安装 Ingestion 与 Read；不得引入 Admin/Health/managed 生命周期实现（B2）。
- 抽取共享鉴权、严格 UTF-8、有界 body、固定错误响应时，不得改变旧 Ingestion 成功/错误语义或 Runtime 绑定。

- 未授权请求对 SDK spy 的调用数为 0，SQLite 写入数为 0；认证先于 body/query 读取。
- Loader、直接构造、Registry 三入口：空白、同类重复、跨类重复一致拒绝；原 Map 后续变更不影响快照；异常与 `toString` 无独特 Key 标记。

- Resource meta/content 成功；NOT_FOUND、OUT_OF_SCOPE、INVALID_URI、TYPE_MISMATCH 固定 400/403/404；不得绕过 SDK。

### A03：严格 JSON、字节上限与旧 Ingestion 回归

- Search 重复键、未知键、尾随垃圾、缺字段、null/错误类型、非法 UTF-8；精确限额与 `+1`；有/无 Content-Length、分块与谎报长度。

- 原 Ingestion 全部既有测试通过，包括 Runtime 绑定、201/200/409/413、严格 UTF-8、关闭竞态。

### A04：Resource 流式与释放

- 大于 `read()` 默认 ByteArray 限额的文件经 HTTP 下载后 SHA-256/字节完全一致；空文件 200。
- 首块失败在提交前映射固定 JSON；中途故障以截断/异常结束，不能追加 JSON 或伪完整结束。
- 客户端断开、超时、超限取消 collect；测试证明 Flow/底层 release 被调用且仅调用一次。
- `maxResourceBytes` 分别覆盖已知长度预检、未知/谎报长度实际计数、精确限额与 `+1`。

### A08：脱敏、边界与全量回归

- 在 Key、query、Memory/Raw 正文、URI、User-Agent 或异常 message 放入独特秘密标记；所有 HTTP 响应、Server 捕获日志、异常链均不含标记。
