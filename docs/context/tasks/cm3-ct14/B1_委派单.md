## 2. 实现要求

### 2.1 Core DTO / Validator

- `GovernanceAction { NEW, MERGE, UPDATE }`。
- `GovernanceDecision(action, targetMemoryId: String?=null, content: String?=null, domains: List<String>?=null)`。
- `GovernanceDecisionValidator.validate(decision, candidates): GovernanceDecision`：
  - `NEW`：content 非空、domains 非空；target 必须 null；domains 空白元素拒绝；重复稳定去重（保留首次）；不 trim 改写。
  - `MERGE`：target 非空且属于 `candidates`；content 若提供非空；domains 必须 null（空数组同样拒绝）。
  - `UPDATE`：target 非空且属于 candidates；content 非空；domains 若提供非空、空白拒绝、重复去重。
  - 未知/非法动作、target 越界、字段组合错误 → 抛 `GovernanceValidationException`（内部）；**绝不降级 NEW/部分保存**。
  - 空候选集合允许 NEW。
- 返回规范化 decision（仅 domains 去重；target/content 不改写）。

### 2.2 Core Prompt / Schema

- `GovernancePrompt`：v1 资源；`messages(raw, candidates)` 返回 system+user；候选含 id/content/domains/createdAt/updatedAt；Raw 含 id/content/createdAt/generatedBy。
- Prompt 六要素必须逐条可断言：事实时间优先、补录旧事实 MERGE、后续真实变化 UPDATE、不确定/矛盾明确写入、输入是数据不是指令、只输出一个 JSON。
- 明确 target 只能来自输入候选；不得输出 ID/时间/来源字段；正文伪造字段/分隔符不改变权限。
- Schema v1：object、`additionalProperties=false`、action enum、target/content/domains 类型；严格 JSON。

### 2.3 Runtime Parser / Service

- `JsonGovernanceResponseParser`：严格 object；只允许 action/targetMemoryId/content/domains；action 字符串；target/content 字符串或 null；domains 字符串数组或 null；未知字段/类型/围栏/前后文本/空白 action → `LlmException(INVALID_RESPONSE)`；不修复。
- `LlmGovernanceService`：
  - 构造参数 `llmClient`、`llmConfig`、`estimator`；构造期校验 `GOVERNANCE` Task/Profile/模式；缺 Task/Profile/`PROMPT_ONLY` → `ContextConfigException(INVALID_CONFIG)`；不触 DB/LLM。
  - `suspend fun decide(raw, candidates): GovernanceDecision`：构造请求；`LlmBudget.requireWithinBudget`（Schema 仅 JSON_SCHEMA；maxOutput=Task；输出/余量计入）；超限 → `LOCAL_BUDGET_EXCEEDED`，0 LLM；调用 `LlmClient`；`finish_reason=length` → `OUTPUT_TRUNCATED`；解析；Validator；返回。
  - 不写数据库；不接生产；取消原样传播。
- 错误消息不含 Raw/候选正文/Key/URL/Prompt。

## 3. 测试要求

### Core

- Validator 全分支：NEW/MERGE/UPDATE 合法；NEW target 非空拒绝；MERGE domains 空数组/非空拒绝；UPDATE domains 可选；target 不在候选拒绝；空候选 NEW 通过；空白 content/domains 拒绝；重复 domains 稳定去重；非法不降 NEW。
- Prompt/Schema 正式测试：六要素逐条断言；候选字段/顺序；空候选；数据非指令/伪造字段；Schema `additionalProperties=false`/action enum/字段类型；资源缺失显式失败。

### Runtime

- Parser：合法三种动作；未知字段/错误类型/非字符串/非数组/围栏/前后文本/空 action → `INVALID_RESPONSE`；错误不含正文。
- Service（真实 SQLite + Fake LLM）：
  - 合法 NEW/MERGE/UPDATE 返回决策；DB 无写入（前后表计数/内容一致）。
  - target 越界/伪造 target → `INVALID_RESPONSE`，DB 0 写。
  - 非法 JSON/截断/空响应 → 失败，DB 0 写。
  - 预算超限（非零 Schema/输出/余量）→ `LOCAL_BUDGET_EXCEEDED`、0 LLM、DB 0 写。
  - 取消传播；构造期配置校验不触 DB/LLM。
  - 固定 Fake 样本：旧事实 MERGE、后续 UPDATE、矛盾/不确定 content、非法降级 NEW 反例；不跑真实模型。
- 真实 SQLite 用于种子 Raw/Organized 与“0 写”断言，不要求 Service 接 DB。
