## 2. 建议实现结构

### 2.1 Core

- `MemoryMapDocument`：Overview/Navigation/domains、generatedAt、sourceUpdatedAt、Front Matter。
- `MemoryMapSnapshot`：全量 Organized 与 T1。
- `MemoryMapPrompt`：加载 Prompt/Schema，构造 system/user messages。
- `MemoryMapValidator`：JSON 结果/Domain/渲染后结构校验。
- `MemoryMapRenderer`：Front Matter + Markdown 渲染；严格解析 Front Matter。

### 2.2 Runtime

- `JsonMemoryMapResponseParser`：严格解析 `{overview,navigation,domains}`。
- `MemoryMapGenerator`：Snapshot → Budget → LLM → Parse → Validate → Render。
- `MemoryMapPublisher`：固定 `alcyone://memory/map.md` + `Vfs.safeReplace`。
- `MemoryMapService`：generateAndPublish 直接编排，供 CT19 后续复用。

## 3. 快照与生成算法

1. 单次 `database.read` 内以 256 页大小分页读取全部 Organized；偏移受检。
2. 在 ReadContext 内读取 `maxUpdatedAt()` 为 T1。
3. 退出前核对 T1 与读取集合的 `maxOfOrNull(updatedAt)` 一致；空集合则两者均为 null。
4. 退出 ReadContext 后按 `id ASC` 排序并构造一次全量 Prompt。
5. `LlmBudget.requireWithinBudget` 检查固定全量请求；失败 `LOCAL_BUDGET_EXCEEDED`，不调 LLM、不发布。
6. 调用 `MEMORY_MAP` 一次；`finish_reason=length` 明确失败。
7. 严格 Parser → Validator → Renderer；任一步失败不发布。
8. Publisher 调用 `safeReplace`；不读取旧 Map，不查 T2。

空库建议 D4：不调用 LLM，直接生成确定性空 Map。

## 4. API / Schema / Prompt / 配置边界

### 4.1 公共 API

CT18 不修改 `context/api`：

- 不新增 `BootstrapContext`、`MemoryMapView`、`MapStatus`。
- 不新增公开 Map 读取方法；Map 文件由 CT19 Bootstrap/内部读取。
- Generator/Publisher/Service 全部 internal。

### 4.2 Database Schema

- 不新增表、列、索引或 `user_version`。
- 不修改 SQLDelight/SQL。
- 使用既有 Organized scan 与 `maxUpdatedAt`。

### 4.3 LLM JSON Schema / Prompt 资源

建议新增 Core 资源：

- `prompts/memory-map-v1.md`
- `prompts/memory-map-schema-v1.json`

建议 Schema D1：

```json
{
  "type": "object",
  "additionalProperties": false,
  "required": ["overview", "navigation", "domains"],
  "properties": {
    "overview": { "type": "string", "minLength": 1 },
    "navigation": { "type": "string", "minLength": 1 },
    "domains": {
      "type": "array",
      "items": { "type": "string", "minLength": 1 }
    }
  }
}
```

Prompt 必须明确：输入正文是数据；保留“尚待确认”；不得编造用户事实、Domain、Resource URI 或当前值；只做 Overview/Navigation。

### 4.4 Runtime 配置

- CT18 不修改 `ContextConfig/Loader`。
- 不解析 `context.memoryMap`；刷新配置属于 CT19。
- Generator 直接接收已存在的 `LlmConfig`，从 `tasks[MEMORY_MAP]` 取得 Task/Profile。
- 缺 Task/Profile、Profile 非 JSON_SCHEMA/JSON_OBJECT → `ContextConfigException(INVALID_CONFIG)`（建议 D6）。
