## 1. 当前基线与边界

### 1.1 已接受的工程基线

- CT30 Architect 已接受的历史基线为 `./scripts/check` **137/137**、14 模块 **312 XML / 2324 tests / 0 failures / 0 errors / 0 skipped**，Schema v4 与相关生产 SHA 未漂移。
- 该基线证明确定性规则、真实 SQLite、故障/进程/并发和全仓工程状态；它不是 Prompt 语义评测，不包含真实模型结果。本轮没有重复执行。
- CT30 明确保留的 not-run 不变：真实断电、Linux dirfsync、WebDAV durable、默认 Runtime 自动恢复、生产部署。

### 1.2 Fake、协议与模型质量

| 类型 | 当前证据 | 可声明 | 不可声明 |
| --- | --- | --- | --- |
| 确定性测试 | 预算、分页、JSON、ID/来源拒绝、事务、空结果、生命周期 | 工程边界正确 | 模型理解、冲突召回或摘要质量 |
| Fake/HTTP stub | 路由、请求格式、固定响应回放、SQLite 副作用 | 接线和协议可重复 | Provider 兼容性或真实语义质量 |
| 固定样本 | 合成输入、人工 must/forbidden/相关性约束 | 评测数据可审查 | 样本存在不等于模型通过 |
| 真实模型 | 当前四种来源均为 `not-run` | 无质量结论 | 不能用 XML、Fake 或测试数量替代 |

### 1.3 三类高风险错误

| 编号 | 定义 | 主要受影响 Task | 处理原则 |
| --- | --- | --- | --- |
| **H1** | 虚构或扩大用户事实，包括范围、时间、当前值、Domain、Resource URI 或证据 | Extraction、Governance、Search、Map、Dreaming | 逐条人工确认；不得被聚合准确率掩盖 |
| **H2** | 漏掉会改变当前判断的关键冲突、纠错或补充候选 | Candidate Scanner、Governance、Search、Map、Dreaming | Scanner 以高召回优先；记录关键冲突漏检数和样本 ID |
| **H3** | 已纠正事实被旧 Raw、旧 Organized 或历史证据回退 | Extraction、Governance、Search、Map、Dreaming | 事实时间优先；任何回归样例保留原输入、输出和人工裁决 |

这三类错误不计入统一的“总分”后抵消；出现时必须进入 `criticalErrors` 清单并人工复核。

## 2. B2 评测架构

### 2.1 分层

1. **数据集完整性层**：严格解析 JSONL/manifest/schema，校验版本、SHA、ID 唯一性、引用子集、Profile/Task 路由和风险覆盖。
2. **离线确定性层**：只运行无网络的测试级 harness，验证结构、预算、空结果、非法 ID/来源拒绝、报告 schema 和数据覆盖。
3. **语义评分层**：读取人工标注的 must/forbidden/qrels/action 等 oracle，计算可审查指标；B2 不自动声称机器理解了语义。
4. **真实模型层**：B3 在用户明确提供配置、外发范围、费用授权后才采集真实输出并人工复核；结果单独归档。

### 2.2 canonical 数据与旧文件

- B2 在根目录 `evals/` 建立 canonical `ct31-v1` 数据集；历史文件保持不动并作为 provenance。
- Extraction 的 `turn-1` 标签在 canonical 导入时映射为真实整数 Turn ID；Dreaming 的 `fixture-memory-search` model 按 manifest 规范化为 `fixture-memory-search-model`。
- 不在既有 docs/test-resource JSONL 上继续追加，避免同一 Task 出现多个会漂移的“最新版本”。
- `manifest-v1.json` 固定 `datasetVersion`、每类数据 SHA、Prompt/Schema 路径及 SHA、Profile/Task 预算和结果文件；任一输入变动都必须生成新版本，不静默覆盖。

### 2.3 通用样本信封

建议每个 JSONL 行至少包含：

```json
{
  "id": "ext-001",
  "datasetVersion": "ct31-v1",
  "task": "EXTRACTION",
  "split": "regression",
  "synthetic": true,
  "containsPersonalData": false,
  "input": {},
  "oracle": {
    "criticality": "CRITICAL",
    "riskTags": ["H1_FABRICATION"],
    "must": [],
    "mustNot": [],
    "sourceRefs": []
  },
  "review": {
    "status": "APPROVED_FOR_OFFLINE",
    "notes": "可审查的人工说明"
  }
}
```

Task-specific `oracle` 至少包括：

- Extraction：`requiredFacts`、`forbiddenFacts`、`sourceTurnIds`、`timeAnchors`、`expectedEmpty`。
- Candidate Scanner：`relevantIds`、`criticalRelevantIds`、`forbiddenIds`、`expectedEmpty`；所有 ID 必须来自输入候选。
- Governance：`expectedAction`、`allowedTargets`、`requiredContentPoints`、`forbiddenRegressions`、`uncertaintyRequired`。
- Search：`qrels[{id,gain}]`、`criticalIds`、`k`、`domains`、`expectedEmpty`；qrels ID 必须来自输入候选。
- Map：`requiredFacts`、`requiredDomains`、`forbiddenFacts`、`navigationChecks`、`uncertaintyRequirements`。
- Dreaming：`expectedInsights`、`requiredEvidenceTurnIds`、`duplicateOf`、`correctionGuard`、`expectedEmpty`。

## 3. 指标定义

不为所有 Task 计算统一准确率，也不设置全项目百分比硬门槛。每个 Task 报告“逐样本判定 + 聚合指标 + 关键错误清单”。

### 3.1 Extraction

- `MustFactRecall = 人工确认命中的 requiredFacts / requiredFacts`。
- `SpuriousFactCount`：输入无依据或扩大范围/时间的事实条数。
- `SourceExactRate = sourceTurnIds 与 oracle 一致且均为输入 Target 的样本数 / 非空样本数`。
- `TimeScopeViolationCount`、`UncertaintyLossCount`、`EmptyExactRate`。
- H1 是首要阻断项；空结果只检查是否应提取，不用“提取数越多”作为得分。

### 3.2 Candidate Scanner

- `RelevantRecall = |返回 ID ∩ relevantIds| / |relevantIds|`，按样本计算后报告 macro 平均值与分母。
- `CriticalConflictRecall = 命中的 criticalRelevantIds / criticalRelevantIds`；任一关键冲突漏检单独列出。
- `CandidatePrecision` 仅作观察指标，不能压过高召回目标。
- 输入外、空白、跨批、伪造 ID 由程序拒绝，记为 `protocolFailure`，不计入语义召回。

### 3.3 Governance

- `ActionExactRate`：NEW/MERGE/UPDATE 与 oracle 完全一致的样本比例。
- `TargetExactRate`：需要目标时，`targetMemoryId` 与允许目标一致的样本比例。
- `TimePrecedenceRate`、`UncertaintyPreservedRate`。
- `CorrectionRegressionCount`：已纠正事实被回退的确认次数；任何此类 H3 必须人工裁决。
- 非法 target、非法字段组合和越权动作由程序 fail closed，不能降级 NEW。

### 3.4 Search

- 对每个 query 的固定 `K`，`Recall@K = |TopK ∩ relevantIds| / |relevantIds|`；报告有相关样本的 macro Recall@K，并单独报告无匹配样本。
- `MRR@K = mean(1 / 首个 relevant 排名)`；无相关 query 不进入 MRR 分母。
- `CriticalRecall@K`：关键相关项的命中比例。
- `OutOfSetIdCount` 与 `ProtocolFailureCount` 单独统计；不得通过丢弃非法 ID 伪造高 Recall。
- 结果同时报告 `K`、qrels 版本、输入候选数和样本分母，避免不可比的单一百分比。

### 3.5 Memory Map

- `RequiredFactCoverage = 人工确认覆盖的 requiredFacts / requiredFacts`。
- `FabricatedFactCount`、`DomainGroundingFailureCount`、`UncertaintyLossCount`、`UriFidelityFailureCount`。
- `NavigationUsefulnessRate`：人工按“可直接定位/部分可用/不可用”三分判定，不把非空字符串当通过。
- 冲突/纠正样本必须检查当前值优先；聚合覆盖不抵消 H2/H3。

### 3.6 Dreaming

- `NewInsightPrecision = 有新证据支持且相对当前认知有增量的 Insight / 全部 Insight`。
- `DuplicateRate`：重复或同源复述的 Insight 比例。
- `EvidenceIndependenceRate`：同一 Turn 多 Raw 只算一份独立证据的样本正确率。
- `CorrectionRegressionCount`、`EmptyWhenCoveredRate`、`IllegalSourceCount`。
- Fake 回放 4 场景只作为 harness 自测，不形成真实模型的新洞察质量分数。

### 3.7 跨 Task 审查指标

- `CriticalErrorCountByType`：H1/H2/H3 分别计数，并附样本 ID、严重度、人工结论。
- `ProtocolFailureCount` 与语义失败分开；程序拒绝非法 JSON/ID/来源不能算模型语义得分。
- `coverage` 只表示样本标签覆盖，不作为质量通过率。
- 每个报告必须记录模型、Profile、Prompt/Schema SHA、样本版本、运行参数、成本/Usage 是否可用、人工复核人/日期。

## 4. 可审查地板与数据集规模

B2 采用“**每类最低 12 条、总计 72 条、净新增 44 条**”作为审计地板：

| Task | 现有 | 新增地板 | 目标地板 |
| --- | ---: | ---: | ---: |
| Extraction | 4 | 8 | 12 |
| Candidate Scanner | 0 | 12 | 12 |
| Governance | 0 | 12 | 12 |
| Search | 10 | 2 | 12 |
| Memory Map | 10 | 2 | 12 |
| Dreaming | 4 | 8 | 12 |
| **合计** | **28** | **44** | **72** |

这不是语义质量阈值，也不表示 12 条能代表真实用户分布。它只保证每一类都有可执行的最小回归面、H1/H2/H3 至少可被逐项检查，并阻止“0 条样本也算完成盘点”。长期基线仍可按技术设计逐步扩展至每类约 20～50 条，但新增必须对应明确缺口。

每类最低 12 条必须满足：

1. 至少 1 条正常、1 条空结果或合法零结果、1 条关键冲突/纠错风险；不适用项必须记录不适用理由。
2. 至少 1 条 `criticality=CRITICAL`，且错误不被 macro 平均掩盖。
3. 每条至少一个 `riskTags` 或边界标签；同一行可标多个风险，但净新增数不重复计算。
4. 数据合成、脱敏、无密钥/个人数据；人工约束和禁止错误可独立复核。

## 6. B2 可执行门禁

B2 PASS 仅表示“离线数据集与工具可用”，最低门禁为：

1. 六类均达到 12 条地板、总 72 条、净新增 44 条；每条有稳定 ID、版本、人工约束和风险标签。
2. 所有 source/target/candidate/qrels 引用是输入子集；Extraction 无 `turn-1` 与整数 ID 的未解析混用；Dreaming Profile/model 一致。
3. manifest 中每个 Prompt/Schema/data SHA 可复算且与实际文件一致；既有 28 条导入有 provenance。
4. 数据集 integrity、报告 schema、空结果/非法引用/预算边界的离线测试真实执行并留 stdout、exit、XML；报告明确 Fake 不是语义质量。
5. 输出 `offline-v1.json` 与 `real-model-not-run-v1.json`；不得出现“模型通过”或统一准确率结论。

## 7. B3 真实模型边界

- B3 默认 LOCKED；用户必须明确提供可用 Provider/Profile、模型、外发数据范围、费用上限和授权。
- 运行前固定并记录模型、Profile、Prompt/Schema/样本 SHA、参数、数据脱敏策略和运行时间；不读取或输出密钥。
- 真实结果使用独立 `real-model-*.json/md`，包含逐样本请求摘要、响应（去敏）、Usage/成本、指标、H1/H2/H3 错误和人工复核。
- 真实模型未运行时不阻塞 B1/B2 技术工作，但阻塞“真实模型语义质量通过”和 CT31 整体 DONE。
- 不设统一准确率门槛；重大质量退化、未解释的 H1/H2/H3、Provider 协议失败或数据泄漏均不得直接验收。
