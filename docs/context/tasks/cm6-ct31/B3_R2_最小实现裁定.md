# CT31 B3 R2 最小实现裁定

## 本次修改（2026-11-14，放行评测可信度定点实现）

- 裁定 R2 只修原始失败证据、Judge 留证、Dreaming/Map 错误断言、Governance 可观测性与运行 SHA；不顺带修改生产 Prompt、解析或业务算法。
- 明确 `KtorLlmClient` 默认观察者为 no-op 的 internal 接缝、失败调用留证状态机、取消清理与 SHA 验证要求，恢复现有 Lead 组织唯一 Worker 实施。
- B3 R1 OPEN，CT31/CM6 未 DONE，CT32 LOCKED；首轮 72 条、canonical/oracle 与既有报告继续冻结，无 Git 写操作。

## 1. 统一失败证据模型与默认 no-op 观察接缝

批准在 `context/runtime` 的 evaluation adapter / `llm` 内增加 **internal、opt-in、默认 no-op** 的原始交换观察接缝，不改变公共 `LlmClient`、`LlmRequest`、`LlmResponse` 或异常正文。

最小结构：

- `ProductionRecordingClient.complete` 在调用 delegate **之前**建立 callId，记录 task/messages/schema、开始时间；此后以 `try/catch/finally` 收口，不再只记录成功响应。
- `KtorLlmClient.callOnce` 每次取得 HTTP status/body 后、进入 2xx/非 2xx 解析前通知观察者；transport/read-body 失败允许无正文的失败观察。观察者接收请求关联信息、attempt、HTTP status（可空）、rawResponse（可空）及安全错误分类。禁止把 API Key、Authorization、baseUrl 写入观察 DTO。
- 默认不安装观察者时，现有生产行为、异常分类、重试、超时、日志和取消语义完全不变。观察器只在 CT31 evaluation 装配；不要在公共异常 `message/cause` 中附加原文。
- 每次 logical `complete` 产生一条终态记录：`SUCCEEDED` / `FAILED` / `CANCELLED`；记录 attempts、elapsed、安全错误类型/错误码、usage/finishReason（若成功）。每次 HTTP attempt 的原文作为该 call 的 exchanges 保存，不能把多次 attempt 拼成不可区分正文。
- `CancellationException` 必须原样重抛；仅在 `finally`/非取消清理区持久化 `CANCELLED` 证据。失败记录写完后才返回 `SampleResult`，不能再由成功路径独占 `production-call-N.json`。
- 原始文件建议为每样本 `raw/production-call-<callId>.json`，含 `request` 与 `exchanges`；`result.json` 仅保留路径、SHA-256 和安全元数据。Judge 使用独立的 `judge.json` raw calls，不混入生产 calls。

必须测试：2xx 非法 JSON、非 2xx、transport failure、成功、请求中取消；断言正文/status/attempts 与终态，断言默认 no-op 和 CE 原样传播。不得只测 recorder 自己返回的 canned success。

## 2. Judge 失败也留原始证据

- `SemanticJudge` 在调用前分配 judgment/callId，异常时保留输入、原始响应（若已收到）、安全错误和 elapsed；不得把失败写成 `rawResponse=""` 且丢失已收到正文。
- Judge 复用第 1 节的原始交换观察；每次 judge 调用都落盘，包括 malformed、length、HTTP/transport failure。取消仍原样传播，并在非取消清理中落盘部分证据。
- `semanticReview` 异常可产生 `REVIEW_REQUIRED`，但原始失败证据必须存在；独立 Judge 仍不是独立模型，不更改现有边界表述。
- 汇总按实际 logical judge calls 计数，同时报告 succeeded/failed/cancelled 与缺失原始证据数；不能用调用次数推断有效 Judge 数。

## 3. Governance 可见失败，不再静默产出业务 FAIL

仅在 `DefaultOrganizationWorker` 增加默认 no-op 的 internal item failure observation（rawId + 安全异常分类），保持原 catch/log/Pending 行为与 CE 传播不变；`ProductionOrganizationExecutor` 暴露本轮观察结果。

- `ProductionEvalRunner.organization` 在本轮 run 后读取失败列表。目标 raw 有失败时，添加 `organization_item_failed=REVIEW_REQUIRED`，返回已有安全错误与失败证据；不能继续仅凭 `associated/pending` 判业务 FAIL。
- 未发生吞错时，现有 deterministic checks 继续执行。测试必须证明 swallowed failure 可观察、其他 raw 不串扰、CE 不转 REVIEW_REQUIRED、默认 Runtime 行为不变。

## 4. Dreaming 只断言真实 checkpoint、pending 与 source attribution

- checkpoint 比较 `sample.input.toDreamingWindow().last().id`（本次选择窗口的 upper/lastTurnId），不能用包含未选择 turn 的 `maxPersistedTurnId`。
- `pending_conserved` 保持输入 pending + 新 Dreaming raw；这是当前 Committer 的真实语义。
- 移除“Dreaming raw 必须已有 Organized backlink”的错误硬断言。Dreaming commit 只写 Raw/Pending/Checkpoint，Organization 是后续阶段。
- 改为持久化并断言每个新 raw 的 `sources` 与其 validated insight sources 一致、非空且属于输入窗口；保留输入 Organized 既有 backlink 作为 artifact 事实，但不把未运行的 Organization 当成本轮结果。
- 用包含额外未选择 turn 的 fixture 证明 checkpoint 不误判；用零 insight 证明仍推进 checkpoint 且不伪造 backlink。

## 5. Map 删除无生产依据的字面导航断言

- 删除 `navigationRequired` 以及 `#id/@domain` substring 的 `navigation_contract` 硬检查；canonical `navigationChecks` 不改，但不得继续作为生产字面契约。
- 保留 `domain_coverage`；新增 `navigation_overview_nonempty`、`no_truncation`。语义完整性与虚构链接由 Judge + H1/H2/H3 人工审查，不由 substring 代替。
- 测试必须包含“navigation 不含 `#/@` 但领域和语义完整”不被误杀，以及空 overview/navigation 不能 PASS。

## 6. 新运行目录与 SHA 可信度

每次真实运行必须写入不可覆盖的 `run.json`，至少包含：manifest bytes SHA-256、六类 dataset bytes SHA-256、model/profile/responseFormat、完整与 partial `report.json` SHA-256、每样本 `result.json`/raw artifacts SHA-256、开始/结束时间、complete 状态、选取参数、测试任务名。

- SHA 必须读取文件 bytes，不得对字符串 `Path` 或重新序列化后的文本求 hash。
- `run.json` 自身除外；每完成一样本更新 manifest，最终写 `complete=true`。运行目录必须为空且新建，禁止覆盖、拼接首轮或任何旧结果。
- `report.json` 增加 `evaluationImplementation`（版本及关键源文件 SHA）与 `rawEvidence` 汇总；`report.md` 明确完整/部分、原始证据缺失数与“不是独立模型/真实用户研究”。
- 测试对实际临时文件改一个字节后验证 SHA 变化，并验证取消后 partial manifest/report 仍存在且 complete=false。

## 7. 实施与验收顺序

1. Worker 先完成第 1～6 节及离线定向测试，Lead 独立初验；Architect 复核通过前不得启动 72 条。
2. 通过后用 `.local/ct31/` 新空目录跑 `ext-001` smoke，核对真实原始交换、Judge、SHA、退出与产物完整性；失败则留证并定点修评测器，不修改旧目录。
3. smoke 通过后再跑六类 72 条全新 production run。按真实反例另开定点修复，不借 R2 放宽 canonical/oracle。
4. 最终全量 `./scripts/check`、Ajv 2020 report 校验、人工 H1/H2/H3。取消测试必须实跑并证明非取消落盘完成。

精确边界：允许上述 evaluation adapter、Ktor internal 观察接缝、Organization 默认 no-op failure observation 及对应测试/文档；禁止公共 API/Schema/依赖变化、默认业务算法/Prompt 变化、canonical/oracle/首轮报告修改、密钥输出与 Git 写操作。
