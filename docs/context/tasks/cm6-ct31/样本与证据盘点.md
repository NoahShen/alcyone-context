## 3. 语义维度和高风险错误覆盖

高风险错误固定为：

- **H1 虚构或扩大用户事实**：输出输入没有的事实、范围、时间、当前值或 Resource URI。
- **H2 漏掉关键冲突候选**：Candidate Scanner/Governance/Search/Map 未发现或未保留会改变当前判断的矛盾、纠错或关键证据。
- **H3 已纠正事实回退**：旧 Raw、旧 Organized 或历史证据覆盖了更晚且已确认的当前认知。

## 5. 当前数据质量问题与限制

### 5.1 Extraction 来源标签不统一

`ext-001`～`ext-003` 的 `constraints.expectedSourceTurns` 为 `turn-1`，但实际输入 Turn ID 为 `1001`、`1002`、`1003`，Prompt/Schema 也要求整数 Turn ID。现有文件没有提供 `turn-1 -> 1001` 的机器可读映射，不能直接据此自动判来源忠实性。B2 必须在 canonical 数据中改为真实整数 ID，并做“expected ⊆ input”校验。

### 5.2 Dreaming 场景模型名不一致

四个场景的 `CANDIDATE_SEARCH` 均写 `profile=fixture-memory-search`，但 `model=fixture-evidence-model`；manifest 中该 Profile 对应 `fixture-memory-search-model`。当前回放按 stage 选 Fake 响应，不会因此失败，但该字段不能用于可信的模型/Profile 审计。B2 canonical 数据须消除该不一致。

### 5.3 Search/Map 缺结构化 qrels 与关键性

当前 `semantic_constraints`、`expected_behavior`、`forbidden_errors` 是自由文本，未提供机器可读的 `relevantIds`、`criticalRelevantIds`、`forbiddenIds`、`K` 或高风险标签。人工可读不等于可直接计算 Recall@K、MRR 或“关键冲突漏检数”。

### 5.4 Candidate Scanner/Governance 没有独立固定集

现有测试中的固定响应可以证明协议与字段边界，但测试源码内嵌输出不构成可独立演进、可版本比较的语义数据集。两者是 CT31 当前最大的样本缺口。

### 5.5 样本规模与边界不足

固定集总量为 28 个顶层案例，低于技术设计建议的每 Task 约 20～50 条；尤其 Candidate Scanner、Governance 为 0，Dreaming 仅 4 场景。不得为了计数直接扩充，但上述高风险与规模缺口必须补足。

约束：

1. 每条新增样本至少标注一个 `riskTags`：`H1_FABRICATION`、`H2_CRITICAL_CONFLICT_MISS`、`H3_CORRECTION_REGRESSION` 或一个明确边界标签；不得只为凑数创建无判定价值的重复句。
2. 每类至少有一条 `criticality=CRITICAL`，其失败按高风险缺陷人工复核，不被聚合平均值掩盖。
3. `must`/`mustNot`、相关 ID、期望动作和来源均须可由人工逐项判定；不允许用字符串相似度代替事实判断。
4. 确定性非法 JSON/ID/来源拒绝继续由 Core/Runtime 测试负责；固定集可包含非法输入，但不得把“程序正确拒绝”计作模型语义得分。

## 8. 当前盘点结论

1. 六类 Task 的 Prompt/Schema 均有 v1 资源；Extraction、Search、Map、Dreaming 有部分固定集，Candidate Scanner 与 Governance 没有独立固定语义集。
2. Fake/确定性证据较完整，但只能证明协议、预算、ID/来源边界、事务与生命周期。
3. H1/H2/H3 目前大多只有部分约束或测试内嵌样例，尚不足以支撑模型质量结论。
4. 真实模型全部 not-run；CT31 不能因 CT30 全量通过而 DONE。
5. B2 的最小可审查方案是统一 canonical 数据集、先修复两项数据引用问题、补充 44 条高价值缺口样本，并只用离线工具产出 `semanticQualityEvaluated=false` 的结构/覆盖报告。
