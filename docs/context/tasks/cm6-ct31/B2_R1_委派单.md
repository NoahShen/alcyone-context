## 1. R1-1 Search 候选与阶段边界

当前 `SearchObservation` 只有正相关 qrels，没有实际候选全集，导致合法无关项被误判为 out-of-set，且 Rerank 可以重新加入 Scanner 未选中的 ID。

必须修复：

1. 明确区分输入候选全集、正相关 qrels（gain > 0）、缺失人工 judgment；不得把所有候选当相关，也不得把合法无关项当伪造 ID。
2. 为实际采集输出定义 Scanner 输入候选全集，以及 Rerank 的实际输入集合。若采用 Scanner→Rerank 链，Rerank 输入必须是 Scanner 合法输出的集合/约定截断，Rerank 输出不得越出其输入。
3. 真正的 `[合法无关项, 相关项]`、K=2 应 Recall=1、MRR=0.5；补相关项位于 K/K+1、合法无关项 vs 伪造项、Rerank 越界、缺失 judgment、重复 ID、关键项首位/顺序反例。
4. 正相关 qrels 为空时 Recall/MRR `NOT_APPLICABLE`；但输出含未判定候选必须有 protocol failure，不得静默过滤错误提高分数。
5. SearchMetrics 增加必要的阶段 protocol 状态/顺序信息，不能用单一 protocolFailureCount 隐藏阶段错误。保持离线无网络/模型。

建议的最小形状（Worker 可细化，但须覆盖上述语义）：

```kotlin
SearchObservation(
    queryId, k, candidateIds,
    judgments: List<RelevanceJudgment>, // 仅正相关；缺 judgment 不属于该集合
    scannerRanking,
    rerankInputIds, // 实际 Rerank 输入，由采集器记录并校验与 Scanner 输出一致
    rerankRanking,
)
```
