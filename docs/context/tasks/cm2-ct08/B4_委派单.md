## 3. 锁定的关闭协议（§f v3）

### 3.1 状态与准入

- 字段：`state: RUNNING/CLOSING/CLOSED`、`inFlight: MutableSet<Job>`、`closeOutcome: CompletableDeferred<Throwable?>`，三者受**同一把普通锁**保护；持锁期间不做任何挂起调用。
- `complete(request)`：
  1. `currentCoroutineContext().ensureActive()`；
  2. `coroutineScope { call = async(start = CoroutineStart.LAZY) { execute(request) } }`；
  3. 锁内准入：`state != RUNNING` → 拒绝；否则 `inFlight += call`，并 `call.invokeOnCompletion { 锁内 inFlight -= call }`；准入/登记与关闭封闭同锁；
  4. 未准入：`call.cancel()` 后抛 `ContextLifecycleException(ContextLifecycleErrorCode.CLOSED, "llm client is closed")`（**先于任何请求构造/校验/HTTP**）；
  5. `call.start(); call.await()`：`CancellationException` 原样传播，不包装、不转 CLOSED。
- 不使用 `Job(parent = ...)` 的游离 Job；在途移除**只在 `invokeOnCompletion`**，`await()` 的 finally 不算完成。

### 3.2 `closeAsync()`（唯一清理入口）

1. 锁内：`CLOSED`/`CLOSING` → 取已有 `closeOutcome` 作为等待者；`RUNNING` → `state = CLOSING`、创建 `closeOutcome`、`snapshot = ArrayList(inFlight)`（显式复制，禁止 `toList()`）、owner = true。
2. 等待者：`closeOutcome.await()`（自身取消只放弃本次等待）；结果非 null 时重抛**同一异常实例**。
3. owner 全程 `withContext(NonCancellable)`：
   - `snapshot.forEach { it.cancel(CancellationException("llm client is closing")) }`；
   - 循环 `pending = 锁内 ArrayList(inFlight)`，空则退出，否则逐个 `join()`（收敛：CLOSING 已封闭准入，`inFlight` 只减不增）；
   - 本地在途真实收尾后关闭自建 `HttpClient`（注入的 client 不关闭，见 §3.4）；
   - `catch (t: Throwable) { outcome = t }`，任何失败都必须发布终态，不得滞留 CLOSING；
   - `finally`：锁内 `state = CLOSED`；`closeOutcome.complete(outcome)`（成功 null / 失败同一异常）。
4. owner 在发布后：`outcome != null` 时抛该异常；`CLOSED` 后重复 `closeAsync()` 仍 await 同一结果并重抛同一失败，**不得直接 return 掩盖失败**。

### 3.3 取消语义

- 调用方取消（请求中/退避中）→ `CancellationException` 原样传播；在途取消**不转 CLOSED**。
- `closeAsync()` 取消在途调用 → 调用方收到 `CancellationException`（不是 `CLOSED`）。
- 等待者（非 owner）在 owner 清理期间被取消 → 只放弃本次等待，owner 仍完成清理并发布结果。
- 关闭后/关闭期间的新调用 → `ContextLifecycleException(CLOSED)` 且 **0 次 HTTP**。

### 3.4 测试接缝与访问器（一律 `internal`，生产默认无行为）

- `internal var closeActionForTesting: (() -> Unit)? = null`：owner 清理最后一步用它替代 `httpClient.close()`（用于注入清理失败或阻塞 owner；生产为 null）。
- `internal fun stateForTesting(): String`（或等价只读）、`internal fun inFlightCountForTesting(): Int`：供 A06 断言终态与在途集合为空。
- 注入的 HttpClient 仍不由 client 关闭（保持 B2 所有权语义）；A06 ④ 用自建 client + `closeActionForTesting` 注入失败。
- 重命名后 KDoc 必须写清：`closeAsync()` 是唯一清理入口，无同步 `close()`。

## 4. Runtime 接线（`AlcyoneContextImpl`）

- `performStart`：`executor → vfs → llm`；`llm = config.llm?.let { KtorLlmClient(it) }`；三者创建成功后才 `startProbe.afterResourcesAcquired()`，随后锁内发布 `RUNNING`。任一失败走既有逆序清理（llm → vfs → executor）。
- `releaseResources(llm, vfs, executor)`：顺序 **llm → vfs → executor**，已有 `NonCancellable` 覆盖；每项独立 try/catch，首个失败为主失败、其余 `addSuppressed`（复用 `chain`）；**不新增 `ReleaseTarget.LLM`**。
- `shutdown`：`RUNNING` 分支与兜底同步块都捕获 `llm` 并置 null；`releaseResources(llmToClose, vfsToClose, executorToClose)`。
- `create` 仍零副作用（不创建 HttpClient/线程）；HttpClient 只在 `start()` 内创建。
- 未配置 `context.llm` → `llm == null`，释放跳过（A01）。
- 内部测试访问器：`internal fun llmClientForTesting(): KtorLlmClient?`（锁内读取）；不新增公开 API。
- 既有 `close()`/`closeAsync()` 同步/挂起桥接协议不变（client 只暴露挂起关闭）。

## 6. 测试要求

### 6.1 `KtorLlmClientCloseTest`（A06 ①～⑤，真实 HTTP + 受控屏障）

1. **调用方取消**：stub 挂起；取消调用协程 → `CancellationException`（`!is LlmException`），取消后 stub 请求数不增长。
2. **关闭后/关闭中新调用**：`closeAsync()` 完成后 `complete` → `ContextLifecycleException(CLOSED)`、0 新请求；用挂起在途 + owner 清理屏障构造 `CLOSING` 窗口，期间新调用同样 `CLOSED`。
3. **在途关闭等待真实完成**：stub 挂起不释放；调用方在 `try/finally` 中设置屏障；`closeAsync()` 返回时 `inFlightCountForTesting() == 0` 且屏障已执行；调用方收到 `CancellationException`（不是 CLOSED）。
4. **清理失败发布与重抛**：`closeActionForTesting` 抛独特异常；`closeAsync()` 抛出该异常；`stateForTesting() == "CLOSED"`；再次 `closeAsync()` 重抛**同一实例**（`assertSame`）。
5. **等待者可取消**：`closeActionForTesting` 阻塞（latch）；owner `closeAsync()` 运行中，第二个 `closeAsync()` 被取消 → 该等待者 `CancellationException`；释放 latch 后 owner 正常完成；后续 `closeAsync()` 正常返回。
