## 3. 锁定的统计契约（§m 5）

按 `(task, profile)` 分组，进程内、重启清零：

| 字段 | 语义 |
| --- | --- |
| `calls` | 到达终态的逻辑调用数（`= successes + failures`） |
| `successes` / `failures` | 成功数 / 抛 `LlmException` 的失败数 |
| `attempts` | 实际执行尝试数之和（失败时取异常 `attempts`，成功时取本次实际次数） |
| `usagePresent` / `usageMissing` | `LlmResponse.usage != null` / `== null` 的调用数 |
| `inputTokens` / `outputTokens` / `totalTokens` | 仅对 `usage != null` 的调用求和；**无样本时为 `null`**（不是 0） |

- **取消（`CancellationException`）与关闭后 `CLOSED` 拒绝不计入统计、不写日志**（不是 LLM 调用终态）。
- 路由前失败（`CONFIGURATION`，task/profile 未解析）**只写失败日志、不计入统计**；路由后失败（`INVALID_REQUEST`/`LOCAL_BUDGET_EXCEEDED`/HTTP/解析类）计入失败，`attempts=0` 仅限未发请求的发送前失败。
- 统计访问器（`internal`）：`internal fun statsForTesting(task: LlmTask, profile: String): LlmCallStats?`；无记录返回 `null`。
- 线程安全：并发调用下计数不得丢失（`ConcurrentHashMap` + 原子/同步计数）。

## 4. 锁定的日志/诊断契约（§g）

- 事件与级别：成功 `llm.call.completed` INFO；失败 `llm.call.failed` WARN。**只在这两个时机各写一条**（不逐次尝试写日志）。
- 字段白名单（仅这些键）：`task`、`profile`、`model`、`attempts`、`statusCode`、`elapsedMillis`、`estimatedInputTokens`、`providerUsagePresent`、`retryable`。
  - 成功：包含 task/profile/model/attempts/statusCode/elapsedMillis/estimatedInputTokens/providerUsagePresent；`retryable` 可省略。
  - 失败：额外包含 `retryable`；`statusCode`/`estimatedInputTokens` 未知时输出 `null`（不得用 0 冒充）。
- **不得**输出：API Key、Authorization、Prompt/messages、schema、请求/响应 body、baseUrl 路径或凭据、Provider 原始 `code`/`requestId`/`finishReason`、异常对象本身（**不把 Throwable 传给 logger**，避免异常链带出正文）。
- 日志消息只允许上述字段与固定事件名；`LlmCallDiagnostics.toString` 同规则、不提供 Key 访问器。
- `elapsedMillis` 用单调时钟（`execute` 入口起算即可，记录为诊断耗时，不是 SLA）。
