## 1. 缺陷事实（Lead 独立复算，不改代码）

`LlmBudget` 现状（`context/runtime/.../llm/LlmBudget.kt`）：

- `estimate()` 只计算、**不做拒绝**；拒绝发生在 `requireWithinBudget()`。
- `saturatedAdd(left, right) = if (left > Long.MAX_VALUE - right) MAX else left + right`：当 `right` 为负时 `Long.MAX_VALUE - right` 自身溢出，条件失真。

按源码语义复算（`task.maxInputTokens=12_000`、`maxOutputTokens=3_000`、`cap=64_000`、`margin=20%`）：

| 输入 | `estimatedInput` | `margin` | `requiredTotal` | 输入预算 | 容量 | 实际结果 |
| --- | --- | --- | --- | --- | --- | --- |
| `estimatePrompt = -1`（真实绕过） | **-1** | 0 | 2_999 | 通过 | 通过 | **`requireWithinBudget` 静默返回 = 预算失效** |
| `estimatePrompt = 1`、`estimateSchema = Int.MIN_VALUE` | 9_223_372_036_854_775_807（饱和） | 92_233_720_368_547_758 | 9_223_372_036_854_775_807 | 不通过 | 不通过 | 抛 `LOCAL_BUDGET_EXCEEDED`（**错分类**：应 `INVALID_REQUEST`） |
| `0 / 0` | 0 | 0 | 3_000 | 通过 | 通过 | 合法，必须继续通过 |

**对 Architect 探针的澄清（供复核参考，不改变阻断结论）**：`.local/validation/cm2/architect/ct08-b1/runtime/NegativeEstimatorProbeTest.kt` 两个用例都调用 `LlmBudget.estimate(...)` 并期望抛异常，但 `estimate` 按设计不拒绝，因此两例的 "completed successfully" 不能区分「绕过」与「不拒绝」。修复后的验收必须同时覆盖**两条入口**：`estimate()` 直接拒绝负数、`requireWithinBudget()` 不再被负数绕过。

## 2. 修复要求（严格照 Architect 1～5）

4. 新增正式回归（`LlmBudgetTest`，Java/Kotlin 断言而非临时探针）：

   - schema 为负（`-1` 与 `Int.MIN_VALUE`）→ `INVALID_REQUEST`，消息含 `estimator.estimateSchema`；

   - 大正数（`Int.MAX_VALUE` × 2）仍饱和为正并触发 `LOCAL_BUDGET_EXCEEDED`（不因饱和变成负数）；
