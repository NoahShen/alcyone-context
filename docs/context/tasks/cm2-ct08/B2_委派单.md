## 3. 契约决定（Lead 已锁定，实现按此，不另行发挥）

### 3.1 路由与发送前校验（全部在 HTTP 之前）

1. `request.task` → `config.tasks[task]`；缺失 → `LlmException(CONFIGURATION)`，消息含 task 名。
2. → `config.profiles[taskConfig.profile]`；运行期缺失 → `CONFIGURATION`。
3. `request.responseFormat` 必须等于 `profile.jsonMode`（两者同枚举，逐一相等）；不一致 → `INVALID_REQUEST`。
4. `jsonMode == JSON_SCHEMA`：`request.schema` 必须非空白且 `Json.parseToJsonElement` 成功，否则 `INVALID_REQUEST`（不是 `INVALID_RESPONSE`）。`JSON_OBJECT` / `PROMPT_ONLY` 忽略 `schema`，不发送。
5. 预算：`LlmBudget.requireWithinBudget(request, schemaToSend, taskConfig, profile, config.safetyMarginPercent, estimator)`；失败即 `LOCAL_BUDGET_EXCEEDED`（`schemaToSend` 对非 JSON_SCHEMA 传 `null`，保持 B1 语义）。
6. 发送前任何失败都 **0 次 HTTP**。

### 3.2 请求

- URL：`baseUrl` 去尾部 `/`；若结果已以 `/chat/completions` 结尾则原样使用，否则追加 `/chat/completions`。
- Header（**逐请求**）：`Authorization: Bearer <profile.apiKey>`、`Content-Type: application/json`、`Accept: application/json`。HttpClient **不设默认 Authorization**。
- HttpClient 配置：`followRedirects = false`、`expectSuccess = false`；**不安装** Ktor `Logging` 插件。
- Body（`JsonObject`，字段顺序无关）：`model`、`messages`（原顺序，`[{role, content}]`）、`max_tokens`（= `decision.effectiveMaxOutputTokens`，即实际发送值）、`response_format`：
  - `JSON_SCHEMA` → `{"type":"json_schema","json_schema":{"name":<task 名小写>,"strict":true,"schema":<解析后的 schema 元素>}}`
  - `JSON_OBJECT` → `{"type":"json_object"}`
  - `PROMPT_ONLY` → **省略该键**

### 3.3 响应（2xx）

1. body 非空且为 JSON 对象，否则 `INVALID_RESPONSE`。
2. `choices[0].message.content` 必须为 string 且 `isNotBlank()`；缺失/空白/类型不符 → 若 body 的 `error.code`/`error.type` 指示 context length 则 `CONTEXT_LIMIT_EXCEEDED`，否则 `INVALID_RESPONSE`。
3. **content 本身的 JSON 校验（§m 硬要求）**：`profile.jsonMode != PROMPT_ONLY` 时，content 必须满足：
   - `trim()` 后**不得**以 ` ``` ` 开头（代码围栏一律拒绝，**不剥离**）；
   - `Json.parseToJsonElement(content)` 必须成功（任意 JSON 元素均可；不做 schema 业务校验、不修复、不提取）；
   - 任一不满足 → `INVALID_RESPONSE`。
   `PROMPT_ONLY` 不要求 content 是 JSON，只要求非空白。
4. `finish_reason` 分类（**拒答优先于截断**）：非空 `choices[0].message.refusal` 或 `finish_reason == "content_filter"` → `MODEL_REFUSAL`；否则 `finish_reason == "length"` → `OUTPUT_TRUNCATED`。其他值不报错。
5. 成功返回 `LlmResponse(content = 原始 content 字符串, usage = 映射后的 TokenUsage?, finishReason = 原始 finish_reason)`（Provider 原值只放返回对象，不进异常/日志）。
6. `usage`：缺失或不是对象 → `usage = null`；`prompt_tokens`/`completion_tokens`/`total_tokens` 逐字段映射到 `inputTokens`/`outputTokens`/`totalTokens`，缺失或非整数 → 该字段 `null`（**不填 0**）。

### 3.4 非 2xx 与传输失败分类

判定顺序（命中即返回，`attempts = 1`，`statusCode` 有则带）：

| 条件 | 分类 |
| --- | --- |
| 401 / 403 | `AUTHENTICATION` |
| 429 且 `error.code`/`error.type` 属 insufficient_quota / quota / billing 类 | `QUOTA_EXCEEDED` |
| 429 其他 | `RATE_LIMITED` |
| body `error.code`/`error.type` 指示 context length（任意状态，未命中上面 401/403/429 额度） | `CONTEXT_LIMIT_EXCEEDED` |
| 408 | `TIMEOUT` |
| 500 / 502 / 503 / 504 | `PROVIDER_UNAVAILABLE` |
| 其他 5xx | `PROVIDER_UNAVAILABLE` |
| 其他 4xx（400/404/409/422 等） | `INVALID_REQUEST` |
| 其他状态 | `PROVIDER_UNAVAILABLE` |
| 连接拒绝/DNS/传输中断等 IO 异常 | `NETWORK`（B2 不重试） |

### 3.5 最小释放路径（非 B4 协议）

- 构造：`KtorLlmClient(config, estimator = ConservativeTokenEstimator(), httpClient: HttpClient? = null)`；`httpClient == null` 时自建 `HttpClient(CIO)` 并**拥有**它（`followRedirects=false`、`expectSuccess=false`）。
- `suspend fun close()`：幂等，仅关闭**自建**的 HttpClient（注入的 client 不关闭）；不实现状态机、等待在途、关闭结果发布、关闭后新调用 `CLOSED` 等（B4）。
- KDoc 明确：这是供测试与后续 B4 接线的**最小释放路径**，不代表完整生命周期契约。
