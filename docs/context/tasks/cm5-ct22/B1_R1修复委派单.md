# CT22 B1-R1 · 直接 DreamingConfig orphan timezone 校验修复

**日期**：2026-11-09
**状态**：**R1 REQUIRED；仅白名单内最小修复**
**依据**：[B1 委派单](B1_委派单.md) §2.3、[Architect 裁定](Architect_裁定.md) D8、[B1 Worker 交付](B1_Worker交付.md)

## 1. 阻断问题

Loader 已拒绝 YAML 中“无 cron 但显式 timezone”，但直接 Kotlin 构造仍可创建：

```kotlin
DreamingConfig(cron = null, timezone = "Europe/London")
```

这违反 D8“`timezone` 单独出现（无 cron）拒绝”，也绕过了 Runtime Config 对象直接构造入口的同一校验口径。

## 2. 修复范围

只允许修改以下 3 文件：

1. `context/runtime/src/main/kotlin/com/github/noahshen/alcyone/context/memory/runtime/dreaming/DreamingConfig.kt`
2. `context/runtime/src/test/kotlin/com/github/noahshen/alcyone/context/memory/runtime/dreaming/DreamingConfigTest.kt`
3. `docs/context/tasks/cm5-ct22/B1_Worker交付.md`

不得修改 ContextConfigLoader、README、Schema、Factory/Impl、既有测试或其他文件。

## 3. 冻结修复语义

- `DreamingConfig()` / `cron=null + timezone=Asia/Shanghai` 保持 manual-only 合法。
- `cron=null + timezone != Asia/Shanghai` → `ContextConfigException(INVALID_CONFIG)`，消息只含字段路径，不挂 cause、不回显原始值。
- `cron != null` 时继续按现有规则校验 cron 与 IANA ZoneId。
- Loader 的 orphan timezone 拒绝保持原样。
- API/DreamingRunCoordinator/Cron/其他组件语义不变。

## 4. 必测

- 默认构造仍 manual-only + Asia/Shanghai。
- 合法 cron + 非默认 IANA timezone 仍通过。
- Loader 既有 dreaming 测试保持通过。
