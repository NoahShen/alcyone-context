## 3. 候选公共契约

### 3.1 DreamingResult

```kotlin
data class DreamingResult(
    val startCheckpoint: Long,
    val endCheckpoint: Long,
    val scannedTurns: Int,
    val discoveredTopics: Int,
    val generatedMemories: Int,
    val completed: Boolean,
)
```

- checkpoint 与计数非负；`startCheckpoint <= endCheckpoint`。
- 无新增 Turn：`start=end=C0`、计数 0、`completed=true`。
- 全量成功：`endCheckpoint=U`。
- 中途失败：通过具名异常/部分结果报告；不得只返回 completed=false 而丢失错误详情。
- `completed` 的精确返回/异常语义待 D1/D2/D15 裁定。

### 3.2 Dreaming 错误候选

新增 `ContextDreamingException` / `ContextDreamingErrorCode` 候选，至少：

```text
ALREADY_RUNNING
```

- 运行中手动请求 → ALREADY_RUNNING。
- Cron 运行中触发 → 直接跳过，不抛给外部调用者、不排队。
- DB/LLM/预算/取消继续保留既有异常：ContextPersistenceException / LlmException / CancellationException。
- 是否新增 INVALID_STATE/CONFIGURATION/PARTIAL 等错误码待裁定。

## 4. 候选运行组件

### 4.1 DreamingRunCoordinator

- 单实例最多一个 Dreaming run。
- `suspend fun runOnce(): DreamingResult` 手动入口：CAS/锁抢占失败 → ALREADY_RUNNING。
- 共享同一个 guard 给 Cron；Cron 请求失败只 skip + 脱敏日志。
- 每轮：
  1. 单次 `database.read` 同时读取 checkpoint C0 与 `maxTurnId()` U。
  2. 校验 `C0 <= U`；无新增直接返回 completed 结果。
  3. 固定 U；后续新 Turn 不进入本次范围。
  4. 分页读取 `(C0,U]`，按 id ASC。
  5. 用动态 Token budget 形成连续批次。
  6. 串行调用 batch processor；成功后把 end checkpoint 推进到实际处理最后 ID。
  7. 任何 batch 失败停止，后续不再处理；CT22 不自行写 Checkpoint。

### 4.2 Batch Processor Seam

候选 internal interface：

```kotlin
internal fun interface DreamingBatchProcessor {
    suspend fun process(batch: List<StoredConversationTurn>): DreamingBatchOutcome
}

internal data class DreamingBatchOutcome(
    val lastTurnId: Long,
    val discoveredTopics: Int,
    val generatedMemories: Int,
)
```

- CT22 fake processor 验证调用顺序/计数；CT23～CT25 实现真实 Topic/证据/Reflection/Commit。
- Processor 返回值必须覆盖本批最后 ID；不得返回批外 ID 或回退。
- Checkpoint 实际持久化由 CT25；CT22 result/end 逻辑必须与后续 CAS 契约兼容。

### 4.3 Token 分批

- 复用 `TokenBatchPlanner` 的分批规则：固定开销、逐条加入、单条超预算失败、不跳过/不截断。
- CT22 使用注入的预算函数/完整请求构造 seam；真实 Topic Discovery 请求在 CT23 接入。
- 若必须在多页间形成批次，采用 page→streaming assembler；不得因 page 边界静默产生语义遗漏。
- 单 Turn 超过预算：当前 run 失败，Checkpoint 保持；不修改 Extraction 状态。

## 5. 配置候选

建议：

```yaml
context:
  dreaming:
    cron: "0 3 * * *"
    timezone: "Asia/Shanghai"
```

- section 缺省或 `{}`：manual-only，无 Cron。
- `cron` 缺省：manual-only；若出现时必须是 UNIX 五字段。
- `timezone` 缺省建议 Asia/Shanghai；需 IANA 时区校验。
- `timezone` 单独出现是否允许、cron 出现时是否必填，待裁定。
- Loader 严格拒绝 unknown/type/非法 cron/非法 timezone；不因缺 Dreaming LLM task 而失败（后续任务校验）。
- ContextConfig 增加 Dreaming 配置后的缺省兼容方式待裁定。

## 6. 单 Worker / Cron / 生命周期候选

- Cron 使用独立 tick source 可注入；启动不立即 run，严格未来，不补跑。
- Cron tick 只请求启动；运行中 skip；不等待 LLM。
- 关闭：同步封新 Cron 请求 → 停止 Cron loop → 取消并 join 自有 run → 共享 close 结果。
- 手动 runOnce 的调用协程取消必须原样传播；不得把 CE 转成普通失败。
- 若 close 与手动 caller 并发，close 是否有权取消外部 caller 的 run 需 D7 裁定。
- 组件不接 Factory/Impl；生命周期测试用 start/activate/close seam。
