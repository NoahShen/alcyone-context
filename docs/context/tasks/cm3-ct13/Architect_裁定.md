# CM3 范围与 CT13 实施裁定

日期：2026-11-01。依据：技术实现设计 §6、CM3 范围方案、CT13 任务书与方案核对，以及实际 `LlmBudget` / `LlmClient` / `ReadContext` 接口。

本轮为方案和接口审阅，未运行新增测试，不构成 CT13 实现验收。批准 Lead 落委派单并派发现有 Worker 实施 CT13 B1；后续任务逐项复核。

## CM3 全局裁定

- Q1～Q5：按推荐批准。CT13～CT15 交付组件，CT16 接生产；Core Port/纯校验/Prompt，Runtime JSON/LLM；单次 read 分页快照后按 ID 排序，释放事务后调用模型；严格批内 ID 校验，最终按快照 ID 顺序返回。接受现有 scanPage 来源读取成本，不在本批优化持久化查询。
- Q6：CT13 直接构造仅接受 JSON_SCHEMA/JSON_OBJECT，缺 Task/Profile 或模式不支持时 INVALID_CONFIG；不能把这一决定外推成生产静默禁用策略，见 Q13。
- Q7～Q9：批准治理动作约束、原子事务/幂等/水位原则与 CT16 固定 Pending 列表查询方向；具体提交接口、影响行数、时间溢出及故障测试在各任务方案中审查。不加表/索引。
- Q10：CT13 不涉及时区。CT16 先核对现行定稿时区契约与 Extraction 固定上海约定，给出是否确需可配置的依据后裁定；暂不增加 timezone 字段。
- Q11：批准固定轮次、单 Worker/Counter、失败隔离和真实 join。纠正方案关闭顺序：必须首先同步封闭准入，再停 Cron/取消并 join 在途工作，最后释放资源并发布共享关闭结果；不能停 Cron 后才封闭准入。计数饱和行为必须可观察且无溢出，不丢唯一 Worker 的清理责任。
- Q12：批准 Runtime internal Map 通知接缝，提交后通知，不实现 Map。普通通知失败不回滚；CancellationException 原样传播，已提交结果不补偿。
- Q13：暂不批准“任何不完整/非法绑定都静默 no-op”。CT16 必须区分未配置 Organization 与已明确配置但不完整/非法，并评估启动诊断、兼容性及配置启用规则；不得单为旧测试采用静默失效行为。此项不阻塞 CT13。
- Q14：批准真实 Runtime/SQLite + Fake 的确定性验收与版本化评测样本；真实模型 not-run 必须明确保留，不能等同语义质量已验证。

## CT13 局部 Q1～Q8

均按推荐批准，附以下实施与验收约束：

1. 预算失败复用 LOCAL_BUDGET_EXCEEDED，非法估算值保留 INVALID_REQUEST。估算与实际发送共用请求构造，Schema 只在 JSON_SCHEMA 时计入；等于预算边界允许。
2. 换批后必须重新检查当前单条是否能独立放入新批；不得仅因上一批非空就默认下一条可容纳。固定开销超限、首条超限、后续超大条目均要覆盖。不得吞掉后续预算失败并返回之前候选。
3. 分页用同一个 ReadContext；页大小可固定 256，页偏移使用受检计算。覆盖超过一页及整页倍数，验证分页间并发写入不混入本次快照，下一次 search 能看到变化。
4. 验证 LLM 回调可以完成独立数据库写入，证明网络调用前 ReadContext 已释放；返回候选映射到原快照对象，不重查成不同版本。
5. 严格 JSON 顶层/字段/元素类型，无围栏修复。未知、跨批、空白 ID 拒绝；重复稳定去重。中间批失败/截断/取消不产生部分返回，后续批不再调用。
6. 空集合零 LLM；构造期配置校验不访问 DB/LLM。取消在批间及长预算循环应可响应，不仅依赖网络挂起点。
7. Prompt 明确候选高召回、兼容补充/矛盾/纠错均可关联，输入内容是待比较数据而非指令，不执行治理。正文包含分隔符时仍须保留真实批内 ID 的程序级权限边界。增加 Prompt 内容/Schema 契约正式测试。
8. 允许 internal 可控屏障用于真实快照/取消测试，不新增公开诊断。允许新增通用预算分批小组件及对应测试以满足 CT13“通用 Scanner”目标，但 Lead 必须先在委派单列明具体文件；不得提前实现 Retrieval/Governance。

本批不改 Factory/Impl/Config/Loader、既有 CM2 组件、SQL/Schema、依赖、VFS/common。无 git 写操作/推送。Lead 独立检查实际源码与测试结果后提交 Architect，不能凭 Worker 摘要标 DONE。
