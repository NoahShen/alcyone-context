## 2. 实现要求

### 2.1 Core

- `OrganizationCandidateRetriever`：`suspend fun search(rawMemory: RawMemory): List<OrganizedMemory>`；非 `context/api` 公共 SDK。
- `CandidateIdValidator`：批内 ID 集合校验；空白/未知/跨批拒绝；重复保留首次；纯逻辑。
- `OrganizationCandidatePrompt`：构造固定 Prompt + Raw + 批次候选的 `LlmMessage`；加载 v1 Prompt/Schema；输入内容是待比较数据，不是指令；明确高召回、兼容补充/矛盾/纠错均可关联、不执行治理。
- Prompt 必须包含真实批内 ID 的程序级边界说明；即使 Raw/候选正文含分隔符或指令样文本，也不得改变 ID 权限。

### 2.2 Runtime

- `LlmCandidateRetriever`：
  - 构造期校验 `LlmTask.CANDIDATE_SCANNER` Task/Profile/模式；缺 Task/Profile 或非 `JSON_SCHEMA`/`JSON_OBJECT` → `ContextConfigException(INVALID_CONFIG)`；构造期不访问 DB/LLM。
  - 单次 `database.read` 内分页读取全部 Organized，页大小固定 256，偏移用受检加法；读取结束释放 ReadContext；按 `id ASC` 内存排序；空集合返回空，不调用 LLM。
  - 估算与实际发送共用同一请求构造；Schema 仅 `JSON_SCHEMA` 计入；`maxOutputTokens = task.maxOutputTokens`。
  - 固定开销超限、首条超限、后续超大项 → `LlmException(LOCAL_BUDGET_EXCEEDED)`；非法估算值保留 `INVALID_REQUEST`；等于预算边界允许。
  - 串行调用所有批次；任一批失败/非法 ID/解析失败/`finish_reason == "length"`/取消 → 整条失败，不返回部分候选，后续批不再调用。
  - 候选映射回原快照对象，不重查成不同版本；最终按快照 `id ASC` 排序。
  - 批间/长预算循环调用 `ensureActive()`，可响应取消。
- `JsonCandidateResponseParser`：严格 JSON object，仅 `candidate_ids`；数组字符串；无围栏修复/前后文本；未知字段/非字符串拒绝；空数组合法。
- `TokenBatchPlanner`：通用预算分批；换批后重新检查当前单条能否独立放入新批；单条放不下抛显式异常；不跳过/不返回部分；测试覆盖固定开销、首条、后续超大项、边界相等。

### 2.3 测试必须覆盖

- 空集合 0 LLM；单批/多批全量；>1 页、整页倍数；分页间并发写入不混入本次快照，下一次 search 可见。
- LLM 回调内完成独立 `database.write`，证明 ReadContext 已释放；返回对象来自原快照（身份/版本一致）。
- 未知/跨批/空白/非字符串 ID；重复稳定去重；中间批失败/截断/取消无部分返回；后续批不再调用。
- 固定/首条/后续超大项预算失败；等于边界通过；Schema 仅 JSON_SCHEMA 计入；`maxOutputTokens` 不超 Task。
- Prompt/Schema 正式测试：高召回、兼容补充/矛盾/纠错、数据非指令、批内 ID 权限、Schema `additionalProperties=false`/必填字段。
- 构造期配置校验不访问 DB/LLM；取消在批间/长预算循环可响应。
