## 2. R1 必须修复

1. **不支持被误报为 ALREADY_RUNNING**：第三方默认 `runDreaming()` 必须 `UNAVAILABLE`，保留 ALREADY_RUNNING 专用于真实重叠。
2. **手动部分绑定延迟失败**：`DreamingBinding` 目前只校验 Cron，Impl 对不完整手动绑定静默不建 Runtime，直到调用才报配置错误。改为任一 Dreaming Task 存在即启动前完整校验；四件全无时才不启用。
3. **close 未等待手动 run**：Coordinator 只 join ownedJob；现有测试甚至明确“close does not wait external manual caller”。但 Impl 随后会关 LLM/SQLite，手动 run 仍 active，违反资源生命周期。手动任务必须在准入时登记、完成时注销；close 封闭准入并等待全部活动 run，不能仅改测试名称。
4. **集成证据不足**：Factory 空库成功不能证明真实 Reflection 链。新增真实 SQLite+受控 HTTP 的非空多批与重启测试；恢复必须含独立 JVM 进程停止场景。
5. **真实模型边界**：本机凭证/订阅检查只说明存在性，不是使用授权。B3 默认 LOCKED；B1/B2 只跑受控 stub/Fake。

## 3. 关键执行约束

- 手动 run 登记、状态封闭与关闭共用同步锁；持锁不挂起。close owner 在 NonCancellable 中 join 已登记手动任务，并取消/join owned run；调用方取消不转 CLOSED。
- 完整绑定可手动运行；无 Cron 不创建周期任务。`create()` 不打开 DB/VFS/HTTP，配置错误先于资源获取。
- 不用 MemoryMap/Organization 的单 Worker 代替 Dreaming 单 Worker；不让 Dreaming 直接写 Organized/Map。
- 崩溃探针用临时 HOME/DB、独立进程，在可控 processor 的真实事务返回后停止，不用 kill 正常构建 Daemon，不污染正式数据。
