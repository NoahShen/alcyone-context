## 1. 本批范围与边界

只修 D1～D6 并补确定性集成测试；保留 CT22～CT25 的 DTO、Prompt/Schema、Evidence/Reflection/Committer、事务、SQLite Schema、Common/VFS 语义。不得借接线缺陷放宽原有协议或断言。

- D1：默认 `AlcyoneContext.runDreaming()` 使用 `ContextDreamingException(UNAVAILABLE)`；`ALREADY_RUNNING` 仅表示真实活动 run 冲突。关闭中/关闭后不得误报 `ALREADY_RUNNING`，应为 `ContextLifecycleException(CLOSED)`。
- D2/D3：四件 Task 全部存在、Profile 均存在且 JSON 模式合法时才启用 Runtime。完全无 Dreaming Task 才可保持 ingestion-only；任一部分绑定、缺 Profile、非法模式或有 Cron 而不完整，在 `create()` 获取资源前抛具名 `INVALID_CONFIG`。无 Cron 不创建周期任务。重复调用校验幂等。
- D4/D5：手动/Cron 仍共用一个 Coordinator；手动在准入时登记、finally 注销，登记与 `beginClosing()` 同一锁且持锁不挂起。close owner 在 `NonCancellable` 内取消/join owned run，并等待 close 封闭准入前登记的手动 run 真正完成，再允许外层释放 LLM/SQLite/VFS。不得取消调用方手动 coroutine；调用方取消仍抛原 `CancellationException`，不得包装成 CLOSED。重复 close 共享同一清理结果。
- D6：start/Cron 失败沿用 Context 的逆序清理与共享失败；公共 Factory 不暴露测试类型，tick/configurator 仅 internal 重载。
- 受控 HTTP 只使用既有 `KtorLlmClient` 与测试 stub，不新建 Adapter。多 Profile 的 model/Key 不串用；测试日志和文档不记录真实凭据、完整请求/响应正文。
- **明确不在本批**：独立 JVM 子进程 kill -9、COMMIT 后进程崩溃探针、固定集语义评测、真实收费模型、Backup/HTTP Dreaming 端点、StartupRecovery、CT27+、CM5 收口、Git 写操作。普通同 JVM 的 close/reopen SQLite 重启集成属于本批；不得把它写成进程崩溃证明。

## 3. 必须证明的接缝与测试矩阵

### 3.1 契约与生命周期

1. 第三方默认入口抛 `UNAVAILABLE`；真正 run 重叠才抛 `ALREADY_RUNNING`。Coordinator/Runtime 在 closing/closed 的 run 请求为 `CLOSED`，手动与 Cron 均不新增准入。
2. 配置矩阵至少覆盖：全空；四件完整无 Cron；四件完整有 Cron；仅一件；缺任意一件 Task；Task 指向缺 Profile；任一 `PROMPT_ONLY`；有 Cron 且无 LLM。失败发生在资源获取前，错误不泄露正文/Key。
3. 用 Deferred barrier 证明：手动已进入 LLM/处理器后 close 被调用，close 尚未返回时活动 run 仍在且资源未释放；放行后手动结果完成，close 才完成，Coordinator `activeRun=false`。再断言关闭后调用 CLOSED。
4. 手动调用方取消仍由调用方观察 CE；该 run 注销且 close 可完成。close owner 被取消仍完成清理；owned run 被 close 取消/join；并发 close 与重复 close 仅执行一次清理并共享失败。不得以 `assertTrue(activeRun)` 继续固化旧缺陷。
5. start 失败与 Cron 启动失败真实触发逆序释放；手动/Cron 互斥：一手动一 Cron 不得同时执行，无排队。

### 3.2 真实公共入口与 SQLite

使用公共 `AlcyoneContextFactory.create()`、真实 Runtime、真实文件 SQLite、测试 VFS、真实 `KtorLlmClient` 和 `127.0.0.1:0` 的 JDK HTTP stub。通过 `ConversationIngestion` 写入不同稳定来源 Turn，模型响应按实际 DTO 构造，不硬编码 Raw ID。

- 非空多批：固定 C0/U，至少两个成功批；Dreaming Topic Discovery/Consolidation、Memory Search Scanner/Rerank、Evidence 三层请求与 Reflection 按真实装配执行。覆盖 Raw/Organized 存在与不存在两条取证路径，Evidence 输出再经真实 Novelty Check。断言 Raw `DREAMING`、合法外部来源、Organization Pending、Checkpoint=U；无 Organized 直写，无 Map 文件生成。
- 动态预算使至少两批，第二批 Reflection 失败：异常为 `DreamingRunException(BATCH_PROCESSING)`，partial 指向首批；SQLite 保留首批 Raw/Pending/Checkpoint，第二批没有 Raw/Pending，Checkpoint 未越过首批。重试成功从首批水位继续，不重复首批。
- 正常重启：真实 `closeAsync()` 后重新 `create()/start()` 同一 DB；已提交批不重做，继续处理余下 Turn。独立进程恢复不在本批。
- HTTP 记录按 Profile 分别断言 model 与 Authorization；至少四个 Dreaming Task 路由不串用。Organization 通知可观测但不由 Dreaming 直接生成 Organized。测试不能通过读取私有 Runtime 代替公共入口验证。
