## 本次修改（2026-10-26，Architect 首次独立复核 R1～R3 定点修正）

根据 Architect 首次独立复核结论（`架构与技术复核.md`），完成 3 项必须修正：

1. **R1：彻底消除 copy 绕过不可变集合保护的漏洞**：
   - 将 `RawMemory`、`ConversationTurn`、`OrganizedMemory`、`StoredConversationTurn` 从 `data class` 改为普通 `class`；
   - 构造参数不带 `val`（如 `sources: List<MemorySourceRef>`），类体中统一执行 `val sources = Collections.unmodifiableList(sources.toList())` 做防御性浅拷贝与不可修改快照；
   - 显式手写 `copy(...)` 委托构造器，确保无论通过直接构造、工厂方法还是 `copy(...)` 传入 mutable list，均无法绕过保护；
   - 显式手写 `equals`、`hashCode`、`toString` 与 `component1..componentN` 解构；
   - `StoredConversationTurn.messages` 同步采用相同保护；
   - 单元测试覆盖直接构造与 copy 传入 mutable list 后的外部篡改隔离、尝试修改返回集合抛 `UnsupportedOperationException`、至少 2 个元素场景，且验证通过 Architect 的 `ModelCopyProbe`。

2. **R2：落地 CM1 基础错误契约（context/api）**：
   - 在 `context/api` 中建立统一异常体系：`ContextException` 抽象基类（继承 `RuntimeException`）；
   - 4 类具名异常与强类型枚举错误码：
     * `ContextConfigException`（`ContextConfigErrorCode`：`INVALID_CONFIG`、`MISSING_ENV`、`UNKNOWN_FIELD`）；
     * `ContextLifecycleException`（`ContextLifecycleErrorCode`：`NOT_STARTED`、`CLOSED`、`START_FAILED`）；
     * `ContextPersistenceException`（`ContextPersistenceErrorCode`：`PERSISTENCE_UNAVAILABLE`、`DATABASE_NOT_INITIALIZED`、`SCHEMA_VERSION_MISMATCH`）；
     * `ContextIngestionException`（`ContextIngestionErrorCode`：`INVALID_TURN`、`PAYLOAD_TOO_LARGE`、`TURN_CONFLICT`、`UNAUTHORIZED`、`FORBIDDEN`）；
   - 严格约束：错误信息不含 API Key、密码、会话正文等敏感信息；`CancellationException` 绝不包装为此类异常；配套单元测试验证完整继承关系与所有枚举码。

3. **R3：补齐 Repository 查询与写入契约**：
   - 在 `context/api` 定义 `SessionKey(val runtimeId: String, val agentId: String, val sessionId: String)`，强制非空白校验；
   - `ConversationReadOps` 与 `ConversationRepository` 补齐：
     * `findIdleSessions(idleBefore: Instant): List<SessionKey>`（从 Pending 候选中枚举所有状态 created_at <= idleBefore 的 Session）；
     * `maxTurnId(): Long?`（Dreaming 固定上界 U = MAX(conversation_turn.id)）；
     * 支持以 `SessionKey` 为入口调用各会话方法；
     * 明确 KDoc 边界：`sessionWindow` 包含锚点自身，按 `timestamp DESC, id DESC` 检索并反序为发生顺序；`idRange` 下界排除、上界包含（`id > fromIdExclusive AND id <= toIdInclusive`），按 `id ASC` 排序；
   - `ConversationTxOps` 的 `insertTurn` 明确 KDoc 契约：当四元业务键已存在但规范化内容不一致时，抛出 `ContextIngestionException(ContextIngestionErrorCode.TURN_CONFLICT, ...)`；
   - `OrganizationPendingReadOps` 与 `OrganizationPendingRepository` 补齐 `hasAnyPending(): Boolean` 全局存在性检查（`SELECT EXISTS(SELECT 1 FROM organization_pending)`），与单项 `exists(rawId: String): Boolean` 并存；
   - `OrganizedMemoryTxOps.advanceUpdatedAt` 明确 KDoc 契约：在同一 WriteSlot 事务中，调用方先读取全局 `MAX(updated_at)`，再按毫秒推进严格更大的时间 `next = max(nowMs, previousGlobalMax.plusMillis(1))`，同事务多条及仅来源 MERGE 亦须依次推进。

### 1.2 持久化记录（context/core，不进 api）

- `StoredConversationTurn`：内部持久化会话记录，包含 SQLite 自增主键 `id: Long`、四元业务键（`runtimeId`/`agentId`/`sessionId`/`sessionTurnId`）、`timestamp: Instant`、`createdAt: Instant`、`messages: List<ChatMessage>`、`extractionStatus: ExtractionStatus`（`PENDING`/`COMPLETE`/`FAILED`）。`messages` 具备完整不可修改快照保护。

### 1.3 基础 Port（context/core）

五个 Repository Port，区分普通 `suspend` 读与 `TransactionContext` 同步写（TxOps），写只能经 `TransactionContext`，避免可挂起事务回调，不提供泛型 `BaseRepository`：

| Port | 普通 suspend Repository | 同步 ReadOps | 同步 TxOps |
|---|---|---|---|
| Conversation | `getById`、`findByBusinessKey`、`sessionWindow`、`latestPending`、`countPending`、`idleCheck`、`findIdleSessions`、`maxTurnId`、`idRange` | 同左（同步） | 幂等 `insertTurn`（冲突抛异常）、`markComplete`、`markFailed` |
| Raw Memory | `findById`、`findByIds`、`scanPage` | 同左（同步） | `insertBatch`（不可更新、不可物理删除） |
| Organized Memory | `findById`、`findByIds`、`findSourcesByOrganized`、`findOrganizedByRaw`、`maxUpdatedAt`、`scanPage` | 同左（同步） | `insertNew`、`update`、`insertSourceLink`、`advanceUpdatedAt` |
| Organization Pending | `exists`、`hasAnyPending`、`nextByRawCreatedAt` | 同左（同步） | `enqueue`、`dequeue` |
| Dreaming Checkpoint | `readCheckpoint` | 同左（同步） | `casUpdateCheckpoint` |

- `ContextDatabase`：`suspend fun <T> read(block: (ReadContext) -> T): T`、`suspend fun <T> write(block: (TransactionContext) -> T): T`；回调同步不可挂起，事务内不跨 LLM/HTTP/VFS。
- `ReadContext` 聚合五个 `ReadOps`；`TransactionContext : ReadContext` 并提供五个 `TxOps`。

必要抽象 Port（仅抽象，不实现后续业务/Adapter）：
- `LlmClient`（统一 `LlmRequest`/`LlmResponse` 契约）；
- `TokenEstimator`（保守估算 + 可配置安全余量）；
- `MemoryIdGenerator`（`nextRawMemoryId()` / `nextOrganizedMemoryId()`）。

### 1.4 时间/ID 基础算法（context/core，CT03 必须现在实现）

- 注入 JDK `Clock`（生产默认 `Clock.systemUTC()`，测试可固定/可控）；Core 内部用 `Instant`。
- 数据库时间文本严格固定 `+08:00` 偏移与 3 位毫秒：`uuuu-MM-dd'T'HH:mm:ss.SSS+08:00`（`uuuu` 四位年），使用 `ZoneOffset.ofHours(8)`，存储在 SQLite 写入边界统一编码；读取时严格反解析并拒绝非规范文本。
- 业务日历与 ID：`MemoryIdGeneratorImpl` 使用 `Asia/Shanghai` 业务日历计算日历日与当天毫秒，补零采用 `Locale.ROOT`，避免本地数字；维护 `lastLogicalMillis + sequence`；时钟回拨不重复。

## 2. 验收重点

1. 模型无基础设施泄漏：`context/api` 不依赖 core 与任何基础设施（仅 Kotlin stdlib + `kotlinx-coroutines-core`）；`context/core` 单向依赖 `api`，不依赖 JDBC/SQLDelight/YAML/Ktor Server。
2. `ConversationTurn` 严格六字段，不含内部 `id`/`createdAt`/`extractionStatus`。
3. `RawMemory`、`ConversationTurn`、`OrganizedMemory`、`StoredConversationTurn` 集合字段在构造与 copy 路径均实现防御性深保护（`Collections.unmodifiableList(sources.toList())`），通过 `ModelCopyProbe` 探针验证。
4. CM1 四类异常与错误码齐备，消息无敏感信息，`CancellationException` 不被包装。
5. Repository 契约补齐 `findIdleSessions`、`maxTurnId`、`hasAnyPending`、KDoc 边界与冲突异常。
6. 上海时间 codec 往返与拒绝非规范文本；固定 `+08:00` 偏移存储。
7. 跨日 ID、同毫秒 101 个 ID 唯一、并发 101 线程生成无重复、时钟回拨不产生重复、阿拉伯 Locale 补零正确。
8. 源码常规 `src/test` `@Test` 与 XML 报告计数严格对齐（均为 **884 例**，差额 0；不含 `webdavTest` 独立源集 43 例。经全工程核查，未发现 `@Disabled`，不存在假设/启用的条件跳过；此前报告的 885 数字系误报，已纠正）；全量常规回归 `./scripts/check` / `./scripts/dev gradle clean build` **884 例**（CT02 840 + CT03 44）全绿；81 个 VFS 基线文件 SHA256 0 mismatch。
