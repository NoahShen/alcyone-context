## 2. 必须修正

### R1：copy 路径仍可破坏模型不可变性

`RawMemory`、`ConversationTurn`、`OrganizedMemory` 只在工厂中包装集合，data class 生成的公开 `copy` 直接接受新集合并绕过工厂。独立 `javap` 确认 JVM 方法公开；Java 消费探针调用 `RawMemory.copy(..., mutableSources, ...)` 后清空原集合，副本 sources 变为 0。

复现源码和结果：`ModelCopyProbe.java`、`model-copy-probe.log`。探针退出码 1，断言为 `Public copy bypasses immutable snapshot`；这不影响常规测试全绿事实，而是揭示其覆盖缺口。

让所有可访问构造与复制路径保持不可修改快照，或不暴露绕过路径；采用简单模型实现，不引入通用不可变框架。StoredConversationTurn.messages 也应隔离输入引用，保证快照记录不被外部集合修改。补实际 JVM copy/构造与多元素集合修改验证，不能只测 create。

### R2：基础错误契约尚未落地

任务书 CT03 包括公开错误契约，CT01 §c 已确定配置、生命周期、持久化、Ingestion 分类；当前 API/Core 未提供对应异常类型/错误码，构造校验只有 IllegalArgumentException。补 CM1 所需的具名错误基础，保持取消不转换、避免原文/Key 等敏感内容进入错误文本。HTTP 映射归 CT07，不在本任务实现服务或复杂错误框架。后续 SQL 故障与 Ingestion 同键冲突必须有可直接使用的类型约定。

### R3：必要 Repository 查询与写入契约不完整

- Conversation 只有已知 Session 的 idleCheck，缺从 Pending 候选中枚举 Idle Session 的入口；缺 Dreaming 固定上界所需的最大内部 Turn ID 查询。给普通 suspend Port 与同步 ReadOps 提供一致的必要方法，SessionKey 使用稳定三元键。
- Pending 的 exists(rawId) 是单项成员判断，不能代表设计中的任意 Pending 存在性。补明确的全局存在性入口。
- 明确 sessionWindow 锚点是否包含、idRange 下界排除/上界包含、分页排序及参数边界，避免 CT05 各实现自行猜测。
- insertTurn 返回类型只包含 CREATED/DUPLICATE，其注释却写内容差异“由上层处理”而未给冲突通道；用本任务具名异常或明确结果定义冲突语义。
- 全局 updated_at 保证仍不能只写成 next > 当前记录：明确调用方在同一 WriteSlot 事务中读取全局 MAX、按毫秒分配推进（含同事务多条和仅来源 MERGE）。SQL 实现与实证留 CT05，本任务锁定 Port 使用契约。
