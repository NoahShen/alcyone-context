## 2. 冻结 API

```kotlin
class OrganizationCommitter(
    private val database: ContextDatabase,
    private val idGenerator: MemoryIdGenerator,
    private val clock: Clock,
    private val maxIdAttempts: Int = 3,
) {
    init { require(maxIdAttempts in 1..3) }

    suspend fun commit(
        rawId: String,
        candidates: List<OrganizedMemory>,
        decision: GovernanceDecision,
    ): OrganizationCommitResult
}
```

`OrganizationCommitResult`：

- `Committed(action: GovernanceAction, organizedMemoryId: String)`
- `AlreadyAssociated(pendingRemoved: Boolean)`

`OrganizationCommitException`：

- 内部具名异常，含安全 `reason` enum。
- reason 至少覆盖 `INVALID_DECISION`、`STALE_TARGET`、`STALE_DECISION`、`ROW_COUNT_MISMATCH`、`ID_COLLISION_EXHAUSTED`、`WATERMARK_EXHAUSTED`。
- 消息不得含 content、domains 原文、Key、URL 或敏感完整业务值。
- `CancellationException` 与 `ContextPersistenceException` 必须原样传播，不包装。

## 3. 冻结事务流程

每次 `commit` 的一次尝试都进入新的 `database.write { tx -> ... }`，并在该事务内按以下顺序执行。

### 3.1 Source/Pending 幂等分支（必须先做）

1. `tx.organizedMemories.findOrganizedByRaw(rawId)` 查询 Source；数据库异常直接传播。
2. `tx.pending.exists(rawId)` 查询 Pending。
3. Source 非空 + Pending=true：只调用 `tx.pending.dequeue(rawId)`；必须恰好 1 行，否则 `ROW_COUNT_MISMATCH`。不校验 decision、不改 Organized、不推进水位，返回 `AlreadyAssociated(true)`。
4. Source 非空 + Pending=false：不写任何表，返回 `AlreadyAssociated(false)`。
5. Source 为空 + Pending=false：抛 `STALE_DECISION`。
6. Source 为空 + Pending=true：进入 §3.2。

### 3.2 决策复验与目标版本

1. 调用 CT14 `GovernanceDecisionValidator.validate(decision, candidates)`；Validator 异常映射为 `INVALID_DECISION`，不得降级 NEW。
2. `NEW`：target 必须仍缺席（由 Validator 保证），无需目标版本检查。
3. `MERGE/UPDATE`：从本次 candidates 找到 `targetMemoryId` 对应候选；`tx.organizedMemories.findById(target)` 必须存在，且 `stored.updatedAt == candidate.updatedAt`。任一不满足 → `STALE_TARGET`；整笔回滚、Pending 保留。

### 3.3 水位

只在实际修改 Organized 时读取 `tx.organizedMemories.maxUpdatedAt()`：

```text
nowMs = clock.instant().truncatedTo(ChronoUnit.MILLIS)
previous == null      -> next = nowMs
previous == Instant.MAX -> WATERMARK_EXHAUSTED
otherwise             -> next = max(nowMs, previous.plusMillis(1))
```

- NEW：`createdAt = nowMs`，`updatedAt = next`。
- MERGE/UPDATE：保留存储目标的 `createdAt`，`updatedAt = next`。
- Source 已关联分支不读取/推进水位。
- 不 clamp、不倒退、不使用事实时间代替系统时间。

### 3.4 动作写入

#### NEW

1. Source/Pending 分支和 Validator 通过后，`idGenerator.nextOrganizedMemoryId()` 生成候选 ID。
2. 在当前事务内预检 `tx.organizedMemories.findById(id) == null`；若已存在，抛内部 ID-collision 信号并退出当前事务。
3. 分配水位。
4. `insertNew(new OrganizedMemory)` 必须 1 行。
5. `insertSourceLink(newId, rawId)` 必须 1 行。
6. `pending.dequeue(rawId)` 必须 1 行。
7. 返回 `Committed(NEW, newId)`。

ID-collision 处理：

- 仅显式预检命中触发整笔重试，最多 `maxIdAttempts` 次。
- 每次重试重新进入新的 `database.write`，重新检查 Source/Pending、复验 decision、重读目标版本与 MAX，并生成新 ID。
- 不捕获/重试任意 `ContextPersistenceException`；禁止 `INSERT OR REPLACE`。
- 重试耗尽抛 `ID_COLLISION_EXHAUSTED`，不得留下 Organized/Source/Pending 部分写。

#### MERGE

1. 分配水位。
2. `decision.content == null`：`advanceUpdatedAt(target, next)` 必须 1 行；content/domains 保持。
3. `decision.content != null`：用当前存储行的 domains、Validator 规范化后的 content、`updatedAt=next` 调一次 `update`，必须 1 行。
4. `insertSourceLink(target, rawId)` 必须 1 行。
5. `pending.dequeue(rawId)` 必须 1 行。
6. 不再调用第二次 `advanceUpdatedAt`。

#### UPDATE

1. 分配水位。
2. content 使用 Validator 规范化后的值；domains 提供时用新值，缺席时用当前存储行 domains；`updatedAt=next`。
3. 调一次 `update`，必须 1 行。
4. `insertSourceLink(target, rawId)` 必须 1 行。
5. `pending.dequeue(rawId)` 必须 1 行。
6. 不再调用第二次 `advanceUpdatedAt`。

所有行数不符均抛 `ROW_COUNT_MISMATCH`，让当前事务回滚。旧 Source 关系必须保留。

## 4. 测试要求（A01～A08）

测试使用真实 SQLite；不得用纯 fake 替代事务正确性。Fake 仅用于 ID 生成、Clock、行数/未知结果测试 wrapper。正式测试放 Runtime test source。

### A01 来源幂等

- 已关联 + Pending：即使 decision 无效/过期，也只出队 1 行；MAX 不变、Organized 不变。
- 已关联 + 无 Pending：no-op 成功。
- 未关联 + 无 Pending：`STALE_DECISION`，0 写入。

### A02 NEW 原子提交

- Source/Pending 存在时 NEW 写入 Organized/Source 并删除 Pending；createdAt/updatedAt/content/domains 正确。
- 预置 ID 冲突：下一次生成新 ID 后成功；旧行不被覆盖。
- 连续 3 次冲突：`ID_COLLISION_EXHAUSTED`，无 Organized/Source 新增，Pending 保留。

### A03 MERGE/UPDATE 语义

- MERGE 无 content：正文/domains 保留，Source insert/Pending delete，水位推进。
- MERGE 有 content：正文更新，domains 不变，水位推进。
- UPDATE domains 提供：content/domains 替换；domains 缺席：content 替换、domains 保留。
- 旧 Source 全部保留，新 Source 增加；Pending 删除。

### A04 版本冲突与过期决策

- 候选快照后修改 target `updated_at`：`STALE_TARGET`，Pending 保留，Organized/Source 0 变化。
- target 不存在：`STALE_TARGET`。
- Validator 拒绝非法字段/越权 target：`INVALID_DECISION`，Pending 保留，0 写。

### A05 全局毫秒水位

- 空表 NEW：`createdAt == updatedAt == nowMs`。
- 已有 MAX 等于 nowMs 或晚于 nowMs：next 严格为 MAX+1ms。
- 同毫秒连续两次提交严格递增。
- DB 原文为上海 `+08:00` 三位毫秒格式。
- previous `Instant.MAX`：`WATERMARK_EXHAUSTED`，不写。

### A06 行数与回滚

- 测试 wrapper 注入 Organized insert/update/advance、Source insert、Pending delete 的 0/2 行返回，断言 `ROW_COUNT_MISMATCH` 且真实事务回滚。
- 用测试临时 SQLite trigger 让 Source insert 或 Pending delete 失败，断言 Organized/Source/Pending 均无半成品；Pending 仍存在。
- 覆盖已关联 Pending 清理 dequeue 行数不符回滚。

### A07 未确认 COMMIT、取消与持久化异常
