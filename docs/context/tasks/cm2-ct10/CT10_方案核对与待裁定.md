## 2. 冲突与待裁定项（历史建议，已被裁定取代）

### D1 Builder 返回类型（阻断接口）

设计 §5.4 固定 `suspend fun build(sessionKey): ExtractionContext?`（null=无 Pending）。但 Architect CT10 目标 #6 要求区分：

- 无 Pending；
- N=1 且单 Turn 确定性超预算（CT11 后续标记 failed）；
- 固定 Prompt/Schema/输出预留本身超容量（配置/固定开销错误，不得标 Turn failed）；
- 正常窗口。

`ExtractionContext?` 无法表达后两类。**建议**改为 sealed 结果（可更新设计契约）：

```kotlin
sealed interface ExtractionBuildResult {
    data class Built(val context: ExtractionContext) : ExtractionBuildResult
    data object NoPending : ExtractionBuildResult
    data class SingleTurnOverBudget(val anchorTurnId: Long, val requiredTotalTokens: Long) : ExtractionBuildResult
    data class FixedOverheadOverBudget(val requiredTotalTokens: Long) : ExtractionBuildResult
}
interface PreExtractionContextBuilder {
    suspend fun build(sessionKey: SessionKey): ExtractionBuildResult
}
```

**备选**：保留 `ExtractionContext?`，新增两个专用异常（`SingleTurnOverBudgetException`/`FixedOverheadOverBudgetException`），但异常控制流不如结果清晰。请裁定。

### D2 `ExtractionContext.turns` 类型（阻断接口）

设计写 `List<ConversationTurn>`；现有公开 `ConversationTurn` 是 Ingestion 输入，无 SQLite `id`/`extractionStatus`，无法满足 Target/History。**建议**使用既有 Core `StoredConversationTurn`（含 id/status/timestamp/messages），不新增平行实体；`ExtractionContext` 只存 `sessionKey + turns`，Target 由 `extractionStatus == PENDING` 判定。请确认。

### D3 Prompt/Schema 归属（范围冲突）

CT10 目标 #3 要求用**真实渲染的完整 LLM 请求**估算（System Prompt、Turn 内容、ID/时间/Target 标记、Schema/协议、输出预留/余量）；但设计 §5.6 将版本化 Prompt/Schema 放在 Extraction（CT11）。若不实现真实 Prompt/Schema，CT10 预算只是近似，不满足目标。

**建议**：CT10 拥有 **Extraction Prompt v1 + JSON Schema v1 + Renderer**（Core `prompts/extraction-v1.md`、`extraction-schema-v1.json`，渲染器纯逻辑）；CT11 复用，只做响应校验/来源映射/原子提交。相应调整任务边界与设计归属。**备选**：CT10 只定义 Renderer 接口并用 CT11 占位资源，但会违反“真实渲染”。请裁定。

### D4 `initialWindowTurns` 配置键/范围

设计只给默认建议 32、可配置，未定路径/范围。候选：

- 平铺：`context.extraction.initialWindowTurns`（与现有 `ExtractionConfig` 平铺字段一致，改动最小）；
- 分组：`context.extraction.builder.initialWindowTurns`（未来 Builder 参数扩展更清晰）。

**建议**平铺，默认 32，`Int` 范围 `1..1024`（防御异常大 LIMIT；上限可改）；逐层未知键拒绝、直接构造与 YAML 同一校验。请裁定键位/上限。

### D5 预算分类与固定开销定义

`LlmBudget.requireWithinBudget` 只抛统一 `LOCAL_BUDGET_EXCEEDED`，不能区分“窗口太大”与“固定开销本身超限”。**建议** Builder 使用 `LlmBudget.estimate`（纯计算）并分类：

1. 基础请求：System Prompt + 空 Turn 渲染 + Schema（如 JSON_SCHEMA）+ 输出预留 + 安全余量；若 `estimatedInput > task.maxInputTokens` 或 `requiredTotal > profile.contextWindowTokens` → `FixedOverheadOverBudget`；
2. 每个 N 的完整请求：任一条件超限 → 折半；`N=1` 仍超 → `SingleTurnOverBudget`；
3. 不调用 LLM、不写库、不抛普通 `LOCAL_BUDGET_EXCEEDED`。

**需确认**：基础请求是否包含“空 user 信封”（协议开销）而非仅 System message；`task.maxInputTokens` 是否对完整输入（含 Prompt/Schema）生效。

### D6 有效 N 与折半序列

若 `initialWindowTurns=32` 但实际可用 Turn 只有 10，首次窗口 K=10。**建议**折半基于**实际读取条数 K**：`K=max(1,K/2)`，避免继续用 32/16 重复读取同一 10 条；若 K=1 仍超 → 单 Turn 结果。序列示例：32→16→8→4→2→1（可用足够时），或 10→5→2→1（不足时）。请确认。

### D7 同一 ReadContext 快照

**建议**：整个 `build` 在一个 `database.read { read -> ... }` 回调内完成：`latestPending` → 循环 `sessionWindow(anchor.timestamp, anchor.id, K)` → 渲染/估算；回调内不挂起、不调 LLM、不等待。为验证“折半期间补录不混入”，需一个 internal 测试接缝（如 `betweenReadsForTesting` 同步钩子）在真实 SQLite 读事务中插入另一连接写入；请确认允许该 internal 接缝。

### D8 单 Turn/固定开销语义（不写库）

**建议**：Builder 只返回 `SingleTurnOverBudget`/`FixedOverheadOverBudget`，不修改 Turn 状态、不写 `failed`；CT11 Service 才执行 `pending→failed` 条件更新并继续下一条 Pending。Builder 不得把这两类误报为 `LlmException`/网络失败。请确认。

### D9 模块归属与可见性

**建议**：

- Core（public，非 `context/api` SDK）：`ExtractionContext`、`ExtractionBuildResult`、`PreExtractionContextBuilder`、`ExtractionPrompt`/Renderer、Prompt/Schema 资源；
- Runtime（internal）：`DefaultPreExtractionContextBuilder`（依赖 `LlmConfig`/`LlmBudget`/`ExtractionConfig`/`ConservativeTokenEstimator`）；
- `ExtractionConfig.initialWindowTurns` 公开字段 + Loader 校验；
- 测试接缝 internal。

**备选**：Builder 整体放 Runtime、Core 仅接口；与建议基本一致，确认即可。

### D10 缺少 LlmConfig/EXTRACTION Task/Profile

Builder 需要 `LlmTask.EXTRACTION` 的 Task/Profile 才能估算。若 `ContextConfig.llm == null` 或缺 `EXTRACTION` 映射：**建议**在 Builder 构造/首次 build 抛 `ContextConfigException(INVALID_CONFIG)`（或返回固定配置错误结果），不静默使用默认预算；CT11 启动时暴露配置错误。请裁定错误形态（构造异常 vs 结果）。

### D11 Profile JSON mode

Extraction 输出契约是 JSON。**建议**要求 `profile.jsonMode` 为 `JSON_SCHEMA` 或 `JSON_OBJECT`；`PROMPT_ONLY` 视为 `CONFIGURATION` 错误（或 CT11 校验失败）。请确认是否在 CT10 构造期拒绝。

### D12 Prompt 渲染格式与版本

设计只规定需提供内部 `id`、原始时间、`target` 标记、角色/正文，未定格式。**建议** v1：

```text
<system prompt>

<turn id="1001" timestamp="2026-10-20T...+08:00" target="true">
user: ...
assistant: ...
</turn>
...
```

System Prompt 覆盖六原则；Target/History 明确标记；不包含 Key/URL/无关元数据；Prompt/Schema 版本常量供 CT11/评测引用。请确认格式/资源路径，或授权 CT10 在实现时定稿。

### D13 CT10 是否接 Runtime/测试分批

CT11 才提供 Extraction Service；CT10 不接 pipeline。**建议分批**：

- **B1**：配置 `initialWindowTurns` + Core 结果/Context/Prompt Renderer + 纯逻辑预算分类（Fake ReadContext）；
- **B2**：Runtime Builder + 真实 SQLite 锚点/同时间戳/连续窗口/快照/折半/单 Turn/固定开销；
- **B3**：集成（真实 LlmConfig/DB/Fake Estimator 或真实估算）+ 全量 `./scripts/check`、81 基线、文档/证据。

请确认是否允许 B3 不接 CT09 pipeline（只作为可复用组件），以及是否调整批次。
