## 2. 锁定的 Core 契约（D1/D6/D11）

### 2.1 DTO

```kotlin
data class ExtractionCandidateMemory(val content: String, val sourceTurnIds: List<Int>)
data class ExtractionCandidate(val memories: List<ExtractionCandidateMemory>)
data class ValidatedExtractionMemory(val content: String, val sources: List<MemorySourceRef.ConversationTurnRef>)
```

- Core public（非 `context/api` SDK）；`sourceTurnIds` 使用 Snapshot 内部 SQLite id。

### 2.2 `ExtractionResultValidator`（Core 规则/实现）

```kotlin
class ExtractionValidationException(message: String) : IllegalArgumentException(message)
interface ExtractionResultValidator {
    fun validate(candidate: ExtractionCandidate, context: ExtractionContext): List<ValidatedExtractionMemory>
}
class DefaultExtractionResultValidator : ExtractionResultValidator
```

规则（任一非法抛 `ExtractionValidationException`，消息只含安全原因，不含 content/来源正文）：
- `candidate.memories` 可为空 → 返回空列表（空 memories 合法）。
- 每条 `content` trim 后非空；`sourceTurnIds` 非空。
- 每个来源 ID 必须存在于 `context.turns`；映射为 `ConversationTurnRef(runtimeId, agentId, sessionId, sessionTurnId)`。
- 重复 source IDs 按**首次出现**确定性去重（去重后仍非空）。
- 整批至少引用一个 Snapshot 时 `extractionStatus == PENDING` 的 Target；仅 History / 窗口外 / 其他 Session 全部拒绝。
- 不自动修复/合并/改写 content；不做语义去重。

### 2.3 `ExtractionCommitter`（Core 原子提交）

```kotlin
data class ExtractionCommitResult(val rawCount: Int)
class ExtractionCommitter(
    database: ContextDatabase,
    idGenerator: MemoryIdGenerator,
    clock: Clock,
    maxIdAttempts: Int = 3,
) {
    suspend fun commit(context: ExtractionContext, memories: List<ValidatedExtractionMemory>): ExtractionCommitResult
}
```

- targets = `context.turns` 中 Snapshot 时 `PENDING` 的 Turn（必须非空；空则抛状态错误）。
- 每次尝试生成整批 Raw：`id = idGenerator.nextRawMemoryId()`、`content`、`generatedBy=EXTRACTION`、`sources` 直接使用 Validated 的 ConversationTurnRef、`createdAt=clock.instant()`（同批一致）；不新增字段。
- 单个 `database.write` 事务内：
  1. 预检每个 Raw ID 不存在（`tx.rawMemories.findById(id) != null` → 触发 ID 碰撞重试）；
  2. 非空 memories：`insertBatch` 行数 == raw 数；逐个 `enqueue` 返回 1；
  3. 逐个 Target `markComplete(id)`，**汇总行数必须 == Target 数**；任一 0 → 抛状态冲突，整笔回滚；
  4. 空 memories：只执行 Target complete（同样校验）。
- ID 碰撞：**仅**预检命中时事务回滚，重新生成整批 ID 并重试整笔，最多 3 次（含首次）；其他持久化失败不重试、不覆盖。
- 不通知 Organization（B2 才做）；不写 failed；`CancellationException` 原样传播；DB 错误原样传播。

## 3. Runtime JSON Validator（D1/D6/D10）

`internal class JsonExtractionResultValidator(private val core: ExtractionResultValidator = DefaultExtractionResultValidator())`：

- 输入 LLM `content` string；必须解析为 JSON **object**；顶层只允许 `memories`（未知字段整批拒绝）；`memories` 必须为数组（可为空）。
- 元素只允许 `content`/`source_turn_ids`；`content` 为非空白 string；`source_turn_ids` 为非空整数数组（不接受 string/bool/浮点/超大整数）；未知字段拒绝。
- 转为 `ExtractionCandidate` 后调用 Core validator；任一非法/JSON 解析失败 → 抛 `LlmException(LlmErrorCode.INVALID_RESPONSE, "invalid extraction response")`，**不**附带原始 content/cause。
- 不修复 Markdown 围栏、不提取部分 JSON。

### 4.3 Runtime `ExtractionCommitterTest`（真实 SQLite）

1. 非空成功：Raw 行数/content/generatedBy/sources/createdAt 正确；每个 Raw 的 organization_pending 存在；Target 全部 complete，History 不变。
2. 空 memories：0 Raw/Pending，Target 全部 complete。
3. Target 状态变化（提交前把某 Target complete/failed）：整笔回滚，0 新 Raw/Pending；状态以 DB 为准。
4. Raw ID 碰撞：预插同 ID；Fake IdGenerator 首次返回已有 ID、随后新 ID → 整批重试成功，已有 Raw 不被覆盖；3 次仍碰撞 → 抛错、0 新 Raw。
5. 事务失败/插入/入队/完成行数不符 → 无部分写（可用受控 Target 变化或 Fake ID 覆盖；不得改 SQL）。
6. 提交不触发 Organization 通知（B1 无通知）；CE 传播。
