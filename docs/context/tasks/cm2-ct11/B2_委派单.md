## 2. 锁定的实现契约

### 2.1 Builder internal 辅助（D4）

在 `DefaultPreExtractionContextBuilder` 增加 **internal**：

```kotlin
internal fun requestFor(context: ExtractionContext): LlmRequest
```

- 用与 `build` 完全相同的 `task/profile/schema/Prompt.messages(context.turns)` 构造 `LlmRequest`（task=EXTRACTION、format=profile.jsonMode、maxOutputTokens=null、schema 按 profile）。
- 不得改变 `build()` 行为/结果；不得复制到另一套配置来源。
- 一致性测试必须证明：真实 Builder 选中的窗口 == Service 发送的 Prompt 窗口（消息内容/顺序/target/schema/format 一致）。

### 2.2 `DefaultExtractionRunner`（internal，实现 Core `ExtractionRunner`）

构造依赖（可测试注入）：
`builder: PreExtractionContextBuilder`、`requestFor: (ExtractionContext) -> LlmRequest`（B3 传 `builder::requestFor`）、`llmClient: LlmClient`、`validator: JsonExtractionResultValidator`、`committer: ExtractionCommitter`、`database: ContextDatabase`、`maxWindowIterations: Int`（防御上限，建议取 `initialWindowTurns` 或等价有界值）、`wakeup: OrganizationWakeup`（internal，见 2.3）、logger。

`execute(sessionKey)`：

1. 循环（每次迭代计数，超过 `maxWindowIterations` 抛技术错误）：
   - `builder.build(sessionKey)`：
     * `NoPending` → 返回；
     * `FixedOverheadOverBudget` → 抛 `ContextConfigException(INVALID_CONFIG)`（技术/配置错误，不写 failed）；
     * `SingleTurnOverBudget` → 短写事务 `markFailed(anchorTurnId)`，**影响行数必须 ==1**；0 → 抛 `ExtractionCommitException` 状态冲突；继续下一条；
     * `Built(context)` → 进入 2。
2. LLM 调用（事务外）：`llmClient.complete(requestFor(context))`；`LlmException`（超时/拒答/截断/网络等）**原样传播**，0 写；`CancellationException` 传播。
3. `validator.validate(response.content, context)` → `ExtractionValidationException`/`LlmException(INVALID_RESPONSE)` 原样传播，0 写；不得部分写。
4. `committer.commit(context, validated)` 原子提交；`rawCount==0` 不唤醒；`rawCount>0` 调用 `wakeup.onRawCommitted()`。
5. 唤醒：`CancellationException` 传播；其他异常**吞掉并记录**（脱敏 WARN，不含 Raw/来源/Key/URL/Prompt），不回滚、不重提取。
6. 返回成功；`SingleTurnOverBudget` 标记 failed 不算失败抛出。

## 3. 测试要求（真实 SQLite + Fake LLM/Builder）

`DefaultExtractionRunnerTest` 至少覆盖：

1. **空 memories 成功**：Fake LLM 返回 `{"memories":[]}`；Target 全部 complete、无 Raw/Pending、wakeup 0、Service 正常返回。
2. **非空成功**：Fake LLM 返回合法 JSON；Raw/Pending/Target 正确、来源映射稳定、wakeup 一次。
3. **Builder 窗口 == Service 发送窗口**：真实 Builder + 真实 SQLite + Fake LLM 捕获 `LlmRequest`；断言消息（system/user）、schema/format、窗口 turns/target 与 `builder.build` 选中一致；调用 `builder.requestFor(context)` 与 Service 发送相同。
4. **非法 JSON/结构/来源**：Fake LLM 返回非法；`LlmException(INVALID_RESPONSE)`、Target pending、0 Raw/Pending、无 wakeup。
5. **LLM 错误**：Fake LLM 抛 `LlmException(TIMEOUT/... )`；0 写、pending；异常原样。
6. **SingleTurn 循环**：Fake Builder 首次返回 SingleTurn(anchorA)，markFailed 成功后返回 Built(anchorB)；断言 A failed、B 成功提交；标记行数 0 时抛 `ExtractionCommitException` 且 0 Raw。
7. **FixedOverhead**：Fake Builder 返回 Fixed → `ContextConfigException(INVALID_CONFIG)`、0 写。
8. **防御上限**：Fake Builder 持续 SingleTurn，超过 `maxWindowIterations` 抛技术错误；无无限循环。
9. **唤醒失败**：Fake wakeup 抛异常；提交成功、Service 正常返回、Raw/Pending 已落库、不重试。
10. **CE**：LLM/事务/唤醒任一抛 CE 原样传播。
11. **无 Pending**：Fake Builder NoPending → 直接返回，无 LLM/写/唤醒。
