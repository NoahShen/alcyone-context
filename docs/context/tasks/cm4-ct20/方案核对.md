## 2. 设计冻结候选

### 2.1 Search 主链

```text
validate query/domains/limit
  → single database.read full Organized scan
  → sort id ASC
  → in-memory explicit Domain filter
  → empty? return [] / 0 LLM
  → TokenBatchPlanner(MEMORY_SEARCH scanner)
  → serial batches; strict parser + batch ID validation
  → dedup all selected IDs
  → one global rerank request over all dedup candidates
  → strict ordered-subset validation
  → short database.read findByIds
  → reorder by rerank IDs; take limit
```

- Scanner/Rerank 都在 ReadContext 外执行；事务内不网络。
- 任一批失败、非法 ID、截断、预算不足或最终权威回读不完整 → 整体失败，不返回部分列表。
- Search 不做 T1/T2 检查或自动重试；允许短暂旧快照。

### 2.2 Domain / limit

- `domains=null` 与 `domains=[]`：候选均视为无过滤。
- 非空 Domain：精确、大小写敏感、任一命中；空白项拒绝，稳定去重。
- 默认 limit 10；建议最大 50。
- limit 在 SQL/LLM 前校验。

### 2.3 Get / GetRaw

- 生命周期检查后直接 `database.read` 精确查询。
- 不存在返回 `null`；数据库错误保留 `ContextPersistenceException`。
- 空/空白 ID 建议 `INVALID_REQUEST`；不调用 LLM/VFS。

### 2.4 Resource Stream

- CT20 不重写 Resource 实现；保留 CT17 的冷启动、64 KiB 分块、完成/异常/取消关闭。
- CT21 全景 E2E 再验证 Search → Memory Resource URI → `read/readStream` 的跨模块取消释放。

## 3. 待裁定决策 D1～D16

| # | 问题 | 推荐 | 影响/风险 |
| --- | --- | --- | --- |
| D1 | Search API 是否保持 `limit: Int = 10` | 保持冻结签名；默认 10 | 若要求配置默认 limit，需要改 nullable/Options |
| D2 | 是否新增 `context.retrieval.search` | 首版仅加 `maxLimit: 50`；默认仍由 API 固定 | 不改配置则常量固定，无法部署调参 |
| D3 | Domain `[]` 语义 | 与 `null` 相同，无过滤 | 更符合“显式非空列表才过滤” |
| D4 | Domain 规范 | 精确、大小写敏感；空白拒绝；trim 后稳定去重 | 避免隐式模糊/ACL 推断 |
| D5 | Query 规范 | trim 后非空白；发送 trim 后文本 | 防止空查询调用 LLM |
| D6 | 缺 MEMORY_SEARCH 绑定 | Search 调用时 `CONFIGURATION`；start/Bootstrap/Get 不受影响 | 不阻止仅使用 Get 的 Runtime |
| D7 | Scanner/Rerank Task | 两者复用 `MEMORY_SEARCH`，Prompt/Schema 分开 | 不新增 LlmTask，配置更简单 |
| D8 | Rerank 触发时机 | 所有非空去重候选都执行一次全局 Rerank | 排序语义一致；增加一次 LLM |
| D9 | Rerank 输出 | 有序、唯一、输入 ID 子集；空允许；未知/重复/空白拒绝；取前 limit | 模型可只返回最相关候选，避免强制全量输出 |
| D10 | 候选顺序 | 全量快照按 `id ASC` 分批；Scanner 选中按首次出现去重；Rerank 输入按 `id ASC` | 保证 Fake 与真实请求确定性 |
| D11 | Scanner 预算 | 复用 TokenBatchPlanner；固定开销/单条超限 `LOCAL_BUDGET_EXCEEDED` | 不跳过、不截断 |
| D12 | Rerank 预算 | 全部去重候选单请求；超限明确失败，不降级批内排序 | 避免伪造全局相关性 |
| D13 | 最终回读缺失 ID | 任一 Rerank ID 最终缺失 → 明确 UNAVAILABLE/失败 | 不返回部分；MVP 无 Organized 删除，正常路径不触发 |
| D14 | 新 Retrieval 异常 | 新增 `ContextRetrievalException(INVALID_REQUEST/CONFIGURATION/UNAVAILABLE)`；DB/LLM 原异常透传 | 公共错误更清晰；新增 API 类型 |
| D15 | 第三方默认方法 | Search/Get 默认抛 `UNAVAILABLE`，真实 Impl 覆盖 | 保持现有实现源兼容；不允许假空结果 |
| D16 | CT20 分批 | B1 组件/纯检索链；B2 公共 API/Factory/Impl/E2E | 降低公共 API 与内部扫描耦合风险 |
