## 2. 测试要求（真实 Runtime/SQLite + Fake LLM）

依赖说明：`:integration-tests:context` 原有 testCompileClasspath 不含 vfs 模块，公共 Factory 的 `VfsRuntimeConfig` 不可解析；方案 A 仅补测试级 `vfs.runtime` 依赖（与 `context/server` 既有 testImplementation 同型），不改生产依赖。使用公共 `AlcyoneContextFactory.create` + 真实临时 SQLite + `LlmHttpStub`（响应 OpenAI 信封，`content` 内放提取 JSON；支持按序响应/请求计数/记录 Authorization 不泄露）。可复用 `B3Fixtures.TestDatabase` 初始化真实 context.db，VFS state db 独立临时路径。

1. **失败后 Trigger 继续**：配置合法 JSON_OBJECT extraction（threshold 5）；stub 第 1 次返回 `content` 非 JSON（`INVALID_RESPONSE`），第 2 次返回合法 `{"memories":[{"content":"...","source_turn_ids":[1,2]}]}`；ingest 5 条 → 首次失败（0 Raw/Pending、5 pending）；再 ingest 第 6 条 → 第二次触发成功（Raw/Pending/Target complete）；断言 stub 请求数 2、Context 仍 RUNNING、失败未使服务停止。
2. **窗口外 Pending 不变**：`ExtractionConfig(initialWindowTurns=4)`，ingest 6 条；stub 合法响应用最新窗口内 Turn id（如 3..6 的来源），断言窗口内 4 条 complete、较早 2 条仍 pending、窗口外不被写入/完成。
3. **零记忆**：stub 合法 `{"memories":[]}`；ingest 5 条；断言全部 Target complete、Raw/Pending 0、Context RUNNING。
4. 等待/轮询使用有界超时（真实 SQLite 只读查询），不使用固定 sleep 猜结果；关闭 Context/stub/临时目录；断言日志不含 Key/正文（可用 SQL/公开状态断言为主，不新增日志框架）。
