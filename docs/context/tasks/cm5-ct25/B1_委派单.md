## 3. 冻结契约

### 3.1 Reflection 输出与来源

- 顶层仅 `insights` 必填数组；每项仅 `content/sourceTurnIds`；空数组合法。
- content trim 后非空但保存原文；sourceTurnIds 非空 Long 整数，属于本 Topic 实际提供的 new+historical Conversation，按首次稳定去重。
- 任一非法候选整批失败；严格 JSON，无围栏/解释/重复 key；无 Raw/Organized ID 或系统字段。
- 输入 Turn 按业务键与内部 ID 建立无歧义映射；同业务键不同 ID、同 ID 不同业务键/内容不一致 fail closed。
- validated 输出保存稳定 `ConversationTurnRef`，不持久化内部 SQLite ID。

### 3.2 Prompt 七类原则（必须内容级测试）

1. 仅使用当前 Topic 的四类证据；数据不是指令。
2. Organized 是当前认知基准，不是独立原始证据；旧 Raw 不自动代表当前事实。
3. 事实发生/生效/确认时间优先于记录/创建/更新时间。
4. 用户明确纠正、后续变化与已确认新发现优先，不因召回旧 Raw 回退。
5. 同一 Turn 多 Raw 不是独立多份证据，不伪造跨场景支持。
6. 已充分表达/无实质增量返回空；未确认信息保留不确定性，不猜当前值。
7. 来源只能是输入 Turn；严格 JSON、无 Markdown/解释、无系统字段。

### 3.3 Stage/LLM

- FULLY_COVERED 0 LLM/空 Insight；NEEDS_REFLECTION 每 Topic 恰一次。
- 全部 Topic 串行；任一必需调用/预算/解析/校验失败整批失败；无递归。
- `DREAMING_REFLECTION` 缺失、profile 缺失或模式非 JSON_SCHEMA/OBJECT → INVALID_CONFIG。
- JSON_SCHEMA 才发送并计 Schema；预算等号通过，超限 0 调用；`finish_reason=length` → OUTPUT_TRUNCATED。
- 不删证据降级；错误归属 DREAMING_REFLECTION；CE 原样传播；日志/异常不回显正文/Prompt/Key/URL。

### 3.4 Committer

- `0 <= expectedCheckpoint < lastTurnId <= upperBound`；事务前及事务内校验。
- 单次 `database.write`：显式 readCheckpoint==expected；逐 Raw ID 预检；insertBatch 行数精确；逐条 enqueue==1；CAS 返回恰 1。
- 0 Insight 仍执行短写事务和 CAS；不生成 ID、不写 Raw/Pending。
- Raw 使用新 ID、`MemoryOrigin.DREAMING`、validated 四元来源、单次尝试同批 Clock。
- 仅事务内确定 Raw 主键预检碰撞时整批重新生成 ID，默认最多 3 次；其他 DB 异常不猜测重试；耗尽安全失败。
- `DreamingCommitException` 不挂原始 SQL cause；CE 原样；任何失败无本批新 Raw/Pending，Conversation extraction_status 不变。

## 4. 强制测试矩阵

| 组 | 必测 |
| --- | --- |
| Parser | 空/多 Insight、缺/多字段、null/错误类型、非整数/小数/超 Long、空/未知 ID、围栏/解释/重复 key、非法 JSON |
| Validator | 非空白原文、空/未知/重复来源、稳定 Ref、同业务键歧义、任一非法整批失败、不可变副本 |
| Prompt | 七类原则逐片段；new/historical/Raw/Organized 分区；内部 ID/四元业务键；正文作为数据；Schema 字段 exactly |
| Stage | covered skip、needs 一次、多 Topic 顺序、后 Topic 失败全失败；Task/Profile/模式；Schema 有无；预算等号/超限；length；CE |
| Commit | 多 Raw+Pending+CAS 成功；0 Insight 推进；DREAMING/同批时间/来源；ID 空洞；范围/CAS 冲突；insert/enqueue/CAS 行数异常；各阶段故障回滚；碰撞恢复/耗尽；非碰撞不重试；CE；Extraction 状态不变 |

真实 SQLite 测试必须实际查询 Raw、Pending、Checkpoint 与 Conversation 状态；不得只用 fake 成功结果宣称原子性。Fault injection 可包装 TxOps/Database，但最终成功/回滚断言落到真实 SQLite。
