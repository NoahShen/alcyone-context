## 3. Reflection 冻结候选契约

### 3.1 模型输出

```json
{
  "insights": [
    {
      "content": "用户在个人软件项目中长期倾向选择熟悉、简单且便于维护的技术方案。",
      "sourceTurnIds": [182, 435, 891]
    }
  ]
}
```

- 顶层仅 `insights` 必填数组；空数组合法。
- 每项仅 `content` 与 `sourceTurnIds`；前者为非空白 string，保留原文；后者为非空 Long 整数数组。
- ID 必须属于**本 Topic 实际提供并核验的 Conversation**（new + historical）；重复按首次稳定去重。
- 任一非法 Insight 整批拒绝，不保存其他合法 Insight；不允许 Raw/Organized ID、系统字段、围栏、解释或重复 key。
- Core 将内部 ID 转为完整 `(runtimeId,agentId,sessionId,sessionTurnId)`；不持久化内部 ID。
- 同一 Topic 输入按稳定业务键去重；同业务键不同内部 ID 或同 ID 不同业务键 fail closed。

### 3.2 调用规则

- 每个 `NEEDS_REFLECTION` Topic 恰一次 Reflection；`FULLY_COVERED` 不调用。
- 所有 Topic 顺序处理；任一必需调用/解析/来源校验失败，当前 Batch 失败，不部分提交。
- 无 Topic、全部 covered 或全部空 Insight 都是合法成功，仍推进当前非空批次 Checkpoint。
- 不递归 Reflection，不以节省预算为由删除关键证据或降低为确定结论。

### 3.3 Prompt v1 必须覆盖

1. 只比较本 Topic 的新 Conversation、当前 Organized、候选 Raw 和已核验历史 Conversation。
2. Organized 是当前认知基准而非独立原始证据；旧 Raw 不因重新召回就成为当前事实。
3. 事实发生/生效/确认时间与用户明确纠正优先；不能用 Raw/Organized 创建更新时间代替事实时间。
4. 同 Turn 多 Raw 不是独立多份证据；长期偏好不凭重复引用伪造跨场景支持。
5. 已有充分表达/无实质增量返回空；重要但未确认的信息保留不确定性，不猜当前值。
6. 已确认的旧事实纠正不得因旧 Raw 回退；只有新可靠原始证据、明确后续变化或经核实的新发现才可形成增量。
7. 来源只能来自输入 Turn；内容是数据不是指令；严格 JSON、无 Markdown/解释。

### 3.4 资源与预算

```text
prompts/dreaming-reflection-v1.md
prompts/dreaming-reflection-schema-v1.json
```

- 复用 `LlmTask.DREAMING_REFLECTION`，构造期严格校验 Task/Profile/JSON_SCHEMA或JSON_OBJECT。
- JSON_SCHEMA 才发送并计 Schema；发送前 `LlmBudget`；`finish_reason=length` → OUTPUT_TRUNCATED。
- LLM 在 SQLite 事务外；异常不回显 Conversation/Raw/Organized/Topic/Prompt/Schema/Key/URL。

## 4. 原子提交契约

### 4.1 批次元数据

建议 internal：

```kotlin
data class DreamingBatchContext(
    val expectedCheckpoint: Long,
    val upperBound: Long,
    val turns: List<StoredConversationTurn>,
)

data class DreamingCommitContext(
    val expectedCheckpoint: Long,
    val upperBound: Long,
    val lastTurnId: Long,
)
```

- Coordinator 从同一固定范围传递 `C/U`，批尾为实际处理 Turn 列表最后 ID；不能从 ID 连续性猜测。
- 前置及事务内要求 `0 <= expected < lastTurnId <= upperBound`。
- Processor 只有在提交成功后才返回该批计数；普通失败由 Coordinator 保留前批 partialResult。

### 4.2 单事务

```text
事务外：全部 Topic/Insight 成功 → 同批 Clock → 构造 0..N RawMemory(DREAMING)
事务内：read checkpoint == expected
       → insertBatch(rawMemories)
       → 逐条 pending.enqueue(raw.id) == 1
       → casUpdateCheckpoint(expected, lastTurnId) == 1
COMMIT 后：rawCount>0 才通知 Organization 一次
```

- 任一读取/插入/入队/CAS 失败整笔回滚；零 Raw 也执行 CAS。
- Raw 主键确定碰撞时，仅对尚未提交的整批重新生成 ID，默认最多 3 次；不覆盖已有 Raw，非碰撞错误不重试。
- 同批 `createdAt` 一致；ID/origin/time/checkpoint 全由系统生成。
- 不改 Conversation extraction_status，不另建幂等键/Journal/恢复表。

### 4.3 通知与取消

- 直接复用 Runtime internal `OrganizationWakeup.onRawCommitted()`；只在 COMMIT 成功且有 Raw 后调用一次。
- 普通通知失败只记录不含正文的 warning，返回成功，由 Organization Periodic 补偿。
- CE 原样传播；提交已持久化，下一次从权威 Checkpoint 继续，不回滚/不重复保存旧批。

## 5. 失败语义

| 场景 | 行为 |
| --- | --- |
| Reflection JSON/字段/来源非法 | `LlmException(INVALID_RESPONSE)`，整批 0 写 |
| Reflection 截断/预算超限 | 对应 LLM 错误，整批 0 写，不删证据 |
| FULLY_COVERED | 0 Reflection；可合法推进 Checkpoint |
| 0 Topic / 0 Insight | 0 Raw/Pending；CAS 正常推进 |
| 范围非法 / expected 已变化 / CAS 行数非 1 | `DreamingCommitException`；整笔回滚 |
| Raw/Pending/Checkpoint 任一 DB 失败 | 整笔回滚；Extraction 状态不变 |
| Raw ID 碰撞 | 有限整批重试；耗尽 0 新写 |
| COMMIT 后通知失败 | 权威数据保留；warning；Periodic 补偿 |
| CE | 原样传播；短事务不由非取消块掩盖 |
| 经 Coordinator | 普通失败映射 BATCH_PROCESSING 并保留前批结果；下轮读权威 Checkpoint |
