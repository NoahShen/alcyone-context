| # | 事实 | 影响 |
| --- | --- | --- |

| F2 | `DreamingBatchOutcome` 已冻结为 `lastTurnId/discoveredTopics/generatedMemories`；普通失败由 Coordinator 包装 `BATCH_PROCESSING` 并保留前批结果，CE 原样传播。 | CT25 可复用 outcome/失败语义，不应另建结果协议。 |
| F3 | CT23 `DreamingTopicBatchProcessor` 是零写入适配器，返回 `generatedMemories=0`；CT24 `LlmDreamingEvidenceStage.collect(batch)` 独立组合 Topic 与三层取证。 | CT25 新增完整 Processor，不删除旧适配器；B1/B2 测试需区分组件 seam 与真实提交路径。 |
| F4 | `DreamingTopicEvidence` 分离 `FULLY_COVERED/NEEDS_REFLECTION`、new/historical Conversation、Organized 与 Raw；FULLY_COVERED 无 Raw/historical。 | FULLY_COVERED 不调用 Reflection；NEEDS_REFLECTION 即使 Raw/历史为空也可只依据本批 Conversation。 |

| F6 | `MemoryIdGenerator`、`RawMemoryTxOps.insertBatch`、`OrganizationPendingTxOps.enqueue(rawId)`、`DreamingCheckpointTxOps.casUpdateCheckpoint` 均已存在；Pending 没有 batch 方法。 | 不新增表/Repository/迁移；Core 在同事务逐条 enqueue 并校验返回 1。 |

## 2. 待裁定方案

| D1 | 范围与分批 | B1：Core Reflection DTO/Validator/Prompt + Runtime strict JSON/Reflection Stage + DreamingCommitter；B2：完整 Batch Processor、CT22 元数据衔接、通知与全量验收。 |
| D2 | 批次元数据 | 新增 internal `DreamingBatchContext(expectedCheckpoint, upperBound, turns)`，Coordinator 在同一 range 组装/处理边界传入；Processor 唯一入口改收 context，不保留仅 turns 的生产便捷重载。 |
| D3 | Coordinator 兼容 | CT22 调度、固定范围、分批、结果聚合不变；旧 CT22/23 fake/zero-write processor 仅用于明确的历史测试。生产 CT25 Processor 必须提交后返回，不能用零写入 adapter 冒充完整链。 |
| D4 | Core 输入/输出 | `DreamingInsightCandidate(content, sourceTurnIds: List<Long>)`、`ValidatedDreamingInsight(content, sources)`；输入上下文为本 Topic 的 new+historical Conversation，按稳定业务键去重，Long ID 唯一映射。 |
| D5 | 来源严格性 | `insights=[]` 合法；每条 content trim 后非空且保留原文；sourceTurnIds 非空、Long 整数、属于本 Topic 实际提供并核验的 Conversation；按首次稳定去重；任一非法整批拒绝。 |
| D6 | Topic 完整性 | 同一 Evidence 中的 Turn 按业务键去重；重复业务键不同内部 ID 或同 ID 不同业务键 fail closed，避免来源歧义。Topic 自身 `sourceTurnIds` 与 Evidence 一致性由 CT23/24 保证，CT25 不重新做语义发现。 |
| D7 | Reflection 调用 | 仅 `NEEDS_REFLECTION` 每 Topic 一次；`FULLY_COVERED` 0 调用/0 Insight；任一 Topic 失败整批失败；不递归 Reflection。 |
| D8 | Prompt 输入 | 只渲染该 Topic 的 new Conversation、当前 Organized、候选 Raw、已核验 historical Conversation；提供内部 Turn ID 与完整业务键、正文、时间及 Raw/Organized 来源关系。内容均视为数据。 |
| D9 | 纠错原则 | 明示 Organized 非独立原始证据、旧 Raw 非当前事实、事实时间优先于记录时间、用户纠正/后续变化优先、同 Turn 多 Raw 非独立证据、无增量返回空、未确认保留不确定性。 |
| D10 | 输出 Schema | 顶层仅 `insights`；每项仅 `content/sourceTurnIds`；camelCase；禁止系统字段/Raw ID/Organized ID 输出；严格 JSON，无 Markdown/解释/重复 key。 |
| D11 | LLM 绑定/预算 | 复用 `DREAMING_REFLECTION`；构造期校验 Task/Profile/JSON 模式；JSON_SCHEMA 才发送并计 Schema；单 Topic 全证据超预算即失败，不删证据/降级。`length` 映射 OUTPUT_TRUNCATED。 |
| D12 | 原子提交上下文 | `DreamingCommitContext(expectedCheckpoint, upperBound, lastTurnId)`；提交前及写事务内验证 `expected < last <= upper`；`expected>=0`、`upper>=0`；批尾取实际处理列表最后 ID。 |
| D13 | 单事务 | 一次 `database.write`：读取并核对 checkpoint==expected，插入全部 Raw，逐条 `pending.enqueue(raw.id)==1`，CAS 到 lastTurnId 且行数恰 1；任一步失败整笔回滚。LLM/Clock/ID 生成均在事务外。 |
| D14 | 零结果 | 全部 Topic 完成但 0 Topic/0 Insight 仍执行一次短写事务并 CAS 推进；不生成 ID、不写 Raw/Pending。 |
| D15 | 系统字段 | 同批统一 `Clock.instant()`；每 Raw 使用新 ID、`generatedBy=DREAMING`、稳定 ConversationTurnRef；模型不提供 ID/time/origin/checkpoint。 |
| D16 | ID 碰撞 | 仅确定 Raw 主键碰撞时重新生成整批尚未提交的 ID，默认最多 3 次；复用 Extraction 的确定碰撞判别，其他 DB 错误不重试；耗尽安全失败且无部分写入。 |
| D17 | 提交异常 | Core `DreamingCommitException` 只含安全原因，不挂原始 SQL cause/正文；CE 原样传播。CAS 冲突、前置范围非法、ID 耗尽、事务失败均不产生新 Raw/Pending。 |
| D18 | 提交后通知 | B2 直接复用 internal `OrganizationWakeup.onRawCommitted()`；仅 rawCount>0 且事务成功后调用一次；普通异常捕获并 SLF4J 脱敏 warning，返回成功；CE 原样传播。 |
| D19 | 完整 Processor | `LlmDreamingBatchProcessor` 串行 Evidence.collect → 每 Topic Reflection → 全量来源校验 → Committer.commit → notify → 返回批尾与真实 Topic/Raw 计数。事务外无写库，提交后不重复保存。 |
| D20 | Factory/Impl | CT25 仍不接公共 Factory/Impl/Cron 生产组装；真实 Coordinator+Processor+SQLite+Fake LLM 集成在 B2 完成，Factory 接线由后续明确批次/CT26 裁定。 |
