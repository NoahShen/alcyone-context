## 3. 附加确认（Worker 执行时必须遵守）

1. **失败原子性证据标准**：每个故障注入用例必须同时断言（a）异常类型/安全消息，（b）真实 SQLite 中本批 Raw/Pending 为 0，（c）Checkpoint 保持 expected，（d）Conversation extraction_status 未变。
2. **CE 用例**：CE 原样传播且事务无部分写入。
3. **ID 空洞用例**：lastTurnId 取实际列表最后 ID；有空洞时 `expected < last <= upper` 仍成立。
4. **同批 Clock**：单次尝试内所有 Raw 共享一个 `Clock.instant()`；碰撞重试生成新 ID 时可取新时间，但同一尝试内一致。
5. **Prompt 渲染**：内部 Turn ID + 四元业务键 + 正文 + 时间 + 来源关系均入 Prompt；Raw/Organized ID 不得出现在输出 Schema。
6. **B1 不接 Coordinator/wakeup/Factory**；完整 Processor 与通知归 B2。
7. 真实 SQLite + Fake LLM；真实模型 not-run；无 Git 写操作；发现阻断立即停止报告，不得越权修复或自行启动 B2。
