## 1. 范围与不变边界

实现只针对权威 `context.db` 的 SQLite Online Backup；可独立打开且发布前、发布后都通过 `PRAGMA quick_check`。Manual 与可选 Cron 共用单任务门禁，固定 URI，不覆盖既有备份。不含 VFS 状态库、WAL/SHM 物理复制、恢复、保留期/清理、HTTP Admin、部署。不得改 CM2～CM5 业务语义、公共 Schema 或 VFS 既有 safeReplace。

## 2. API / 配置 / 错误

`context/api` 新增 `backup/BackupModels.kt`：

- `BackupResult(uri, completedAt, quickCheck)`；`QuickCheckResult(phase, ok)`，phase=`PRE_PUBLISH` / `POST_PUBLISH`；`BackupWorkerState = IDLE | RUNNING | STOPPED | FAILED`；`BackupStatus(state, lastResult, lastFailureCode)`。
- `ContextBackupErrorCode = NOT_RUNNING | ALREADY_RUNNING | QUICK_CHECK_FAILED | PUBLISH_FAILED | UNAVAILABLE`。
- `ContextBackupException(code,message,cause?)`；`runBackup(): BackupResult` 默认 UNAVAILABLE；`backupStatus(): BackupStatus` 默认 STOPPED。

Runtime `BackupConfig(cron=null,timezone="Asia/Shanghai")` 沿用 Dreaming 的五字段 cron / IANA timezone 校验。`context.backup` 只接受 `cron`、`timezone`，无 cron 时 timezone 非法。配置默认值进 `ContextConfig` 与所有实际构造点；`backupMount="/backups"` 不在 v1 配置。

持久化错误映射 UNAVAILABLE，目标已存在/发布错误映射 PUBLISH_FAILED，quick_check 非 ok 映射 QUICK_CHECK_FAILED；保留生命周期 NOT_STARTED/CLOSED。异常/日志只含固定 URI 与脱敏原因，不含 SQL/正文/密钥。

## 3. VFS publishNew

- `Vfs.publishNew(uri, content: InputStream): NodeInfo` 默认 UNSUPPORTED_OPERATION；InputStream 不归调用方关闭。
- 新增 `Storage.publishNew(path, input, ...)`，能力 `atomicPublishNew` 默认 false；Local FS true，WebDAV false。CT27 Backup 仅接受 true，WebDAV 明确拒绝。
- Local FS 在目标同挂载同目录建唯一隐藏临时文件，`CREATE_NEW` 分块复制（不一次性读全文件），每块检查协程取消，fsync，原子 move 且**不替换**，失败清自己临时文件；目标已存在保留。移动前失败不得留下半目标；移动后失败按 UNKNOWN/PARTIAL。
- Core 走既有 write 路由、readOnly、限额、目录/文件冲突和父目录创建；流字节累计不得超 `defaultWriteMaxBytes`。已存在物理文件 ALREADY_EXISTS；已登记目录 CONFLICT。
- 新物理文件登记为稳定 Node，事件 FILE_CREATED；Node+Event 同事务，物理完成后状态失败 STATE_ERROR+PARTIAL。不覆盖、不清理已发布目标，不改 safeReplace。

## 4. SQLite Online Backup 适配

不用普通 JDBC dump、文件 copy 或 `VACUUM INTO`。在 `ContextDatabaseExecutor` 增加 `suspend fun backupTo(destination: Path)`，与业务写共用唯一写 Slot 的公平排队；保持 read slots 可服务既有读。使用 Xerial `SQLiteConnection` / `Database` / `Backup` Online Backup API（新依赖 `org.xerial:sqlite-jdbc` 由 runtime 使用；persistence 仍使用现有 JDBC）。

回调只在写 Slot 固定线程访问 `SQLiteConnection.database` 原生只读 backup handle；不开放普通 Connection、不放宽 ScopedJdbc 白名单。目标在固定线程用 Xerial 打开；逐页 step 并检查取消；正常 finish/关闭，失败/取消 dispose 且清目标临时文件。显式 `close()`、回调内 nested/close 沿用 Executor 准入与 inFlight；失败映射持久化异常，取消原样传播。`ContextDatabaseImpl` 暴露内部 `backupTo`，不改业务 `ContextDatabase.read/write` 接口。

临时文件名含 random UUID，禁止复用固定 destination 与 symlink；只允许普通文件。临时文件不能出现在 VFS 挂载树内，避免扫描误读。

## 5. Service / quick_check / 发布

`context/runtime/backup`：

1. 生命周期 RUNNING 且 single-flight acquire；备份与发布共用状态 `RUNNING`。
2. 用配置父目录外独立临时目录（`Files.createTempDirectory`），Online Backup 生成临时快照。
3. 独立 JDBC 只读连接执行 **exact** `PRAGMA quick_check`（不是 quick_check(1)），收集完整行；仅一行 `ok` 才算通过。
4. `Files.newInputStream` 调用 `vfs.publishNew`；失败保留旧目标，最终删除临时快照/目录。
5. 用**独立新 JDBC 只读连接**打开 VFS `openStream` 的完整快照到另一个临时文件，再次执行完整 quick_check；`VfsStreamOptions` 的调用限额不得截断合法大快照。只做字节复制，不创建整库 ByteArray。
6. 每次生成唯一备份 URI，时间由实例 Clock，状态包含 lastResult/lastFailureCode；已成功发布的备份即使状态记录失败也不得删。

`backupStatus` 不做 I/O；STARTING/STOPPING 也如实返回状态；NOT_STARTED/CLOSED 按 Context 生命周期拒绝 Manual。Manual/Cron 同时进行时第二者 `ALREADY_RUNNING`；Cron 与已有 Dreaming pipeline 互斥独立。

## 6. Runtime 生命周期与 Cron

start 在已验证 DB/VFS 后创建 `DatabaseBackupService` 与 `BackupPipeline`，在 RUNNING 后 activate。`cron=null` 不创建常驻调度资源；cron 使用 Asia/Shanghai 或已校验 IANA timezone，tick 只 merge 信号，不在 Cron 线程执行 backup。close 顺序：先关闭 Backup Cron/通知，等待在途 backup 在 lifecycle shutdownTimeout 内收尾；再 Dreaming、Map、Organization、Extraction、LLM、VFS、DB。start/close 竞态必须回收半构造 service/pipeline；取消 close 不抢关在途 backup 使用的 DB/VFS。
