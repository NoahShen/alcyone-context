## 3. 执行记录

### 3.1 探针实际运行与结果

通过 `./tools/validation/cm1-compat-probe/run-probe.sh` 执行，实测结果：

1. **P1（SQLDelight `JdbcSqliteDriver` real execute 路径行为）**：PASS
   - `fkRightAfterSet=0`、`fkAfterSecondSet=0`：通过真实 execute 路径执行 `PRAGMA foreign_keys=ON`，下一条语句读取返回值仍为 0，证实 `ThreadedConnectionManager` 在语句结束后调用 `closeConnection()` 关闭并移除了物理连接，连接级 PRAGMA 不持续；
   - 驱动级事务（`transacter.transaction`）期间，事务与连接绑定在发起线程（`ThreadLocal`），异程线程检测到 `currentTransaction() == null`；
   - 跨线程调用 `closeConnection()` 被正确拒绝抛出 `IllegalStateException`；
   - 在未通过 `closeConnection` 释放连接的情况下调用 `driver.close()`，物理连接保持开启（`driverCloseIsNoOp=true`），证实 `stock JdbcSqliteDriver` 的 `close()` 为空操作，会造成连接泄漏；
   - **CT04 结论**：CT04 必须显式实现固定物理连接的 Slot 方案（§h7），不能直接使用 stock `JdbcSqliteDriver(fileUrl)`。

2. **P2（Xerial PRAGMA / JSON1 / version 直接断言）**：PASS
   - 建表移至 `query_only=ON` 前，消除了原先将建表失败误认为非法 JSON 拒绝的伪阳性；
   - `journal_mode=wal`、`synchronous=2`、`busy_timeout=5000`、`foreign_keys=1`、`query_only=1`、`sqlite_version=3.49.1` 全部直接断言通过；
   - `json_valid('[1]')=1`、`json_type('["a"]')=array` 直接断言通过；
   - 写入非法 JSON 触发异常，精准断言异常包含 `CHECK constraint failed: json_valid(t)`；
   - `query_only=ON` 触发写入异常，精准断言 `SQLITE_READONLY`。

3. **P3（Online Backup API WAL 源实测）**：PASS
   - 源库真实建立在 `PRAGMA journal_mode=WAL` 下，断言 `sourceJournalMode=wal`；
   - 备份执行时源连接保持处于打开状态（`sourceStillOpenDuringBackup=true`）；
   - 调用 `srcNative.backup("main", dstDb, null)` 返回 `rc=0`，目标文件非空（12288 字节）；
   - 独立只读打开目标文件断言行数正确且 `PRAGMA quick_check` 返回 `ok`。
