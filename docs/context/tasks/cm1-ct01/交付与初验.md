### 2.3 探针关键发现与落地指导

#### P1 发现：`stock JdbcSqliteDriver` 对文件库无法保证物理连接固定
1. **`javap` 字节码核对结果**：
   - `JdbcDriver.close()` 字节码为 `0: return`（空操作）；
   - `ThreadedConnectionManager.close()` 字节码同样为 `0: return`；
   - `ThreadedConnectionManager` 使用 `ThreadLocal<Connection>`，在无外部事务时，`execute()` 执行后立即调用 `closeConnection()` 关闭物理连接并清理 ThreadLocal；
   - 若调用方通过 `getConnection()` 获取连接后直接调用 `driver.close()`，物理连接**不会被关闭，造成连接泄漏**。
2. **运行时实测验证**：
   - 通过 real SQLDelight execute 路径执行 `PRAGMA foreign_keys=ON`，下一条语句读取返回值仍为 `0`（连接已被关闭并重新开辟，连接级 PRAGMA 失效）；
   - 驱动级事务（`Transacter.transaction`）期间，事务与连接强绑定在发起线程（`ThreadLocal`），异程线程看到 `currentTransaction() == null`；
   - 跨线程调用 `closeConnection()` 被明确拒绝抛出 `IllegalStateException: Connections must be closed on the thread that opened them`；
   - 在未通过 `closeConnection` 释放连接的情况下调用 `driver.close()`，连接仍然处于开启状态（`driverCloseIsNoOp=true`）。
3. **CT04 落地决定**：
   - **严禁直接使用 stock `JdbcSqliteDriver(fileUrl)` 作为 Context 的 Slot 实现**；
   - CT04 必须采用**显式固定物理 `Connection` 的适配方案**（如每个 Slot 自持一条独立的 `java.sql.Connection`，或等价的自定义 `JdbcDriver` 实现），连接级 PRAGMA（WAL/FULL/foreign_keys/query_only/busy_timeout）必须直接作用于该物理连接并在整个 Slot 生命周期内持续有效（见 §h7）。

#### P2 发现：PRAGMA 设置生效，JSON1 严格校验
- `PRAGMA foreign_keys=ON`、`synchronous=FULL(2)`、`busy_timeout=5000`、`journal_mode=WAL`、`query_only=ON` 在独立物理连接上设置后全部准确读取；
- `json_valid('[1]') == 1`、`json_type('["a"]') == 'array'` 证明内置 SQLite 3.49.1 完整支持 JSON1；
- `CREATE TABLE p2(t TEXT CHECK (json_valid(t)))` 下写入非法 JSON `'{bad'` 时，被精准拦截并抛出 `SQLiteException: [SQLITE_CONSTRAINT_CHECK] A CHECK constraint failed (CHECK constraint failed: json_valid(t))`；
- `query_only=ON` 生效后执行写入精准被拒：`SQLiteException: [SQLITE_READONLY] Attempt to write a readonly database`。

#### P3 发现：Online Backup API 必须使用 `"main"` 作为数据库名
- 源库在 `journal_mode=WAL` 且源连接保持开启状态下，调用 `NativeDB.backup("main", dstPath, null)` 返回 `rc=0`（`SQLITE_OK`）；
- 目标文件生成 12288 字节，独立只读打开目标库查询数据完整，`PRAGMA quick_check` 返回 `ok`；
- **排雷记录**：`backup` 的第一个参数必须是连接内部的数据库名 `"main"`，若错误传入源文件物理路径，会返回 `rc=1` 且目标文件保持 0 字节。
