## 3. 必测补强

### 3.1 Consolidation Prompt/Schema

- 直接读取 `DreamingTopicConsolidationPrompt.schema()`。
- 断言严格结构至少包含：
  - `"topics"`、四字段 `title/description/keywords/sourceTurnIds`；
  - Topic `additionalProperties=false`；
  - 四字段 required；
  - `sourceTurnIds` integer 数组且 `minItems=1`；
  - 不含 `topicId`/`confidence`/`generatedBy`/`checkpoint`/`createdAt`。
- 对 Discovery 和 Consolidation 都执行缺失资源 fail-fast 反射测试；不得只测 Discovery。

### 3.2 Consolidation 预算等号

- Fake LLM 第一次返回 2 个合法 Discovery Topic，第二次返回合法 Consolidation 结果。
- 通过受控 estimator 构造 **Consolidation** `estimatedInput == maxInputTokens` 且 `input + output reserve + margin == contextWindowTokens`。
- 断言请求数为 2、第二请求为 Consolidation、调用成功返回最终 Topic。
- 保留既有 Consolidation 超限测试，证明超限时 0 Consolidation 调用。

### 3.3 两阶段 JSON Schema 模式

- JSON_SCHEMA 且 Discovery 返回 2 Topics：
  - 第一请求 schema = `DreamingTopicDiscoveryPrompt.schema()`；
  - 第二请求 schema = `DreamingTopicConsolidationPrompt.schema()`；
  - 两请求 responseFormat = JSON_SCHEMA。
- JSON_OBJECT 且同样 2 Topics：
  - 两请求 schema 均为 null；
  - 两请求 responseFormat = JSON_OBJECT。
- 不得只断言 Discovery 请求。

### 3.4 Budget adapter 的 Schema 计费差异

- 使用同一 `LlmDreamingTopicBatchBudget` 路径、同一 batch 和非零 `schemaTokens` 估算器：
  - JSON_SCHEMA 下 Schema Token 进入 requiredTotalTokens/导致超限；
  - JSON_OBJECT 下 Schema Token 不计入并可接受。
- 断言两种模式均不调用 LLM。
