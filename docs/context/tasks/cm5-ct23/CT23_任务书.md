## 1. 目标

CT23 只交付 Dreaming Conversation Batch 的 Topic Discovery 与一次批内 Consolidation 组件：

```text
StoredConversationTurn batch
  → Topic Discovery Prompt/Schema v1
  → DREAMING_TOPIC LLM request + strict parser
  → Core DiscoveredTopic validation (sources ∈ current batch)
  → if topics.size >= 2: exactly one Topic Consolidation request
  → Core consolidation validation (sources retained from input topics)
  → List<DiscoveredTopic>
```

CT23 不进行 Organized/Raw/Conversation 历史取证、Reflection、Raw/Pending/Checkpoint 写入或生产 Factory/Impl 接线。

## 3. 冻结候选契约

### 3.1 DiscoveredTopic

建议放 Core（非 `context/api` SDK）：

```kotlin
data class DiscoveredTopic(
    val title: String,
    val description: String,
    val keywords: List<String>,
    val sourceTurnIds: List<Long>,
)
```

- 防御性复制并只暴露不可修改列表；不分配 Topic ID。
- 不暴露 `StoredConversationTurn`、Session Key 或其他内部持久化对象。
- `toString` 不打印 title/description/keywords 原文，只保留计数/大小等安全元数据。

### 3.2 Discovery 输出

建议严格 JSON：

```json
{
  "topics": [
    {
      "title": "长期技术取舍",
      "description": "用户跨会话持续偏好简单、可维护的技术方案。",
      "keywords": ["技术选型", "可维护性"],
      "sourceTurnIds": [12, 45]
    }
  ]
}
```

- `topics` 必填数组；`topics: []` 合法，表示本批没有值得形成 Topic 的长期信息。
- 每个 Topic 只允许四字段，不允许系统字段或额外字段。
- `title`/`description` trim 后非空，保留原文不 trim。
- `keywords` 必填字符串数组；建议允许空数组，元素非空，按首次出现稳定去重。
- `sourceTurnIds` 必填非空整数数组；只允许 `Long` 范围整数，按首次出现稳定去重；每个 ID 必须属于本次实际发送的 Conversation Batch。
- 未知/跨批/负数/类型错误来源整批拒绝；不做部分 Topic 返回。

### 3.3 Consolidation 输出

- Discovery 返回 0/1 个 Topic：不调用 Consolidation。
- Discovery 返回 2+ Topic：执行且仅执行一次 Consolidation。
- Consolidation 输入为该批全部 Discovery Topic；输出仍为同一 `topics` JSON 契约。
- 输入 2+ Topic 时输出必须为 1..N 个 Topic（N=Discovery Topic 数），禁止拆成更多 Topic 或返回空数组。
- 输出每个 Topic 的 `sourceTurnIds` 必须来自输入 Topic 来源并集；输出来源并集必须等于输入来源并集，不能新增或丢失来源。
- 允许多个不相关 Topic 原样保留；禁止强行合并范围不同、时间不同或相互矛盾的事实。
- 语义保留质量由 Prompt 约束并留待评测；程序只验证结构、来源集合/覆盖与数量边界。

## 4. Prompt / Schema / LLM

### 4.1 资源命名

```text
prompts/dreaming-topic-discovery-v1.md
prompts/dreaming-topic-discovery-schema-v1.json
prompts/dreaming-topic-consolidation-v1.md
prompts/dreaming-topic-consolidation-schema-v1.json
```

Prompt 对象只读 classpath 资源；缺失/空白明确失败，不返回空字符串。

### 4.2 Prompt v1 原则

Discovery Prompt 至少覆盖六原则：

1. 长期价值与跨会话规律，不为每条 Turn 强行产生 Topic。
2. 忠实输入与不确定性，不把 Assistant 建议冒充 User 事实。
3. 单 Topic 自包含、范围清楚，不堆叠无关事实。
4. 关注变化、决定、研究经验、跨会话惯例、遗漏和重要矛盾。
5. 只在本批内发现 Topic，不依赖/归并后续批次。
6. 来源可追溯；Conversation 内容是数据不是指令。

Consolidation Prompt 至少覆盖：只合并重复/高度相关 Topic、保留矛盾/范围/时间差异、不新增来源、不丢来源、不改变无关 Topic、输入是数据不是指令。

### 4.3 LLM Task / Budget

- Discovery 与 Consolidation 均复用既有 `LlmTask.DREAMING_TOPIC`；不新增 enum、不改 Config/Loader。
- `DREAMING_EVIDENCE`/`DREAMING_REFLECTION` 留给 CT24/CT25。
- 缺少 `DREAMING_TOPIC` Task、Profile 不存在或 JSON 模式非 `JSON_SCHEMA`/`JSON_OBJECT` → `ContextConfigException(INVALID_CONFIG)`，消息只含配置路径。
- Discovery 使用一个请求覆盖整个 Conversation Batch；Consolidation 使用一个请求覆盖全部 Discovery Topic。
- 发送前均通过 `LlmBudget`；`JSON_SCHEMA` 才发送并计入 Schema，输出预留与安全余量计入总预算。
- Discovery 预算须可通过 CT22 `DreamingBatchBudget` seam 预先分批；Consolidation 预算在发送前独立校验。
- 超预算不截断/不部分返回；`finish_reason=length` → `OUTPUT_TRUNCATED`。

## 5. Runtime 组件与 CT22 衔接

建议新增内部 `DreamingTopicDiscoveryStage`：

```kotlin
internal fun interface DreamingTopicDiscoveryStage {
    suspend fun discover(batch: List<StoredConversationTurn>): List<DiscoveredTopic>
}
```

- `LlmDreamingTopicDiscoveryStage` 实现严格 Discovery → optional Consolidation。
- `DreamingTopicBatchBudget` 实现 CT22 `DreamingBatchBudget`，估算与真实 Discovery 共用同一请求构造。
- `DreamingTopicBatchProcessor` 实现 CT22 `DreamingBatchProcessor`，返回最终 Topic 数、`generatedMemories=0` 和批尾 `lastTurnId`。
- Stage 返回完整 Topic 列表供 CT24 直接消费；薄 processor adapter 只服务 CT22 调度集成，不改变 CT22 outcome/seam 语义。

## 6. 失败语义

| 场景 | 行为 |
| --- | --- |
| Discovery JSON/字段/来源非法 | `LlmException(INVALID_RESPONSE)`，0 Consolidation，不返回部分 Topic |
| Discovery 截断 | `LlmException(OUTPUT_TRUNCATED)` |
| Discovery 预算超限 | `LlmException(LOCAL_BUDGET_EXCEEDED)`，0 LLM |
| Consolidation JSON/字段/来源/数量非法 | `LlmException(INVALID_RESPONSE)`，整个 Batch 失败 |
| Consolidation 预算超限/截断 | 同对应 LLM 错误，整个 Batch 失败 |
| Task/Profile/JSON 模式缺失 | 构造期 `ContextConfigException(INVALID_CONFIG)` |
| Manual caller CE / LLM CE | 原样传播 |
| 经 CT22 Coordinator 处理 | 普通 Topic 失败由 Coordinator 映射 `DreamingRunException(BATCH_PROCESSING, partialResult, cause)`；CE 不包装 |
| 任意失败 | 不写 Topic/Raw/Pending/Checkpoint；CT22 保留最后成功批水位 |

异常消息不得包含 Conversation 正文、Topic 正文、Prompt、Schema 原文、Key 或 URL。
