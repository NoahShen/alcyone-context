## 1. 契约与默认行为

- `operation_id` UUID；kind 仅 SAFE_REPLACE/PUBLISH_NEW/NATIVE_FILE_MOVE/COPY_FILE_MOVE；保存 source/target URI、mount/storage key、已知 Node ID、阶段、generation、epoch millis、受限诊断枚举。不得保存异常 message、内容、Authorization、URL credentials 或任意自由文本。
- 新建 operation generation=0；每次合法迁移 `WHERE operation_id=? AND generation=?`，expected 不匹配/已关闭必须失败，不能覆盖更新。只追加事实、单调 generation；CLOSED 后不可复活。
- journal 为显式组件注入，**默认 disabled 时既有 Vfs/事务/Storage 调用次数、错误 effect、通知行为不变**。普通 `AlcyoneVfs.create` 不自动开始恢复，不自动重放，不新增公共 API。
- 同一 Runtime/StateBoundary 单写者；不加 lease/fencing/跨进程锁，不支持多进程恢复。reconcile 也经共享 boundary 串行读取。

## 2. 外部写前后的精确接缝

所有 journal begin/advance 都是独立短 SQLite 事务，在持有 `StateBoundary` 时执行；不能持 SQLite 写事务跨 Storage I/O。

| 操作 | 开始/变更前必须持久化 | 物理返回后记录 | 最终同事务关闭 |
| --- | --- | --- | --- |
| safeReplace | 预检及父目录处理完成后、调用 `storage.safeReplace` 前：STORAGE_REPLACE_REQUESTED | STORAGE_REPLACE_OBSERVED | Node+Event+journal CLOSED |
| publishNew | 预检及父目录处理后、调用 `storage.publishNew` 前：PUBLISH_REQUESTED | PUBLISH_OBSERVED | 同上 |
| native file move | 目标全新/源身份/父目录完成后、`storage.move` 前：NATIVE_MOVE_REQUESTED | NATIVE_MOVE_OBSERVED | 同上 |
| copy file move | 源读与长度校验后、目标 `write` 前：TARGET_WRITE_REQUESTED；目标写完并 stat/全部长度校验后、源 `delete` 前：SOURCE_DELETE_REQUESTED | TARGET_WRITE_OBSERVED；SOURCE_DELETE_OBSERVED | Node 路径+Event+journal CLOSED |

- 每一次 progress 写失败都必须停止后续外部写并保留原异常/effect；不能 warn 后继续，不能将失败标为 NONE。若失败发生于物理操作后，保留 PARTIAL/UNKNOWN，并由原操作 ID 留待 reconcile。
- Storage 异常后 best-effort 写受限失败诊断/保留待核对，诊断失败作为 suppressed，不能覆盖 Storage/CE；不得因此自动补偿。
- 最后 `pipeline.commitInsideBoundary` 内 Node/Metadata/Event/journal close 同一 `UnitOfWork.inTransaction`。RecordingScope 必须转发 recovery 视图。close 失败则 Node/Event/journal close 一起回滚，外部文件保留，原 STATE_ERROR+PARTIAL 语义保持。
- 目录 move、普通 write/delete 不接 journal，原行为不变。父目录创建仍按原 effect 报告，不宣称 journal 覆盖目录副作用。

## 3. 只读 reconcile

- 显式构造/调用才运行；可列待核对 operation 并读取单条。对每个 operation 读 source/target Storage stat、对应 Node/path 映射，报告持久阶段、源/目标存在与类型/长度、Node 是否存在/路径/ID、`RECONCILE_REQUIRED`。
- 不把 target 存在推断为整体成功；特别 copy move 要分别报告 target/source，不能因 target 存在关闭操作。
- 不写 journal 阶段（除明确的只读查询）、不改 Node/Metadata/Event、不发事件、不删除临时文件、不重试 Storage 写、不自动 CLOSED。Storage/stat 故障转受限观察错误，报告未知而非成功。
- 默认启动没有 reconcile 调用。普通 Runtime 行为不变。
