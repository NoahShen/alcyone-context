## 1. 待冻结范围

1. **VFS 操作恢复**：Storage 成功而 Registry/跨 Mount 源删除失败时，首版不能假定自动回滚；需明确可持久诊断/恢复入口，不能让普通重启擅自重放外部写或伪造成功。
2. **可靠 Event Consumer**：在既有 Event Log 上增加显式消费进度与重启恢复；重复/乱序/崩溃窗口须可验证，至少 at-least-once，不虚构 exactly-once。不得破坏实时 Flow 或让 Consumer 失败回滚 VFS。
3. **原子发布**：Local FS 备份/Memory Map 临时文件→fsync/原子 rename→目录同步与重启验证；WebDAV 无原生原子 rename 时继续显式拒绝，不能假装完成。

## 2. 方案必须回答

- 恢复数据存哪里、谁拥有锁/进度、单写者与多进程边界；重启是否自动执行，如何避免与现有启动路径冲突。
- Event consumer offset/last-event-id 的事务边界、重复交付、损坏/落后/追赶、关闭中信号与背压；是否只提供 Port/组件而不接默认生产。
- 原子发布的 same-filesystem 限制、临时文件所有权、失败清理、旧文件保留、fsync 目录能力和 Local FS 实跑；WebDAV 显式拒绝。
- 分批写集合、真实 SQLite/Local FS/崩溃窗口测试，与 VFS 既有 81 基线、Context 全量回归和 not-run 清单。
