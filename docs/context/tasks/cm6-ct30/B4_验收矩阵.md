## 2. 验收矩阵

### A01 恢复持久意图、阶段与事务边界

- **要求**：外部写前持久化具体阶段；move 的目标写入与源删除分开；进度写失败停止后续外部写；Node/Event/journal close 使用既有事务边界。
- **已批准证据**：[B1 Architect 复核](B1_Architect复核.md) 第 1 节记录 generation + phase CAS、CLOSED 拒绝、Node/Event/journal close 原子回滚、四操作请求前/外部写阶段/成功 close/default disabled 均通过。
- **真实结果**：B1 Architect fresh Core/Persistence/integration-vfs 命令 exit 0；XML **339 + 58 + 121 = 518**，0 failure/error/skipped。日志 `/tmp/ct30-b1-architect-three.log`。
- **结论**：**PASS（边界内）**。journal 是持久事实记录，不是 Storage/SQLite 分布式事务。

### A02 Schema 分版迁移与失败回滚

- **要求**：v1→v2→v3→v4 分版迁移，旧 Mount/Node/Metadata/Event 保留；失败不得提交新版本或残留半成品结构。
- **已批准证据**：B1 记录真实的 v1→v2→v3、v2→v3 及失败迁移原子回滚；B2 记录真实 v1→v4、v3→v4 与失败 v3→v4 回滚。R1-3 明确验证打开失败后 `user_version=3`、旧 event/journal 可读、无 `event_v4`/`consumer_cursor`/sequence 残留。
- **Schema 身份**：v2/v3/v4 当前 SHA 见 §1.2，分别与 B1/B2 已批准生产 SHA 一致。
- **结论**：**PASS**。

### A03 四类文件操作的恢复接缝与默认禁用

- **要求**：只覆盖文件 safeReplace、publishNew、native move、copy move；默认 Runtime 不自动恢复；目录 move 和普通 write/delete 不扩范围。
- **已批准证据**：B1 记录四操作故障窗口、BEGIN/advance 失败阻断后续外部写、受限诊断、CE 原样传播、默认 disabled 兼容；静态与真实栈均确认 `recoveryJournal = null` 的默认路径保持，公共 Vfs/API 未接 recovery。
- **结论**：**PASS（边界内）**。目录 move、普通 write/delete 仍保留既有 PARTIAL 语义。

### A04 重启、跨进程与只读 reconcile

- **要求**：强杀后 journal/物理事实可读；显式 reconcile 只读 Storage/Node 并报告事实；不自动重放、补偿或伪造成功事件。
- **已批准证据**：B1 记录双 JVM 强杀后的 pending/真实文件事实、独立重开、reconcile 前后 DB/文件摘要不变、UNKNOWN/CLOSED/缺失 Node 安全处理；Architect 明确这些是进程故障点证据，不是真实断电证明。
- **真实结果**：B1 Architect 三模块 exit 0，日志 `/tmp/ct30-b1-architect-three.log`；B2 独立 JVM 子进程在 handler 成功后 `halt(97)`，第二进程 exit 0 并再次投递同一 eventId，cursor 最终为 2。
- **结论**：**PASS（边界内）**。单 Runtime/StateBoundary 单写者；不提供跨进程 lease、自动修复者或 exactly-once。

### A05 v4 event sequence、cursor 与 at-least-once

- **要求**：event 在事务重建后按旧 rowid 稳定编号；整批成功才提交 cursor；处理成功而 cursor 未提交时允许重复；消费者以 eventId 幂等。
- **已批准证据**：[B2 Architect 复核](B2_Architect复核.md) §1～§3 明确 event_id 唯一、sequence 稳定、读批释放 DB 锁、整批成功才 CAS、失败从原 cursor 重读，不跳过。R1 正式测试覆盖 poll、v3→v4、迁移回滚与真实 SQLite 锁/失败关闭。
- **真实结果**：R1 定向 Core 4、Persistence 4、integration 3 + 独立 JVM 1 全绿；五项生产 SHA 全部通过。Lead 最终全量 `./scripts/check` exit 0、137/137，14 模块 **2307=2307**、0 failure/error/skipped，日志 `/tmp/ct30-b2-r1-check.log`。
- **结论**：**PASS（边界内）**。承诺 **at-least-once**；批次成功与 cursor 提交之间崩溃可重投整批，不宣称 exactly-once。

### A06 有界 poll、顺序、失败、取消和 close

- **要求**：无 wakeup 时 poll 保底；同毫秒/倒时钟仍按 sequence；普通失败不跳过、不死信，CE 不吞；close 停止新批并等待已领取批，仅成功批提交。
- **已批准证据**：B2 R1 正式测试直接覆盖无 hint poll、同毫秒两条和倒时钟一条收到 1/2/3；真实慢 handler 时 append 2 秒内完成；失败批 close 后 cursor 不提交且不无限重试。B2 Architect 确认 CE/close 和 cursor 失败边界。
- **结论**：**PASS**。

### A07 Local FS durableDirectorySync 能力

- **要求**：`durableDirectorySync` 默认 false，与 atomic replace/publish 独立；Local FS 实测平台能力；支持时真实 fsync 失败必须报错，不支持时保留既有原子非 durable 行为。
- **已批准证据**：B3 Architect 复核接受默认 `LocalFsStorage.create` 的真实临时挂载根 probe：当前 macOS arm64 输出 `actual=true capability=true`，正式测试不注入 directorySyncer、不 skip。capability false 的既有分支保持。
- **限制**：Linux dirfsync、真实断电、内核崩溃和硬件 flush **NOT-RUN**；不得把 macOS arm64 结果外推为跨平台保证。
- **结论**：**PASS（macOS arm64 边界内）**。

### A08 safeReplace/publishNew 原子发布与临时文件身份

- **要求**：rename/hard-link 后同步目标父目录，清理后同步目录；发布后失败保新；只清本次创建的 staging；未知归属保留，不删外部替换文件；WebDAV durable/publishNew 不虚报。
