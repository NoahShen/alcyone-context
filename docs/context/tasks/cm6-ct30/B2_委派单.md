## 实现契约

1. v3→v4 用单个事务重建 event：`sequence INTEGER PRIMARY KEY AUTOINCREMENT`，`event_id` 唯一且原 event_type/node_id/occurred_at/uri/operation_id/source_uri/target_uri 全保留。旧数据按稳定 rowid 连续编号；新插入由 SQLite 分配，不能用 UUID/occurredAt/实时 Channel 排序。新增 cursor 表（consumer_id 主键、next_sequence/必要时间），查询按 sequence 有界排序。
2. Core 的持久事件读取模型包含 sequence 与完整 EventRecord 字段；提供 reader/cursor Port 与显式 ReliableEventConsumer，放 Core/Persistence，不改现有公共 Vfs/VfsEvent API。consumerId 仅进程内单实例，不实现多进程 lease。
3. 初始 cursor 默认 EARLIEST，显式 LATEST；在短事务内确定起点。读批短事务后立即释放 DB 锁，单协程处理整批；仅整批全部处理成功后另一个短事务推进 cursor。处理成功但 cursor 提交前崩溃会重投，at-least-once；接口/文档明确按 eventId 幂等。
4. 处理失败不跳过、不死信，有界退避持续重试；CE/fatal 原样不吞。batchSize 默认100、合法1..1000；poll默认100ms且可取消，可支持仅提示的 wakeup hint，不得拿 hint 当可靠来源。
5. close 停止领取新批，等待已领取批完成且只提交全部成功批；关闭失败/重开边界清楚，不能提交失败批或无限领取。处理时不得持 StateBoundary/DB transaction。
6. v1→v2→v3→v4、v3→v4 真实迁移：旧事件字段、eventId、sequence 唯一连续，失败迁移原子回滚。既有 EventRecord.append/状态事件事务仍工作。
7. 真实 SQLite + 独立 JVM 测试覆盖：重启 backlog；实时通知丢失仍可靠；同毫秒/乱时钟按 sequence；批处理失败重试不跳过；背压不持锁；处理成功 cursor 提交前强杀重投；close 等已领取；CE；EARLIEST/LATEST；默认实时 Flow 满可丢回归。
