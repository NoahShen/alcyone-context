## 冻结语义

1. **safeReplace**：保留同目录 temp、完整写+file force、类型/长度确认、ATOMIC_MOVE+REPLACE。rename 成功后、`stat` 成功返回前执行目标父目录 `FileChannel.open(parent, READ).force(true)`（或经验证等价 API）。不能回退普通 move/先删后移。
2. **publishNew**：file force/fileKey/hard-link no-clobber 不变；link 成功发布新目标后、清理 staging 前同步父目录。输入/临时身份/no-clobber 语义不变。
3. **目录能力**：构造时在真实挂载根做实际目录 open+force 探测；dir fsync 与 rename/hard-link 分开。探测 false 时保留既有原子非 durable 行为，但 capability 必须 false；探测 true 而实际调用失败不得静默降级。
4. **失败事实**：rename/link 前保旧/无目标；发布成功而 dir fsync/stat/cleanup 失败保新，绝不反向覆盖或删除新目标。公开失败 effect 至少 PARTIAL；如果已有 UNKNOWN 阶段要求更宽，保留 UNKNOWN 不降低。公开消息不泄漏物理路径。
5. **临时清理**：只清 fileKey 一致的自有 temp，orphan 不自动清。发布/清理共享目录项持久边界；清理 unlink 后需要目录同步，其失败如实报告且不能破坏已发布目标。成功返回前不得留下“报告 durable 但目录同步未成功”的路径。
6. **WebDAV**：`durableDirectorySync=false`，atomicReplace/atomicPublishNew false 与显式拒绝保持。
7. **验证边界**：正常/强杀进程重开只能证明进程重启可见与既定故障点；真实断电、内核崩溃、Linux/硬件 flush not-run。macOS 能力探测结果须记录，不能跨平台承诺。

## 必要测试

- 通过测试 seam 断言 safeReplace 在 rename 后 force 正确目标父目录，publishNew 在 link 后 force 正确父目录；顺序不是 rename 前假装 durable。
- rename/link 前失败：旧目标保留/新目标不存在；发布后 dirfsync 失败：新目标保留、effect 正确、错误可诊断且不泄密。
- capability true/false 分支独立；false 不阻断既有原子操作；true 后实际失败不静默。
- safeReplace 成功替换、publishNew 成功新发布/已存在拒绝、临时文件清理与真实进程重开保持；cleanup unlink 后同步失败的 effect/新目标语义有测试。
