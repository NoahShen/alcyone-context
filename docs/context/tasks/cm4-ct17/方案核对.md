## 2. 缺口与冲突

### C1 G3 是明确 VFS 能力缺口

现有 API 没有一种组合能同时满足：

- 不删除旧目标；
- 不暴露半写文件；
- 写入失败时旧内容仍可读；
- 状态/事件仍通过 VFS 提交；
- Context 不直接接触物理路径。

因此必须扩展 VFS；Context 侧 `write + move`、`delete + move`、直接 NIO 均不可接受。

### C2 “失败保旧”与跨存储原子性冲突

即使物理替换原子，VFS Node/Event 状态库仍是另一个 SQLite。物理替换成功后状态提交失败时，不可能用单事务恢复旧文件与旧状态。需把失败分成：

- 原子提交前失败：旧文件完整保留；
- 原子提交成功、状态提交失败：新文件完整存在，但返回 `STATE_ERROR + PARTIAL`，不能声称旧版保留。

如果产品要求任何错误返回都必须旧文件不变，则必须新增旧内容备份/回滚或恢复机制；这不是当前最小 VFS 安全替换能严格保证的。

### C3 WebDAV 能力不一致

Local FS 在 POSIX 同目录 rename 语义下可让读者看到旧文件或新文件，但 Java `ATOMIC_MOVE` 对已有目标的精确覆盖行为仍须实跑确认，不能只凭参数名宣称保证；WebDAV `MOVE` 覆盖行为依赖服务端实现，现有测试也未证明原子替换。首版不得把 WebDAV 普通 MOVE 包装成 `safeReplace` 成功。

### C4 Resource 边界尚未定义

设计要求“只访问允许的 `alcyone://resources/...`”，但当前没有：

- `ResourceMetadata` 字段契约；
- Resource 错误码；
- `loadMeta/read/readStream` 实现；
- URI 范围门与 VFS 异常映射；
- Flow 取消/关流回归。

### C5 流取消不能保证立即打断 native read

`ReaderHandle` 用同一把锁保护 read 与 release；正在阻塞的 native read 返回前，close 无法进入。可保证不泄漏和最终释放，不能保证硬实时中断。若验收要求毫秒级取消，需要先改 VFS native/流生命周期，超出当前“Context Flow 适配”范围。

## 3. G3 推荐方案

### 3.1 API 选项

| 选项 | 描述 | 结论 |
| --- | --- | --- |
| A | `Vfs.safeReplace(uri, content: ByteArray): NodeInfo` | **推荐**；语义显式，误用概率低 |
| B | 给 `WriteMode` 增加 `ATOMIC_REPLACE` | 可行但把高风险能力混入通用 write；默认/第三方实现兼容需额外审查 |
| C | Context 侧 `write + move`/`delete + move` | 不可行，违反 G3 |
| D | Context 直接写物理文件 | 明确禁止，绕过 VFS Node/Event/路由/状态 |

建议签名：

```kotlin
interface Vfs {
    /**
     * 目标文件不存在则创建，存在则完整替换。
     * 禁止先删除目标；后端无法提供一致安全替换时返回 UNSUPPORTED_OPERATION。
     */
    suspend fun safeReplace(
        uri: VfsUri,
        content: ByteArray,
    ): NodeInfo
}
```

接口可为新方法提供默认 `UNSUPPORTED_OPERATION` 实现，避免第三方内存实现源码破坏；`DefaultVfs/AlcyoneVfs` 覆盖真实实现。不得宣称 JVM ABI 不变。

### 3.2 LocalFs 实现建议

1. 在目标同 Mount、同目录创建唯一临时文件；临时文件不登记 Node、不发业务事件。
2. 完整写入并确认临时文件属性；临时内容受 `defaultWriteMaxBytes` 限额。
3. LocalFs Adapter 在挂载根内执行同文件系统原子 replace；可评估 `Files.move(temp,target,ATOMIC_MOVE,REPLACE_EXISTING)`，但 JVM/平台对既有目标与 option 组合的精确语义必须由真实探针确认，并由 Architect 批准最终实现。
4. 成功后由 VFS 提交 Node/Event：目标原本不存在 → `FILE_CREATED`；已存在 → `FILE_WRITTEN`，保留原 Node ID/Metadata。
5. 任何提交前失败清理临时文件；清理失败作为 suppressed 或诊断，不覆盖主错误。
6. 禁止调用 `delete(target)`，禁止把“先删再 rename”当降级，禁止跨 Mount 回退复制。

### 3.3 WebDAV 与能力位

- `StorageCapabilities` 建议增加 `atomicReplace`（或等价能力），默认 `false`；LocalFs 仅在真实探针通过后 `true`。
- WebDAV 未验证时 `safeReplace` 返回 `UNSUPPORTED_OPERATION`，不得执行普通覆盖。
- 若未来要求 WebDAV Map 发布，需单独验证具体服务端 `MOVE Overwrite: T` 的原子性、失败语义和重开行为；不能以本机 WsgiDAV 结果代表所有服务端。

### 3.4 失败矩阵建议

| 阶段/结果 | 旧 Map | 返回 |
| --- | --- | --- |
| 参数/URI/限额/路由/只读/目标目录/能力不支持 | 保留 | 原错误码，`effect=NONE` |
| 临时文件写入/确认失败 | 保留 | 后端错误，按已知临时副作用报告；不发布 |
| 原子 replace 前取消 | 保留 | `CancellationException` |
| 原子 replace 失败且确认目标未变 | 保留 | 后端错误；不得伪造成功 |
| 原子 replace 成功、Node/Event 提交成功 | 新完整版 | 成功 |
| 原子 replace 成功、Node/Event 提交失败 | 新完整版，旧状态可能残留 | `STATE_ERROR + PARTIAL`；由 Architect 明确验收口径 |

## 4. G4 Resource 访问方案

### 4.1 公共 API

建议 CT17 只增加：

```kotlin
interface AlcyoneContext {
    suspend fun loadMeta(uri: String): ResourceMetadata
    suspend fun read(uri: String): ByteArray
    fun readStream(uri: String): Flow<ByteArray>
}
```

- `readStream` 必须冷启动：调用方法本身不打开文件，首次 collect 才打开 VFS 流；每次 collect 独立获取并关闭一条流。
- 不新增 `write/delete/move` 等 Resource 管理入口；管理仍归 VFS。
- 不暴露 `VfsUri`、`NodeInfo`、`StorageStat`、OpenDAL 或物理路径。

### 4.2 `ResourceMetadata` 字段选项

| 选项 | 字段 | 评价 |
| --- | --- | --- |
| A | `uri: String, sizeBytes: Long?, modifiedAt: Instant?` | **推荐最小契约**；VFS 可直接提供，不伪造 MIME |
| B | A + `mimeType: String?` | 可作提示，但 VFS 无 MIME；只能扩展名猜测或恒 null，需明确 |
| C | 直接复用 `NodeInfo` | 拒绝；泄漏 VFS Node ID/type/storage 等内部概念 |

`sizeBytes/modifiedAt` 可为 null，表示后端不提供，不能伪造为 0 或当前时间。

### 4.3 URI 范围与规范化

建议三个方法统一规则：

1. 只接受 `VfsUri.parse(uri)`；任何解析失败映射 `INVALID_URI`。
2. 路径首段必须严格等于 `resources`；`memory`、其他 namespace、逻辑根均 `OUT_OF_SCOPE`。
3. Resource 文件至少包含一个资源路径段；`alcyone://resources`、`alcyone://resources/` 视为越界/非法，而不是目录元数据。
4. `read/readStream` 只允许文件；目录由 VFS `TYPE_MISMATCH` 映射。
5. 不自行解码、拼接或 `startsWith("alcyone://resources")`；避免 `resources-other`、双重编码、query/fragment 绕过。
6. 保留 VFS 的 Mount/只读/后端路径限制，不在 Context 放行。

### 4.4 ByteArray 读取

- `read` 调用 `vfs.read(VfsUri, ReadOptions())`，复用 VFS 默认 16 MiB 可配置上限；不在 Context 再复制一个常量。
- 超限映射 `LIMIT_EXCEEDED`；不得先无界 `openStream().readAllBytes()` 绕过 VFS ByteArray 限额。
- 正常返回原始字节，不解析文本/PDF/图片。

`loadMeta` 建议调用 `vfs.stat` 取得实际类型/大小/修改时间。当前 `stat` 可能懒注册 Node 并写 VFS 状态库，但不发文件变更事件、不改 Resource 内容；若“只读”要求 VFS 状态零写入，则需新增非注册 stat 能力或另定实现，见 D15。

### 4.5 Flow 读取建议

建议固定分块 64 KiB，不新增配置。伪代码：

```kotlin
fun readStream(uri: String): Flow<ByteArray> = flow {
    val target = requireResourceFile(uri)
    val opened = vfs.openStream(target, VfsStreamOptions())
    try {
        while (true) {
            currentCoroutineContext().ensureActive()
            val buffer = ByteArray(64 * 1024)
            val count = withContext(Dispatchers.IO) { opened.stream.read(buffer) }
            if (count < 0) break
            if (count > 0) emit(buffer.copyOf(count))
        }
    } finally {
        opened.close()
    }
}
```

实现时注意：

- `emit` 必须在 Flow 自身上下文中，不能从 `withContext(IO)` 内直接 emit。
- 取消时 `finally` 必须请求关闭；若当前 read 阻塞，关闭会在 read 返回后完成。
- 正常完成、读取异常、采集端取消、下游 `take(n)` 提前结束均走同一关流路径。
- 若已有主异常，close 异常挂 suppressed；无主异常时 close 失败映射具名读取失败。
- 不把已经读到的部分字节声明为完整文件；Flow 异常终止即可。

### 4.6 错误映射建议

新增 `ContextResourceException`（名称可裁定），建议错误码：

| Context 错误码 | 触发 |
| --- | --- |
| `INVALID_URI` | VfsUri 解析失败 |
| `OUT_OF_SCOPE` | 非 `/resources/...` 或空资源路径 |
| `NOT_FOUND` | VFS NOT_FOUND |
| `TYPE_MISMATCH` | 目标是目录 |
| `LIMIT_EXCEEDED` | ByteArray/Flow 超限 |
| `UNAVAILABLE` | 存储/状态/关闭失败 |
| `CLOSED` | Context 或 VFS 已关闭 |

- `CancellationException` 原样传播，不包装。
- 消息只含安全操作类别与逻辑 URI，可含错误码，不回显物理路径、凭据、后端原文。
- 是否公开 cause 需确认；即便保留 cause，也不能改变“上层按 Context 错误码分支”的契约。

## 5. Context 生命周期与所有权

- Resource 方法只在 RUNNING 接受；CREATED/STARTING/STOPPING/CLOSED 分别映射 `NOT_STARTED`/`CLOSED`，不触 VFS。
- `readStream` 是冷 Flow：方法调用时可不检查生命周期，首次 collect 时必须检查；Flow 不应在 Context 关闭后继续打开新流。
- Context 关闭先取消/回收调用方未关的 VFS 流；Flow 自身 finally 仍负责幂等 close。
- 不新增 Resource 后台 Worker、不占用 LLM、不写 Context SQLite。
- `resources` namespace/mount 缺失时建议调用时返回具名配置/不可用错误，不在 create/start 强制，避免破坏 CM1 最小配置兼容。Architect 若要求启动门，需同步调整现有测试与兼容策略。

| D5 | “失败保旧”边界 | 原子提交前保旧；提交后状态失败 PARTIAL、内容完整 | 验收口径自相矛盾 |
| D6 | safeReplace 首建/父目录/未注册文件/目录行为 | 允许首建与补父目录；目录拒绝；未注册文件可替换并登记 | 首版 Map 可能无法首次发布 |
| D7 | Resource 是否文件-only、`/resources/<non-empty>` | **是** | URI/目录边界无法冻结 |
| D8 | `ResourceMetadata` 字段 | `uri/sizeBytes/modifiedAt` 最小集 | 公共 API 不稳定 |
| D9 | Resource 错误类型/cause | 新 `ContextResourceException` + 安全 code；cause 策略明确 | 上层可能耦合 VFS 异常 |
| D10 | Flow 分块与取消保证 | 64 KiB；取消后关闭且不泄漏，不承诺立即打断 native | 验收可能错误要求硬实时取消 |
| D11 | 缺少 resources mount 时启动失败还是调用失败 | **调用时具名失败**，保持最小配置兼容 | 现有 CM1/CM2/CM3 测试与运行兼容性受影响 |
| D12 | `readStream` 多次 collect 语义 | 每次独立冷流、独立开流/关流 | 资源所有权不清 |
| D13 | close 失败优先级 | 有主异常挂 suppressed；正常完成时映射读取失败 | 可能吞掉句柄关闭故障 |
| D14 | 是否允许为测试新增 internal seam | 仅允许只读计数/受控失败注入，不进公共 API | 无法确定性验证关流/失败阶段 |
| D15 | `loadMeta` 是否允许 VFS Node 懒注册副作用 | 接受内部懒注册但不发文件变更事件；严格零状态写则另增非注册 stat | 公共“只读”语义与 VFS 范围不清 |

## 10. 结论

- **G4 可关闭**：现有 VFS `read/openStream` 足够，CT17 只需在 Context 侧增加严格 URI 范围、错误映射、冷 Flow 与关流生命周期。
- **G3 尚未关闭**：现有 VFS 明确缺少安全替换，且“物理替换后状态提交失败”无法用跨存储事务保证旧版保留。必须先由 Architect 批准 VFS 公共能力、后端范围和失败矩阵。
- CT17 建议拆为 **B1 VFS safeReplace** 与 **B2 Context Resource**；B1 是 CT18 的硬前置，B2 不依赖 Map 生成。
- 当前仅完成只读方案；未派发 Worker、未改生产/测试/依赖、未运行真实模型、无 git 写操作。
