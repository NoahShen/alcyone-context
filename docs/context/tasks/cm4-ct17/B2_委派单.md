## 1. 任务

只实现 Context Resource 只读访问：

```text
AlcyoneContext
  → loadMeta(uri): ResourceMetadata
  → read(uri): ByteArray
  → readStream(uri): Flow<ByteArray>

ContextResourceAccess
  → 严格 /resources/<non-empty> URI 范围
  → VFS stat/read/openStream
  → ContextResourceException 安全映射
  → 冷 Flow / 64 KiB 分块 / 每次 collect 独立关流
```

不得实现 Map、Bootstrap、Search/Get、Resource 写入/删除/移动、HTTP 路由或 Resource 语义索引。

## 2. 冻结公共契约

### 2.1 API

在 `AlcyoneContext` 增加：

```kotlin
suspend fun loadMeta(uri: String): ResourceMetadata
suspend fun read(uri: String): ByteArray
fun readStream(uri: String): Flow<ByteArray>
```

新增：

```kotlin
data class ResourceMetadata(
    val uri: String,
    val sizeBytes: Long?,
    val modifiedAt: Instant?,
)
```

- `uri` 为规范化后的 `alcyone://resources/...` 字符串。
- `sizeBytes/modifiedAt` 为 null 表示后端不提供，不伪造 0 或当前时间。
- 不增加 MIME、Node ID、VfsUri、StorageStat、物理路径或目录元数据。

新增：

```kotlin
enum class ContextResourceErrorCode {
    INVALID_URI,
    OUT_OF_SCOPE,
    NOT_FOUND,
    TYPE_MISMATCH,
    LIMIT_EXCEEDED,
    UNAVAILABLE,
}

class ContextResourceException(
    val errorCode: ContextResourceErrorCode,
    message: String,
) : ContextException("[$errorCode] $message")
```

- 不从 VFS 异常复制 cause，避免把 OpenDAL/物理路径异常链暴露到公共 API。
- `CancellationException` 原样传播。
- Context 生命周期错误继续使用 `ContextLifecycleException`：CREATED/STARTING → `NOT_STARTED`；STOPPING/CLOSED → `CLOSED`。

### 2.2 URI 范围

三个方法统一：

1. 只使用 `VfsUri.parse`，禁止字符串前缀/自行解码。
2. 路径首段必须严格等于 `resources`。
3. 至少一个非空资源路径段；`alcyone://resources` 与 `alcyone://resources/` 均 `OUT_OF_SCOPE`。
4. 只允许文件；目录 `TYPE_MISMATCH`。
5. `memory`、其他 namespace、逻辑根、query/fragment、双重编码等均具名失败。

### 2.3 loadMeta

- 调用 `vfs.stat(uri, StatOptions())`。
- 允许 VFS 内部 Node 懒注册，但不得发文件变更事件，不得写 Resource 内容。
- `NodeInfo.type` 必须为 FILE；否则 `TYPE_MISMATCH`。
- 返回 `NodeInfo.uri.toString()`、`storage.sizeBytes`、`storage.modifiedAt`；缺失属性保持 null。

### 2.4 read

- 调用 `vfs.read(uri, ReadOptions())`。
- 复用 VFS 默认 16 MiB 可配置上限，不复制常量，不先无界 `readAllBytes()`。
- 返回原始字节，不解析文本/PDF/图片。

### 2.5 readStream

- 方法调用时不打开文件；首次 collect 才检查生命周期并打开 VFS 流。
- 每次 collect 独立 `openStream` / `close`。
- 固定 64 KiB 分块，不新增配置；零长度文件不 emit。
- 完成、读取异常、collector 取消、`take(n)` 提前结束、Context/VFS 关闭均关流。
- 不承诺打断正在阻塞的 native read；只承诺取消后请求关闭且最终不泄漏。
- 有主异常时 close 异常挂 suppressed；无主异常时 close 失败映射 `UNAVAILABLE`。

## 3. 错误映射

| VFS 结果 | Context 结果 |
| --- | --- |
| VfsUri 解析失败 | `ContextResourceException(INVALID_URI)` |
| 非 `/resources/<non-empty>` | `ContextResourceException(OUT_OF_SCOPE)` |
| `NOT_FOUND` | `NOT_FOUND` |
| `TYPE_MISMATCH` | `TYPE_MISMATCH` |
| `LIMIT_EXCEEDED` | `LIMIT_EXCEEDED` |
| `MOUNT_NOT_FOUND` / `CLOSED` / `STORAGE_*` / `STATE_ERROR` / 其他依赖失败 | `UNAVAILABLE`；若已确定 Context 生命周期关闭，使用 `ContextLifecycleException(CLOSED)` |
| `CancellationException` | 原样传播 |

错误消息只包含操作类别和安全逻辑 URI；不得包含物理路径、凭据、后端原文或 Resource 正文。

## 4. Runtime 接入边界

建议新增 internal `ContextResourceAccess`，仅依赖 `Vfs`：

```kotlin
internal class ContextResourceAccess(
    private val vfs: Vfs,
) {
    suspend fun loadMeta(uri: String): ResourceMetadata
    suspend fun read(uri: String): ByteArray
    fun readStream(uri: String): Flow<ByteArray>
}
```

`AlcyoneContextImpl`：

- RUNNING 时持有 `ContextResourceAccess`；
- CREATED/STARTING 拒绝 `NOT_STARTED`；
- STOPPING/CLOSED 拒绝 `CLOSED`；
- 关闭时清空 Resource access，不把 VFS 引用泄漏到关闭后；
- `readStream` 返回冷 Flow，每次 collect 在 Flow 内重新取得当前 RUNNING Resource access；
- 不修改 `AlcyoneContextFactory`、`ContextConfig`、Loader、SQL、Schema 或 VFS 生产代码。

## 6. 失败矩阵

| 场景 | 结果 |
| --- | --- |
| 空字符串/非法 VFS URI | `INVALID_URI`，零 VFS I/O |
| 非 resources、namespace root、空资源路径 | `OUT_OF_SCOPE`，零 VFS I/O |
| 缺 resources namespace/mount | `UNAVAILABLE`；Context 仍可 start |
| 文件不存在 | `NOT_FOUND` |
| 目录目标 | `TYPE_MISMATCH` |
| ByteArray 超 VFS 限额 | `LIMIT_EXCEEDED` |
| VFS storage/state/closed 故障 | `UNAVAILABLE` 或已确认生命周期 `CLOSED` |
| `loadMeta` 懒注册 | 允许；不发文件变更事件、不写 Resource 内容 |
| Flow 正常完成 | 关闭一次，返回完整分块 |
| Flow open/read 失败 | 终止流，关闭底层资源 |
| collector 取消/`take(n)` | 终止流，关闭底层资源 |
| close 失败且无主异常 | `UNAVAILABLE` |
| close 失败且有主异常 | 主异常保留，close 失败 suppressed |
| CancellationException | 原样传播 |

## 7. 测试矩阵

### 7.1 API

| 用例 | 断言 |
| --- | --- |
| ResourceMetadata | 三字段、null 统计值、无 VFS/物理类型 |
| AlcyoneContext 方法集合 | `loadMeta/read/readStream` 签名和 Flow 返回类型 |
| ContextResourceException | 继承 ContextException；所有错误码可实例化；消息含 code；不暴露 cause 链 |
| API classpath | 仍无 SQLite/Ktor/SnakeYAML/OpenDAL 等基础设施 |

### 7.2 URI 与错误映射

| 用例 | 断言 |
| --- | --- |
| 合法 URI | `/resources/a.txt`、嵌套路径、百分号编码规范化 |
| 非法 URI | scheme、空段、query、fragment、反斜杠、双重编码 → INVALID_URI |
| 越界 URI | root、resources root、memory、其他 namespace、resources-other → OUT_OF_SCOPE |
| VFS 映射 | NOT_FOUND/TYPE_MISMATCH/LIMIT_EXCEEDED/MOUNT_NOT_FOUND/CLOSED/STORAGE_ERROR |
| 取消 | CancellationException 原样传播 |
| 敏感信息 | 异常消息/cause 无物理路径、后端原文、正文 |

### 7.3 loadMeta

| 用例 | 断言 |
| --- | --- |
| 文件元数据 | canonical uri、size/modifiedAt、null 属性 |
| 目录 | TYPE_MISMATCH |
| 懒注册 | `stat` 可调用；无文件变更事件；无 Resource 内容写入 |
| 不存在/缺 mount | NOT_FOUND/UNAVAILABLE |

### 7.4 read

| 用例 | 断言 |
| --- | --- |
| 原始字节 | 二进制逐字节一致，不解析 |
| 默认选项 | 调用 `ReadOptions()`，复用 VFS 16 MiB 可配置上限 |
| 零字节/边界/超限 | 0 正常；等于上限正常；超限 LIMIT_EXCEEDED |
| VFS 故障 | 具名映射，不返回空字节 |

### 7.5 readStream

| 用例 | 断言 |
| --- | --- |
| 冷流 | 方法调用不 open；首次 collect 才 open |
| 分块 | 64 KiB；大于 64 KiB 文件多块；零文件不 emit |
| 多次 collect | 每次独立 open/close，资源计数归零 |
| 正常完成 | 全部字节一致；close 一次 |
| open/read 失败 | 终止；已开资源 close |
| `take(n)` | 提前终止并 close |
| collector 异常 | close 后异常传播 |
| collector 取消 | CE 传播；close 调用 |
| Context 关闭 | 已开流被回收；后续 collect CLOSED |
| close 失败 | 无主异常 → UNAVAILABLE；有主异常 → suppressed |
