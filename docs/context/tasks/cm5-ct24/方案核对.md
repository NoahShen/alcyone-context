## 2. 建议流程

```text
collect(batch, topics)
  └─ one read: full Organized + full Raw snapshots
      ├─ for each topic:
      │    Organized scanner batches (MEMORY_SEARCH)
      │    → Novelty Check (DREAMING_EVIDENCE)
      │       ├─ FULLY_COVERED → TopicEvidence(skipReflection=true)
      │       └─ NEEDS_EVIDENCE
      │            Raw scanner batches (DREAMING_EVIDENCE)
      │            → reverse Organized for each Raw hit
      │            → Conversation Need decision
      │            → resolve selected Raw source chains
      │            → stable Turn lookups + 1 before/1 after same-session neighbors
      │            → TopicEvidence(skipReflection=false)
      └─ DreamingBatchEvidence(topics)
```

## 4. 需 Architect 明确的细项

1. 是否接受 B1/B2 拆分。
2. 是否批准新增只读 `sessionWindowAfter` SQL/ReadOps；若不允许，需明确替代且可证明正确的相邻 Turn 方案。

4. Conversation Need 输出是否采用 `memoryIds`（选择待追溯 Raw），而非布尔/直接 Turn ID。
5. 相邻半径是否固定前 1/后 1；是否需要配置（Lead 推荐不新增配置）。
6. Evidence DTO 是否采用 `DreamingTopicEvidence` + `DreamingBatchEvidence` 推荐形态。
7. RawMemoryRef chain 检测到循环时是否 fail closed（Lead 推荐 fail）。
8. Raw 命中无任何关联 Organized 是否保留为历史证据候选而不是失败（Lead 推荐保留并 Prompt 警示）。

## 5. 测试矩阵候选

### 5.1 Core

- Novelty DTO/三种决策组合、covered IDs 子集/空/未知/重复。
- 三 Prompt 内容：数据非指令、相关≠无增量、全历史、冲突/纠错、Conversation 必要性、无系统字段。
- 三 Schema strict/required/additionalProperties=false。
- 资源缺失/空白 fail-fast。

### 5.2 Organized / Raw Scanner

- 全量 snapshot、分页/批边界、空快照 0 LLM。
- 批内 ID 权限、跨批/未知/空 ID 拒绝；重复稳定去重；最终 id/时间顺序。
- Raw 双 origin、历史补录、失败批次停止后续、预算边界、截断、CE。
- Organized first-layer + Raw reverse Organized 合并去重；缺失反查 ID fail。

### 5.3 Conversation trace

- ConversationTurnRef 四元定位；缺 turn fail。
- RawMemoryRef 单链、菱形、多链、missing、自循环、双节点循环。
- selected Raw → direct/transitive conversation refs；同 Turn 多 Raw 只出现一次。
- 同 Session 前后邻居、同 timestamp id tie-break、不跨 Session、边界首尾、batch turns 不扩邻。
- selected memoryIds 越权/重复/空响应。

### 5.4 Evidence DTO / CT23 composition

- topics=[] → empty evidence。
- FULLY_COVERED skips raw/conversation and sets skipReflection。
- NEEDS_REFLECTION has new/historical separation and stable lists.
- one topic failure aborts whole batch, no partial evidence returned。
- CT23 Topic Stage + CT24 collector with real SQLite + Fake LLM; no writes.

## 6. 风险

- Novelty/Conversation Need 的语义判断无法程序证明；只能保证模型只能从程序提供的 ID 中选择，且 `FULLY_COVERED` 不能无依据。
- 全历史 Raw/Organized 每 Topic 扫描成本高；设计接受，本任务不引入 Embedding/全局索引。
- 新 forward-window SQL 是只读能力补口；若不允许新增，任何基于“不断放大 sessionWindow”的替代都可能读取过多或实现复杂，应重新裁定。
- Fake LLM 不证明真实模型在冲突/纠正/独立证据上的判断质量，CT26 固定集评测仍需保留。
