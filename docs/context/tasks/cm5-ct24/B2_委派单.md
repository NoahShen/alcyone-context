## 2. 冻结契约

### 2.1 Conversation Need

- 只处理 B1 `NEEDS_EVIDENCE` 且 `rawMemories` 非空的 Topic。
- `FULLY_COVERED` 或 Raw candidate 为空：0 Conversation Need LLM，historical Conversation 为空。
- 单请求输入：Topic、Topic 对应 current batch turns、全部 B1 Raw candidates。不得把未命中的全历史 Raw 送入。
- 使用既有 `LlmTask.DREAMING_EVIDENCE`；不新增 enum/Config。
- 严格 JSON：`{"memoryIds":["R-MEM-0001"]}`；`memoryIds` 为字符串数组，可为空，不允许其他字段。
- 每个 ID 必须非空白且属于本次 B1 Raw candidate 集；重复按首次出现稳定去重；跨 Topic/未知/空白整批失败。
- 请求发送前 `LlmBudget.requireWithinBudget`；JSON_SCHEMA 才计/发送 Schema；`finish_reason=length` → `OUTPUT_TRUNCATED`；CE 原样传播。
- Prompt 只要求模型在关键来源、范围/时间不清、证据冲突、用户纠正或独立性问题需要原文核实时选择 Raw。

Core：

```kotlin
class DreamingConversationNeed(val memoryIds: List<String>)
object DreamingConversationNeedValidator
class DreamingConversationNeedValidationException(message: String) : IllegalArgumentException(message)
```

- Validator 接受 candidate ID 集合并返回稳定去重后的防御性副本；异常只含安全规则名，不含正文/ID。

### 2.2 RawMemoryRef 递归追溯

- **Raw 证据口径固定为“全部 B1 Raw hits + chain Raw”**。Conversation Need 的 `memoryIds` 只决定哪些 Raw 作为 Conversation source trace roots，不是 final `rawMemories` 的白名单；不得因未选中追溯而删除已召回 Raw。
- roots 仅为 Conversation Need 选中的 B1 Raw；roots 已存在于 B1 snapshot。
- 对每个 Raw 的 `MemorySourceRef`：
  - `ConversationTurnRef(runtimeId, agentId, sessionId, sessionTurnId)` 通过四元业务键 `findByBusinessKey` 定位；
  - `RawMemoryRef(memoryId)` 递归读取源 Raw。
- 直接/间接链接到的 Raw 全部纳入 `rawMemories`：B1 candidates + chain Raw，按 id 稳定去重、最终 `(createdAt ASC, id ASC)`。
- 重复访问已完成的菱形依赖不失败；检测到 cycle（含自循环）立即整批失败。
- Raw 缺失或 ConversationTurnRef 不可定位立即整批失败；不得静默截断/跳过。
- 幂等访问集合只能用于已完成的 visited 节点，不能掩盖当前 recursion stack 中的 cycle。
- 所有 DB 读取在短 read scope 内完成，LLM 不在 read/write transaction 内。

### 2.3 链中 Raw → Organized 补全

- 对最终全部 evidence Raw（包括 B1 candidate 与 recursive chain Raw）逐一执行：
  1. `organizedMemories.findOrganizedByRaw(rawId)` 取全部关联 id；
  2. `findByIds(ids)` 全部回读。
- 任一关联 id 缺失整批失败。
- 与 B1 first-layer/reverse Organized 合并，按 id 稳定去重并 `id ASC`。
- Raw 无关联 Organized 保留为历史原始证据，不失败；Prompt/CT25 继续负责“未关联 Raw 不是当前事实”的语义。

### 2.4 相邻 Turn

- 每个从 `ConversationTurnRef` 定位出的关键 Turn：同 Session 前 1/后 1。
- 前邻居复用 `sessionWindow(anchor timestamp, anchor id, limit=2)`，过滤 anchor 后取同 Session 前一条。
- 后邻居新增只读 `sessionWindowAfter(runtimeId, agentId, sessionId, afterTimestamp, afterId, limit)`：
  - `timestamp > ? OR (timestamp = ? AND id > ?)`；
  - `ORDER BY timestamp ASC, id ASC LIMIT ?`；
  - anchor 排除自身；参数化；不跨 Session；升序直出。
- 本批 Topic `sourceTurnIds` 不扩邻；只对 Raw 来源链定位出的关键 Turn 扩邻。
- 每个关键 Turn 仅扩一层；邻居不再递归扩邻。
- 任何 anchor/邻居读失败整批失败。

### 2.5 去重与排除

- Raw by `id`；Organized by `id`；Conversation by 四元业务键 `(runtimeId, agentId, sessionId, sessionTurnId)`。
- 同一 Turn 被多个 Raw/多条链引用只出现一次。
- `historicalConversationTurns` 排除与当前 Topic `newConversationTurns` 同业务键的 Turn。
- historical 最终按 `(timestamp ASC, id ASC)`；new 保持 current batch 原顺序。
- 同 Turn 多 Raw 只计一个独立 Turn；不得通过重复 Raw 放大独立证据数。

### 2.6 最终证据 DTO

Runtime internal：

```kotlin
enum class DreamingEvidenceDecision { FULLY_COVERED, NEEDS_REFLECTION }

class DreamingTopicEvidence(
    val topic: DiscoveredTopic,
    val decision: DreamingEvidenceDecision,
    val newConversationTurns: List<StoredConversationTurn>,
    val organizedMemories: List<OrganizedMemory>,
    val rawMemories: List<RawMemory>,
    val historicalConversationTurns: List<StoredConversationTurn>,
)

class DreamingBatchEvidence(val topics: List<DreamingTopicEvidence>)
```

- 全部列表防御性复制并不可修改；`toString` 只含 decision/计数，不含 Topic/Turn/Raw/Organized 正文或业务 ID。
- B1 `FULLY_COVERED` → final `FULLY_COVERED`：organized 非空；raw/historical 空；new turns 保留。
- B1 `NEEDS_EVIDENCE` → final `NEEDS_REFLECTION`：raw/historical 可空；organized 为合并后集合。
- NEEDS 时 final `rawMemories` 固定包含**全部 B1 Raw hits ∪ recursive chain Raw**；Need 选择仅缩小 Conversation/history 追溯范围，不缩小 Raw 证据集合。
- 不提供 Reflection 行为，不写任何权威表。

### 2.7 CT23 组合 Stage

新增 Runtime internal `LlmDreamingEvidenceStage`：

```kotlin
suspend fun collect(batch: List<StoredConversationTurn>): DreamingBatchEvidence
```

- 空 batch 维护 CT23 既有失败语义（由 discovery stage 处理），不返回伪造空证据。
- 顺序：`DreamingTopicDiscoveryStage.discover` → B1 collector → B2 Conversation Need/trace/enrich → final DTO。
- 任一 Topic/链/邻居失败整个 batch 无部分 Evidence；CE 原样传播。
- 不修改 `DreamingTopicBatchProcessor`/outcome，不接触 Coordinator。

## 6. 必测矩阵

### 6.1 Core / Parser / Prompt

- Conversation Need DTO 防御性复制、空合法、重复首次稳定去重。
- 空白/未知/跨 candidate ID 拒绝；异常无正文/ID。
- 资源与 Schema strict/required/additionalProperties=false/string array。
- Conversation Prompt 六条内容级断言逐片段验证：数据非指令、candidate 边界、必要原文、冲突/范围/纠正/独立性、严格 JSON、无系统字段。
- Parser unknown/missing/type/围栏/前后文本/重复 key/截断拒绝，错误无 cause/正文。

### 6.2 sessionWindowAfter

- 空表；anchor 前/中/后；首 Turn/尾 Turn；anchor 自身排除。
- 同 timestamp 的 id tie-break：只返回 `(timestamp,id)` 严格大于 anchor 的行。
- 不跨 runtime/agent/session；升序；limit 与 0/负数。
- SQL 参数化、7 参数、query plan 使用 `idx_turn_session_time`；Schema SHA 不变。
- ReadOps、TxOps、Repository 三入口语义一致。

### 6.3 Conversation Need / LLM

- FULLY/空 Raw：0 Conversation Need LLM。
- NEEDS 非空：单请求包含 Topic/turns/all candidates，ID 子集校验，empty 合法。
- 预算等号通过/超限 0 LLM；JSON_SCHEMA/JSON_OBJECT schema 发送/省略。
- 非法/跨候选/空白/truncate/CE/失败原子性；异常无 Prompt/正文/Key/URL。

### 6.4 Raw Ref / Conversation trace

- direct ConversationTurnRef 四元业务键（内部 id 不同也可定位；错误业务键失败）。
- RawMemoryRef 单层/多层/菱形；链中 Raw 全部进 final evidence。
- 自循环/两节点及以上循环 fail closed；missing raw/turn 失败。
- 所有 chain Raw 均做 Raw→Organized 反查；反查缺失失败；无关联 Raw 保留。
- 同 Turn 多 Raw、重复 ref、多个 roots 稳定去重。
- current topic turns 从 historical 排除；同业务键即使内部 id 不同也排除。

### 6.5 Neighbors / Final Evidence / Stage

- 前/后各 1；首尾边界；同 timestamp id tie-break；跨 Session 不拼接。
- 本批 source turns 不扩邻；邻居不递归扩邻；多 anchor 邻居 union 去重。
- FULLY final：raw/historical 空、organized 非空。
- NEEDS final：全部 B1 Raw hits ∪ chain Raw、列表防御性复制、稳定排序、安全 toString、无写操作。
- 真实 SQLite：CT23 discovery/consolidation → B1 collector → Need → chain → reverse → business-key turn → SQL neighbors → final evidence。
- Fake LLM 验证阶段顺序、请求任务/schema/预算；LLM 不在 DB read/write context；CE/失败无部分结果。

预计新增 30～45 个测试，不注水、不砍矩阵。
