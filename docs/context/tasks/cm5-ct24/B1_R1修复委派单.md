1. `LlmDreamingEvidenceCollector.truncated()` 固定写入 `task=LlmTask.DREAMING_EVIDENCE`。Organized Scanner 实际使用 `MEMORY_SEARCH`，截断时错误归属任务。

这影响错误可观测性与分类一致性，不改变业务输出/证据选择决策。

- Organized Scanner 的 `OUTPUT_TRUNCATED` → `LlmException.task = MEMORY_SEARCH`，profile/model 使用 `memorySearchProfile` 安全元数据。
- Novelty/Raw Scanner 的 `OUTPUT_TRUNCATED` → `LlmException.task = DREAMING_EVIDENCE`，profile/model 使用 `evidenceProfile`。
- Organized Parser/批内 ID 校验失败 → `INVALID_RESPONSE` 且 `task = MEMORY_SEARCH`。
- Novelty/Raw Parser/ID/Novelty Validator 失败 → `INVALID_RESPONSE` 且 `task = DREAMING_EVIDENCE`。
- 反查 organized ID 缺失仍整批失败；不得把持久化关系缺失误标成模型正文错误之外的新公共 API/错误码。
