## 1. 目标

CT24 只交付 Dreaming Topic 的分层证据收集与来源核实组件：

```text
List<DiscoveredTopic> + current Conversation Batch
  → full Organized snapshot
  → MEMORY_SEARCH scanner batches → relevant Organized
  → Novelty Check (DREAMING_EVIDENCE)
      ├─ FULLY_COVERED → skip topic reflection
      └─ NEEDS_EVIDENCE ↓
  → full Raw snapshot（EXTRACTION + DREAMING）
  → DREAMING_EVIDENCE Raw scanner batches → candidate Raw
  → raw → organized_memory_source 反查全部当前 Organized
  → Conversation Need decision → selected Raw
  → resolve RawMemory.sources / RawMemoryRef chains → stable ConversationTurnRef
  → same-session previous/next neighbors + current batch turns
  → List<DreamingTopicEvidence> for CT25 Reflection
```

CT24 不生成 Insight/Raw/Pending，不推进 Checkpoint，不接 Factory/Impl。

## 3. 冻结候选契约

### 3.1 Novelty Check

输入：Topic、Topic 对应 batch Conversation、全部 relevant Organized candidate。

建议输出：

```json
{"decision":"NEEDS_EVIDENCE","coveredOrganizedIds":[]}
```

或：

```json
{"decision":"FULLY_COVERED","coveredOrganizedIds":["O-MEM-0001"]}
```

- `decision` 只允许 `NEEDS_EVIDENCE`/`FULLY_COVERED`。
- `NEEDS_EVIDENCE` 必须携带空 `coveredOrganizedIds`。
- `FULLY_COVERED` 必须携带非空、去重、全部属于本次 relevant Organized 的 ID 子集。
- 没有任何 Organized candidate 时程序不调用 Novelty 模型，直接 `NEEDS_EVIDENCE`；不能用空候选证明覆盖。
- “检索到相关 Organized”不能自动跳过；只有模型明确 `FULLY_COVERED` 且通过程序 ID 权限校验才跳过 Raw 层。
- Prompt 必须定义：只有确认现有 Organized 已充分表达 Topic，且没有新增事实、限定条件、变化、纠错或值得验证的矛盾时，才可 `FULLY_COVERED`。

### 3.2 Organized 层

- 每批一次 `database.read` 读取完整 Organized 快照，按 `id ASC` 稳定。
- 每个 Topic 以全量 Organized 作为候选，不做 Agent/Domain 硬过滤。
- 用 CT20 `MemorySearchPrompt.scannerMessages`、`JsonMemorySearchResponseParser`、`MemorySearchIdValidator`、`TokenBatchPlanner` 与 `LlmBudget` 组合批次。
- Scanner 每批 `candidate_ids` 必须属于该批；跨批/未知/空白失败。
- 首批出现稳定去重，最终映射回原快照并按 `id ASC` 排序。
- 任一批失败/截断/预算超限/非法 ID → 当前 Topic/Batch 失败，不返回部分 Organized。

### 3.3 Raw 层

- Novelty 为 `NEEDS_EVIDENCE` 时执行。
- 每批一次读取完整 Raw 快照，按 `(createdAt ASC, id ASC)`；不过滤 `generatedBy`。
- 每个 Topic 对全量 Raw Scanner；用 `TokenBatchPlanner` 分批。
- Raw Scanner 输出 `candidate_ids`，每批 ID 必须属于该批；稳定去重，最终映射回原快照。
- 命中 Raw 后由 `organizedMemories.findOrganizedByRaw(rawId)` 反查全部 Organized ID，并 `findByIds` 全部回读；缺失任一关联 → 失败。
- 第一层和反查层 Organized 合并后按 `id ASC` 稳定去重。
- 未关联 Organized 的 Raw 可作为历史原始证据候选，但 Prompt 不得把它当当前事实。

### 3.4 Conversation Need

- Raw candidates 非空时，执行一次 `DREAMING_EVIDENCE` Conversation Need 请求。
- 建议输出严格 JSON：`{"memoryIds":["R-MEM-0001"]}`；可为空。
- 每个 `memoryId` 必须属于本次 Raw candidate 集；重复按首次稳定去重；不得选择跨 Topic/Raw 批 ID。
- 空候选不调用 LLM，直接跳过 Conversation 追溯。
- Prompt 只在关键来源、范围/时间不清、证据冲突、用户纠正或独立性问题需要原文核实时选择 Raw。

### 3.5 RawMemoryRef 与 Conversation 追溯

- 当前 `RawMemory.sources` 已支持：
  - `MemorySourceRef.ConversationTurnRef(runtimeId, agentId, sessionId, sessionTurnId)`
  - `MemorySourceRef.RawMemoryRef(memoryId)`
- 对 Conversation Need 选中的 Raw：
  - `ConversationTurnRef` 通过四元业务键 `findByBusinessKey` 定位，不能把 SQLite 内部 Turn ID 当长期来源。
  - `RawMemoryRef` 递归读取源 Raw，收集其直接/间接 ConversationTurnRef；链中 Raw 全部纳入证据。
  - 重复 Raw/Turn 稳定去重；菱形重复不失败。
  - 缺失 Raw/Turn 或检测到 RawMemoryRef 循环 → 当前 Batch 失败。
- 本批增量 Conversation 已由 Topic `sourceTurnIds` 提供，可直接复用，不重复回读。

### 3.6 相邻 Turn

- 相邻定义为**同一 `(runtimeId, agentId, sessionId)` Session 内**按 `(timestamp, id)` 的前一条与后一条，不使用全局 SQLite id 相邻。
- 每个追溯出的关键 Turn 默认取前 1/后 1 条邻居；本批 Topic 来源 Turn 不额外扩邻。
- 前后邻居必须来自同一 Session；跨 Session 不拼接。
- 若现有 ConversationReadOps 无“后向窗口”，建议新增只读 `sessionWindowAfter`：
  - `timestamp > anchor OR (timestamp == anchor AND id > anchorId)`
  - `ORDER BY timestamp ASC, id ASC LIMIT ?`
  - 参数化 SQL、只读、无 Schema/索引/迁移修改。
- 任何锚点/邻居读取失败均使当前 Batch 失败；不静默忽略。

### 3.7 证据 DTO（CT25 输入）

建议 Runtime internal：

```kotlin
enum class DreamingEvidenceDecision { FULLY_COVERED, NEEDS_REFLECTION }

data class DreamingTopicEvidence(
    val topic: DiscoveredTopic,
    val decision: DreamingEvidenceDecision,
    val newConversationTurns: List<StoredConversationTurn>,
    val organizedMemories: List<OrganizedMemory>,
    val rawMemories: List<RawMemory>,
    val historicalConversationTurns: List<StoredConversationTurn>,
)

data class DreamingBatchEvidence(
    val topics: List<DreamingTopicEvidence>,
)
```

- 列表防御性复制；稳定排序。
- `FULLY_COVERED`：organized 非空，raw/historical conversation 为空；CT25 跳过 Reflection。
- `NEEDS_REFLECTION`：可包含 0..N Raw 与 0..N Conversation；new batch turns 始终可复用。
- `historicalConversationTurns` 排除已存在于 `newConversationTurns` 的同一业务键。
- 同一 Turn 被多个 Raw 引用时只出现一次，防止被当作独立多份证据。

## 4. LLM 绑定 / Prompt / 预算

### 4.1 Task 映射

- Organized 层 Scanner：复用既有 `LlmTask.MEMORY_SEARCH`。
- Novelty Check / Raw Scanner / Conversation Need：共同使用既有 `LlmTask.DREAMING_EVIDENCE`。
- 不新增 Task enum、不改 Config/Loader。
- 两个 Task 均须映射存在 Profile 且 JSON 模式为 `JSON_SCHEMA`/`JSON_OBJECT`；否则构造期 `ContextConfigException(INVALID_CONFIG)`。

### 4.2 Prompt 资源

```text
prompts/dreaming-evidence-novelty-v1.md
prompts/dreaming-evidence-novelty-schema-v1.json
prompts/dreaming-evidence-raw-v1.md
prompts/dreaming-evidence-raw-schema-v1.json
prompts/dreaming-evidence-conversation-v1.md
prompts/dreaming-evidence-conversation-schema-v1.json
```

- 三份 Prompt 均声明输入是数据不是指令、程序级 ID 边界、严格 JSON、禁止 Markdown/解释。
- Novelty 必须说明“相关 ≠ 无增量”，冲突/纠错/范围变化不能提前结束。
- Raw Prompt 必须覆盖所有历史 Raw、不得因 Organized 已召回而省略全量扫描、未关联 Raw 不是当前事实。
- Conversation Prompt 必须针对来源忠实性、冲突、时间/范围、用户纠正与独立性选择必要 Raw。

### 4.3 预算

- 所有请求发送前经 `LlmBudget`；`JSON_SCHEMA` 才发送并计 Schema。
- Organized/Raw Scanner 使用 `TokenBatchPlanner` 串行分批；任一批失败整体失败。
- Novelty/Conversation Need 为单请求全量相关输入；超预算明确失败，不截断/部分返回。
- `finish_reason=length` → `OUTPUT_TRUNCATED`。
- LLM/DB 事务外；事务内不做网络。

## 5. 失败语义

| 场景 | 行为 |
| --- | --- |
| Organized/Raw 任一批 LLM/预算/非法 ID/截断 | 当前 Topic/Batch 失败，无部分证据 |
| Novelty 非法/覆盖 ID 越权 | 当前 Batch 失败 |
| Raw 反查关联 Organized 缺失 | 当前 Batch 失败 |
| Conversation Need 非法/跨候选 ID | 当前 Batch 失败 |
| RawMemoryRef 缺失或循环 | 当前 Batch 失败 |
| ConversationTurnRef 不可定位 | 当前 Batch 失败 |
| 相邻 Turn 读取失败 | 当前 Batch 失败 |
| CE | 原样传播 |
| 经未来 CT25/Coordinator 接线 | 普通证据失败映射 `DreamingRunException(BATCH_PROCESSING)`；Checkpoint 不前移 |

内部异常可携带安全的 stage/cause，不回显 Conversation/Raw/Topic 正文、Prompt、Key/URL。
