CT04已通过整体独立验收；授权原CM1 Paseo Lead组织CT05，按Paseo worker配置委派实现。状态IN_PROGRESS；本任务不包含CT06 Runtime或CT07 Ingestion/HTTP服务。

## 目标与依据

实现Core现有五类Repository Port、ReadOps/TxOps及ContextDatabase适配，复用CT04的固定连接/短作用域执行器与SQLDelight生成查询。依据三份Context设计、CT01实施契约、CT03既有类型契约、开发计划CT05条目；相关源码在context/core的repository与ContextDatabase/ReadContext/TransactionContext，基础实现在context/persistence-sqldelight。

## 实现边界

- Persistence承担SQL与JSON/时间映射；Core保持接口和领域模型，不引入JDBC/SQLDelight/YAML/Ktor实现依赖。普通suspend Repository通过执行器取得短读作用域；事务内同步Ops绑定同一scope/session和物理连接，禁止开启嵌套事务、裸连接或把作用域活性延续到回调之外。
- SQLDelight已有驱动/生成机制继续复用，不新增连接池或自行重写驱动。业务接线不得放宽F1文件保护、F2关闭或F3受控JDBC/SQL边界；确需新增最小白名单能力须提供实际消费证据并复核，不裸透delegate。
- Conversation按四元业务键幂等：同规范化时间和有序正文返回原ID且createdAt不变；异内容冲突具名TURN_CONFLICT。覆盖窗口锚点/排序、全状态最近createdAt空闲判定、pending计数、id范围边界。
- RawMemory不可变插入与查询；OrganizedMemory及来源双向关联、Pending出入队/全局存在性；来源完整性按现有外键契约，不提前实现Extraction/Organization流水线。
- 条件状态更新返回真实影响行数；全局updatedAt水位按既有Port契约在同一写事务读取/分配/推进，使用common TimeCodec固定毫秒格式；Checkpoint仅expected匹配且next向前时CAS，不能无条件覆盖或伪造更新成功。
- 不擅改Schema/公开契约、不增加业务流水线、Runtime/HTTP、Map或备份，不修改VFS。遇设计冲突先由Lead给具体差异与最小建议，交Architect决定。

## 验收

1. 使用真实文件SQLite覆盖所有Port的正常/空结果/边界/约束，查询结果与独立库状态对应；JSON顺序/转义/时间文本往返，不靠返回值代替落库断言。
2. 通过真实ContextDatabase适配验证原子提交/失败回滚、读快照、同scope多Repository共享事务、重复/并发业务键、CAS竞争与影响行数、来源正反查询、全局水位；取消和异常链沿用CT04契约。
3. Ops/生成查询在scope后及跨线程不能继续使用，普通prepared/绑定/查询连续调用正常，不破坏已验收关闭与资源所有权。作用域入口不绕开CT04保护。
4. 对设计要求的核心查询提供EXPLAIN QUERY PLAN证据，核对既有索引适配；不为测试硬编码整个计划文本，不无依据新增索引。
5. 最终必要模块测试、格式与全工程回归通过；实际源码/XML计数及最终SHA自洽。81既有基线不变；证据在.local/validation/cm1/，任务/方案/交付文档在本目录。
