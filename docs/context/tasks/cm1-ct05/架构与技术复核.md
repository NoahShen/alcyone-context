## 2. R1 严格JSON解码不能将非字符串正文强制转换

ContextJsonCodecs.decodeMessage仅使用JsonPrimitive.contentOrNull，未检查isString。真实文件库独立探针B1Probe.java将合法JSON数组中的content分别写为数字123和布尔true，Repository读取成功并返回字符串123/true。probe.log记录两条 accepted 结果，javac/java均退出0。

这违反ChatMessage.content:String与当前严格解码契约，错误类型静默改变数据，亦可能使重复请求被错误视为内容一致。要求role/content都显式验证JSON字符串类型，数值、布尔、null、对象/数组及缺字段拒绝为ContextPersistenceException(PERSISTENCE_UNAVAILABLE)，异常完整链不回显原文；正常字符串数字/布尔文本、转义/中文及消息顺序保持。无需修改Schema/Core/API或CT04保护层。
