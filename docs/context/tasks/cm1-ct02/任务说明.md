CT02 是 CM1 的第二个任务，负责建立 Context 系统的工程骨架与基础构建验证入口。

### 1.1 覆盖范围
- **工程骨架**：
  - `context/api`
  - `context/core`
  - `context/persistence-sqldelight`
  - `context/runtime`
  - `context/server`
  - `integration-tests/context`
- **构建规范与工具链**：
  - `settings.gradle.kts` 注册与项目访问器配置
  - `gradle/libs.versions.toml` 依赖追加与单一来源锁定
  - 继承根 `build.gradle.kts` 的 `jvmToolchain(21)`、JUnit Platform 与 Spotless ktlint 约束
- **依赖方向与隔离验证**：
  - 静态编译依赖与运行依赖树核验
  - 架构边界隔离性单元测试断言（通过 ClassLoader 验证未授权基础设施类在 classpath 上不存在）
- **真实测试与对齐**：
  - 每个新模块编写 2 个最小骨架测试，覆盖包名规范、关键依赖类型实例化、架构边界隔离与端到端集成

- **既有 VFS 模块兼容保证**：
  - 既有 81 个 VFS 源码与构建文件 SHA256 100% 一致（零侵入）
  - 既有 828 个常规单元与集成测试全部无损通过
  - `./scripts/t31-consumer-check` SDK 打包与消费者端验证 100% 通过

### 1.2 严格守界与禁止事项
- **不修改既有模块**：严禁修改 `vfs/*`、`common/*`、`integration-tests/vfs/*` 下的任何文件；
- **不篡改既有版本**：`gradle/libs.versions.toml` 既有依赖项版本（Kotlin 2.2.21, SQLDelight 2.1.0, Coroutines 1.10.2 等）严格保持不变；
- **不提前发布**：不得将 context 模块加入根 `build.gradle.kts` 的 `publishableArtifacts`；
- **不添加伪造生产类**：`src/main/kotlin` 不创建伪造的业务类，不在 `AlcyoneContext` 上声明未实现的 TODO 桩代码；
- **不越界修改入口文件**：不修改 `README.md`、`开发计划.md`、`开发进度.md`、根 `AGENTS.md`，不修改 Architect 维护的 `架构与技术复核.md`；
