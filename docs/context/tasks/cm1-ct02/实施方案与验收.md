```kotlin
pluginManagement { repositories { mavenCentral(); gradlePluginPortal() } }
dependencyResolutionManagement {
    repositoriesMode.set(RepositoriesMode.FAIL_ON_PROJECT_REPOS)
    repositories { mavenCentral() }
}

rootProject.name = "alcyone-context"
include(
    ":common",
    ":vfs:api",
    ":vfs:core",
    ":vfs:storage",
    ":vfs:persistence",
    ":vfs:runtime",
    ":integration-tests:vfs",
    ":vfs:git-backup",
    ":context:api",
    ":context:core",
    ":context:persistence-sqldelight",
    ":context:runtime",
    ":context:server",
    ":integration-tests:context",
)
```

### 2.2 类型安全访问器优势与对齐
开启 `TYPESAFE_PROJECT_ACCESSORS` 后，Gradle 自动为所有子项目生成强类型的 Kotlin DSL 访问器：
- `:context:api` → `projects.context.api`
- `:context:core` → `projects.context.core`
- `:context:persistence-sqldelight` → `projects.context.persistenceSqldelight`（中划线自动映射为驼峰）
- `:context:runtime` → `projects.context.runtime`
- `:context:server` → `projects.context.server`
- `:vfs:runtime` → `projects.vfs.runtime`

这与 CT01 实施契约 §a 及本任务提示中要求的依赖声明语法完全一致，杜绝了基于字符串的 `project(":context:api")` 容易发生的拼写错误，且重构时由编译器静态检查。

### 6.2 第二重：828 个原有常规套件零回归验证

### 6.3 第三重：独立 JVM 进程 VFS 消费者回归验证

- **验证流程**：
