## 2. 冻结行为

### 2.1 公共 API

`AlcyoneContext` 增加：

```kotlin
suspend fun bootstrap(): BootstrapContext
```

- 第三方默认实现返回 `memoryMap=null`、`mapStatus=UNKNOWN`、`BootstrapContext.DEFAULT_CAPABILITIES`。
- 真实 `AlcyoneContextImpl` 覆盖该方法，但只读进程内 Map 缓存，不查 SQLite 水位、不读 VFS、不调 LLM、不发刷新任务。
- 未启动：`ContextLifecycleException(NOT_STARTED)`。
- STOPPING/CLOSED：`ContextLifecycleException(CLOSED)`。
- RUNNING 且未配置 `context.memoryMap`：`memoryMap=null`、`mapStatus=MISSING`、固定 capabilities。
- RUNNING 且已配置：返回 Pipeline 当前原子快照；允许初始 `UNKNOWN`，破损 Map 不返回正文，旧有效 View 可随 `UNKNOWN` 返回。
- capabilities 固定使用 `BootstrapContext.DEFAULT_CAPABILITIES`。

### 2.2 Factory / 配置门

- 公共 `create()` 签名不变；仍为零副作用。
- 在任何资源打开前调用 `validateMemoryMapBinding(contextConfig.memoryMap, ownedLlmConfig)`。
- `context.memoryMap=null`：不建 Map pipeline、不要求 LLM。
- 显式配置：必须存在 `MEMORY_MAP` Task/Profile，Profile 为 `JSON_SCHEMA`/`JSON_OBJECT`；否则 `ContextConfigException(INVALID_CONFIG)`。
- Factory 内部测试重载可增加默认为 null 的 Memory Map 注入项，至少支持：
  - `memoryMapGenerator: MemoryMapGeneratorPort?`
  - `memoryMapTickSource: MemoryMapPeriodicTickSource?`
  - `memoryMapPipelineConfigurator: ((MemoryMapPipeline) -> Unit)?`
- 公共 `create()` 必须传 null，生产默认构造 `MemoryMapGenerator` + `MemoryMapPublisher` + `MemoryMapService`。
- 不新增公共 Factory 参数、公开类型或依赖。

### 2.3 Start / Activate

- Map pipeline 只使用本次 start 已取得的真实 DB/VFS/LLM；create 仍零资源。
- 显式配置时构造一个 `MemoryMapPipeline`；未配置时零 pipeline。
- Pipeline 在 RUNNING 发布前可以启动并持有启动检查信号，但不得读取/生成/发布。
- RUNNING 发布后依次激活 Organization、Extraction、MemoryMap；`start()` 不等待 Map 生成完成。
- 任一构造/start 失败走既有启动失败路径：逆序释放已取得 Map/Organization/Extraction/LLM/VFS/executor，最终 CLOSED，共享原失败。

### 2.4 Organization Wakeup

- 生产默认必须把 OrganizationMapWakeup 接到当前 MemoryMapPipeline.requestRefresh()。
- Organization 完整轮次成功提交 Organized 后调用；仅合并信号，不等待 LLM/发布。
- 若 Map 未配置、Pipeline 已 closing 或请求未被接受，通知安全 no-op，不影响已提交 Organization。
- 保留测试注入能力，但公共生产路径不得继续使用永久 no-op。

### 2.5 Close / Worker 状态

- 进入 STOPPING 的同一状态锁内同步封闭 MemoryMapPipeline 准入。
- 关闭顺序冻结为：`Extraction → Organization → MemoryMap → LLM → VFS → executor`。
- MemoryMapPipeline 先停 Cron、再取消并真实 join Coordinator；并发 close 共享失败。
- `ContextStatus.workers` 仅在 `context.memoryMap` 已配置时增加 `"memoryMap"`：
  - CREATED/STARTING：IDLE
  - RUNNING：映射 internal `MemoryMapWorkerStatus` 的 IDLE/RUNNING/FAILED
  - STOPPING/CLOSED：STOPPED
- 单轮 Map 失败记录 FAILED，不把整个 Context 标 FAILED。

## 4. 测试矩阵

### 4.1 API

| 用例 | 必须断言 |
| --- | --- |
| 第三方默认 bootstrap | null + UNKNOWN + DEFAULT_CAPABILITIES |
| Bootstrap 模型 | 不复制、不持久化、无副作用 |

### 4.2 Factory / 配置门

| 用例 | 必须断言 |
| --- | --- |
| 未配置 memoryMap | create/start 不要求 LLM、不建 pipeline |
| 缺 LLM | create 抛 INVALID_CONFIG，零文件副作用 |
| 缺 MEMORY_MAP Task/Profile | create 抛 INVALID_CONFIG |
| PROMPT_ONLY | create 抛 INVALID_CONFIG |
| JSON_SCHEMA/JSON_OBJECT | create 通过；start 建一个 pipeline |

### 4.3 Runtime Wiring / Bootstrap

| 用例 | 必须断言 |
| --- | --- |
| NOT_STARTED / CLOSED | bootstrap 分别抛 NOT_STARTED / CLOSED，零 I/O/刷新 |
| RUNNING 未配置 | null + MISSING + fixed capabilities |
| RUNNING 已配置初始状态 | UNKNOWN/null 或最近缓存快照，不等待生成 |
| 启动检查异步 | start 不被受控阻塞的生成卡住；activate 后只执行一次 |
| ContextStatus | memoryMap 条目 IDLE/RUNNING/FAILED/STOPPED 映射正确 |
| 生成成功后 bootstrap | 返回 STALE View；下一轮水位追平 CURRENT；不读 VFS |

### 4.4 Organization Wakeup

| 用例 | 必须断言 |
| --- | --- |
| 生产 effective wakeup | 调用后只请求 MemoryMapPipeline；不等待 LLM |
| Map 未配置 | wakeup 安全 no-op |
| closing/closed | request false/no-op，不抛普通失败 |
| Organization 已提交 | 通过 effective wakeup 触发 Map 刷新 |

### 4.5 Lifecycle / Failure

| 用例 | 必须断言 |
| --- | --- |
| RUNNING 前 | Map 0 读取、0 生成、0 发布 |
| STOPPING 窗口 | 同锁 beginClosing；新请求拒绝 |
| close 顺序 | Extraction → Organization → MemoryMap → LLM → VFS → executor |
| 在途生成 | close 取消并真实 join；Context 最终 CLOSED |
| Map 单轮失败 | workers.memoryMap=FAILED，Context 仍 RUNNING |
| start 构造/启动失败 | Map 资源逆序释放，共享原失败，CLOSED |
| 并发 close | 共享主失败与 suppressed，不重复关闭 |

### 4.6 Runtime E2E

使用真实 Context SQLite + 真实 VFS LocalFs + JDK HTTP stub，禁止真实模型：

- 预置 Organized Memory，真实 `AlcyoneContextFactory.create()` + `initializeDatabase()` + `start()`。
- `MEMORY_MAP` 请求经真实 Ktor client 发送到本机 Fake LLM HTTP stub。
- 等待 bootstrap 出现完整 Map；断言 Front Matter/正文、`STALE` 或 `CURRENT`、capabilities。
- 重复 bootstrap 不新增 LLM 请求、不查 DB/VFS。
- `ContextStatus.workers.memoryMap` 可观测。
- close 后 bootstrap=CLOSED；无后台生成残留。
