## 4. 验收组织与执行顺序

每个里程碑启动时通过 Paseo 创建一个 Lead，同一里程碑修复尽量复用原 Lead。Architect 给出范围、设计章节、允许修改目录、任务边界和验收标准；Lead 通过 Paseo 委派 Worker 实现，Architect 不直接编写生产代码或越级调度 Worker。

每项按 `TODO → IN_PROGRESS → IN_REVIEW → DONE` 推进：Worker 提交代码、自测与 Commit；Lead 检查实际 Diff 并独立初验后立即交 Architect。Architect 独立检查代码、依赖、关键路径和必要测试；未通过则列明问题、影响、修复要求和重验用例，交原 Lead 组织修复。未复核通过不得标 DONE 或启动依赖任务。

每个里程碑结束另做集成复核，记录 Commit 范围、已完成项、实际命令/结果、风险与结论。普通实现决策自主推进；涉及权威结构、事务语义、外部协议或 VFS 核心能力变更时，先完成可审查的差异方案，再按用户要求确认重大变更。

测试证据分别标识 Worker 自测、Lead 初验和 Architect 独立执行。测试数量只是辅助信息，必须有直接状态断言；`BUILD SUCCESSFUL`、日志“完成”或 Fake 的成功都不能代替真实 SQLite 原子性、实际进程重启和文件内容验证。
