## 1. 目标与依据

本计划首先交付可独立嵌入宿主应用的 **Alcyone VFS Kotlin SDK**：支持 Local FS 与 WebDAV、稳定 Node Identity、Mount 路由、Metadata、持久化状态和变更事件。完成此阶段后，再规划 Memory Governance 和 Retrieval。

依据：

- [AGENTS.md](../AGENTS.md)：开发约束与设计差异说明。
- [项目搭建说明 v0.1](<Alcyone Context 项目搭建说明 v0.1.md>)：工程模块和当前阶段边界。
- [Personal Context System 设计说明 v0.3](<Alcyone Personal Context System 设计说明 v0.3.md>)：整体定位。
- [VFS 技术设计 v0.2](vfs/Alcyone_Virtual_File_System_VFS_技术设计_v0.2.md)：技术路线与核心语义。
- [VFS 核心用例 v0.2](vfs/Alcyone_VFS_核心用例文档_v0.2.md)：功能与异常验收依据。

当前仓库已有通过独立验收的 T05 七模块根构建骨架与项目内工具链，以及 T06 已实现的公共 API 类型与 `common` 工具库；尚无 Core、Storage、持久化和 Runtime 的业务实现；T04 独立验证工程保留。下列任务的能力是否已实现，以实际状态与验收证据为准。核心任务共 32 项，具体进度以任务表为准；开发计划本身的编写不计入实现进度。

暂不纳入核心交付：Memory 治理、Retrieval、HTTP Server、CLI 产品、分布式部署、独立 MQ、通用 Storage Watch、完整 Secret System、S3 等额外后端。

## 6. 开发 Agent 的执行协议

设计文档保持简洁：每项用 2～3 句话说明规则，配一个简单例子；沿用已有架构与用例，不重复展开。具体字段、SQL 和锁可在对应开发任务中明确并同步必要结论，不作为继续推进的文档前置条件。

由用户逐项将任务交给专门的开发 Agent 实现，再交回当前对话独立验收。当前对话只维护文档、审查和运行必要检查，不添加或修改实现代码；开发 Agent 按以下顺序执行：

1. 阅读 `AGENTS.md`、本计划、相关设计决策与当前代码，确认前置任务实际可用。
2. 将任务更新为 `IN_PROGRESS`，记录负责人。存在其他工作区改动时，保留并避免覆盖。
3. 完成任务范围内的实现与有针对性的测试；需要改变已确定契约时同步设计和受影响任务。每份被修改文档均在前部列出本次主要修改及涉及章节。
4. 执行验收命令，记录实际结果。基础设施不可用或验证未完成时，准确记录限制。
5. 完成自测后更新为 `IN_REVIEW`，提交变更清单和验收证据，等待用户交回当前对话验收；不自行标记 DONE 或继续下一任务。
6. 验收问题交回开发 Agent 修复；独立验收通过后由验收方记录 `DONE`。

任务指令模板：

```text
请按 AGENTS.md 和 docs/开发计划与进度.md 执行任务 Txx：<任务名称>。
先核实前置任务及相关设计决策，再完成本任务的实现、测试和文档。
不要自动扩大到后续里程碑。遇到契约缺口时在对应设计文档记录决策；
重大歧义说明影响和建议，同时继续不受影响的工作。
完成自测后更新为 IN_REVIEW，填写负责人和验收证据，报告命令、结果和剩余问题。
等待用户安排独立验收，不自行标记 DONE 或继续下一任务。
```

设计任务可以直接交给 Agent 开始。后续实现任务应以已验收的契约作为输入；不能把本文的决策问题或建议当成已经完成的设计。
